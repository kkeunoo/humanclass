# 1. 연산자란?

연산자는 값에 계산이나 비교 등의 동작을 수행하는 기호입니다.

```js
10 + 20
```

구성:

```text
10, 20
→ 피연산자

+
→ 연산자
```

JavaScript 연산자는 다음과 같은 작업에 사용됩니다.

```text
숫자 계산
값 할당
증가·감소
두 값 비교
조건 결합
결과 선택
자료형 확인
```

두 원본 모두 HTML의 `<head>` 안에 내부 `<script>`를 작성합니다.

본문은 비어 있으며 결과는 개발자 도구 Console에서 확인합니다.

# 5. 기본 증가 계산

공통 원본:

```js
let j = 10;

j = j + 1;
j += 1;
j++;
```

각 문장이 차례로 실행됩니다.

```text
초기 j = 10
j = j + 1 → 11
j += 1    → 12
j++       → 13
```

세 줄은 “같은 작성법을 비교만 한 것”이 아니라 실제로 모두 실행됩니다.

---

# 6. 기본 감소 계산

공통 원본:

```js
j--;
```

앞선 계산 후 `j`가 13이므로 결과는 12입니다.

```text
j-- 실행 전 13
j-- 실행 후 12
```

단독 문장으로 사용하면 전위와 후위 모두 최종적으로 1을 증가하거나 감소시킵니다.

---

# 7. 전위 증가와 감소

공통 원본:

```js
++j;
--j;
```

현재 값을 먼저 1 증가 또는 감소시킵니다.

이 코드들은 각각 독립 문장이므로:

```text
++j → 13
--j → 12
```

최종 `j`는 다시 12가 됩니다.

---

# 8. 복합 할당 연산자

```js
j += 1
```

다음 표현과 비슷한 의미입니다.

```js
j = j + 1
```

다른 예:

```js
j -= 2
j *= 3
j /= 4
j %= 5
```

| 연산자 | 예 | 의미 |
| --- | --- | --- |
| `+=` | `a += 2` | `a = a + 2` |
| `-=` | `a -= 2` | `a = a - 2` |
| `*=` | `a *= 2` | `a = a * 2` |
| `/=` | `a /= 2` | `a = a / 2` |
| `%=` | `a %= 2` | `a = a % 2` |

---

# 9. 증가·감소 연산자는 단항 연산자

원본은 증가·감소를 학습합니다.

```js
k++
++k
k--
--k
```

이 네 연산자는 피연산자 하나에 적용되므로 모두 **단항 연산자**입니다.

```text
k++
→ 피연산자 k 하나

++k
→ 피연산자 k 하나
```

전위와 후위의 차이는 단항·이항 구분이 아니라 **표현식이 평가될 때 반환되는 값의 시점**입니다.

---

# 10. 내 코드의 부정확한 주석

내 코드:

```js
//단항(++k_더하기를 먼저 함), 이항(k++_더하기를 뒤에 함)연상자의 차이
// ex) -5(단항), 7-5(이항)
```

보존해야 할 부분:

- `연상자`는 `연산자`의 오타입니다.
- `++k`를 단항, `k++`를 이항으로 구분한 설명은 부정확합니다.
- `++k`와 `k++`는 모두 단항 연산자입니다.
- `-5`는 단항 마이너스입니다.
- `7 - 5`의 `-`는 두 피연산자를 사용하는 이항 뺄셈입니다.

정확한 구분:

```text
++k → 전위 증가 단항 연산자
k++ → 후위 증가 단항 연산자
-5  → 단항 부정
7-5 → 이항 뺄셈
```


`k++`가 독립 문장으로 실행된 후 출력하므로 `k`는 11입니다.

```text
출력: k++ 이후 : 11
```

# 12. 독립 문장에서 `++k`

공통 원본:

```js
++k;
console.log('++k 이후 : '+ k)
```

앞선 `k++`로 11이 된 뒤 `++k`가 실행되므로 12입니다.

```text
출력: ++k 이후 : 12
```

독립 문장에서는 전위와 후위 모두 값 자체를 1 증가시킵니다.

# 13. 후위 증가의 반환값

공통 원본:

```js
k = 10;

console.log('k++', k++)
console.log('k', k)
```

첫 번째 출력에서 `k++` 표현식은 증가 전 값 10을 반환합니다.

그 후 변수 `k`는 11이 됩니다.

```text
k++ → 출력값 10
k   → 현재값 11
```

예상 출력:

```text
k++ 10
k 11
```

---

# 14. 전위 증가의 반환값

공통 원본:

```js
k = 10;

console.log('++k', ++k)
console.log('k', k)
```

`++k`는 먼저 11로 증가한 뒤 그 값 11을 반환합니다.

```text
++k → 출력값 11
k   → 현재값 11
```

---

# 15. 전위와 후위 핵심 비교

| 표현 | 변수 변경 | 표현식이 반환하는 값 |
| --- | --- | --- |
| `++k` | 먼저 증가 | 증가된 값 |
| `k++` | 평가 후 증가 | 증가 전 값 |
| `--k` | 먼저 감소 | 감소된 값 |
| `k--` | 평가 후 감소 | 감소 전 값 |

독립 문장에서는 최종 변수 변화만 보면 같지만, 다른 연산 안에 들어가면 결과가 달라집니다.

# 16. `m = k++ + 1`

공통 원본:

```js
k = 10;
let m = k++ + 1;
```

평가 순서:

```text
1. k++가 기존 값 10을 반환
2. k는 11로 증가
3. m = 10 + 1
```

결과:

```text
m = 11
k = 11
```

강사님 원본에는 다음 확인용 주석이 있습니다.

```js
// m? 11, k? 11
```

내 코드에는 이 주석이 없습니다.

# 17. `m = ++k + k++`

공통 원본:

```js
k = 10;
m = ++k + k++;

console.log(`m: ${m}, k: ${k}`)
```

평가 순서:

```text
초기 k = 10

++k
→ k를 11로 변경
→ 11 반환

k++
→ 현재 값 11 반환
→ 이후 k를 12로 변경

m = 11 + 11
```

결과:

```text
m = 22
k = 12
```

# 18. 내 코드의 설명 주석

내 코드:

```js
//++k에서 k가 11이 된 이후에 값이 뒤로 넘어가기때문에 뒤에 있는 k도 11이 되어있고
//k가 11인 상태에서 ++하기 떄문에 12가 출력됨
```

보존할 오타:

```text
떄문에
→ 때문에
```

설명의 핵심 흐름은 맞지만 “12가 출력됨”만으로는 `m`과 `k`가 구분되지 않습니다.

정확한 결과:

```text
m에는 22가 저장된다.
최종 k는 12가 된다.
```

# 21. `k-- + ++k - --k` 계산

평가 순서:

```text
초기 k = 10

k--
→ 10 반환
→ k는 9

++k
→ k는 10
→ 10 반환

--k
→ k는 9
→ 9 반환

```


# 22. 내 코드의 독립 표현식

# 23. 내 코드의 증감 설명 검토

내 코드:

```js
//--나 ++는 계산할 때 우선으로 바로 적용하고, 뒤에++ 또는 --는 계산 후 그 다음값에 적용
//k가 10에서 뒷--가 되어 9로 넘어간 상태에서 앞++하여 10, 그 다음에 앞--되어 9가 됨
```

전위는 먼저 변경된 값을 반환하고, 후위는 기존 값을 반환한 뒤 변수를 변경한다는 핵심은 담겨 있습니다.

다만 “계산 후 그 다음값에 적용”보다 다음처럼 설명하면 명확합니다.

```text
후위 연산자는 현재 표현식에는 변경 전 값을 제공하고,
해당 피연산자의 값은 그 직후 증가 또는 감소한다.
```

# 24. 복잡한 증감식의 실무 권장안

다음 코드는 학습용으로는 실행 순서를 연습할 수 있습니다.

```js
m = k-- + ++k - --k
```

실무에서는 읽기 어렵고 실수가 생기기 쉽습니다.

```js

const second = k

k -= 1
const third = k

m = first + second - third
```

가능하다면 증감 연산과 다른 계산을 한 문장에 섞지 않는 편이 좋습니다.

# 26. 논리 연산자

내 코드 주석:

```js
//and, or, not 논리연산자
```

공통으로 다루는 연산자:

```text
&& → AND

!  → NOT
```

원본은 Boolean 값을 사용해 결과를 확인합니다.

---

# 27. 논리 AND

공통 원본:

```js
let boolA = true;
let boolB = false;

let result = boolA && boolB;
console.log('and : ', result)
```

두 값이 모두 truthy일 때 오른쪽까지 평가하고 결과를 반환합니다.

Boolean 예제에서는:

```text
true && false
→ false
```

---

# 28. 논리 OR

공통 원본:

```js
result = boolA || boolB;
console.log('or : ', result)
```

Boolean 예제에서는 하나라도 true이면 true입니다.

```text
true || false
→ true
```

결과:


# 30. Truthy와 Falsy 확장 학습

원본은 `true`와 `false`만 사용하지만 논리 연산자는 Boolean 이외의 값에도 적용됩니다.

대표 falsy 값:

```js
false
0
-0
0n
""
null
undefined
NaN
```

그 외 대부분의 값은 truthy입니다.

```js
Boolean("0")  // true
Boolean([])   // true
Boolean({})   // true
```

---

# 31. 논리 연산자의 반환값

`&&`와 `||`는 항상 Boolean만 반환하는 것이 아닙니다.

```js
"회원" && "로그인 완료"
// "로그인 완료"

"" || "기본값"
// "기본값"
```

원본에서는 Boolean만 사용해 결과가 true 또는 false로 보입니다.

---

# 32. 단락 평가

```js
left && right
```

왼쪽이 falsy이면 오른쪽을 평가하지 않을 수 있습니다.

```js
left || right
```

왼쪽이 truthy이면 오른쪽을 평가하지 않을 수 있습니다.

이를 short-circuit evaluation, 즉 단락 평가라고 합니다.

조건부 함수 호출 등에 활용할 수 있지만 읽기 어려워지지 않도록 주의합니다.

# 33. 비교 연산자 결과

내 코드 주석:

```js
//비교연산자 true or false로 나옴
```

비교 연산 결과는 Boolean입니다.

공통 원본:

```js
console.log('같은가? ', boolA == boolB)
console.log('같지않은가? ', boolA != boolB)
```

현재 값:

```text
boolA = true
boolB = false
```

결과:

```text
true == false  → false
true != false  → true
```

# 34. 느슨한 동등 비교 `==`

공통 원본:

```js
let n = 3
let o = "3"

console.log("n == o", n == o)
```

결과:

```text
true
```

`==`는 필요할 경우 비교 전에 타입 변환을 수행합니다.

문자열 `"3"`이 숫자 3과 비교되면서 숫자로 변환될 수 있습니다.

---

# 35. 내 코드의 `==` 설명 검토

내 코드:

```js
//javascript 한정으로 숫자와 문자여도 값이 같다고 인식함
```

이 설명은 지나치게 넓습니다.

숫자와 문자열이면 언제나 같다고 판단하는 것이 아닙니다.

```js
3 == "3"       // true
3 == "03"      // true
3 == "3개"     // false
0 == ""        // true
```

정확한 표현:

```text
느슨한 동등 연산자 ==는 비교 과정에서 타입 강제 변환을 수행할 수 있다.
변환된 값이 같으면 true가 될 수 있다.
```

# 36. 느슨한 부등 비교 `!=`

내 코드에는 다음 출력이 추가되어 있습니다.

```js
console.log("n != o", n != o)
```

현재 값에서는:

```text
3 != "3"
→ false
```

강사님 코드에는 이 출력이 없습니다.

`!=` 역시 타입 강제 변환을 수행할 수 있습니다.

# 38. 엄격한 동등 비교 `===`

공통 원본:

```js
console.log("n === o", n === o)
```

결과:

```text
false
```

숫자 `3`과 문자열 `"3"`은 값의 표현이 비슷해도 타입이 다릅니다.

`===`는 `==`와 달리 동등 비교를 위해 타입을 강제로 맞추지 않습니다.

# 39. 내 코드의 `===` 설명 검토

내 코드:

```js
//===은 값도 같고 형식도 같은가를 확인 (문자, 숫자 등)
```

여기서 `형식`보다 `자료형`이라는 표현이 정확합니다.

개선 표현:

```text
===는 두 피연산자의 타입이 같고 값도 같은지 검사한다.
```

객체의 경우에는 내용이 같아 보이는지가 아니라 같은 객체 참조인지 비교합니다.

```js
{} === {} // false
```

# 40. 엄격한 부등 비교 `!==`

공통 원본:

```js
console.log("n !== o", n !== o)
```

결과:

```text
true
```

타입이 다르므로 엄격하게 같지 않습니다.

실무에서는 특별한 이유가 없다면 `==`, `!=`보다 `===`, `!==`를 우선하는 경우가 많습니다.

# 41. 동등 연산자 비교표

| 표현 | 결과 | 이유 |
| --- | --- | --- |
| `3 == "3"` | `true` | 타입 변환 후 비교 |
| `3 != "3"` | `false` | 타입 변환 후 같음 |
| `3 === "3"` | `false` | 타입이 다름 |
| `3 !== "3"` | `true` | 타입이 다름 |
| `3 === 3` | `true` | 타입과 값이 같음 |

# 69. 결합 방향

```text

→ 8
```

# 70. 표현식과 문장

표현식은 값을 만듭니다.

```js
const result = 10 + 10 - 9
```

# 83. 면접·복습 포인트

## Q1. 전위 증가와 후위 증가의 차이는 무엇인가요?

전위 증가는 변수를 먼저 증가시키고 증가된 값을 반환합니다. 후위 증가는 기존 값을 반환한 후 변수를 증가시킵니다.

## Q2. `++k`와 `k++`는 각각 단항·이항 연산자인가요?

아닙니다. 둘 다 하나의 피연산자에 작용하는 단항 연산자입니다.

## Q3. `k = 10; m = ++k + k++;`의 결과는 무엇인가요?

첫 `++k`가 11을 반환하고, `k++`도 현재 값 11을 반환한 후 k를 12로 만듭니다. 따라서 m은 22, k는 12입니다.

## Q4. `&&`와 `||`는 항상 Boolean을 반환하나요?

아닙니다. 단락 평가 과정에서 피연산자 중 하나를 그대로 반환할 수 있습니다.

## Q5. `3 == "3"`과 `3 === "3"`의 차이는 무엇인가요?

`==`는 타입 변환 후 비교하여 true가 될 수 있고, `===`는 타입 변환 없이 비교하므로 false입니다.

## Q6. 왜 엄격한 동등 연산자를 우선하나요?

암묵적 타입 변환으로 인한 예기치 않은 비교 결과를 줄이고 의도를 명확히 하기 위해서입니다.

## Q7. `typeof null`은 무엇인가요?

`"object"`입니다. null 여부는 `value === null`로 확인하는 것이 명확합니다.

## Q8. 삼항 연산자는 언제 사용하는 것이 적합한가요?

간단한 조건에 따라 두 값 중 하나를 선택할 때 적합합니다.

## Q9. 몫을 구할 때 `parseInt(number)`보다 적합한 방법은 무엇인가요?

양수 내림은 `Math.floor()`, 소수 부분 제거는 `Math.trunc()`를 검토합니다.

## Q10. `toFixed(2)`의 반환 타입은 무엇인가요?

문자열입니다.

## Q11. 1000 / 794를 둘째 자리에서 절삭하면 얼마인가요?

1.25입니다. 일반적인 반올림은 1.26입니다.

## Q12. 나머지 연산자는 어떤 실무 문제에 활용할 수 있나요?

짝수·홀수 판별, 페이지 묶음, 순환 인덱스, 잔액과 거스름돈, 균등 분배의 남은 수량 계산 등에 활용할 수 있습니다.

# Key Summary

- 연산자는 값에 계산, 비교, 할당, 조건 선택 등의 동작을 수행한다.
- `j = j + 1`, `j += 1`, `j++`는 모두 실행되므로 값이 세 번 증가한다.
- `++k`, `k++`, `--k`, `k--`는 모두 단항 연산자다.
- 전위 증가는 먼저 값을 바꾸고 변경된 값을 반환한다.
- 후위 증가는 기존 값을 반환한 뒤 값을 바꾼다.
- `k = 10; m = k++ + 1`의 결과는 m 11, k 11이다.
- `k = 10; m = ++k + k++`의 결과는 m 22, k 12이다.
- `k = 10; m = k-- + ++k - --k`의 결과는 m 11, k 9이다.
- 내 코드의 `++k`는 단항, `k++`는 이항이라는 설명은 부정확하다.
- 내 코드의 `연상자`, `떄문에`는 원본 오타다.
- 독립된 `10 + 10 - 9`는 계산되지만 결과를 사용하지 않는다.
- `&&`는 AND, `||`는 OR, `!`는 NOT 연산자다.
- 논리 연산자는 항상 Boolean만 반환하는 것이 아니라 피연산자를 반환할 수 있다.
- `==`와 `!=`는 타입 강제 변환을 수행할 수 있다.
- `===`와 `!==`는 타입을 강제로 맞추지 않고 비교한다.
- 실무에서는 특별한 이유가 없다면 엄격 비교를 우선 검토한다.
- `typeof 3`은 `"number"`, `typeof "3"`은 `"string"`이다.
- 삼항 연산자는 `조건 ? 참 값 : 거짓 값` 구조다.
- `num % 2 === 0`으로 짝수 여부를 판별할 수 있다.
- 내 코드는 홀수 예제, `!boolB`, `n != o`를 추가했다.
- 구매 가능 수량은 나눗셈의 정수 몫, 남는 돈은 나머지로 구한다.
- 10,000원으로 4,800원 상품은 2개 사고 400원이 남는다.
- 8,000원에서 15% 할인하면 6,800원이다.
- 1234의 십의 자리 이하를 버리면 1200이다.
- `1000 / 794`를 둘째 자리에서 절삭하면 1.25, 반올림하면 1.26이다.
- `toFixed(2)`는 반올림된 문자열을 반환한다.
- 17,000원은 5,000원권 3장과 1,000원권 2장으로 나눌 수 있다.
- 강사님 문제 3의 `q3_4`는 계산하지만 사용하지 않는다.
- 강사님 문제 5는 계산 변수만 있고 출력문이 없다.
- 내 코드는 문제 결과를 템플릿 리터럴과 단위로 출력한다.
