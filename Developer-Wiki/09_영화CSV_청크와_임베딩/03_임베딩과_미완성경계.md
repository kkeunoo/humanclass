## 1. 이 장에서 배울 것

한 청크씩 요청하는 방식과 여러 청크를 묶는 방식을 구별한다. 응답 index와 원래 청크의 대응, 숫자 표현 방식과 차원, actions 준비와 helpers.bulk 전송을 설명한다. 아직 없는 그래프·추천 평가까지 완성으로 확대하지 않는다.

## 2. 무엇이며, 왜 필요한가

### 같은 청크를 다른 요청 모양으로 보낼 수 있다

Gemini 함수는 각 청크의 content를 하나씩 임베딩 요청에 넣는다. OpenAI 함수는 content를 목록으로 모으고 최대 2047개씩 잘라 요청한다. 2047은 이 코드가 정한 묶음 크기다. 실제 서비스의 모든 입력 한도·토큰 합계·현재 계정 제한을 이 숫자 하나로 보장할 수는 없다.

받은 벡터는 해당 청크와 정확히 짝을 이루어야 한다. OpenAI 응답 data의 index는 **그 요청 안의 입력 위치**다. 원본은 index 순으로 정렬한 뒤 last_index로 전체 청크 목록의 현재 위치에 벡터를 넣는다. 두 번째 묶음에서 응답 index는 다시 0부터일 수 있으므로 요청 안 위치와 전체 위치를 구별한다.

| 구분 | 원본 Gemini | 원본 OpenAI |
| --- | --- | --- |
| 입력 | 청크 하나의 content | 여러 content 목록 |
| 응답 | embeddings[0].values | data의 index·embedding |
| 요청 차원 | 768 | 768 |
| 입력 청크 | embedding 필드 제자리 추가 | embedding 필드 제자리 추가 |
| 반환 | actions 목록 | actions 목록 |

`encoding_format='float'`는 숫자 목록 표현을 요청한다. Base64는 다른 표현 형식이며 비밀키로 보호하는 암호화가 아니다. 원본의 “기본값 Base64·양방향 암호화” 메모는 바로잡아야 한다. API의 기본 표현과 SDK가 내부적으로 처리하는 표현도 같은 것으로 추측하지 말고, 여기서는 명시한 float를 기준으로 읽는다.

### 준비된 actions는 아직 저장 결과가 아니다

각 action은 ES_INDEX·movieId-chunk_index·청크 본문을 담는다. 이 함수를 반환한 뒤 최신 bulk 경로가 인덱스 존재를 확인하고 없으면 매핑을 만든 다음 helpers.bulk를 호출한다. dense_vector의 dims=768은 임베딩 요청 크기와 맞춰야 한다. 같은 차원이어도 서로 다른 모델의 벡터를 한 공간처럼 섞으면 안 된다.

원본 bulk는 인덱스 확인 전에 makeChunk와 외부 임베딩을 먼저 수행한다. 적재 대상·설정 검사가 실패해도 앞의 외부 요청은 이미 실행됐을 수 있다. 외부 임베딩과 저장은 하나의 자동 롤백 작업이 아니다. 이 순서를 코드에서 읽는 것이 중요하다.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 필요한 파일 전체.** 같은 장의 폴더 구조를 유지한다. Python만 사용한다. 두 파일을 같은 폴더에 두고 `python example.py`를 실행한다. 응답은 index가 뒤섞인 고정 자료다. 2차원 벡터는 대응 관계를 보기 위한 가상 값이며 원본 768차원 매핑에 전송하지 않는다.



**[vector_tools.py](실습/책형_복습/03_임베딩과_미완성경계/vector_tools.py) — 새 예제 전체 파일**

```python
def attach_vectors(chunks, response_rows, index_name, dimensions=2):
    rows = sorted(response_rows, key=lambda row: row['index'])
    if [row['index'] for row in rows] != list(range(len(chunks))):
        raise ValueError('입력과 응답 index를 확인하세요.')
    actions = []
    for chunk, row in zip(chunks, rows):
        vector = row['embedding']
        if len(vector) != dimensions:
            raise ValueError('벡터 차원을 확인하세요.')
        source = {**chunk, 'embedding': vector}
        actions.append({
            '_index': index_name,
            '_id': f'{chunk["movieId"]}-{chunk["chunk_index"]}',
            '_source': source,
        })
    return actions
```

**[example.py](실습/책형_복습/03_임베딩과_미완성경계/example.py) — 새 예제 전체 파일**

```python
from vector_tools import attach_vectors

chunks = [
    {'movieId': 1, 'chunk_index': 0, 'content': '첫 조각'},
    {'movieId': 1, 'chunk_index': 1, 'content': '둘째 조각'},
]
response_rows = [
    {'index': 1, 'embedding': [0.3, 0.4]},
    {'index': 0, 'embedding': [0.1, 0.2]},
]
actions = attach_vectors(chunks, response_rows, 'practice_movies')
print('ID:', [a['_id'] for a in actions])
print('첫 벡터:', actions[0]['_source']['embedding'])
print('둘째 벡터:', actions[1]['_source']['embedding'])
print('원본 유지:', 'embedding' not in chunks[0])
try:
    attach_vectors(chunks, response_rows[:1], 'practice_movies')
except ValueError as error:
    print(error)
print('외부 전송:', False)
```

응답 목록은 1번이 먼저지만 index로 정렬하면 입력 0번과 0번 벡터가 연결된다. 새 예제는 응답 개수·인덱스·차원을 확인하고 원본 청크를 복사하는 개선안이다. zip은 짝인 두 목록을 함께 반복하는 새 풀이 표기이며 원본의 last_index 반복과 같은 목적을 드러낸다. 서버와 임베딩 모델을 호출하지 않고 대응 관계만 검사한다.

**실행 결과:**


```python
def embedding_with_gemini(chunks):
    # 임베딩 모델 가져오기
    api_key = os.getenv('GEMINI_API_KEY')
    client = genai.Client(api_key=api_key)

    actions = []
    for chunk in chunks :
        # 임베딩 하기
        result = client.models.embed_content(
            model='gemini-embedding-2',
            contents=[
                types.Content(
                    parts=[
                        types.Part.from_text(text=chunk['content'])
                    ]
                )
            ],
            # 384, 768은 64의 배수로 딱 떨어지는 수
            config=types.EmbedContentConfig(
                # 디멘션이 달라진다고 해도 실질적인 토큰에는 영향을 주지 않는다
                # 단, 벡터가 많아지기에 저장공간이 커지고 검색이 느려진다
                output_dimensionality=768
            )
        )
        # 임베딩 한 결과 저장
        chunk['embedding'] = result.embeddings[0].values

        # ES용 데이터 형식으로 저장
        actions.append({
            '_index': os.getenv('ES_INDEX'),
            '_id': f'{chunk["movieId"]}-{chunk["chunk_index"]}',
            '_source': chunk
        })
        # gemini가 1분당 제한이 있기 때문에 0.7초로 sleep을 걸어줌
        time.sleep(0.7)

    return actions
```

```python
def embedding_with_openai(chunks):
    # 임베딩 모델 가져오기
    api_key = os.getenv('OPENAI_API_KEY')
    client = OpenAI(api_key=api_key)

    actions = []
    last_index = 0
    time_before = time.time()

    contents = [ chunk['content'] for chunk in chunks ]

    for idx_start in range(0, len(contents), 2047) :
        contents_part = contents[idx_start: idx_start + 2047]

        # 임베딩 하기
        # OpenAI의 경우 list를 주면 결과도 list로 나온다
        result = client.embeddings.create(
            model='text-embedding-3-small',
            input=contents_part,
            encoding_format='float', # 기본값: base64 형태(양방향 암호화)
            # dimensions=1
            dimensions=768
        )

        # print(result)

        # 혹시 몰라서 내용 중 'index' 기준으로 정렬
        '''
        CreateEmbeddingResponse(
            data=[
                Embedding(embedding=[1.0], index=0, object='embedding'), 
                Embedding(embedding=[1.0], index=1, object='embedding')
            ], 
            model='text-embedding-3-small', 
            object='list', 
            usage=Usage(
                prompt_tokens=17, 
                total_tokens=17)
            )
        '''
        vectors = [ sort_data.embedding for sort_data in sorted(result.data, key=lambda item : item.index) ]

        for idx, vector in enumerate(vectors) :
            chunks[last_index]['embedding'] = vector
            # chunk['embedding'] = vectors[idx]

            # ES용 데이터 형식으로 저장
            actions.append({
                '_index': os.getenv('ES_INDEX'),
                '_id': f'{chunks[last_index]["movieId"]}-{chunks[last_index]["chunk_index"]}',
                '_source': chunks[last_index]
            })

            last_index += 1

        time_after = time.time()
        print('걸린 시간 (2047개) : ', time_after - time_before)
        time_before = time.time()

    return actions
```

**발췌 바로 풀이:** 여러 content를 2047개씩 요청하고 응답 index로 정렬한 다음 전체 위치 last_index를 이동한다. 응답 누락·중복 index·차원을 명시적으로 검사하는 코드는 없다. encoding_format은 float로 명시되어 있으며 Base64를 암호화로 설명한 주석은 교정한다.

```python
def bulk():
    # target = makeChunk()[0:10]
    target = makeChunk()
    actions = util.embedding_with_openai(target)

    # 1. 만약에 엘라스틱서치에 인덱스가 없다면 새로 만들기(있으면 기존 인덱스에 데이터 넣기)

            index=os.getenv('ES_INDEX'),
```

현재 강사님도 util에 임베딩 함수를 구현했고 라우터의 bulk도 작성했다. 예전 교재 상태를 유지하지 않고 현재 정의로 다시 인용했다. 같은 이름 embedding을 두 번 정의해도 경로 등록에는 각각의 함수 객체가 들어갈 수 있지만 모듈의 마지막 이름은 뒤 함수를 가리킨다. 역할에 맞는 다른 함수명이 읽기 쉽다. 아직 그래프 노드·간선 구현이 있다는 뜻은 아니다.

## 5. import·함수·입력·출력이 연결되는 흐름

`makeChunk 전체 목록 → util 임베딩 함수 → SDK 요청 → 응답 index/벡터 → chunk.embedding → actions → bulk 경로의 매핑 확인 → helpers.bulk → 성공/오류 또는 예외`다. 앞 10개 미리보기 경로와 전체 적재 경로는 호출량이 다르다. 새 vector_tools에는 응답을 붙이는 함수 전체를 제공했고 외부 SDK 호출은 포함하지 않았다.

<a id="review"></a>

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 청크 ID와 응답 정렬을 고려하고 768차원 매핑까지 연결했다. **아쉬운 점:** 입력 dict를 제자리 변경하고 응답 개수·차원 검사를 생략했으며 대상 확인보다 외부 임베딩이 앞선다. **개선:** 대상·설정과 입력을 먼저 확인하고 입력/응답의 대응을 검사한다. source를 별도 dict로 만들어 재사용 시 이전 결과가 바뀌지 않게 할 수 있다. 새 예제의 검사는 원본에 적용한 수정이 아니다.

원본 오류·수업용 단순화·목적에 따른 설계를 나눈다. 새 개선안은 당시 내 코드나 D 드라이브 수정본이 아니다.

## 8. 결과를 추적하고 한 가지 바꾸기

| 자리 | 예제의 의미 |
| --- | --- |
|입력 0/1 | 첫·둘째 청크 |
|응답 index 1/0 | 반환 목록의 순서는 뒤섞임 |
|정렬 뒤 0/1 | 원래 입력 위치와 대응 |
|_id 1-0/1-1 | 영화·청크 식별 |
|actions | 저장 요청 준비·실제 저장 아님 |

| 한 가지만 변경 | 예상 |
| --- | --- |
|응답 순서만 바꿈 | index로 같은 청크에 연결 |
|응답 하나 누락 | 새 예제 ValueError |
|벡터 숫자 개수 변경 | 새 예제 차원 오류 |
|원본 함수에 같은 chunks 재사용 | embedding 필드가 추가·대체된 상태 |

벡터가 다른 청크에 붙으면 요청 안 index와 전체 위치를 구별한다. 실제 벌크 실패라면 인덱스명·필드·차원·부분 실패를 확인한다. 원본의 모든 청크를 준비한 뒤 앞 10개만 전달하는 경로는 준비량과 외부 요청량이 같지 않다. 실제 서비스 오류는 고정 응답 예제의 성공으로 대신 설명하지 않는다.

**확인 범위:** 새 예제는 임시 폴더에서 Python 처리·요청 모양·고정 응답 가공을 확인한다. Elasticsearch나 AI 서비스의 실제 연결·적재·검색·임베딩·답변 성공을 재현한 것은 아니다. 원본 함수의 별도 검사도 외부 호출을 기록 대역으로 바꾼 범위이며 원본 파일과 패키지는 수정하지 않는다.

## 9. 추가로 알면 좋은 것과 출처

> 💡 **TIP · 수업 범위 밖:** 요청 묶음의 토큰 예산·재시도·동시 호출·모델별 인덱스 분리·운영 기록은 추가 학습이다. LangGraph의 그래프·노드·간선은 현재 두 소스에 구현 근거가 없어 **이후 첨부**로 남긴다.



09 소스는 작업 중 변경을 감지해 2026-10-30 확보한 사본을 기준으로 집필했다. 이후 변경은 별도 재검토 대상이다. 확인한 라이브러리 의미와 수업 밖 확장을 구분한다. 위 출처는 본문의 설명 근거이며 TIP에 적힌 새 주제를 이미 배운 것으로 간주하지 않는다.

## 10. 복습과 빠른 정리

1. 응답 index와 전체 last_index는 같은 범위의 위치인가?
2. actions를 반환한 것과 bulk 성공은 같은가?
3. Base64는 암호화인가?

<details>
<summary>풀이 — 먼저 결과와 이유를 적은 뒤 펼치기</summary>

1. 응답 index는 요청 안 위치이고 last_index는 전체 입력 위치다.
2. 준비와 실제 전송·응답을 구별한다. 최신 원본에는 전송 호출도 있지만 실제 성공은 미확인이다.
3. 데이터 표현 형식이며 암호화가 아니다.

</details>
