## 2. 현재 소스와 작성 출처

작업 중 소스 변경을 감지해 2026-10-30 양쪽 util.py·router/es_router.py의 사본을 확보했다. 인용·실행 검사는 이 사본 기준이며 이후 원본 수정분은 별도 검토 대상이다. 실제 파일을 조용히 고치거나 가상환경에 새 패키지를 설치하지 않았다.

사용자 확인상 **recall_at_k부터의 후반부는 놓친 수업의 강사님 코드를 옮긴 복습 자료**다. 복사 시작점은 사용자 추정임을 남긴다. 앞의 기존 작성 부분과 구분하며, 이 후반부를 학생 직접 작성 성과·부족함으로 평가하지 않는다. 같은 코드라 중복 인용을 줄이고 동작·수식·전달값을 상세하게 풀이한다.

## 3. 이전 안내에서 바뀐 내용

최신 양쪽에는 임베딩·bulk·콘텐츠 기반 추천·시간 분할·협업 필터링·Recall@K 함수와 평가 경로가 있다. 따라서 예전의 “강사님 임베딩 pass·bulk 미구현·추천 없음” 안내는 현재에 맞춰 고쳤다. 구현됨과 외부 서비스 성공·실제 추천 품질은 구분한다.

강사님은 사용자 값 검사에 .values, 이웃 50·pearson을 사용하고 내 기존 협업 함수는 Series 인덱스 검사, 이웃 30·cosine을 사용한다. 시간 변환 결과를 실제 열에 반영하지 않는 문제는 양쪽에 있다. read의 Literal 이름은 여전히 import 목록에 없어 주석 평가 시 NameError를 확인했다. Python 3.14의 지연 평가 때문에 함수 정의 즉시 항상 실패한다고 일반화하지 않는다.

## 5. 추가로 알면 좋은 것과 이후 첨부

📚는 본문 의미를 확인한 공식 출처, 💡는 추가 설계다. 최신 강사님 CBF의 재검색은 벡터, 내 코드는 문자 검색으로 다르다. 강사님 적재·질문은 모두 Gemini이고 내 적재는 OpenAI다. 두 코드의 일부를 혼합할 때는 차원 수만으로 벡터 호환을 보장하지 않는다. 강사님 bulk에는 기존 인덱스 삭제·재생성이 있고 내 bulk는 기존 인덱스를 유지한다. 강사님만의 search_vector는 수강 범위 미확인이라 상세 정의를 04장 하단 TIP에 두었다. 벡터 검색의 공통 개념은 [08 단원](../08_Elasticsearch와_RAG/04_벡터와_하이브리드검색.md)에서 복습한다. 그래프 실행·운영 추천 서비스는 이후 첨부 대상이다.
