## 2. 무엇이며, 왜 필요한가

### 비슷한 내용을 찾는 것과 비슷한 평점 관계를 찾는 것

콘텐츠 기반 검색은 제목·장르·태그 같은 자료의 특징을 썼다. 협업 필터링은 여러 사용자가 여러 영화에 준 평점 관계를 사용한다. 여기서는 사용자 기반 KNNWithMeans에 cosine 유사도와 이웃 최대 30명을 지정했다. 비슷한 평점 성향의 다른 사용자 정보를 이용하되 개인 평균 차이를 고려하는 방식이다. 원본의 Reader는 평점 범위를 0.5~5.0으로 설명하고 Dataset이 사용자·영화·평점 세 열을 학습 자료로 바꾼다.

| 설정·자료 | 뜻 | 혼동하기 쉬운 것 |
| --- | --- | --- |
| k=30 | 예측에 참고할 이웃의 최대 수 | 추천할 영화 30개가 아님 |
| user_based=True | 사용자 사이 유사도 사용 | 영화 내용 벡터 검색과 다름 |
| top_k=10 | 최종 상위 추천 수 | 이웃 수와 별개 |
| model.predict(...).est | 예측 평점 | 실제 평점·확률 아님 |

자료가 부족하면 실제 사용 이웃 수는 k보다 작을 수 있다. 이웃 기반 평점 예측을 했다고 정답을 측정한 것은 아니다. 이미 본 영화 제외와 후보 범위도 추천 결과를 바꾼다.

### 왜 사용자별 최신 기록을 따로 남길까?

미래 행동을 예상하려면 미래 기록을 먼저 학습하는 문제를 줄여야 한다. 원본은 사용자별 timestamp 순으로 정렬해 최신 일부를 test로 남기고 나머지를 train으로 쓴다. 기록 하나뿐인 사용자는 train에만 둔다. test_count는 ceil(행수×비율)을 쓰되 최소 1, 학습에 최소 한 행은 남기도록 제한한다. 비율 0.2라도 사용자 세 행이면 시험 한 행이 된다.

같은 timestamp면 original_order로 원래 행 순서를 보존한다. 이는 같은 시각의 실제 선후 관계를 알아냈다는 뜻이 아니라 코드의 일관된 정렬 기준이다. 전체가 정확히 80:20이 되는 무작위 분할과도 다르다.

### 외부 ID와 내부 ID

원래 CSV의 userId·movieId는 raw ID다. Surprise 학습 표는 내부에서 연속 번호를 쓰므로 to_inner_uid로 사용자를 바꾸고 train_set.ur에서 그 사용자의 이미 평가한 영화 내부 ID를 찾는다. 다시 to_raw_iid로 원래 movieId를 얻는다. 내부 번호 0이 영화 ID 0이라는 뜻이 아니다.

후보는 학습 표에 등장한 영화 중 사용자가 이미 평가한 것을 뺀 목록이다. 원본 movies.csv 전체의 모든 영화를 후보로 만든 것이 아니다. 마지막에 예측 평점으로 정렬해 top_k를 고른다. 평점이 없는 새 영화·새 사용자의 처리는 이 방식의 별도 한계다.

**[cf_tools.py](실습/책형_복습/05_시간분할과_협업필터링/cf_tools.py) — 새 예제 전체 파일**

```python
import math
import pandas as pd
from surprise import Dataset, Reader, KNNWithMeans


def recent_split(ratings, test_size=0.2):
    if not 0 < test_size < 1:
        raise ValueError('시험 비율은 0보다 크고 1보다 작아야 합니다.')
    data = ratings.copy()
    data['original_order'] = range(len(data))
    data['timestamp'] = pd.to_numeric(data['timestamp'], errors='coerce')
    if data['timestamp'].isna().any():
        raise ValueError('유효한 timestamp가 필요합니다.')
    test_indices = []
    for _, group in data.groupby('userId', sort=False):
        if len(group) <= 1:
            continue
        ordered = group.sort_values(['timestamp', 'original_order'], kind='stable')
        count = min(len(ordered) - 1, max(1, math.ceil(len(ordered) * test_size)))
        test_indices.extend(ordered.tail(count).index.tolist())
    test = data.loc[test_indices].sort_values('original_order').drop(columns='original_order')
    train = data.drop(index=test_indices).sort_values('original_order').drop(columns='original_order')
    return test.reset_index(drop=True), train.reset_index(drop=True)


def recommend(train, user_id, top_k=2):
    if user_id not in set(train['userId']):
        raise ValueError('학습 자료에 없는 사용자입니다.')
    if top_k <= 0:
        raise ValueError('추천 수는 양수여야 합니다.')
    reader = Reader(rating_scale=(0.5, 5.0))
    dataset = Dataset.load_from_df(train[['userId', 'movieId', 'rating']], reader)
    train_set = dataset.build_full_trainset()
    model = KNNWithMeans(k=30, sim_options={'name': 'cosine', 'user_based': True}, verbose=False)
    model.fit(train_set)
    inner_id = train_set.to_inner_uid(user_id)
    seen = {train_set.to_raw_iid(movie_id) for movie_id, _ in train_set.ur[inner_id]}
    candidates = [train_set.to_raw_iid(i) for i in range(train_set.n_items) if train_set.to_raw_iid(i) not in seen]
    result = [{'movieId': movie_id, 'score': model.predict(user_id, movie_id).est} for movie_id in candidates]
    result.sort(key=lambda row: row['score'], reverse=True)
    return result[:top_k]
```

def split_train_test(test_size: float = 0.2):
    '''
        과거 평점을 학습시켜고, 미래 평점으로 평가하자
        test_size : 미래 평점의 비율(평가, 테스트용 정답 데이터의 비율)

        사용자 별로
        최신 평점은 평가용
        과거 평점은 학습용

        평점이 한 건 뿐인 사용자는 학습 데이터에만 둔다
        만약에 timestamp가 같다면 원본 행 순서로 정렬한다
    '''

    # 평점 파일 읽기
    frame_ratings = util.load_csv('ratings.csv')

    # 원본 유지를 위해 깊은복사하여 사용
    data = frame_ratings.copy()

    # 읽어 온 csv의 길이를 가져와서 원본의 순서대로 row num 생성
    data['original_order'] = range( len(data) )

    # timestamp를 숫자타입으로 변경
    # errors='coerce' : 변경이 안 되는 것은 NaN으로 강제로 변경
    # errors='ignore' : 변경 실패 시 원본 유지
    # errors='raise' : ValueError 발생하고 즉시 중단
    valid_data = pd.to_numeric( data['timestamp'], errors='coerce' )

    # N/A가 아닌 것만 뽑아준다 
    # data[ True or False] >>>> 참인 행(row, document)만 반환
    valid_data = data[data['timestamp'].notna()].copy()

    # 시간이 N/A 즉, 비어있는 것만 뽑아준다
    no_time = data[data['timestamp'].isna()].copy()

    test_indices = []

    # userId가 같은 데이터끼리 group by 한다
    # sort의 기본값은 True이고, userId로 정렬하지 않고 원래 등장 순서를 유지
    # False로 하면서 userId로 다시 한 번 정렬하는 것
    # 원래 id, value이나 id를 사용하지 않을 것이기 때문에 '_' 로 처리
    for _, group in valid_data.groupby('userId', sort=False) :

        # 평점을 하나만 준 사용자는 건너뛰기
        # 하나만 있는 것은 학습과 정답 데이터로 나눌 수 없기 때문에 건너뜀
        if len(group) <= 1 :
            continue

        # 과거와 미래를 나누기 위해서 timestamp 기준으로 정렬한다
        # sort_values : 같은 게 있다면 original_order 기준으로 정렬해라
        # kind='stable' : 그래도 같은게 있다면, 정렬 전 순서 유지
        # kind에 사용할 수 있는 것
        # quicksort(기본값), mergesort, heapsort, stable
        # 오름차순
        ordered = group.sort_values(['timestamp', 'original_order'], kind='stable')

        # 전체 데이터 중 test_size 비율로 뽑았다
        # 소수점으로 나올 수 있기 때문에 0.4등의 결과를 1로 ceil을 사용하여 올림 처리
        # test_count = math.ceil(len(ordered) * test_size)
        # if test_count < 1 :
        #     test_count = 1

        # if test_count > len(ordered) - 1 :
        #     test_count = len(ordered) - 1

        # max : 둘 중에 큰 값을 돌려준다
        # 그걸 이용하여 최소값을 지정할 때 사용
        # max(1, test_count)
        # min : 둘 중에 작은 값을 돌려준다
        # 그걸 이용하여 최대값을 지정할 때 사용
        # min(test_count, len(ordered) - 1)

        # 위에 있는 코드를 아래처럼 합칠 수 있다
        test_count = min(len(ordered) - 1, max(1, math.ceil(len(ordered) * test_size)))

        # 슬라이싱을 써도 되지만, tail로 사용
        # tail : 끝에서 몇 개 (head와 반대, 기본값은 5)
        # 미리 시간 오름차순으로 정렬해 두었기 때문에 최신 데이터는 끝에 있다
        # .index : index만 모은다(dataframe이 가진 PK) 이후 원본에서 이걸 제외하면 train data
        test_indices.extend(ordered.tail(test_count).index.tolist())

    # 실제 테스트 데이터 추출
    # loc[]에 index를 주면 해당 index 자료만 뽑아 옴
    test = valid_data.loc[test_indices].copy()
    
    # 학습 데이터 추출
    train = valid_data.drop(index=test_indices)

    # 내가 활용하기 위해 추가한 row num으로 원래 순서대로 재정렬(복구) 후 컬럼 지우기
    # 그러면 거의 원본에서 필요한 데이터만 추출한 결과를 만들 수 있다
    test = test.sort_values('original_order', kind='stable').drop(columns='original_order')
    train = train.sort_values('original_order', kind='stable').drop(columns='original_order')

    # reset_index : pandas 내부 index를 재정리
    # drop=True를 안 해주면, 132 라고하면 123이 아니라 1323이 되는것을 막기 위함 (새로 추가됨)
    # → 엉망인 것은 버려라
    return test.reset_index(drop=True), train.reset_index(drop=True)
```

**발췌 바로 풀이:** 원본은 to_numeric의 결과를 valid_data에 넣지만 곧 원래 data 필터로 덮어써 변환을 실제 timestamp에 반영하지 않는다. no_time을 만들어도 train/test에 다시 넣지 않아 결측 시간 행은 두 결과에서 빠진다. 실제 CSV가 정상 숫자여도 이 경계 처리는 별도다. 반환 순서는 test, train이므로 일반적인 train_test_split과 순서를 혼동하지 않는다.

    #   - 문서 길이나 단어의 빈도 수는 달라도 주제가 비슷한지 판단할 때 좋다

    # sim_options의 name에 들어갈 수 있는 것들
    # msd(거리) : 기본값(Mean Squared Difference), 빠르고 대용량 데이터에 좋음 (평균 제곱을 하면 더 극명해짐)
    # cosine(방향) : 코사인 유사도(Cosine Similarity), 무난하고 취향 패턴 분석에 좋음
    # pearson : 피어슨 상관계수(애매한 값들), 편향 완화가 필요할 때 좋음
    # pearson_baseline : 피어슨 베이스라인, 조금 느리고 연산이 많아 데이터가 부족한데 정밀한 예측이 필요할 때 

    # user_based : 사용자 기반인지 아이템 기반인지
    #   - True : 내 취향과 평점 패턴이 비슷한 다른 사용자(이웃)이 이 아이템에 몇점을 주었는가?
    #   - False : 이 아이템을 좋아하는 사람들이 좋아하는 다른 유사한 아이템은 무엇인가?
    n_neighbors = 30
    model = KNNWithMeans(
        k=n_neighbors,
        sim_options={
            'name': 'cosine',
            'user_based': True
        },
        verbose=False # 학습 과정 출력 여부
    )

    # 사용 할 모델에게 학습
    model.fit(train_set)

    # 내가 평가 한 목록을 구한다
    # to_inner_uid : 사용자 id로 Surprise 내부 index를 변환한다
    inner_user_id = train_set.to_inner_uid(userId)

    # ur : user rating
    #   - user1이 영화1에는 3점, 영화2에는 3.5점을 줬다고 할 때 사용자 중심의 정보
    # ir : item rating
    #   - 영화1은 user1에게 3점 user2에게 1.5점을 받았다고 할 때 아이템 중심의 정보
    # Surprise용으로 바꿔놓은 train_set안에서 uid에 대한 movieId와 rating이 나옴
    rated_movies = set()
    for inner_movie_id, rating in train_set.ur[inner_user_id] :
        # to_raw_iid : inner_movie_id를 원본의(raw) iid(item id)로 바꿔라
        #   - 내부 영화 index를 원래 movieId로 바꿔주는 것
        rated_movies.add(train_set.to_raw_iid(inner_movie_id))

    # 학습 데이터 중 없는 목록을 구한다
    candidate_movies = [ 
        train_set.to_raw_iid(inner_movie_id)
        for inner_movie_id in range(train_set.n_items) 
        if train_set.to_raw_iid(inner_movie_id) not in rated_movies
    ]
    # n_items : length
    # for inner_movie_id in range(train_set.n_items) :
    #     if train_set.to_raw_iid(inner_movie_id) not in rated_movies :
    #         candidate_movies.append(train_set.to_raw_iid(inner_movie_id))

    # 그 목록의 예상 평점을 계산한다
    # 너라면 이 영화에 평점을 얼마 줄 것 같다는 예측
    recommend = []
    for movieId in candidate_movies :
        # 예상 평점 (학습한 모델을 쓰는 유일한 구간)
        # est : estimated 예측/추정의 약자, 예측한 평점
        # score = model.predict(userId, movieId).est : 예측의 추정치를 꺼냄
        score = model.predict(userId, movieId).est
        recommend.append({
            'movieId' : movieId,
            'score' : score
        })

    # 평점이 높은 순으로 정렬(내림차순 reverse=True)
    recommend.sort(key=lambda x:x['score'], reverse=True)

    return recommend[:top_k]
```

**발췌 바로 풀이:** userId not in data["userId"]는 Series의 값이 아니라 인덱스 포함 여부를 확인해 의도와 다를 수 있다. 값을 확인하도록 고쳐야 한다. 이후 Surprise로 학습한 뒤 내부 ID를 원래 영화 ID로 돌리고 이미 평가한 영화를 빼서 예측 점수로 정렬한다.

현재 양쪽 소스 모두 시간 분할과 협업 필터링을 작성했다. split_train_test는 CSV를 매번 읽고 collaborative_filtering은 호출할 때마다 학습한다. 반환 test는 이 추천 함수 안에서 평가에 사용하지 않는다. 최신에는 recall_at_k와 평가 경로도 추가되어 다음 장에서 별도로 설명한다. 평가 경로와 추천 함수의 내부 작업은 구분해서 읽는다.
