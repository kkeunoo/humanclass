## 2. 무엇이며, 왜 필요한가

### 콘텐츠 기반 추천은 무엇을 비교하나?

사용자가 선택한 영화의 내용 특징을 바탕으로 비슷한 영화를 찾는 방식이다. 이번 코드는 장르와 태그를 Counter로 센 뒤 자주 나온 것을 검색어로 사용한다. 평점의 사용자 간 유사도를 학습하는 다음 장과 다르다. “추천”이라는 이름이 있다고 모두 같은 모델이 있는 것은 아니다.

search_movies는 title^4·genres·tags^2·content^3에 multi_match를 한다. ^4 같은 표기는 검색 관련도 계산에서 해당 필드의 중요도를 높이는 요청이다. 점수가 반드시 네 배가 되거나 추천 정확도가 네 배가 된다는 뜻은 아니다. terms_movieId는 movieId 목록에 속하는 청크를 검색한다. 인덱스가 청크 단위이므로 영화 하나가 여러 hit로 나올 수 있다.

### Counter에는 무엇을 한 항목으로 줄까?

Counter는 반복 가능한 자료의 항목별 횟수를 센다. 문자열을 update하면 글자 하나씩, 문자열 목록을 update하면 목록의 단어 하나씩 센다. `update('김밥')`과 `update(['김밥'])`은 다른 결과다. 영화의 genres와 tags가 문자열 목록이기 때문에 원본이 목록을 update하는 것이 중요하다.

| 과정 | 예제의 자료 | 결과 |
| --- | --- | --- |
| 선택 영화 특징 | comedy 두 번·action 한 번 | 장르 빈도 |
| 태그 특징 | fun 두 번·friendship 한 번 | 태그 빈도 |
| most_common(5) | 많이 나온 순 | 상위 단어 목록 |
| dict.fromkeys | 순서 유지·동일 단어 한 번 | 중복 없는 검색 단어 |
| join | 단어 목록 | 다음 검색의 문자열 |

원본은 특징을 검색문으로 만든 후 search_movies를 다시 호출한다. 이미 선택한 영화를 자동 제외하는 조건은 없다. 청크마다 같은 장르·태그가 반복 저장됐다면 긴 영화의 여러 청크가 빈도를 더 많이 올릴 수 있다. 또한 terms의 size=len(ids)*5가 모든 청크를 보장하는 것도 아니다. 영화별 추천과 청크별 검색의 단위를 구별해야 한다.

> 📚 **출처 · 본문 설명 확인:** [Python Counter](https://docs.python.org/ko/3/library/collections.html#collections.Counter) · [Elastic multi_match](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-multi-match-query) · [terms](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-terms-query). 배운 의미 확인 근거다. 아래 표·전체 예제·풀이를 외부 문장 그대로 옮기지 않았다. 확인일: 2026-10-30.

**[feature_tools.py](실습/책형_복습/04_영화검색과_콘텐츠기반추천/feature_tools.py) — 새 예제 전체 파일**

```python
from collections import Counter


def build_query(selected_sources, top_n=5):
    genre_counter = Counter()
    tag_counter = Counter()
    for source in selected_sources:
        genre_counter.update(source.get('genres', []))
        tag_counter.update(source.get('tags', []))
    terms = [term for term, _ in genre_counter.most_common(top_n)]
    terms.extend([term for term, _ in tag_counter.most_common(top_n)])
    return ' '.join(dict.fromkeys(terms))
```

**[example.py](실습/책형_복습/04_영화검색과_콘텐츠기반추천/example.py) — 새 예제 전체 파일**

```python
from collections import Counter
from feature_tools import build_query

selected = [
    {'movieId': 1, 'genres': ['comedy'], 'tags': ['fun', 'friendship']},
    {'movieId': 2, 'genres': ['comedy', 'action'], 'tags': ['fun']},
]
print('검색문:', build_query(selected))
print('문자열:', dict(Counter('김밥김밥')))
print('단어 목록:', dict(Counter(['김밥', '김밥'])))
print('빈 선택:', repr(build_query([])))
```

첫 함수는 실제 원본의 특징 집계 부분을 독립시킨 새 예제다. Counter의 most_common은 빈도 순이고 같은 빈도일 때는 먼저 만난 순서가 영향을 준다. dict.fromkeys는 중복을 제거하되 순서를 보존한다. terms.extend에 사용한 리스트 컴프리헨션은 새 설명 표기이며 원본의 두 목록 더하기와 목적이 같다. 빈 선택은 빈 문자열이며 실제 검색할지 중단할지는 다음 호출자의 정책이다.

**실행 결과:**

```text

문자열: {'김': 2, '밥': 2}
단어 목록: {'김밥': 2}
빈 선택: ''
```

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 장르·태그 목록과 검색을 연결하고 중복 검색어를 정리했다. **아쉬운 점:** 청크 수가 특징 빈도에 영향을 주고, 선택 영화 제외·빈 선택·후보 중복 제거가 명시되지 않았다. **개선:** 영화 단위로 특징을 모을지 청크를 그대로 셀지 먼저 정한다. top_n과 결과 수를 구별하고 실제 추천 평가 전에는 품질을 주장하지 않는다.

원본 오류·수업용 단순화·목적에 따른 설계를 나눈다. 새 개선안은 당시 내 코드나 D 드라이브 수정본이 아니다.

## 9. 추가로 알면 좋은 것과 출처

> 💡 **TIP · 수업 범위 밖:** 영화별 중복 제거·개인화 가중치·선택 영화 제외·추천 평가용 정답 구성은 추가 설계다. 여기서는 현재 코드의 특징 기반 검색을 실제 학습 내용으로 설명하며 협업 필터링과 섞지 않는다. **강사님 추가 구현·수강 범위 미확인:** 아래 search_vector는 현재 강사님 파일에만 있어 추가로 알면 좋은 것으로 분류했다. 강사님 적재와 질문은 모두 Gemini다. 내 OpenAI 적재와 강사님 Gemini 질문 함수를 혼합하려면, 같은 768차원이라는 이유만으로 같은 표현 공간이라고 가정할 수 없다. 실제 호환·검색 품질은 검증하지 않았다. 호출하는 util.embedding_with_gemini의 전체 정의는 03장에 있다.

```python
def search_vector(keyword: str, size: int = 10) :

    # 검색어를 백터로 바꾼다
    # 그런데 기존의 embedding_with_gemini는 수정 없이 활용하고 싶다

    querys = [{
        'content': keyword,
        'movieId':0,
        'chunk_index':0,
    }]
    vectors = util.embedding_with_gemini(querys)
    '''
        [
            {
                '_index': os.getenv('ES_INDEX'),
                '_id': f'{chunk["movieId"]}-{chunk["chunk_index"]}',
                '_source': {
                                'content': keyword,
                                'embedding': vector
                            }
            }
        ]
    
    '''
    vector = vectors[0]['_source']['embedding']

    response = util.es.search(
        index=os.getenv('ES_INDEX'),
        knn={
            'field': 'embedding',
            'query_vector': vector,
            'num_candidates': max(size*10, 50),
            'k': size
        },
        size = size
    )

    return response
```
