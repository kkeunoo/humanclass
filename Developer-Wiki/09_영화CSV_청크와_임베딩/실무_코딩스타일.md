## 1. 이 장에서 배울 것

영화·청크·사용자·평점·추천의 단위를 구별한다. 입력 값 검사·반환 순서·원본 변경·외부 요청·학습·평가의 경계를 설명한다. 과거 Wiki 설명과 현재 파일이 달라질 때 실제 소스로 상태표를 갱신한다.

## 2. 무엇이며, 왜 필요한가

### 이름에 단위를 담는다

movieId는 영화 식별, chunk_index는 영화 안 조각 번호, index는 현재 처리 행 위치, userId는 평점을 남긴 사용자다. 모두 정수여도 서로 대체할 수 없다. 추천에서 몇 개라는 말도 이웃 수·청크 수·영화 수·최종 반환 수 중 무엇인지 적어야 한다.

| 작업 | 계약에 적을 내용 |
| --- | --- |
| CSV 읽기 | 어떤 표·실패 None 또는 예외 |
| 텍스트 만들기 | 제목·장르·태그·평점 사용 여부 |
| 청크 | 문자 크기·겹침·ID·원본 변경 |
| 임베딩 | 요청 모델·차원·응답 대응·제자리 변경 |
| 분할 | 사용자별 시간·반환 test/train 순서 |
| 추천 | 학습 카탈로그·본 영화 제외·예측 평점 |
| 평가 | 평가 함수·호출 경로·실제 점수의 구분 |

함수 이름이 split_train_test여도 실제 반환이 test, train이면 그 계약에 맞게 받아야 한다. Series에 `in`을 썼다고 값 포함 검사가 되는 것도 아니다. Python 문법이 실행된다는 사실과 의도한 자료를 검사했다는 사실은 구별한다.

### 상태표도 코드처럼 갱신한다

이번 최신 소스에는 이전에 없던 bulk·콘텐츠 추천·협업 필터링이 있다. 예전의 pass 인용을 현재 상태로 남겨 두면 교재가 틀린 지도를 제공한다. 구현됨·원본에서 발견한 결함·새 개선안·실제 실행 검증·미완성의 다섯 구분을 함께 기록한다. 구현됨이 외부 서비스 성공을 뜻하지 않으며 추천 반환이 품질 평가 완료를 뜻하지 않는다.

> 📚 **출처 · 본문 설명 확인:** [pandas Series](https://pandas.pydata.org/docs/reference/api/pandas.Series.html) · [Surprise Trainset](https://surprise.readthedocs.io/en/stable/trainset.html). 계약·상태표는 현재 양쪽 원본을 검토해 새로 구성한 집필 제안이다. 배운 의미 확인 근거다. 아래 표·전체 예제·풀이를 외부 문장 그대로 옮기지 않았다. 확인일: 2026-10-30.

**[request_tools.py](실습/책형_복습/실무_코딩스타일/request_tools.py) — 새 예제 전체 파일**

```python
def validate_request(user_id, top_k, train_user_ids):
    if user_id not in set(train_user_ids):
        raise ValueError('학습 자료에 없는 사용자입니다.')
    if not isinstance(top_k, int) or top_k <= 0:
        raise ValueError('추천 수는 양의 정수여야 합니다.')
    return user_id, top_k
```

**[example.py](실습/책형_복습/실무_코딩스타일/example.py) — 새 예제 전체 파일**

```python
from request_tools import validate_request

print('정상:', validate_request(10, 2, [10, 20, 30]))
for user_id, top_k in [(99, 2), (10, 0)]:
    try:
        validate_request(user_id, top_k, [10, 20, 30])
    except ValueError as error:
        print(error)
print('원본 사용자 목록:', [10, 20, 30])
```

set으로 실제 사용자 값 집합을 만든 뒤 포함 여부를 확인한다. 정상 입력은 사용자 ID와 추천 수를 그대로 반환하고 원본 목록을 수정하지 않는다. 이 검사는 모든 자료형을 엄격하게 보장하는 완성 스키마가 아니다. Python에서 bool이 int의 하위 타입인 경계, 타입 강제 변환·HTTP 오류 정책 등은 별도 설계가 필요하다.

**실행 결과:**

```text
정상: (10, 2)
학습 자료에 없는 사용자입니다.
추천 수는 양의 정수여야 합니다.
원본 사용자 목록: [10, 20, 30]
```

## 5. import·함수·입력·출력이 연결되는 흐름

`경로의 userId/top_k → 값 검사 → 사용자별 시간 분할 → 학습 → 후보별 예측 → 정렬 → 추천 반환 → 별도 평가`다. 이 새 예제는 첫 값 검사까지만 실행한다. request_tools의 전체 정의를 제공했고 이름이 같은 숨은 모듈을 요구하지 않는다. 입력 확인 성공과 모델 품질은 다른 결과다.

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 원본의 역할별 helper·ID 보존·시간 분할 의도를 유지한다. **아쉬운 점:** 이름의 단위와 반환 순서, 실제 상태가 설명과 어긋난 곳이 있다. **개선:** 함수 계약 표·구현 상태·확인 범위를 함께 남기고 준비·외부 호출·모델 학습을 분리한다. 새 검사가 원본에 반영된 것처럼 설명하지 않는다.

원본 오류·수업용 단순화·목적에 따른 설계를 나눈다. 새 개선안은 당시 내 코드나 D 드라이브 수정본이 아니다.

## 7. 강사님 코드가 도움이 되는 비교



강사님은 사용자 값 검사에 .values를 붙였고 이웃 수·유사도도 내 설정과 다르다. 실제 활성 줄을 기준으로 비교한다. 사용자 확인상 recall_at_k부터의 후반부는 어제 수업의 강사님 코드를 옮긴 부분으로 취급하고, 직접 작성 성과나 부족함으로 평가하지 않는다. 정확한 복사 경계는 사용자 추정임을 기록한다.

타입은 맞는데 결과가 다르면 값의 단위와 인덱스를 본다. 현재 설명이 코드와 다르면 원본 해시·정의·활성 줄을 대조한다. 오류 로그 뒤 빈 자료만 보이면 반환 계약을 읽는다. 문서가 길어져도 실행 조건·한계·다음 연결을 생략하지 않는다.

**확인 범위:** 새 예제는 임시 폴더에서 Python 처리·요청 모양·고정 응답 가공을 확인한다. Elasticsearch나 AI 서비스의 실제 연결·적재·검색·임베딩·답변 성공을 재현한 것은 아니다. 원본 함수의 별도 검사도 외부 호출을 기록 대역으로 바꾼 범위이며 원본 파일과 패키지는 수정하지 않는다.
