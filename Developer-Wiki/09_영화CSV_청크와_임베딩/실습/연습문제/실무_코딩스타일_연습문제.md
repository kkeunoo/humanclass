## 목표와 준비

영화·청크·사용자·평점·추천의 단위를 구별한다. 입력 값 검사·반환 순서·원본 변경·외부 요청·학습·평가의 경계를 설명한다. 과거 Wiki 설명과 현재 파일이 달라질 때 실제 소스로 상태표를 갱신한다.

[본문 3절](../../실무_코딩스타일.md#example)의 폴더·설치·입력·실행 조건부터 확인한다. 아래 필요한 파일 전체를 같은 구조로 저장한다. 가져오는 함수·모델 정의도 빠뜨리지 않는다.

## 문제 1. 실행 결과 예상

**request_tools.py**

```python
def validate_request(user_id, top_k, train_user_ids):
    if user_id not in set(train_user_ids):
        raise ValueError('학습 자료에 없는 사용자입니다.')
    if not isinstance(top_k, int) or top_k <= 0:
        raise ValueError('추천 수는 양의 정수여야 합니다.')
    return user_id, top_k
```

**example.py**

```python
from request_tools import validate_request

print('정상:', validate_request(10, 2, [10, 20, 30]))
for user_id, top_k in [(99, 2), (10, 0)]:
    try:
        validate_request(user_id, top_k, [10, 20, 30])
    except ValueError as error:
        print(error)
print('원본 사용자 목록:', [10, 20, 30])
```

실행 전에 결과를 먼저 적는다. 자료의 모양·분류 결과·확률·점수·현재 변수의 대상을 구별한다.

<details>
<summary>풀이</summary>

```text
정상: (10, 2)
학습 자료에 없는 사용자입니다.
추천 수는 양의 정수여야 합니다.
원본 사용자 목록: [10, 20, 30]
```

set으로 실제 사용자 값 집합을 만든 뒤 포함 여부를 확인한다. 정상 입력은 사용자 ID와 추천 수를 그대로 반환하고 원본 목록을 수정하지 않는다. 이 검사는 모든 자료형을 엄격하게 보장하는 완성 스키마가 아니다. Python에서 bool이 int의 하위 타입인 경계, 타입 강제 변환·HTTP 오류 정책 등은 별도 설계가 필요하다.

| 입력 | 값 검사 | 다음 단계 |
| --- | --- | --- |
|10, 2 | 통과·같은 값 반환 | 실제 앱이면 학습/추천 |
|99, 2 | 사용자 없음 | 중단 |
|10, 0 | 추천 수 오류 | 중단 |

</details>

## 문제 2. 이유 설명

1. 정수 ID라면 사용자·영화·청크를 서로 바꿔도 되는가?
2. 입력 검사가 성공하면 추천 성능이 좋은가?
3. 함수에 pass가 있으면 어떤 상태로 기록하는가?

<details>
<summary>풀이</summary>

1. 자료형이 같아도 의미와 단위가 다르다.
2. 입력 계약만 통과했으며 학습·평가는 별도다.
3. 실제 반환·구현 범위를 보고 미완성으로 구별한다.

</details>

## 문제 3. 한 가지만 바꾸기

| 한 가지만 변경 | 예상 |
| --- | --- |
|같은 사용자 ID 반복 | 집합 검사 의미 동일 |
|top_k를 음수로 | 새 예제 오류·원본 슬라이스는 다른 결과 가능 |
|입력 확인만 성공 | 추천 품질은 아직 미확인 |
|반환 순서를 뒤바꿈 | 호출자의 변수 의미도 다시 맞춰야 함 |

<details>
<summary>막힐 때 확인</summary>

타입은 맞는데 결과가 다르면 값의 단위와 인덱스를 본다. 현재 설명이 코드와 다르면 원본 해시·정의·활성 줄을 대조한다. 오류 로그 뒤 빈 자료만 보이면 반환 계약을 읽는다. 문서가 길어져도 실행 조건·한계·다음 연결을 생략하지 않는다.

</details>

## 채점과 복습

정상 출력뿐 아니라 입력 열·정답·분할·평가 대상의 차이도 설명한다. 새 예제는 독립 실행이며 실제 검색·AI 서비스 성공과 구별한다. TIP 확장은 필수 조건이 아니다. 정의→입력→호출→반환→다음 평가의 흐름을 연결한다.
