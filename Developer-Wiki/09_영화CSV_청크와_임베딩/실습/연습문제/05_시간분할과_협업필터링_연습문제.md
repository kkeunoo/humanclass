실제 수업 내용을 바탕으로 **새로 구성한 연습문제**다. 원본·당시 내 코드·새 개선안을 구별한다. 예상 → 이유 → 한 가지 변경 순서로 푼다.

## 목표와 준비

콘텐츠 특징과 평점 관계의 차이, 사용자별 시간 분할, raw/inner ID, 이웃 수 k와 추천 수 top_k를 설명한다. 원본의 Series 포함 검사와 timestamp 처리 결함을 이해하고, 추천 목록 생성과 추천 성능 평가가 다른 단계임을 구별한다.

[본문 3절](../../05_시간분할과_협업필터링.md#example)의 폴더·설치·입력·실행 조건부터 확인한다. 아래 필요한 파일 전체를 같은 구조로 저장한다. 가져오는 함수·모델 정의도 빠뜨리지 않는다.

## 문제 1. 실행 결과 예상

**cf_tools.py**

```python
import math
import pandas as pd
from surprise import Dataset, Reader, KNNWithMeans


def recent_split(ratings, test_size=0.2):
    if not 0 < test_size < 1:
        raise ValueError('시험 비율은 0보다 크고 1보다 작아야 합니다.')
    data = ratings.copy()
    data['original_order'] = range(len(data))
    data['timestamp'] = pd.to_numeric(data['timestamp'], errors='coerce')
    if data['timestamp'].isna().any():
        raise ValueError('유효한 timestamp가 필요합니다.')
    test_indices = []
    for _, group in data.groupby('userId', sort=False):
        if len(group) <= 1:
            continue
        ordered = group.sort_values(['timestamp', 'original_order'], kind='stable')
        count = min(len(ordered) - 1, max(1, math.ceil(len(ordered) * test_size)))
        test_indices.extend(ordered.tail(count).index.tolist())
    test = data.loc[test_indices].sort_values('original_order').drop(columns='original_order')
    train = data.drop(index=test_indices).sort_values('original_order').drop(columns='original_order')
    return test.reset_index(drop=True), train.reset_index(drop=True)


def recommend(train, user_id, top_k=2):
    if user_id not in set(train['userId']):
        raise ValueError('학습 자료에 없는 사용자입니다.')
    if top_k <= 0:
        raise ValueError('추천 수는 양수여야 합니다.')
    reader = Reader(rating_scale=(0.5, 5.0))
    dataset = Dataset.load_from_df(train[['userId', 'movieId', 'rating']], reader)
    train_set = dataset.build_full_trainset()
    model = KNNWithMeans(k=30, sim_options={'name': 'cosine', 'user_based': True}, verbose=False)
    model.fit(train_set)
    inner_id = train_set.to_inner_uid(user_id)
    seen = {train_set.to_raw_iid(movie_id) for movie_id, _ in train_set.ur[inner_id]}
    candidates = [train_set.to_raw_iid(i) for i in range(train_set.n_items) if train_set.to_raw_iid(i) not in seen]
    result = [{'movieId': movie_id, 'score': model.predict(user_id, movie_id).est} for movie_id in candidates]
    result.sort(key=lambda row: row['score'], reverse=True)
    return result[:top_k]
```

**example.py**

```python
import pandas as pd
from cf_tools import recent_split, recommend

ratings = pd.DataFrame([
    [10, 1, 4.0, 100], [10, 2, 5.0, 110], [10, 3, 3.0, 120],
    [20, 1, 4.0, 100], [20, 3, 5.0, 110], [20, 4, 2.0, 120],
    [30, 2, 5.0, 100], [30, 4, 3.0, 110], [30, 3, 4.0, 120],
], columns=['userId', 'movieId', 'rating', 'timestamp'])
test, train = recent_split(ratings)
print('학습·시험 행:', len(train), len(test))
print('사용자 10의 시험 영화:', test[test['userId'] == 10]['movieId'].tolist())
result = recommend(train, 10)
print('추천 영화:', [row['movieId'] for row in result])
print('예측 평점:', [round(float(row['score']), 6) for row in result])
print('시험을 평가했는가:', False)
```

실행 전에 결과를 먼저 적는다. 자료의 모양·분류 결과·확률·점수·현재 변수의 대상을 구별한다.

<summary>풀이</summary>

```text
학습·시험 행: 6 3
사용자 10의 시험 영화: [3]
추천 영화: [3, 4]
예측 평점: [5.0, 3.5]
시험을 평가했는가: False
```

세 사용자의 최신 한 행씩 test로 남기고 여섯 행으로 학습한다. 사용자 10은 학습에서 영화 1·2를 이미 평가했으므로 후보는 학습 카탈로그의 3·4다. 모델의 실제 예측 평점으로 순위를 얻는다. 시험에 3이 있고 추천에도 3이 있다는 사실은 이 작은 자료의 결과지만, 함수가 Recall@K나 평점 오차를 계산한 것은 아니다. 새 코드는 사용자 값 포함 확인·timestamp 변환·유효 입력 검사를 고친 개선안이다.

| 사용자 10 | 가상 자료 |
| --- | --- |
|과거 학습 영화 | 1·2 |
|최신 시험 영화 | 3 |
|학습 카탈로그 | 1·2·3·4 |
|미평가 후보 | 3·4 |
|예측 정렬 | 3의 5.0·4의 3.5 |
|품질 평가 | 현재 예제는 계산 안 함 |

## 문제 2. 이유 설명

1. 이웃 k와 추천 top_k는 같은가?
2. raw ID와 inner ID를 구별하는 이유는?
3. 추천을 반환하면 평가도 끝난 것인가?

<details>
<summary>풀이</summary>

1. 모델이 참고할 이웃 수와 최종 반환 수다.
2. 원래 영화·사용자 ID와 학습 표 내부 번호는 다르다.
3. 남겨 둔 정답과 지표로 비교하는 별도 단계가 필요하다.

</details>

## 문제 3. 한 가지만 바꾸기

| 한 가지만 변경 | 예상 |
| --- | --- |
|top_k를 1로 | 이웃 수는 30 그대로·추천 한 개 |
|기록 한 개뿐인 사용자 추가 | 그 기록은 학습에만 남음 |
|timestamp를 잘못된 문자로 | 새 예제 ValueError |
|학습에 없는 사용자 요청 | 새 예제 값 검사에서 오류 |
|test_size를 0으로 | 새 예제 오류·원본은 max(1,...)로 한 행 선택 가능 |

<details>
<summary>막힐 때 확인</summary>

사용자가 있는데 없다고 나오면 Series 인덱스와 값 검사를 구별한다. to_inner_uid 오류는 학습에 남은 사용자 여부를 본다. 후보가 비면 학습 카탈로그 전체를 이미 평가했는지 확인한다. 숫자가 아닌 시간은 단순 정렬 전에 변환을 실제로 적용했는지 살핀다.

</details>

## 채점과 복습

정상 출력뿐 아니라 입력 열·정답·분할·평가 대상의 차이도 설명한다. 새 예제는 독립 실행이며 실제 검색·AI 서비스 성공과 구별한다. TIP 확장은 필수 조건이 아니다. 정의→입력→호출→반환→다음 평가의 흐름을 연결한다.
