# 03. 영화 임베딩과 벌크 적재 — 요청·응답 정렬·저장 경계를 구별하기 — 연습문제

실제 수업 내용을 바탕으로 **새로 구성한 연습문제**다. 원본·당시 내 코드·새 개선안을 구별한다. 예상 → 이유 → 한 가지 변경 순서로 푼다.

## 목표와 준비

한 청크씩 요청하는 방식과 여러 청크를 묶는 방식을 구별한다. 응답 index와 원래 청크의 대응, 숫자 표현 방식과 차원, actions 준비와 helpers.bulk 전송을 설명한다. 아직 없는 그래프·추천 평가까지 완성으로 확대하지 않는다.

[본문 3절](../../03_임베딩과_미완성경계.md#example)의 폴더·설치·입력·실행 조건부터 확인한다. 아래 필요한 파일 전체를 같은 구조로 저장한다. 가져오는 함수·모델 정의도 빠뜨리지 않는다.

## 문제 1. 실행 결과 예상

**vector_tools.py**

```python
def attach_vectors(chunks, response_rows, index_name, dimensions=2):
    rows = sorted(response_rows, key=lambda row: row['index'])
    if [row['index'] for row in rows] != list(range(len(chunks))):
        raise ValueError('입력과 응답 index를 확인하세요.')
    actions = []
    for chunk, row in zip(chunks, rows):
        vector = row['embedding']
        if len(vector) != dimensions:
            raise ValueError('벡터 차원을 확인하세요.')
        source = {**chunk, 'embedding': vector}
        actions.append({
            '_index': index_name,
            '_id': f'{chunk["movieId"]}-{chunk["chunk_index"]}',
            '_source': source,
        })
    return actions
```

**example.py**

```python
from vector_tools import attach_vectors

chunks = [
    {'movieId': 1, 'chunk_index': 0, 'content': '첫 조각'},
    {'movieId': 1, 'chunk_index': 1, 'content': '둘째 조각'},
]
response_rows = [
    {'index': 1, 'embedding': [0.3, 0.4]},
    {'index': 0, 'embedding': [0.1, 0.2]},
]
actions = attach_vectors(chunks, response_rows, 'practice_movies')
print('ID:', [a['_id'] for a in actions])
print('첫 벡터:', actions[0]['_source']['embedding'])
print('둘째 벡터:', actions[1]['_source']['embedding'])
print('원본 유지:', 'embedding' not in chunks[0])
try:
    attach_vectors(chunks, response_rows[:1], 'practice_movies')
except ValueError as error:
    print(error)
print('외부 전송:', False)
```

실행 전에 결과를 먼저 적는다. 자료의 모양·분류 결과·확률·점수·현재 변수의 대상을 구별한다.

<details>
<summary>풀이</summary>

```text
ID: ['1-0', '1-1']
첫 벡터: [0.1, 0.2]
둘째 벡터: [0.3, 0.4]
원본 유지: True
입력과 응답 index를 확인하세요.
외부 전송: False
```

응답 목록은 1번이 먼저지만 index로 정렬하면 입력 0번과 0번 벡터가 연결된다. 새 예제는 응답 개수·인덱스·차원을 확인하고 원본 청크를 복사하는 개선안이다. zip은 짝인 두 목록을 함께 반복하는 새 풀이 표기이며 원본의 last_index 반복과 같은 목적을 드러낸다. 서버와 임베딩 모델을 호출하지 않고 대응 관계만 검사한다.

| 자리 | 예제의 의미 |
| --- | --- |
|입력 0/1 | 첫·둘째 청크 |
|응답 index 1/0 | 반환 목록의 순서는 뒤섞임 |
|정렬 뒤 0/1 | 원래 입력 위치와 대응 |
|_id 1-0/1-1 | 영화·청크 식별 |
|actions | 저장 요청 준비·실제 저장 아님 |

## 문제 2. 이유 설명

1. 응답 index와 전체 last_index는 같은 범위의 위치인가?
2. actions를 반환한 것과 bulk 성공은 같은가?
3. Base64는 암호화인가?

<details>
<summary>풀이</summary>

1. 응답 index는 요청 안 위치이고 last_index는 전체 입력 위치다.
2. 준비와 실제 전송·응답을 구별한다. 최신 원본에는 전송 호출도 있지만 실제 성공은 미확인이다.
3. 데이터 표현 형식이며 암호화가 아니다.

</details>

## 문제 3. 한 가지만 바꾸기

| 한 가지만 변경 | 예상 |
| --- | --- |
|응답 순서만 바꿈 | index로 같은 청크에 연결 |
|응답 하나 누락 | 새 예제 ValueError |
|벡터 숫자 개수 변경 | 새 예제 차원 오류 |
|원본 함수에 같은 chunks 재사용 | embedding 필드가 추가·대체된 상태 |

<details>
<summary>막힐 때 확인</summary>

벡터가 다른 청크에 붙으면 요청 안 index와 전체 위치를 구별한다. 실제 벌크 실패라면 인덱스명·필드·차원·부분 실패를 확인한다. 원본의 모든 청크를 준비한 뒤 앞 10개만 전달하는 경로는 준비량과 외부 요청량이 같지 않다. 실제 서비스 오류는 고정 응답 예제의 성공으로 대신 설명하지 않는다.

</details>

## 채점과 복습

정상 출력뿐 아니라 입력 열·정답·분할·평가 대상의 차이도 설명한다. 새 예제는 독립 실행이며 실제 검색·AI 서비스 성공과 구별한다. TIP 확장은 필수 조건이 아니다. 정의→입력→호출→반환→다음 평가의 흐름을 연결한다.
