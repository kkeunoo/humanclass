실제 수업 내용을 바탕으로 **새로 구성한 연습문제**다. 원본·당시 내 코드·새 개선안을 구별한다. 예상 → 이유 → 한 가지 변경 순서로 푼다.

## 목표와 준비

필드 가중치·terms의 ID 목록·Counter의 반복 단위를 설명한다. 선택 영화→특징 빈도→중복 없는 검색문→재검색을 연결하고 청크 반복에 따른 빈도 왜곡·이미 선택한 영화 제외 여부를 점검한다.

[본문 3절](../../04_영화검색과_콘텐츠기반추천.md#example)의 폴더·설치·입력·실행 조건부터 확인한다. 아래 필요한 파일 전체를 같은 구조로 저장한다. 가져오는 함수·모델 정의도 빠뜨리지 않는다.

## 문제 1. 실행 결과 예상

**feature_tools.py**

```python
from collections import Counter


def build_query(selected_sources, top_n=5):
    genre_counter = Counter()
    tag_counter = Counter()
    for source in selected_sources:
        genre_counter.update(source.get('genres', []))
        tag_counter.update(source.get('tags', []))
    terms = [term for term, _ in genre_counter.most_common(top_n)]
    terms.extend([term for term, _ in tag_counter.most_common(top_n)])
    return ' '.join(dict.fromkeys(terms))
```

**example.py**

```python
from collections import Counter
from feature_tools import build_query

selected = [
    {'movieId': 1, 'genres': ['comedy'], 'tags': ['fun', 'friendship']},
    {'movieId': 2, 'genres': ['comedy', 'action'], 'tags': ['fun']},
]
print('검색문:', build_query(selected))
print('문자열:', dict(Counter('김밥김밥')))
print('단어 목록:', dict(Counter(['김밥', '김밥'])))
print('빈 선택:', repr(build_query([])))
```

실행 전에 결과를 먼저 적는다. 자료의 모양·분류 결과·확률·점수·현재 변수의 대상을 구별한다.

<details>
<summary>풀이</summary>

```text
검색문: comedy action fun friendship
문자열: {'김': 2, '밥': 2}
단어 목록: {'김밥': 2}
빈 선택: ''
```

첫 함수는 실제 원본의 특징 집계 부분을 독립시킨 새 예제다. Counter의 most_common은 빈도 순이고 같은 빈도일 때는 먼저 만난 순서가 영향을 준다. dict.fromkeys는 중복을 제거하되 순서를 보존한다. terms.extend에 사용한 리스트 컴프리헨션은 새 설명 표기이며 원본의 두 목록 더하기와 목적이 같다. 빈 선택은 빈 문자열이며 실제 검색할지 중단할지는 다음 호출자의 정책이다.

| 단계 | 새 예제 |
| --- | --- |
|장르 빈도 | comedy 2·action 1 |
|태그 빈도 | fun 2·friendship 1 |
|검색 단어 | comedy·action·fun·friendship |
|검색문 | 네 단어를 공백으로 연결 |
|실제 재검색 | 이 작은 예제는 실행하지 않음 |

## 문제 2. 이유 설명

1. Counter.update의 문자열과 목록은 어떻게 다른가?
2. 이 함수는 평점을 학습하는가?
3. 같은 영화 청크가 많으면 빈도는 어떻게 되는가?

<details>
<summary>풀이</summary>

1. 문자 단위와 목록 항목 단위다.
2. 장르·태그의 빈도로 검색문을 만들며 평점 모델은 없다.
3. 같은 특징이 반복 집계될 수 있어 추천 단위를 검토해야 한다.

</details>

## 문제 3. 한 가지만 바꾸기

| 한 가지만 변경 | 예상 |
| --- | --- |
|같은 영화 청크를 두 번 추가 | 같은 특징 빈도가 다시 증가 |
|genres를 문자열로 전달 | 문자를 세어 의도와 달라짐 |
|top_n을 1로 | 장르·태그 각 1개 선택 |
|빈 선택 | 빈 검색문·원본의 뒤 호출 정책 확인 |

<details>
<summary>막힐 때 확인</summary>

한 글자씩 검색문이 나오면 Counter에 목록 대신 문자열을 넣었는지 본다. 선택 영화만 계속 나오면 제외 조건이 있는지 확인한다. 추천 목록이 영화 수보다 많으면 청크 단위를 영화 단위와 구별한다.

</details>

## 채점과 복습

정상 출력뿐 아니라 입력 열·정답·분할·평가 대상의 차이도 설명한다. 새 예제는 독립 실행이며 실제 검색·AI 서비스 성공과 구별한다. TIP 확장은 필수 조건이 아니다. 정의→입력→호출→반환→다음 평가의 흐름을 연결한다.
