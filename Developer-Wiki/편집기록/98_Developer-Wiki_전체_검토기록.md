## 편집 원칙

- 실제 수업 내용이 본문이다. 수업 밖 내용은 **‘추가로 알면 좋은 것’**으로 분리했다.
- 해당 주제의 강사님 코드를 먼저, 내 실제 코드를 아래에 놓았다. 원본 오류·미완성 흐름을 숨기지 않고 실제 동작을 설명했다.
- `0716_exam2_vibe`, `0716_exam3_vibe`, `03_database/00_CSS`를 근거에서 제외했다. FastAPI `request.headers`·`response_model`은 배운 내용으로 분류하지 않았다.

## 검증의 의미

각 과목의 최종 기록에는 확인한 원본 인용·링크·대표 동작·실행하지 않은 범위가 적혀 있다. 통합본 Markdown **204개**, 문서 링크 **1,523개**, 그중 문서 내 이동 링크 **598개**, 보존 원본 **524개**의 SHA-256을 검사했다. 문서 내 이동 링크는 명시적 `id`와 GitHub 제목 주소를 대조했으며 끊긴 항목이 없었다. 과목별 원본 발췌의 정확한 행은 각 과목의 검사 기록을 따른다. 완성 ZIP 내부 파일도 작업 파일과 바이트 단위로 대조했다. **정적 검증은 모든 프로그램을 실행했다는 뜻이 아니다.** 외부 API·실제 DB·서버 업로드처럼 환경과 데이터에 따라 달라지는 작업은 각 과목의 한계를 따른다.

완료 후 재검토에서 양쪽 JavaScript `12_dom_content.html`의 시계 실습이 이미 본문에 있음을 확인하고 [통합 용어색인](../99_Developer-Wiki_통합_용어색인.md)에 찾는 길을 추가했다. `workspace_python`에서는 별도 시계 실습을 확인하지 못했다. 과목별 완료 ZIP 7개와 통합 ZIP의 구성 파일도 다시 대조했다. 이전 중간저장 ZIP은 당시 상태를 담은 기록물이므로 완료본 검사에 포함하지 않았다.

이후 첨부된 개인 학습 메모를 다시 읽고 **원본 발췌·개인 메모·재구성 예제**의 구분을 첫 화면에 명시했다. JavaScript의 개발자도구 관찰과 FastAPI의 가상환경 실행 메모는 각각 관련 장에 보조 설명으로 넣고, 출처가 부족한 지도 타일 내부 구조·Git 작업·scikit-learn·Elastic 관련 주제는 [첨부 메모 반영·보류 기록](99_첨부메모_반영_및_이후첨부.md)에 ‘이후 첨부’로 남겼다. CSS 목차에 남아 있던 ‘나머지 과목 완료 후 전체 목차 편집’ 문구도 현재 상태에 맞게 고쳤다.

2026-10-26에 00~09의 폴더 구조를 다시 맞췄다. 모든 과목에 `실습/연습문제/README.md`, 각 수업 본문 장에 대응하는 새 문제 한 개, 실무 코딩스타일과 종합실습을 두었다. 문제는 총 **127개**다(00: 1, 01: 8, 02: 17, 03: 34, 04: 27, 05: 19, 06: 10, 07: 3, 08: 5, 09: 3). 본문 끝에서 그 장의 문제로 바로 이동한다. **실제 강사님 문제와 내 당시 풀이**는 기존 `실습-OOO` 본문이나 SQL 원본 문제 비교에서 따로 읽으며, 새 문제를 원본으로 표시하지 않았다.

## 2026-10-28 재학습용 본문 개편

사용자가 기존 Wiki가 **원본 코드 발췌 중심이라 다시 배우는 데 부족하다**고 지적하여, 00부터 09까지 과목별 Markdown을 숫자 순서로 다시 검토했다. 본문은 **개념 → 작은 설명용 예시와 예상 결과 → 강사님·내 원본 비교 → 실제 동작·오해 교정 → 같은 페이지의 보충 → 장별 연습문제** 흐름으로 다듬었다. 새 예시는 수업 원본이나 실제 서비스 응답으로 표시하지 않았다.

- 00~04는 각 과목 폴더의 본문·실습·안내·옛 경로 문서를 개별 재검토했다. HTML·CSS·JavaScript·Python의 새 예제와 결과를 보강하고, 본문보다 앞선 문법이나 수업 밖 기능을 필수 문제로 요구한 부분을 바로잡았다.
- 05 SQL은 조회·조인·변경·트랜잭션·재귀 CTE의 작은 표와 결과를 먼저 두고, 실제 실행되는 조건과 주석을 대조했다. 특히 self join의 `SMITH` 조건을 빼고 결과를 일반화했던 설명을 수정했다.
- 06 FastAPI는 요청과 응답 흐름을 먼저 설명하고, 개인 메모의 가상환경 명령은 **개인 학습 메모**로 구분해 넣었다. `request.headers`와 `response_model`은 배운 본문에 넣지 않았다. SQLite 연결 문맥 관리와 원본 주석의 차이도 고쳤다.
- 07 데이터 분석은 RandomForest가 무엇인지, 나무 수·난수 고정·학습·분류·확률의 역할을 작은 결과 예시와 함께 설명했다. F1·ROC AUC·교차 검증·GridSearchCV의 역할도 나눠 읽도록 했다.
- 08 Elasticsearch·RAG는 문서·인덱스·매핑부터 검색·청크·벡터·순위 합치기·질문응답까지 한 단계씩 잇고, 원본의 `doc2 = doc`과 저장 본문의 차이를 개선점으로 명시했다.
- 09 영화 CSV는 `movieId` 관계와 문자열·청크의 결과 모양을 먼저 보여 주었다. 강사님 `pass`, 학생의 임베딩 요청 코드, 미구현 ES 벌크, 실제 외부 실행 결과를 서로 구별했다.

00~09의 과목 README와 전체 첫 화면, 최상위 README도 새 읽기 순서에 맞췄다. 첨부 메모의 반영·보류 기록은 FastAPI 가상환경 안내의 실제 위치와 07~09의 새 수업 근거를 반영했다. **최신 통합 검사 수치와 최종 압축 검사는 이번 개편 산출물을 만든 뒤 다시 확인한다.** 이전 문단의 2026-10-26 수치는 당시 상태의 기록이다.
