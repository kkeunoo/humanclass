## 여섯 기준으로 다시 읽은 결과

1. **처음 배우는 학생:** 과목 README → 개념과 작은 예시·결과 → 강사님/내 원본 → 동작 설명 → 복습 순서를 유지한다. 실행 준비 메모는 FastAPI 첫 장에서 개인 메모로 표시해 앱 원본 발췌와 구분했다.
2. **실제 코드와 새 설명:** 원본 발췌의 출처·행, 설명용 재구성, 개인 학습 메모를 다른 표기로 구별한다. 첨부 텍스트는 원본 코드 인용으로 바꾸지 않았다.
3. **두 코드 비교:** 실제로 같은 코드면 같다고 말하고, 오류·미완성은 각 장에서 차이를 설명한다. 학생 쪽에만 있는 미래 주제는 억지로 강사님 비교를 만들지 않고 보류했다.
4. **나중의 복습:** 각 장의 원본 경로, 한계, 추가편, [통합 용어색인](../99_Developer-Wiki_통합_용어색인.md)을 이용해 다시 확인할 수 있다. 수업 당시 주석이 틀리면 주석과 실제 동작을 분리한다.
5. **이동 흐름:** 첫 화면은 HTML → CSS → JavaScript → Python → SQL → FastAPI → 데이터 분석 → Elasticsearch·RAG → 영화 CSV 순서로 연결하고, 과목 안에서는 README와 장 앞머리·끝의 이동 링크를 따른다. 보조 메모는 해당 장의 설명 또는 끝부분에서 읽는다.
6. **첨부 텍스트:** 위 표처럼 이미 반영된 주제, 이번에 보강한 메모, 추가편, 이후 첨부를 분리했다. 비밀번호·접속 주소·API 키 같은 값은 이 기록과 Wiki에 복사하지 않았다.
