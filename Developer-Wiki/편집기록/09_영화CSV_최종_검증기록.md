# 09 영화 CSV·청크·임베딩 검증 기록

[09 단원 목차](../09_영화CSV_청크와_임베딩/README.md) · [편집기록 목차](README.md)

2026-10-26. 양쪽 `workspace_python/08_langgraph`의 `api.py`, `util.py`, `router/es_router.py`와 MovieLens CSV를 대조해 README와 본문 3장을 작성했다. 가상환경 생성물·키 값은 제외했다.

- **실제 본문:** CSV 읽기와 `movieId` 관계 확인, 제목·장르·태그의 텍스트 결합, 50글자 청크·15글자 겹침, 학생이 작성한 Gemini·OpenAI 임베딩 action 준비.
- **원본 비교:** 강사님 코드 먼저, 내 코드 아래에 배치했다. 출처·행 번호가 있는 발췌 19곳을 현재 파일과 대조했다. 강사님 임베딩 두 함수는 `pass`, 내 두 함수는 반환까지 작성돼 있다. 앞선 범위 선정 기록의 “내 OpenAI 함수가 미완성 시작 부분”이라는 판단은 최신 파일을 다시 읽고 **정정**했다.
- **입력 자료:** 양쪽 MovieLens CSV 네 개의 파일 내용이 같다. 학생 파일 기준 데이터 행은 `movies.csv` 9,742개, `tags.csv` 3,683개, `ratings.csv` 100,836개다. 이 수치는 원본 CSV 자체를 센 것이며 API 실행 응답은 아니다.
- **실행 경계:** 양쪽 라우터는 `Literal`을 import하지 않았다. 내 `/es/bulk`는 `pass`다. 코드에 LangGraph 그래프 생성이 없다. 외부 API와 ES에 연결하지 않았고 임베딩 성공·저장·검색 결과는 확인하지 않았다.
- **주석 교정:** Base64는 암호화가 아니다. 내 라우터에서 중복된 `embedding` 함수명과 수동 태그 딕셔너리 결과를 곧바로 `groupby` 결과로 덮는 흐름을 구별했다.

이후 파일이 추가되면 기존 문서를 자동으로 완료 표시하지 않고 새 실제 구현과 다시 대조한다.
