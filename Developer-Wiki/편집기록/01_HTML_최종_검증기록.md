# 01 HTML — 최종 개편·검증 기록

2026-09-18 · [HTML 읽기 안내](../01_HTML/README.md)

## 완료 범위

현재 HTML의 기존 13개 문서에 처리 방침을 적용했다. 01~07은 실제 수업 원본 비교로 재작성하고, 폼 전송을 07-02로 분리했다. 08·09는 추가편 이동 안내, 10은 수업 범위 기본 복습으로 개편했다. README를 완성하고 옛 읽기법·편집 기록은 새 안내로 연결했다. 추가편 4개와 실행용 HTML 2개를 제공한다.

Wiki 전체 README와 통합 색인의 최종 편집은 사용자 요청대로 모든 과목 이후에 수행한다. 이번에는 그 문서가 가리키는 기존 HTML 링크가 끊기지 않도록 호환 안내를 넣었다.

## 수업 근거와 분류

- 강사님과 내 `workspace_html/01_hello.html`~`07_form.html`, `03_상대주소/03_a.html`, `asset/detail.html`을 기준으로 비교했다.
- 실제 원본 발췌 43곳의 주석·이름·값을 그대로 유지했다. 행 번호는 각 ZIP의 파일 기준이다.
- 설명용 수정·재구성은 원본과 구분했다. 원본이 잘못되었을 때 발췌를 몰래 고치지 않고 아래에서 교정했다.
- 사용자 지정 제외 자료를 근거로 사용하지 않았다. 개인 과제에 태그가 있다는 이유로 상세 설계를 필수 진도에 편입하지 않았다.
- `tel:`·`mailto:`와 color·date·time·number·range는 원본에 있어 메인에 유지했다.
- 시맨틱 전체 설계·ARIA·새 미디어·추가 입력 검증·협업 설계는 추가편으로 분리했다.
- 사용자가 학습을 확인한 dataset은 JS 과목의 메인으로 남길 것을 추가편에서도 명시했다.

## 기존 내용과 BACKUP의 처리

| 이전 내용 묶음 | 최종 위치·처리 |
| --- | --- |
| 문서 선언·태그·속성·title | 01 기본 장, 반복 정의 통합 |
| 제목·강조·문단·공백·문자 참조 | 02 기본 장 |
| 경로·페이지 이동·링크 | 03 기본 장 |
| 목록·중첩·정의 목록 | 04 기본 장 |
| 표·병합·구역·원본 오류 | 05 기본 장 |
| 이미지·동영상 원본 | 06 기본 장 |
| 입력·선택·label·초기화 | 07 기본 장 |
| name/value·GET·POST·서버와 구분 | 07-02 기본 장 |
| 08의 페이지 유형별 반복 골격 | 추가편 01의 역할 표·하나의 예제·유형별 판단 표로 통합 |
| 09의 원본 오류 교정 | 해당 기본 장으로 회수. 추가편 03에 찾아갈 위치 정리 |
| 09의 설계 약속·검수 | 추가편 03 |
| 10의 큰 교육 사이트·후속 기능 | 추가편 04로 축약 재구성, 미디어·폼·표 확장은 추가편 02로 분리 |
| 읽기법·과거 검사 주장 | README와 현재 기록으로 통합. 과거 검사 결과를 새 결과로 사용하지 않음 |

BACKUP의 HTML 13개 파일도 대조했다. 문서 구조·태그/속성·제목·문단·링크·목록·이미지·표·폼은 같은 주제의 기본 장에서 설명하고, 시맨틱은 추가편 01로 연결한다. 전역 속성 문서의 `id`·`title`·`lang`·`hidden`은 실제 원본 범위만 기본 장에 남기고, 그 밖의 확장은 추가편 02에서 분리했다. 두 옛 README는 별도 목차로 이중 운영하지 않는다.

기존의 모든 문장·문제를 보존한 판은 아니다. 같은 설명과 큰 예제의 반복을 통합하고, 원본 밖 기능은 역할·전제·추가 예제로 재작성했다. 제공된 원본 ZIP과 추출 원본은 수정하지 않았다.

## 실제 동작 확인

Windows 환경의 Codex 내장 브라우저와 `127.0.0.1` 로컬 HTTP 서버를 사용했다. 테스트 서버는 받은 예시 값을 화면에 돌려줄 뿐, 외부 발송이나 업무 데이터 저장을 하지 않는다. 도구용 서버 구현은 Wiki 학습 진도에 넣지 않았다.

| 검증 | 결과 |
| --- | --- |
| 문단 공백·문자 참조·중첩 목록 | 이전 작업에서 설명과 표시 일치 확인 |
| 상대·루트 경로, 내부 이동 | 로컬 도착 페이지·fragment 확인 |
| 표 병합 | 2행×3열 점유와 rowSpan/colSpan 확인 |
| 양쪽 title | 강사님 Document, 내 주석 문자열 포함 확인 |
| 이미지 파일 | 양쪽 ZIP의 PNG 바이트 해시 동일. 원본 100×83 |
| 이미지 크기 | 200×300 지정 결과, 너비만 200인 경우 200×166 확인 |
| 동영상 | controls·loop 활성, autoplay 비활성, 로드·버튼 재생·시간 진행 확인 |
| label·select·textarea·reset | 클릭으로 선택 변경, 분류·메모 변경 후 초기 상태 복원 확인 |
| placeholder | 키보드로 값을 모두 지우면 빈 value와 힌트 상태, reset 뒤 초기값 확인 |
| GET/POST 수정 예제 | 둘 다 song=hello, fixed=A, coffee=1, coffee=2. 이름 없는 입력·disabled 제외 |
| 강사님 마지막 coffee 선택 | coffee=on, gender=남자, sel1=4 확인 |
| 내 마지막 coffee 선택 | coffee=5, gender=여자, sel1=4 확인 |
| textarea 원본 차이 | 강사님 br·주석 모양이 값에 포함됨, 내 들여쓰기·줄바꿈도 값에 포함됨 |
| 기본 종합복습 | 초기 쿼리와 폼·오후 추가 선택 쿼리 모두 문서와 일치 |
| 추가 프로젝트 | 빈 필수값, 잘못된 이메일의 검증과 정상 예시 값 제출 확인 |

미디어 검증 당시 외부 영상은 제공되었으나 이후 가용성까지 보장하지 않는다. 전체 반복 재생 경계를 정밀 측정하지 않았다. 전화·메일 앱 실행, 외부 검색 제출, 실제 신청 저장·메일 발송, 모든 브라우저·스크린 리더 검수는 수행하지 않았다.

## 문서·링크 검사

- HTML Markdown 18개와 관련 편집 기록 2개, 총 20개를 검사했다.
- 내부 링크 144개: 대상 파일·명시적 앵커 연결 확인.
- 기존 Wiki 다른 문서에서 HTML로 연결하는 주소 203개: 대상 유지 확인. 옛 앵커 191개는 이동 안내로 연결하며, 개편 전 절과 새 절이 동일하다는 의미는 아니다.
- 원본 발췌 43곳: 원본의 해당 행과 텍스트 일치.
- 추출 원본 524개: 개편 전 SHA-256 해시와 일치.
- 실행용 HTML 2개: 각 Markdown의 전체 예제와 일치.
- 코드블록·접기 태그 여닫기, 중복 명시적 앵커, 미완성 치환 표식 검사 통과.
- 로컬 Markdown 미리보기에서 README 목차·표·링크를 확인했다. 종합복습의 정답 접기가 열리고 예제가 코드로 표시되며, 폼 장의 코드블록 10개·표 5개가 표시됨을 확인했다. 확인한 화면에서 페이지 전체의 가로 넘침은 없었다.

로컬 Markdown 렌더링과 접기·표시 검사를 수행했다. 이는 GitHub 서버에 게시하여 렌더링한 검사와는 구분한다. 기술 설명의 정확성 참고 링크는 각 장에 넣었으며, 공식 문서 전체를 배웠다는 뜻은 아니다.
