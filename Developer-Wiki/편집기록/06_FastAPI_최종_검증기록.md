# 06 FastAPI 최종 검증 기록

2026-10-26. 강사님과 내 `workspace_python` 실제 코드로 01–09장을 개편하고, 두 원본에 있는 별도 비밀번호 해시 실습을 07-02로 분리했다. 수업 파일의 업로드 폼과 브라우저 쿠키 팝업도 본문에 포함했다. 기존 Wiki의 `request.headers` 직접 읽기와 `response_model`은 원본에서 찾지 못했고, 사용자도 배우지 않았다고 확인했으므로 [추가편](../06_FastAPI/추가편_기존자료_학습범위_분류.md)으로 분류했다.

## 재검토에서 바로잡은 부분

- 첫 앱의 `return` 없는 경로는 404가 아니라 JSON `null` 응답이다.
- 내 `Todo` 모델의 `value1/value2`와 경로 함수의 `.id` 사용이 맞지 않으며, 내 요청 처리의 일부 분기에는 `data`가 정의되지 않는다.
- 강사님 리다이렉트는 POST→303→GET이고, 내 코드는 GET→307→GET이다. 앞 요청의 쿼리값이 다음 URL에 실리는지도 다르다.
- SQLite의 `with sqlite3.connect(...)`는 트랜잭션 종료에 관여하지만 연결 객체를 자동으로 닫는 문법은 아니다.
- 강사님 SQLModel `Emp3`에는 `table=True`가 없고 내 코드에는 있다. 저장 대상과 실제 테이블 존재를 구분했다.
- 파일 업로드에서 `file2` 목록은 이름만 출력하고 저장하지 않는다. 강사님의 선택 파일 선언 뒤 `None` 검사 누락도 적었다.
- 쿠키 `max_age=1000`은 10초가 아닌 1000초다. 세션 `/login`은 비밀번호를 검사하지 않는다.

## 검증 범위와 한계

FastAPI 폴더 Markdown **16개**, 링크 **64개**, 원본 발췌 **104곳**, 보존 원본 해시 **524개**를 확인했다. 발췌는 지정한 파일·행의 내용과 일치하고, 코드 울타리와 링크도 검사했다. Wiki 첫 화면과 쿠키·세션, Jinja 문서는 **숨긴 내부 웹페이지**로 읽기 흐름을 확인했다. 실제 DB 연결, 업로드 서버 실행, 인증 흐름의 운영 환경 검사는 수행하지 않았다. 원본에는 DB 접속 정보와 세션 비밀키가 직접 있으므로 Wiki 발췌에는 옮기지 않았다. ZIP 내부 파일과 작업 파일의 바이트 일치도 검사했다.
