## 왜 이 내용을 배우는가?

Media Query은(는) 이후 예제와 문제를 이해하기 위한 기본 도구다. 문법만 외우기보다 어떤 상황에서 필요하고, 코드가 어떤 순서로 동작하는지 이해해야 다른 문제에도 적용할 수 있다.

> [!TIP]
> 문법을 외우기 전에 **무엇을 해결하기 위한 문법인지** 먼저 확인한다. 같은 문법도 목적을 이해하면 다른 예제에서 다시 사용할 수 있다.

> [!NOTE]
> **💡 WHY — 왜 중요한가?**  
> 화면 크기마다 사용할 수 있는 공간이 다르므로 동일한 배치를 그대로 유지할 수 없다. 미디어 쿼리는 조건에 따라 필요한 스타일만 덮어쓴다.

> [!TIP]
> **⭐ 실무 TIP**  
> 모바일에서 필요한 핵심 콘텐츠와 터치 영역을 먼저 확인하고, breakpoint는 실제 레이아웃이 무너지는 지점에서 정한다.

> [!IMPORTANT]
> **📌 반드시 기억하기**  
> 미디어 쿼리는 별도 페이지를 만드는 것이 아니라 기존 스타일을 조건부로 재정의한다.

> [!WARNING]
> **⚠️ 주제별 자주 하는 실수**  
> 기기 이름만 보고 breakpoint를 정하거나 데스크톱 스타일을 모두 복사하면 중복이 커진다.

> [!NOTE]
> **🏫 수업 메모**  
> 예제 코드를 실행한 뒤 값이나 선택자를 하나씩 바꾸고, 결과가 달라지는 이유를 자신의 말로 설명한다. 정답 코드보다 실행 순서와 오류 원인을 설명할 수 있는지가 더 중요하다.

# 개념과 수업 예제

```css
.cards { display: flex; gap: 20px; }

@media (max-width: 768px) {
  .cards { flex-direction: column; }
  .desktop-menu { display: none; }
}
```

## 모바일 대응 원칙

- 고정 너비 대신 `%`, `max-width`를 함께 사용한다.
- 작은 화면에서 가로 배치를 세로로 전환한다.
- 클릭 영역을 너무 작게 만들지 않는다.
- 긴 메뉴는 아코디언이나 모바일 메뉴로 바꾼다.

## 주의사항

미디어 쿼리에서 기존 스타일을 전부 다시 쓰지 말고 달라지는 속성만 덮어쓴다.

# 자주 하는 실수

- 예제 코드를 그대로 복사하고 각 줄의 역할을 확인하지 않는 실수
- 입력값과 출력값의 자료형을 확인하지 않는 실수
- 한 번에 많은 코드를 작성해 오류가 발생한 위치를 찾기 어렵게 만드는 실수
- 브라우저 또는 콘솔에서 직접 결과를 확인하지 않는 실수

> [!WARNING]
> 오류가 발생하면 코드를 한꺼번에 바꾸지 않는다. 선택 결과, 변수값, 자료형, 조건식 결과를 `console.log()` 또는 출력문으로 하나씩 확인한다.

# 실무 연결
