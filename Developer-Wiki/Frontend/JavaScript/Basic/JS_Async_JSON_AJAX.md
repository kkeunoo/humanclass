> [!NOTE]
> **💡 WHY — 왜 중요한가?**

> [!TIP]
> **⭐ 실무 TIP**  
> 요청, 응답 확인, JSON 변환, 화면 반영 단계를 나누고 각 단계의 값을 콘솔에서 확인한다.

> [!IMPORTANT]

> 비동기 작업은 코드가 작성된 순서와 완료되는 순서가 다를 수 있다.

> [!WARNING]
> **⚠️ 주제별 자주 하는 실수**  
> 응답이 오기 전에 결과 변수를 사용하거나 JSON 변환 단계를 생략하면 원하는 데이터에 접근할 수 없다.

> [!NOTE]
> **🏫 수업 메모**  
> 예제 코드를 실행한 뒤 값이나 선택자를 하나씩 바꾸고, 결과가 달라지는 이유를 자신의 말로 설명한다. 정답 코드보다 실행 순서와 오류 원인을 설명할 수 있는지가 더 중요하다.

# 개념과 수업 예제

## 타이머와 실행 순서

```js
console.log('1');
setTimeout(() => console.log('2'), 0);
console.log('3');
// 1, 3, 2
```

## JSON

```js
const text = '{"name":"kim","age":20}';
const user = JSON.parse(text);
const again = JSON.stringify(user);
```

## AJAX 기본 흐름

```js
fetch('https://example.com/data')
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error(error));
```

## 실무 연결

페이지 전체를 새로고침하지 않고 서버 데이터를 받아 목록을 갱신한다.

## 주의사항

- 네트워크 요청은 즉시 완료되지 않는다.
- 응답 상태와 데이터 구조를 확인한다.
- 외부 API 키를 소스 코드에 그대로 공개하지 않는다.

# 자주 하는 실수

- 예제 코드를 그대로 복사하고 각 줄의 역할을 확인하지 않는 실수
- 입력값과 출력값의 자료형을 확인하지 않는 실수
- 한 번에 많은 코드를 작성해 오류가 발생한 위치를 찾기 어렵게 만드는 실수
- 브라우저 또는 콘솔에서 직접 결과를 확인하지 않는 실수

> [!WARNING]
> 오류가 발생하면 코드를 한꺼번에 바꾸지 않는다. 선택 결과, 변수값, 자료형, 조건식 결과를 `console.log()` 또는 출력문으로 하나씩 확인한다.
