## 왜 이 내용을 배우는가?

연산자와 조건문은(는) 이후 예제와 문제를 이해하기 위한 기본 도구다. 문법만 외우기보다 어떤 상황에서 필요하고, 코드가 어떤 순서로 동작하는지 이해해야 다른 문제에도 적용할 수 있다.

> [!TIP]
> 문법을 외우기 전에 **무엇을 해결하기 위한 문법인지** 먼저 확인한다. 같은 문법도 목적을 이해하면 다른 예제에서 다시 사용할 수 있다.

# 개념과 수업 예제

## 연산자

```js
const total = price * quantity;
const isAdult = age >= 20;
const canEnter = isAdult && hasTicket;
```

## 비교 연산자

가능하면 값과 자료형을 함께 비교하는 `===`, `!==`를 사용한다.

```js
console.log(1 === '1'); // false
console.log(1 == '1');  // true
```

## if

```js
if (score >= 90) {
  console.log('A');
} else if (score >= 80) {
  console.log('B');
} else {
  console.log('C');
}
```

## switch

```js
switch (menu) {
  case 'coffee': console.log('커피'); break;
  case 'tea': console.log('차'); break;
  default: console.log('메뉴 없음');
}
```

## 주의사항

조건 범위는 큰 값부터 검사한다. 입력값 검증 없이 비교하면 빈 문자열이 0처럼 변환되는 등 예상하지 못한 결과가 생길 수 있다.

> [!TIP]
> 문제를 바로 코드로 옮기지 말고 **입력 → 처리 → 출력**을 먼저 한 줄씩 적는다. 그 다음 필요한 변수, 반복 횟수, 조건식을 정하면 코드가 단순해진다.

## 공통 문제 해결 순서

1. 입력값이 문자열인지 숫자인지 확인한다.
2. 정상 입력과 비정상 입력을 먼저 구분한다.
3. 여러 조건이 겹칠 때는 범위가 큰 조건 또는 예외 조건부터 검사한다.
4. 조건문 내부에는 결과 처리만 두고, 변환과 검증은 앞에서 끝낸다.
5. 경계값인 `0`, `60`, `24`처럼 조건이 바뀌는 지점을 직접 테스트한다.

## 문제 1. 양수와 음수 판별

### 문제

사용자가 입력한 값을 숫자로 변환하고 양수인지 음수인지 출력한다. 숫자가 아니거나 입력을 취소한 경우도 처리한다.

### 접근 방법

- `prompt()`의 반환값은 문자열 또는 `null`이다.
- 빈 문자열을 `Number()`로 바꾸면 `0`이 되므로 변환 전에 빈값을 확인한다.
- 숫자 변환 뒤 `Number.isNaN()`으로 변환 실패를 확인한다.
- 수학적으로 0은 양수도 음수도 아니므로 요구사항에 따라 별도로 처리하는 편이 명확하다.

### 개선 풀이

```js
const input = prompt('숫자를 입력하세요.');

if (input === null || input.trim() === '') {
  console.log('입력이 취소되었거나 비어 있습니다.');
} else {
  const value = Number(input);

  if (Number.isNaN(value)) {
    console.log('숫자만 입력하세요.');
  } else if (value > 0) {
    console.log('양수입니다.');
  } else if (value < 0) {
    console.log('음수입니다.');
  } else {
    console.log('0입니다.');
  }
}
```

### 개인 풀이와 강사 풀이 비교

| 구분 | 장점 | 보완할 점 |
|---|---|---|
| 개인 풀이 | 취소, 빈값, 문자 입력 같은 예외 상황을 적극적으로 고려했다. | 자동 형 변환에 기대는 조건은 의도를 읽기 어렵게 만들 수 있다. |
| 강사 풀이 | 핵심 분기 구조가 짧고 수업 개념을 빠르게 확인할 수 있다. | 실제 입력에서는 빈 문자열이나 문자가 들어올 수 있으므로 검증을 추가해야 한다. |

> [!IMPORTANT]
> `if (input >= 0)`처럼 문자열을 바로 숫자와 비교하면 JavaScript가 자동 형 변환을 수행한다. 동작은 할 수 있지만, 학습과 실무 모두 `Number(input)`처럼 변환을 명시하는 편이 안전하다.

### 테스트 값

```text
10       → 양수입니다.
-3       → 음수입니다.
0        → 0입니다.
공백     → 입력이 취소되었거나 비어 있습니다.
hello    → 숫자만 입력하세요.
취소     → 입력이 취소되었거나 비어 있습니다.
```

## 문제 2. 홀수와 짝수 판별

### 핵심 원리

정수를 2로 나눈 나머지가 0이면 짝수이고, 0이 아니면 홀수다.

```js
const input = prompt('정수를 입력하세요.');
const value = Number(input);

if (input === null || input.trim() === '' || !Number.isInteger(value)) {
  console.log('정수를 입력하세요.');
} else if (value % 2 === 0) {
  console.log('짝수입니다.');
} else {
  console.log('홀수입니다.');
}
```

### 자주 틀리는 표현

```js
// 잘못 읽히기 쉬운 코드
if (!value % 2 == 0) { }
```

`!`가 먼저 실행되어 숫자가 불리언으로 바뀐다. 원하는 조건을 직접 표현한다.

```js
value % 2 !== 0
```

> [!TIP]
> 조건식은 “코드가 짧은가”보다 “말로 그대로 읽히는가”가 중요하다. `value % 2 === 0`은 “2로 나눈 나머지가 0과 같다”라고 바로 읽힌다.

## 문제 3. 가진 돈에 따라 교통수단 선택

### 문제 해결 생각 순서

1. 택시를 탈 수 있는 최소 금액을 확인한다.
2. 그보다 적다면 버스를 탈 수 있는지 확인한다.
3. 둘 다 불가능하면 걷는다.
4. 큰 금액 조건부터 검사하면 범위를 중복해서 적지 않아도 된다.

```js
const money = 5200;

if (money >= 7000) {
  console.log('택시를 탄다.');
} else if (money >= 3000) {
  console.log('버스를 탄다.');
} else {
  console.log('걸어간다.');
}
```

### 좋지 않은 방식

```js
if (money >= 3000 && money < 7000) { }
```

앞선 `if (money >= 7000)`이 실패한 뒤의 `else if`라면 이미 `money < 7000`인 상태다. 같은 조건을 반복할 필요가 없다.

### 실무 연결

회원 등급, 배송비, 할인율처럼 구간을 나누는 로직도 같은 방식으로 작성한다. 경계값을 표로 먼저 정리하면 오류가 줄어든다.

| 금액 | 결과 |
|---:|---|
| 7000 이상 | 택시 |
| 3000 이상 7000 미만 | 버스 |
| 3000 미만 | 도보 |

## 문제 4. 현재 시각에서 35분 후 계산

### 접근 방법

- 먼저 분에 35를 더한다.
- 60분 이상이면 시간으로 넘긴다.
- 24시 이상이면 0시부터 다시 계산한다.

```js
let hour = 23;
let minute = 51;

minute += 35;
hour += Math.floor(minute / 60);
minute %= 60;
hour %= 24;

console.log(`${hour}시 ${minute}분`);
```

### 왜 이 풀이가 좋은가

`if`를 여러 번 겹치는 대신 나눗셈의 몫과 나머지를 사용한다. 35분뿐 아니라 135분처럼 더 큰 값에도 동작한다.

> [!WARNING]
> `minute = minute - 60`만 한 번 실행하면 120분 이상 증가하는 상황에서는 잘못된 값이 남을 수 있다. 범용적으로 만들려면 몫과 나머지를 사용한다.

## 문제를 더 잘 푸는 방법

- 조건을 코드로 쓰기 전에 표로 만든다.
- `0`, 최소값, 최대값, 바로 이전 값과 바로 다음 값을 테스트한다.
- 입력 검증과 실제 문제 해결 로직을 분리한다.
- 복잡한 조건은 불리언 변수에 이름을 붙인다.

```js
const isEmpty = input === null || input.trim() === '';
const isNumber = !Number.isNaN(Number(input));
```

# 자주 하는 실수

- 예제 코드를 그대로 복사하고 각 줄의 역할을 확인하지 않는 실수
- 입력값과 출력값의 자료형을 확인하지 않는 실수
- 한 번에 많은 코드를 작성해 오류가 발생한 위치를 찾기 어렵게 만드는 실수
- 브라우저 또는 콘솔에서 직접 결과를 확인하지 않는 실수

> [!WARNING]
> 오류가 발생하면 코드를 한꺼번에 바꾸지 않는다. 선택 결과, 변수값, 자료형, 조건식 결과를 `console.log()` 또는 출력문으로 하나씩 확인한다.
