## 1. 이 장에서 배울 것

직접 SDK 호출과 LangChain의 모델 호출을 구별하고, 역할이 다른 메시지와 프롬프트 입력값을 추적한다. 콘솔 스트리밍과 HTTP 응답의 경계를 확인한다.

<a id="concepts"></a>

## 2. 무엇이며, 왜 필요한가

프롬프트는 모델에 줄 입력이다. 메시지 목록으로 만들면 시스템 지시, 사용자 질문, 앞선 모델 답변의 역할을 구별할 수 있다. `ChatPromptTemplate`은 이름과 질문 같은 자리에 값을 채워 메시지 목록을 만든다. `MessagesPlaceholder`는 대화 이력처럼 길이가 달라지는 메시지 목록을 받는다.

| 코드 | 무엇이 들어가나 | 결과를 어디에서 보나 |
| --- | --- | --- |
| `model.invoke(prompt)` | 한 질문 문자열 | LangChain 메시지의 `content` |
| `model.invoke(messages)` | 역할이 있는 대화 목록 | LangChain 메시지의 `content` |
| `model.stream(messages)` | 역할이 있는 대화 목록 | 반복해서 받는 메시지 조각 |
| `template.invoke(values)` | 템플릿에 채울 값 | 채워진 프롬프트 값 |

<a id="example"></a>

## 3. 작은 예제로 먼저 이해하기

**설명용 전체 예제.** [실행 파일](실습/책형_복습/01_모델호출과_메시지/example.py)을 해당 장의 Python 환경으로 실행한다. 모든 입력과 모델 대역은 복습용이며 외부 서비스에 요청하지 않는다.

```python
from langchain_core.messages import HumanMessage
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder

template = ChatPromptTemplate.from_messages([
    ('system', '영화 도우미'),
    MessagesPlaceholder('history', optional=True),
    ('human', '{question}'),
])
prompt = template.invoke({
    'history': [HumanMessage('액션을 좋아해요')],
    'question': '영화 하나 추천해 주세요',
})
for message in prompt.to_messages():
    print(message.type, message.content)
```

**실행 결과**

```text
system 영화 도우미
human 액션을 좋아해요
human 영화 하나 추천해 주세요
```

## 4. 내 폴더의 실제 코드 읽기

**원본 발췌 · D:/workspace/workspace_python/08_langgraph/router/langchain_router.py 185–201행**

```python
@router.get("/langchain/gpt/messages_placeholder")
def messages_placeholder(name: str, prompt: str):
    prompt_template = ChatPromptTemplate.from_messages([
        ("system", "너는 친절한 조수야"),
        MessagesPlaceholder("history", optional=True), # optional=True는 선택사항으로 없어도 됨
        ("human", '{prompt}') # 아직 '{prompt}'라는 글씨일 뿐이다
    ])

    prompt_template.invoke({
        "history": [
            HumanMessage("내 이름은 근욱이야."),
            AIMessage("안녕하세요. 근욱님! 친절히 알려드릴께요"),
        ], 
        "prompt": prompt
    })

    print(prompt_template)
```

**풀이:** `history`에 기존 사용자와 AI 메시지를 넣고 `prompt`에 이번 질문을 넣는다. 원본은 `invoke()`의 반환값을 저장하지 않고 템플릿 객체를 `print()`한다. 별도 반환문이 없어 구성된 대화나 모델 답변이 HTTP 응답으로 전달되지 않는다. `name`도 이 함수의 메시지 구성에는 쓰이지 않는다.

<a id="connections"></a>

## 5. import·함수·입력·출력이 연결되는 흐름

`api.py`의 `include_router(langchain_router)`가 `/langchain/...` 실습을 FastAPI 앱에 붙인다. `/original/gpt`와 `/original/gemini`는 공급자 SDK를 직접 호출해 각 SDK의 응답 객체를 돌려준다. `/langchain/gpt`, `/langchain/gpt/multi`, `/langchain/gpt/message`, `/langchain/gemini`는 LangChain 모델로 호출한다. `/langchain/gpt/stream`의 `for chunk`는 `print(chunk.content, ...)`로 서버 콘솔에 쓴다.

<a id="review"></a>

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점.** 단발 질문, 역할이 있는 메시지, 템플릿을 다른 경로에서 비교할 수 있다.

**아쉬운 점.** `history`는 코드에 들어 있는 예시이며 요청 간에 자동으로 저장되는 기록은 없다. 프롬프트 출력을 보려면 `invoke()` 결과를 변수에 담고 메시지 목록을 확인한다. 브라우저에서 순차 응답이 필요하다면 HTTP 전송 방식도 설계해야 한다.

<a id="teacher"></a>

## 7. 강사님 코드가 도움이 되는 비교

강사님 코드도 템플릿 실습과 모델 호출 실습을 분리하고 스트림 조각은 콘솔에 출력한다. 같은 동작은 한 번만 읽고, 직접 SDK 방식과 LangChain 방식의 메시지·응답 모양을 비교한다.

<a id="results"></a>

## 8. 결과를 추적하고 한 가지 바꾸기

`history` 항목을 입력에서 빼고 실행한다. `optional=True`라서 가운데 메시지만 빠지는지 확인한다. `question`까지 빼면 템플릿에 필요한 변수가 비는 상황을 관찰할 수 있다.
