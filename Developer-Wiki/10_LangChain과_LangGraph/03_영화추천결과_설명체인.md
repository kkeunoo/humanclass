# 영화 추천 결과를 설명하는 체인

## 1. 이 장에서 배울 것

추천 점수를 계산하는 부분과 모델이 설명을 만드는 부분을 연결한다. 모델 입력에 실제로 어떤 근거가 있는지 확인한다.

<a id="concepts"></a>

## 2. 무엇이며, 왜 필요한가

추천 함수는 후보와 점수를 계산한다. 설명 체인은 후보를 받아 사람이 읽기 쉬운 문장을 만든다. 현재 `es_router.hybrid()`가 주는 자료는 영화 ID별 제목과 점수다. 줄거리와 한글 제목을 요구하려면 그 정보가 있는 별도 자료를 찾아 전달해야 한다. 프롬프트의 검색 요청과 코드가 검색 도구를 호출하는 동작을 구별한다.

<a id="example"></a>

## 3. 작은 예제로 먼저 이해하기

**설명용 전체 예제.** [실행 파일](실습/책형_복습/03_영화추천결과_설명체인/example.py)을 해당 장의 Python 환경으로 실행한다. 모든 입력과 모델 대역은 복습용이며 외부 서비스에 요청하지 않는다.

```python
from langchain_core.messages import AIMessage
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnableLambda

hybrid = {30: {'title': '복습용 영화', 'score': 0.03252}}
prompt = ChatPromptTemplate.from_messages([
    ('system', '주어진 후보만 설명한다.'), ('human', '후보: {hybrid}'),
])


def fixed_model(messages):
    text = messages.to_messages()[-1].content
    assert '복습용 영화' in text and '0.03252' in text
    return AIMessage(content='복습용 영화 · RRF 점수 0.03252')


chain = prompt | RunnableLambda(fixed_model) | StrOutputParser()
print(chain.invoke({'hybrid': hybrid}))
```

**실행 결과**

```text
복습용 영화 · RRF 점수 0.03252
```

<a id="review"></a>

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점.** 추천 후보 생성과 설명을 분리해 같은 후보로 두 모델의 응답을 비교할 수 있다.

**아쉬운 점.** JSON을 요구해도 `StrOutputParser`를 통과한 값은 문자열이다. 내 개인 풀이의 HTML 요청도 HTML HTTP 응답 설정과 별개다. 검색 도구 연결 없이 한글 제목이나 줄거리를 물으면 확인된 근거가 부족하다. 답변에 추가된 영화 ID와 원본 후보를 비교하는 검증을 개선안으로 고려할 수 있다.

<a id="teacher"></a>

## 7. 강사님 코드가 도움이 되는 비교

강사님 소스에도 추천을 설명하는 공동 경로가 있다. 내 개인 경로는 HTML 표현을 요청하고 공동 풀이는 JSON 형태를 요청한다. 응답 표현의 요청과 실제 타입·HTTP 표현을 각각 확인한다.

<a id="results"></a>

## 8. 결과를 추적하고 한 가지 바꾸기

고정 후보의 제목을 바꾸면 현재 대역의 `assert`에서 실패한다. 실제 모델에는 이런 단정문이 없으므로 출력에서 원본 후보를 검증하는 코드를 별도로 설계해야 한다.

<a id="tips"></a>

## 9. 추가로 알면 좋은 것과 출처

> 💡 **추가로 알면 좋은 것:** 영화 ID를 구조화해서 반환하면 원본 후보에서 누락되거나 추가된 ID를 비교할 수 있다. 외부 검색은 검색 함수와 출처·조회 시각을 명시한 뒤 연결한다.
