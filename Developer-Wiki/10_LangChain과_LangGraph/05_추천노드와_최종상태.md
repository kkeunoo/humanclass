## 1. 이 장에서 배울 것

CBF·CF·BM25 노드의 입력 차이와 추천 결과의 공통 모양을 설명한다. 청크 중복 제거, 점수 출처, 설명 단계의 근거를 구별한다.

<a id="concepts"></a>

## 2. 무엇이며, 왜 필요한가

CBF와 키워드 검색은 Elasticsearch의 청크 응답을 받는다. CF는 영화 ID와 예측 평점 목록을 받는다. 영화 상세 정보를 함께 보여주려면 CF의 ID로 Elasticsearch를 다시 검색한다. 공통 함수는 청크마다 `_source`에서 영화 정보를 꺼내고, 같은 영화는 첫 hit만 남긴다.

| 노드 | 쓰는 입력 | 다음 단계가 받는 값 |
| --- | --- | --- |
| CBF | `list_movieId` | 검색 hit를 영화 단위로 정리한 `recommends` |
| CF | `userId` | 평점으로 찾은 ID를 재조회한 `recommends` |
| BM25 | `question` | 키워드 검색 hit를 정리한 `recommends` |
| 설명 | 질문·추천 방식·후보 목록 | `explain` 문자열 |

## 3. 작은 예제로 먼저 이해하기

**설명용 전체 예제.** [실행 파일](실습/책형_복습/05_추천노드와_최종상태/example.py)을 해당 장의 Python 환경으로 실행한다. 모든 입력과 모델 대역은 복습용이며 외부 서비스에 요청하지 않는다.

```python
hits = [
    {'_source': {'movieId': 7, 'title': 'A'}, '_score': 2.0},
    {'_source': {'movieId': 7, 'title': 'A'}, '_score': 1.9},
    {'_source': {'movieId': 5, 'title': 'B'}, '_score': 1.5},
]
seen = set()
recommends = []
for hit in hits:
    source = hit['_source']
    movie_id = source['movieId']
    if movie_id in seen:
        continue
    seen.add(movie_id)
    recommends.append((movie_id, source['title'], hit['_score']))

print(recommends)
print(recommends[:1])
```

**실행 결과**

```text
[(7, 'A', 2.0), (5, 'B', 1.5)]
[(7, 'A', 2.0)]
```

## 4. 내 폴더의 실제 코드 읽기

**원본 발췌 · D:/workspace/workspace_python/08_langgraph/router/langgraph_router.py 98–157행**

```python
def nomarlize(response, top_k = 10):
    movieIds = set()
    recommends = []

    for hit in response['hits']['hits'] :
        source = hit['_source']

        movieId = source.get('movieId')
        if movieId not in movieIds :
            movieIds.add(movieId)

            recommends.append({
                'movieId' : movieId,
                'title' : source.get('title', ''),
                'genres' : source.get('genres', []),
                'tags' : source.get('tags', []),
                'score' : hit.get('_score', -1)
            })
        # top_k개가 지나면 break로 끝낼수도 있다

    return recommends[:top_k]

def cbf(state: State):
    # def content_based_filtering(list_movieId: list, top_k:int = 10):
    response = content_based_filtering(state.list_movieId)

    recommends = nomarlize(response, state.top_k)

    # return 은 json형식으로 해줘야 basemodel에 들어감
    return {
        'recommends' : recommends
    }

def cf(state:State):
    '''
    [{
        'movieId' : movieId,
        'score' : score
    }]   
    '''
    result = collaborative_filtering(state.userId)
    movieIds = set()

    for info in result :
        movieIds.add( info.get('movieId', 0) )

    response = term_movieId(movieIds)

    recommends = nomarlize(response, state.top_k)
    return {
        'recommends' : recommends
    }

def bm25(state: State):
    response = search_movies(state.question)

    recommends = nomarlize(response, state.top_k)
    return {
        'recommends' : recommends
    }
```

**풀이:** 내 코드의 `nomarlize`는 정규화 함수의 이름이다. 이 함수에서 `set`은 방문한 ID를 기억하는 용도이고, 결과는 `append()`한 목록을 반환해 첫 검색 순서를 유지한다. [09 RRF](../09_영화CSV_청크와_임베딩/07_CBF_CF와_RRF_하이브리드추천.md)에서 집합 자체에 순위를 붙이는 부분과 비교한다.

## 5. import·함수·입력·출력이 연결되는 흐름

`cf()` → `collaborative_filtering(userId)` → 영화 ID 추출 → `term_movieId()` 재조회 → `nomarlize()` → `explain()`. 재조회 후 저장하는 `score`는 Elasticsearch hit의 `_score`다. CF의 예측 평점과 순위가 계속 필요하면 원래 결과를 영화 ID로 매칭해 따로 넘겨야 한다. `explain()`은 프롬프트·모델·텍스트 파서 체인에 질문과 후보를 준다.

<a id="review"></a>

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점.** 노드마다 다른 응답을 공통 필드로 정리해 설명 단계를 공유한다.

**아쉬운 점.** `state.top_k`는 정리 결과의 슬라이스에 사용된다. 앞선 추천 함수 호출에는 전달하지 않아 더 큰 `top_k`를 줘도 앞 단계 기본 후보 수의 한계가 남는다. CF 후보는 집합으로 넘겨 원래 예측 순위와 점수를 잃을 수 있다. 실제 ID 목록 전달과 점수 매칭을 개선안으로 둔다.

<a id="teacher"></a>

## 7. 강사님 코드가 도움이 되는 비교

강사님은 같은 역할에 `normalize`라는 이름을 쓴다. 양쪽이 CF 후보를 재조회하는 구조를 공유하며, 결과의 `_score`는 두 코드 모두 CF의 원점수가 아니다. 점수 이름과 출처를 구분해서 읽는 것이 핵심이다.

<a id="results"></a>

## 8. 결과를 추적하고 한 가지 바꾸기

첫 두 hit의 순서를 바꾼다. 영화 7의 결과는 한 개지만 어떤 점수가 남는지 확인한다. `top_k`를 1에서 2로 바꿔 결과 개수를 비교한다.

<a id="tips"></a>

## 9. 추가로 알면 좋은 것과 출처

> 💡 **추가로 알면 좋은 것:** 추천 점수와 검색 점수를 별도 필드로 두면 어떤 값이 설명에 쓰였는지 추적하기 쉽다. 영화 ID와 원본 근거를 함께 남기면 출력 검증에도 활용할 수 있다.
