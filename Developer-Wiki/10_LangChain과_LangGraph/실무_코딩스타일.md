## 1. 이 장에서 배울 것

그래프 입력, 상태 갱신, 사용자 응답을 이름과 타입으로 읽는다. 모델 대역과 고정 후보로 추천 단계와 설명 단계를 별도로 확인한다.

<a id="concepts"></a>

## 2. 무엇이며, 왜 필요한가

상태 필드는 단계 사이의 계약이다. `recommend_type`은 경로 선택, `recommends`는 후보, `explain`은 설명, `error`는 실패 정보를 담는다. 각 단계가 쓰는 값과 읽는 값을 이름으로 정리하면 오타와 잘못된 타입을 찾기 쉽다.

<a id="example"></a>

## 3. 작은 예제로 먼저 이해하기

**설명용 전체 예제.** [실행 파일](실습/책형_복습/실무_코딩스타일/example.py)을 해당 장의 Python 환경으로 실행한다. 모든 입력과 모델 대역은 복습용이며 외부 서비스에 요청하지 않는다.

```python
from pydantic import BaseModel, ConfigDict, Field, ValidationError


class RecommendationState(BaseModel):
    model_config = ConfigDict(extra='forbid')
    question: str
    recommends: list[dict] = Field(default_factory=list)


print(RecommendationState(question='영화 추천').recommends)
try:
    RecommendationState.model_validate({'question': '영화 추천', 'recommedns': []})
except ValidationError as error:
    print(error.errors()[0]['loc'][0], error.errors()[0]['type'])
```

**실행 결과**

```text
[]
recommedns extra_forbidden
```

## 4. 내 폴더의 실제 코드 읽기

**원본 발췌 · D:/workspace/workspace_python/08_langgraph/router/langgraph_router.py 36–54행**

```python
class State(BaseModel):
    list_movieId: Optional[list[int]] = None        # CBF에서 사용 할 영화 ID 목록
    userId: Optional[int] = None                    # CF에서 사용 할 유저 ID
    top_k: int = 10                                 # 가져올 결과 값 개수
    question: str                                   # 사용자 질문

    recommend_type: Optional[str] = None            # 사용할 추천 방식, 3개 말고는 못 들어옴
    recommend_type_reason: Optional[str] = None     # 추천 타입 선정의 이유

    recommends: Optional[list[dict]] = []           # 추천 목록들

    explain: Optional[str] = 'LLM 응답 없음'         # 최종 답변

    error: Optional[str] = None                     # 에러 메세지

class RecommendType(BaseModel):
    recommend_type: Literal['CBF', 'CF', 'BM25']    # 사용할 추천 방식, 3개 말고는 못 들어옴
    recommend_type_reason: str                      # 추천 타입 선정의 이유

```

**풀이:** 추천 방식, 이유, 목록, 설명, 오류가 한 객체에 모여 있다. 노드들은 전체 상태를 재작성하는 대신 자기 단계에서 바꿀 필드를 딕셔너리로 반환한다.

<a id="connections"></a>

## 5. import·함수·입력·출력이 연결되는 흐름

`RecommendType`은 분류 모델 결과의 형태이고 `State`는 그래프가 공유하는 형태다. `/langgraph/recommend`가 받는 초기 요청과 마지막 사용자 응답의 공개 필드도 별도로 정의할 수 있다.

<a id="review"></a>

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점.** `Literal`로 분류 결과 후보를 제한하고, 선택과 추천과 설명을 함수로 나눴다.

**개선 방향.** 외부 요청의 스키마를 좁히고, 실행 중 변경되는 상태와 API가 공개할 응답을 구별한다. 위 예제는 Pydantic에 입력을 직접 검증하게 해 오타를 잡는다. 이 설정을 그래프 전체에 추가했다고 가정하지 않는다.

<a id="teacher"></a>

## 7. 강사님 코드가 도움이 되는 비교

강사님 `recommends` 초기화 키와 내 오타가 작은 이름 차이에서 발생하는 문제를 보여 준다. 공동 코드처럼 상태의 역할을 한곳에서 정리하고, 초기 입력과 반환에 같은 키를 쓰는지 함께 읽는다.

<a id="results"></a>

## 8. 결과를 추적하고 한 가지 바꾸기

`recommedns`를 `recommends`로 바꾸고 검증 실패가 사라지는지 확인한다. 다음으로 `recommends`에 문자열을 넣고 필드 이름과 값 타입 검증을 구별한다.
