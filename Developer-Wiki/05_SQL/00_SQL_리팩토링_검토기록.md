## 결론

기존 학습량을 축약하지 않고 각 주제 앞에 정의·필요성·입력 조건·실행 가능한 보충 SQL·실제 결과·논리적 처리 단계·원본 발췌·실습과 해설을 보강했다. 제목·목차만 바꾼 개정이 아니다. 새 파일로 개념을 지나치게 쪼개지 않고 기존 분류 안에서 설명을 연결했다.

수업 코드·교사 코드가 항상 정답이라는 전제도 두지 않았다. 실제 초기화 데이터에서 우연히 맞는 결과와 일반적인 데이터에서도 맞는 논리를 구분했고 반례를 추가했다.

## 2. 기존 설명에서 발견한 실제 문제

### 작은 표의 결과가 전체 EMP 결과처럼 읽히는 부분

기존 02·05·06번 V3 복습은 일부 입력만으로 조건·집계를 설명하면서 SQL에는 FROM emp를 적었다. 전체 14행 테이블에서 바로 실행하면 그 작은 결과와 달라진다.

원래 표·설명·코드는 지우지 않았다. 가정 입력임을 명시하고 그 표를 실제로 만드는 CTE 및 검증 결과를 추가했다. 전체 EMP의 결과는 앞의 보충 실습에서 별도로 보여 준다. 현재 시각 출력도 실행마다 달라지는 형식 예시임을 명시했다.

### 잘못된 CAST 설명

18번 기존 본문에서 BIGINT 컬럼 자료형을 CAST 대상 구문으로도 사용할 수 있다고 설명한 부분을 수정했다. MariaDB 12.3.2에서 CAST(1 AS BIGINT)는 1064 문법 오류를 확인했다. 숫자 범위를 늘릴 때는 지원하는 SIGNED/UNSIGNED 등과 실제 입력 의미·오버플로를 검토하도록 안내했다.

### 출처의 잘못된 공통화 예방

내 평균 SQL의 GROUP BY에는 sal까지 있지만 강사님은 해당 평균 SQL에서 deptno·job만 묶는다. 첫 검토의 공통 오류 해석을 실제 출처 재대조로 수정했다. 강사님 원본에 없는 ‘문제6 개선’ 주석을 억지로 대응시키지 않고 실제 JOIN 질의 위치를 발췌했다.

## 3. 실제 MariaDB 검증

기존 사용자 학습 DB에 접속하거나 수정하지 않고 별도 데이터 디렉터리·전용 로컬 연결의 MariaDB를 사용했다. 초기화 SQL의 EMP·DEPT·SALGRADE 데이터를 같은 값으로 준비했으며 원본 Script.sql 전체는 실행하지 않았다.

| 검증 묶음 | 개수 | 결과 |
| --- | ---: | --- |
| 주제별 보충 SQL의 결과 집합·상태 | 20 | 예상 값·열·행과 모두 일치 |
| 논리 반례·상태 변화 추가 SQL | 7 | 모두 일치 |
| 작은 가정 입력의 CTE 재현 | 3 | 모두 일치 |
| 의도적 오류 사례 | 5 | 기대 오류 번호 확인 |
| EXPLAIN 전·후 실험 | 1묶음 | ALL→range, 선택 인덱스·추정 rows 관찰 |

오류 사례는 PK 중복 1062, 부모 없는 FK 1452, NOT NULL 위반 1048, ONLY_FULL_GROUP_BY 1055, 지원하지 않는 BIGINT CAST 1064다. 긴 오류 메시지의 연결번호·DB 이름·표시 방식은 환경마다 달라질 수 있다.

조회·반례에서는 실제 14명·4부서·5등급, 알려진 COMM 4개·합계2200·평균550, 1981년 입사10명, 조직 깊이별 1·3·8·2명을 확인했다.

변경 실습에서는 새 테이블의 급여 1000→1100→ROLLBACK 후1000, 계좌 일부·전체 취소, 일반 DDL 뒤 ROLLBACK으로 앞 변경이 복원되지 않는 상황을 확인했다. 기존 원본 EMP·DEPT의 저장 내용은 변경하지 않았다.

- 주요 목차로 개념·비교·실습·정답에 바로 갈 수 있고 전체 상세 목차는 펼쳐 찾을 수 있다.

## 5. 검증 한계와 다시 확인할 사항

새 SQL 30개를 결과 비교했다는 사실은 기존 모든 SQL을 실행했다는 뜻이 아니다. 원본에는 오류 시연·순서 의존·이미 없는 테이블 조회·전체 삭제 등이 섞여 있어 통째로 실행하지 않았다.

검증 환경의 버전·SQL_MODE·문자셋·테이블 상태를 사용자 수업 환경과 동일하다고 가정하지 않는다. 특별한 ORACLE 모드 등에서는 함수 의미가 달라질 수 있다. 큰 데이터의 성능·동시 사용자·복구 시나리오를 모두 실증하지 않았으며 EXPLAIN 변경은 처리시간 개선의 증명이 아니다.

새 wiki_demo_* CREATE 예제는 새 이름으로 한 번 실행하는 순서다. 이름 충돌 시 멈추고 다른 이름을 선택한다. 재실행 편의를 위한 DROP·TRUNCATE를 앞에 붙여 사용자의 기존 자료를 지우지 않는다.

00_SQL 읽기법은 실제 입력값을 한 곳에서 확인하는 공통 자료이며 핵심 주제를 다시 여러 파일로 쪼개는 목적이 아니다. 개념별 설명은 각각의 기존 01~20 파일 안에 있다.
