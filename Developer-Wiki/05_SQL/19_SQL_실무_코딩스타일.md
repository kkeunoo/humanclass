# 19. SQL 실무 코딩스타일 — 수업 쿼리를 읽고 점검하기

[SQL 목차](README.md) · [종합실습](20_SQL_종합실습.md)

이 문서는 원본 수업의 19번 단원이 아니다. 강사님과 내 `Script.sql`의 **이미 학습한 별칭·그룹·조인·변경 문장**을 다시 읽는 연습이다. 아래 쿼리는 원본 발췌가 아닌 **설명용 재구성**이며 실제 수업 퀴즈는 [원본 문제 비교](실습_SQL_원본문제_비교.md)에 있다.

## 1. 조회 결과의 각 열이 어디서 왔는지 보이게 하기

[JOIN 원본 비교](12_SQL_JOIN.md)에서 강사님은 긴 별칭으로도 실행해 보았고, 나는 `e`, `d`로 표를 구분했다. `deptno`처럼 양쪽에 있는 열은 어느 표의 값인지 지정한다.

```sql
-- 수업 EMP·DEPT로 재구성한 조회 예시
SELECT e.ename, d.dname, e.deptno
FROM emp e
JOIN dept d ON e.deptno = d.deptno;
```

`e`는 사원, `d`는 부서다. 제공된 초기 자료에서 **SMITH의 `e.deptno=20`**은 `DEPT`의 20번과 연결되어 부서 이름 **RESEARCH**를 결과에 보여 준다. 이 한 행은 원본 전체 결과가 아니라 읽는 방법을 확인하는 예다.

`ON`이 빠지면 원하지 않는 모든 조합이 나올 수 있다. 결과 행 수가 예상보다 많을 때는 조인 조건을 먼저 확인한다.

## 2. 그룹을 만든 기준과 출력 열을 맞추기

[GROUP BY 원본 비교](06_SQL_GROUP_BY와_HAVING.md)에는 내 코드가 `job`을 출력하면서 `deptno`만 묶은 실험이 있다. 이 경우 그룹 안의 직업이 여럿이면 결과가 정해지지 않거나 설정에 따라 오류가 난다. 강사님 코드처럼 출력할 비집계 열을 함께 묶는다.

```sql
-- 수업 범위의 재구성 예시
SELECT deptno, job, COUNT(*) AS person_count
FROM emp
GROUP BY deptno, job;
```

`WHERE`는 묶기 **전의 행**, `HAVING`은 묶은 **뒤의 그룹**을 거른다는 순서도 함께 확인한다.

## 3. 변경 쿼리는 대상 행을 먼저 확인하기

원본 `Script.sql`에는 표 생성·삭제와 데이터 변경이 섞여 있다. [DML](15_SQL_DML.md)과 [트랜잭션](16_SQL_Transaction.md)의 동작을 읽은 뒤, 별도 연습 DB에서 변경 대상 조건을 `SELECT`로 먼저 확인한다. 다음 두 문장은 **같은 조건의 행을 확인하고 변경한다는 흐름**을 보여 주는 재구성 예시다. 이 문서를 읽기 위해 실행할 필요는 없다.

```sql
SELECT empno, ename, sal FROM emp WHERE empno = 7369;
UPDATE emp SET sal = sal + 100 WHERE empno = 7369;
```

원본 전체를 한 번에 실행해 결과를 비교하지 않는다. 어떤 문장이 앞서 실행되었는지에 따라 표와 행 상태가 달라진다.
