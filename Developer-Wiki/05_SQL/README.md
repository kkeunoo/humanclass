# SQL — 표와 관계를 읽는 나의 교재

SQL은 표의 자료를 조회하고 구조와 값을 관리하는 언어다. 실제 강사님·내 Script.sql과 초기화 자료를 근거로 개념부터 다시 설명했다. 강사님 코드는 필요한 차이에만 인용하고 내 원본 바로 옆에 풀이·장점·한계·개선 방향을 남겼다.

## 1. 읽는 순서

[데이터 준비와 표 읽기](00_SQL_실습데이터와_스크립트_읽기.md)에서 시작한다. 본문은 목표 → 개념 → 작은 예제 → 내 코드 → 연결 → 평가 → 필요한 비교 → 결과·실험 → TIP·출처 → 복습의 같은 흐름이다. 개념을 알고 다시 찾을 때는 아래 표로 이동한다.

| 질문 | 본문 |
| --- | --- |
| 어떤 열·행을 볼까? | 01–04 SELECT·조건·패턴·정렬 |
| 여러 행을 요약할까? | 05–06 집계·그룹 |
| 한 값을 바꿔 보여 줄까? | 07–09 함수·CASE |
| 결과·표를 연결할까? | 10–13 UNION·서브쿼리·조인 |
| 구조·행·확정 상태를 바꿀까? | 14–16 DDL·DML·트랜잭션 |
| 경로·번호·계층을 다룰까? | 17–18 인덱스·자동 번호·재귀 |

## 4. 자료와 검증 조건

원본 EMP는 초기14명, DEPT4개, SALGRADE5개다. 새 book_emp·book_dept는 가상 자료이며 각 본문 3절에 전체 준비 SQL·실행 파일·예상 결과가 있다. 11·18·실제 문제 장은 반례·계층을 위해 준비 자료가 다르므로 그 장의 준비문부터 다시 읽는다.

공통 행·값은 별도 SQLite 메모리 DB에서 교차 확인하고 MariaDB 공식 문법과 대조했다. MariaDB 서버 실행·정확한 오류 번호·현재 문자열 설정·성능 측정을 확인한 것으로 표시하지 않는다. 대응할 수 없는 숫자·날짜·자동 번호 함수는 조건을 붙인 예상이라고 적었다. 실제 DB와 사용자의 기존 브라우저는 제어하지 않았다.
