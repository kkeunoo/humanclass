## 1. 이 백과를 읽는 순서

각 파일 앞의 ‘개념에서 실제 실행까지’에서 용어가 무엇이고 왜 필요한지 먼저 읽는다. 보충 SQL의 입력·자료형·결과를 예상한 뒤 실행 순서를 따라간다. 내·강사님 원본의 발췌에서 어느 부분에 쓰였는지 확인한다. 이어 번호형 상세 본문·여러 사례·종합실습·정답·체크리스트로 반복해서 익힌다.

단순히 함수 이름을 외우거나 코드 전체를 한 번 복사하는 방식이 아니다. Result 한 행의 의미를 설명하고 다른 입력에서도 같은 업무 질문을 만족하는지 판단하는 것이 목표다. 💡는 보충 지식·반례·실무 확장임을 나타낸다.

## 2. 클라이언트·서버·데이터베이스·테이블이란?

SQL 편집기는 명령을 보내고 결과를 표시하는 클라이언트다. MariaDB 서버는 연결을 받아 데이터와 구조를 관리하고 SQL을 처리한다. 데이터베이스는 테이블 등을 묶는 이름 공간이며 테이블은 열 정의와 행 데이터를 저장하는 구조다.

```text
SQL 편집기에서 질의 실행
→ 연결된 MariaDB 서버
→ 선택한 데이터베이스의 테이블·열·권한 확인
→ 구문 분석·계획·데이터 처리
→ 결과 열·행 또는 변경 결과·오류 반환
→ 클라이언트가 Result Grid나 메시지로 표시
```

DBMS는 데이터 관리 소프트웨어이고 SQL은 그 소프트웨어에 요청하는 언어다. SQL 편집기 기능인 자동완성·Ctrl+클릭·결과 내보내기는 SQL 문법과 구분한다.

## 3. 실행 전에 확인하는 것

아래는 데이터 변경 없는 확인 명령이다. 현재 선택한 데이터베이스를 확인한 뒤 실습 테이블이 준비되어 있는지 점검한다.

```sql
SELECT DATABASE() AS current_database,
       VERSION() AS server_version,
       @@session.sql_mode AS session_sql_mode,
       @@session.autocommit AS auto_commit;
SHOW TABLES;
SHOW CREATE TABLE emp;
```

DATABASE()가 NULL이면 기본 데이터베이스를 선택하지 않은 상태일 수 있다. 다른 DB의 같은 이름 테이블에 연결했거나 DML로 행을 변경한 경우 결과가 달라진다. 실습 데이터를 다시 만든다는 이유로 기존 업무 DB에 초기화·DROP을 적용하지 않는다. 별도 학습 DB에서 원본 초기화 자료를 사용한다.

이번 검증은 기존 사용자 MariaDB의 데이터 디렉터리가 아닌 별도 디렉터리·연결의 환경에서 했다. 원본 Script.sql 전체를 실행하지 않았다.

## 5. 논리적 처리와 실제 실행 계획은 다르다

```text
작성할 때
SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT

이해할 때의 논리적 흐름
FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT

실제 접근 방식 확인
옵티마이저가 선택한 실행 계획 → EXPLAIN·실측
```

단계별 표는 ‘이 조건이면 어느 행이 남는가’를 설명하기 위한 모델이다. 실제 서버가 모든 행마다 내가 적은 조건을 왼쪽부터 같은 순서로 평가하거나 중간 표를 항상 물리적으로 저장한다는 뜻이 아니다. 비싼 함수·예외를 피하려고 AND의 왼쪽 조건이 반드시 먼저 실행된다고 의존하지 않는다.

## 6. 결과를 읽을 때 구분하는 것

| 관찰 대상 | 의미 | 주의 |
| --- | --- | --- |
| SELECT 결과 | 클라이언트에 반환된 행·열 | 계산·별칭은 원본 변경이 아님 |
| COUNT·AVG 결과 | 선택·연결·그룹된 입력의 요약 | 분모와 NULL 제외 확인 |
| DML 메시지 | 변경·매칭 등에 대한 실행 보고 | 0행도 정상 종료 가능 |
| 사후 SELECT | 실제 현재 값 | 같은 연결·트랜잭션에서 보는 값인지 확인 |
| 오류 메시지 | 실패 종류·대상·SQLSTATE | 앞선 문장·암묵 커밋까지 모두 취소된다는 뜻 아님 |
| EXPLAIN | 예상 접근 계획 | 추정 rows와 실제 시간은 다름 |

NULL은 클라이언트에서 빈 칸·특정 기호로 표시될 수 있다. ''·0과 구분한다. ORDER BY가 없으면 출력 행의 앞뒤를 고정 정답으로 쓰지 않는다.

## 7. 작은 가상 표와 실제 EMP를 구분한다

기존 설명의 작은 입력 표는 반복 이해를 돕는 자료다. 그 표만 있다고 가정한 결과와 FROM emp로 전체 14명을 조회한 결과는 같지 않을 수 있다. 02·05·06번에는 작은 표를 그대로 만들어 재현하는 보충 CTE를 넣었다. 입력을 작게 만드는 이유는 처리 원리를 확인하려는 것이며 실제 자료를 임의로 생략했다는 뜻이 아니다.

## 8. 변경 실습의 안전 기준

DDL·DML 실습은 새 wiki_demo_*·_PRACTICE 테이블에서 한다. 기존 객체와 이름이 충돌하면 새 이름을 선택한다. 이번 문서의 CREATE는 한 번 실행하는 예제이며 재실행 시 이미 존재한다는 오류를 확인하고 멈춘다. 편의를 위해 기존 데이터를 DROP으로 지우지 않는다.

DML은 대상 SELECT→START TRANSACTION→변경→사후 검증→COMMIT/ROLLBACK을 한 업무로 설계한다. 일반 DDL은 미확정 DML을 확정할 수 있으므로 이 경계 안에 무심코 넣지 않는다. ROLLBACK은 이미 확정된 모든 과거 업무를 되돌리는 버튼이 아니다.
