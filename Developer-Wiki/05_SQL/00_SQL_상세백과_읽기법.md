# SQL 읽기 안내 — 문장과 현재 상태를 함께 보기

[SQL 목차](README.md)

## 1. 먼저 확인할 것

어떤 DB·표·현재 행을 읽는지 확인한다. 원본 Script.sql은 조회·수정·실패·재시도가 섞인 학습 기록이다. 처음부터 끝까지 실행되는 정답 설치본이 아니다. 제공 초기 자료의 결과와 현재 DB 결과가 다를 수 있다.

## 2. 결과를 따라 읽는 질문

| 질문 | 확인할 부분 |
| --- | --- |
| 결과 한 행은 무엇인가? | 사원·부서·급여 등급 |
| 연결은 무엇인가? | 같은 번호·급여 범위·관리자 관계 |
| 빠지면 안 되는 대상은? | 외부 조인의 보존 방향 |
| 필터는 어느 범위인가? | 안쪽·바깥·개인·그룹 |
| NULL은 무슨 뜻인가? | 미정 값·빈 매칭·계산 없음 |
| 순서·동점은? | ORDER BY·LIMIT |

논리적 처리 순서는 뜻을 이해하기 위한 도구다. 서버의 실제 실행 계획이 항상 문장 순서대로 움직인다는 설명으로 읽지 않는다.

## 3. 원본·새 예제·개선안

원본은 현재 경로·행 범위를 표시하고 주석 오류도 그대로 보존했다. 바로 아래 풀이에서 교정한다. 새 가상 자료·반례·개선안은 당시 내 작성물과 나눴다. 예전 원본에서 코드가 이동했으면 현재 위치를 다시 찾았다. 강사님도 잘못된 COUNT나 조건을 남길 수 있어 요구를 기준으로 공정하게 비교한다.

## 4. 실행과 확인의 한계

각 장 전체 파일은 준비문·본문 SQL을 포함한다. MariaDB의 새 연습 연결에서 같은 연결을 유지한다. 임시 표는 예제를 위한 새 실행 장치이며 수업에서 상세 수명·권한까지 배웠다는 뜻은 아니다. 임시 표에 외래 키를 만든 것으로 설명하지 않는다.

이 작업에서는 원본 DB에 연결하지 않았다. 공통 조회는 SQLite 교차 확인, MariaDB별 함수·트랜잭션·자동 번호·제약의 상세 차이는 공식 문서 대조와 조건부 예상이다. 다른 DB에서 일부 구문이 실행됐다고 모든 MariaDB 의미를 검증했다고 말하지 않는다.

## 5. 복습과 이후의 나

예상한 행·열·값과 이유를 적고 장별 문제를 푼다. 실제 문제의 연도 범위·빈 그룹·다른 부서 동점 같은 반례를 스스로 만들어 본다. 스타일은 보기 좋게 정리하는 것과 의미를 바꾸는 것을 나눈다. 나중에는 TIP의 실행 계획·동시성·설계 주제를 현재 기본 개념에 연결할 수 있다.
