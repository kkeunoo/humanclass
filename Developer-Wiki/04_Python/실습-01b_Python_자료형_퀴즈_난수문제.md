# 실습 01b. 숫자 맞히기·투표 — 횟수의 정의와 최댓값 대상

## 1. 이 장에서 배울 것

정답 시도를 포함한 횟수와 틀린 횟수를 구분한다. 후보별 집계와 최다 득표자 찾기를 나누고, max(dict)의 실제 비교 대상과 아직 없는 동점 정책을 설명한다.

실제 원본·새 예제·개선안·선택 학습을 구분하고 입력·실행 순서·반환값·출력을 연결한다.

<a id="concepts"></a>

## 2. 무엇이며, 왜 필요한가

시도 횟수를 정답 입력까지 포함하려면 비교 전에 한 번씩 늘린다. 틀렸을 때만 늘리면 실패 횟수다. 같은 count라는 이름이라도 증가 위치가 정의를 결정한다. 숫자 맞히기에서 작은 입력이면 UP, 큰 입력이면 DOWN이고 같으면 종료한다.

투표는 후보를 뽑는 단계·횟수를 세는 단계·가장 큰 표 수를 찾는 단계로 나눈다. counts.get(name,0)+1은 처음 등장한 후보를 0에서 시작해 한 표 더한다. max(counts)는 값이 아니라 키를 대상으로 한다.

| 데이터 | max를 적용한 대상 | 결과 |
| --- | --- | --- |
| {'a':3,'b':1,'c':1} | 딕셔너리 키 | c |
| 위 항목의 표 수 비교 | 3·1·1 | a가 최다 |

두 결과가 우연히 같았던 난수 실행만 보면 오류를 놓칠 수 있다. 그래서 아래 예제는 가상 뽑기 순서와 답을 고정하여 누구나 같은 결과를 추적하게 했다. 실제 난수 생성 결과라고 보고하지 않는다.

> 📚 **출처 · 본문 설명 확인:** [Python 딕셔너리 순회](https://docs.python.org/ko/3/tutorial/datastructures.html#looping-techniques), [max](https://docs.python.org/ko/3/library/functions.html#max). 실제 배운 문법의 의미를 확인한 근거다. 예제·표·풀이 자체는 수업 자료를 바탕으로 새로 구성했다. 외부 문장을 직접 인용하지 않았다. 이번 문법 확인 기간: 2026-10-28~29.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 전체 코드.** [실행 파일](실습/책형_복습/실습-01b_Python_자료형_퀴즈_난수문제.py)을 제공한다. Python이 설치된 환경에서 새 .py 파일로 저장해 실행한다. 터미널은 그 파일이 있는 폴더에서 열고 `python 파일이름.py`를 실행한다. VS Code의 Python 실행 기능을 사용해도 된다. 결과는 터미널에 표시된다.



```python
answer = 50
guesses = [20, 70, 50]  # 설명용 입력 순서
count = 0
for guess in guesses:
    count += 1
    if guess < answer:
        print('UP')
    elif guess > answer:
        print('DOWN')
    else:
        print('정답 시도', count)
        break
ballots = ['a', 'b', 'a', 'c', 'a']  # 설명용 투표 순서
counts = {}
for name in ballots:
    counts[name] = counts.get(name, 0) + 1
print(counts)
print('키의 max', max(counts))
winner = None
best_count = -1
for name, votes in counts.items():
    if votes > best_count:
        winner = name
        best_count = votes
print('최다', winner, best_count)
```

입력 20·70·50의 세 번 모두 시도로 세어 정답은 3회다. 투표 다섯 개를 집계하면 a 3·b 1·c 1이다. max(counts)의 c와 실제 최고 표 수의 a가 달라 원본 오류를 드러낸다. 새 비교 루프는 배운 items·if·누적 대입을 사용한다. 같은 표 수에서는 처음 집계된 후보를 유지하도록 >만 썼으며 모든 동점자를 반환하는 정책은 아니다.

**예상 출력 또는 관찰:**

```text
UP
DOWN
정답 시도 3
{'a': 3, 'b': 1, 'c': 1}
키의 max c
최다 a 3
```

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_python/quiz/01_quiz.py` 89–105행

```python
print('\n문제3','- - '*10)
import random
com = random.randint(1,100)
user = -1
count = 0

# 시간 날 때 문자 입력받는 방어코드도 넣기
while com != user :
    user = int(input('숫자를 입력하세요.'))
    if com > user :
        print('UP 입니다.')
        count += 1
    elif com < user :
        print('DOWN 입니다.')
        count += 1
    elif com == user :
        print(f'정답입니다! 시도횟수 : {count}')
```

**발췌 바로 풀이:** 강사님은 `while True` 안에서 `count += 1`을 **정답 비교 전에** 하므로 첫 번째 시도에 맞히면 1회다. 다만 입력 줄은 주석 처리하고 `num=q3`으로 정답을 바로 넣어 두어 **실제 입력 게임으로 실행되지는 않는다**. 내 코드는 `input()`을 받아 UP/DOWN을 보여 주지만 `count`를 **틀렸을 때만** 늘린다. 따라서 처음에 맞히면 `시도횟수 : 0`, 두 번 틀리고 맞히면 2가 나온다. 문제의 “몇 번째에 맞췄는지”라면 정답 시도까지 세는 강사님의 위치가 더 맞는다. 내 주석에 있는 숫자 아닌 입력의 방어 코드는 아직 구현되지 않았다.

```python
print('\n문제5','- - '*10)
import random
keys = input('나나')
key = keys.split(' ')

a = 0 # 랜덤 값 1일때 투표
b = 0 # 랜덤 값 2일때 투표
c = 0 # 랜덤 값 3일때 투표

for i in range(0,100) :
    vote = random.randint(1, 3)
    if vote == 1 :
        a += 1
    elif vote == 2 :
        b += 1
    elif vote == 3 :
        c += 1

print(a, b, c)
print(keys)
print(key)

print(vote)
```

**발췌 바로 풀이:** 강사님은 `random.choice(후보)`로 100번 뽑아 `득표.get(투표,0)+1`로 후보별 횟수를 센다. 내 실행 코드는 난수 1·2·3에 맞춰 `a`, `b`, `c` 수를 올리고 세 값을 출력한다. 나는 후보 이름을 추가로 입력받아 `key` 목록으로 나누지만, 그 이름과 세 카운터를 **연결해 최다 득표자의 이름·표 수를 구하는 부분은 없다**. 마지막의 `print(vote)`도 마지막으로 뽑은 숫자 하나를 보여 줄 뿐이다.

import random
candidate = ['a','b','c']
voteGet = {}

for i in range(100) :

    voteGet[vote] = voteGet.get(vote, 0) + 1

print(voteGet)

강사님은 입력 대신 num=q3를 활성화해 첫 시도 정답으로 시험하고 count를 먼저 늘려 1이다. 내 실제 입력 게임은 UP·DOWN 갈래에서만 증가하여 처음 맞히면 0이고 두 번 틀리면 2다. 내 투표는 1·2·3 난수에 맞춰 a·b·c를 세지만 입력한 후보 이름과 연결하지 않는다. 별도 test.py는 딕셔너리 집계를 했어도 max(voteGet)으로 키를 고른다.

## 5. 선언·호출·파일이 연결되는 흐름

난수 정답 또는 가상 답 준비 → 입력 → 횟수 증가 위치 → 대소 비교 → 안내·종료다. 투표는 뽑은 후보 → get 기본값 → +1 저장 → 전체 집계 → 표 수 비교 순서다. 마지막 print(vote)는 마지막 한 번 뽑은 값이지 최다 득표자나 전체 표 수를 계산한 결과가 아니다.

<a id="review"></a>

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 내 입력 게임과 100회 집계는 실제 입력·반복을 구현했다. **요구와 차이:** count는 실패 횟수이며 입력 후보 이름은 카운터에 연결되지 않았다. **공통 논리 오류:** max(dict)로 최다 표 수를 찾았다는 해석은 강사님·내 별도 시도 모두 교정한다. **개선:** 후보 이름을 키로 집계한 뒤 항목의 표 수를 비교하고 시도 횟수 정의를 먼저 정한다.

개선안은 D 드라이브 원본을 수정한 결과가 아니다. 실제 오류·수업용 단순화·목적에 따른 선택을 구별한다.

## 7. 강사님 코드가 도움이 되는 비교



강사님의 정답 비교 전 count 증가는 정답 시도까지 세는 요구에 더 맞다. 다만 실제 사용자 입력은 주석이다. 강사님 딕셔너리 get 집계는 내 후보 이름 연결에 참고되지만 마지막 max는 정답으로 가져오지 않는다. 잘된 부분과 미완성 부분을 따로 평가한다.

## 8. 결과를 추적하고 한 가지 바꾸기

| 상황 | 강사님 count | 내 count |
| --- | --- | --- |
| 첫 입력 정답 | 1 | 0 |
| 두 번 틀린 뒤 정답 | 증가 규칙상 3 | 2 |

표의 강사님 두 번째 줄은 입력 줄을 활성화하여 해당 입력 순서를 준 경우의 규칙 비교다. 원본 활성 num=q3는 언제나 첫 시도다. 100표에서는 카운터 합이 100인지 확인하고, 후보 최고값은 키가 아니라 득표 수로 판단해야 한다.

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| 첫 guess를 50으로 | 정답 시도 1 | 정답도 한 번 |
| 증가를 오답 갈래로 이동 | 정답 2 | 실패 횟수만 셈 |
| ballots에 b 세 개 추가 | b가 4표로 최다 | 값 기준 비교 |
| 비교를 >=로 변경 | 동점에서 뒤 후보로 교체 | 정책 차이 |

횟수가 하나 적으면 정답 갈래의 증가 여부를 본다. 이긴 후보가 이상하면 max 대상이 키인지 확인한다. 입력한 이름이 결과와 무관하면 집계 키로 실제 사용했는지 본다. 난수를 고정 출력 예시와 같게 만들려고 코드 오류를 의심하지 않는다.
