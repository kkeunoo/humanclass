# 09-02. while과 반복 종료 — 조건이 끝나는 길과 break의 길

## 1. 이 장에서 배울 것

while의 반복 전 검사와 상태 변경을 추적한다. 조건 종료·break·while의 else 차이를 설명한다. 난수 결과를 고정 횟수로 외우지 않고 실제 활성 코드와 주석 속 시도를 구별한다.

실제 원본·새 예제·개선안·선택 학습을 구분하고 입력·실행 순서·반환값·출력을 연결한다.

<a id="concepts"></a>

## 2. 무엇이며, 왜 필요한가

while은 블록에 들어가기 전에 조건을 검사하고, 블록이 끝나면 다시 검사한다. 처음부터 조건이 거짓이면 본문은 한 번도 실행하지 않는다. 반복 중 어떤 값이 바뀌는지 찾지 못하면 종료 이유도 설명할 수 없다.

```text
조건 검사 → 참 → 본문·상태 변경 → 다시 검사
         → 거짓 → 반복 종료
본문의 break → 가장 가까운 반복에서 즉시 나가기
```

| 종료 경로 | while 뒤 else | 의미 |
| --- | --- | --- |
| 조건이 거짓이 되어 종료 | 실행 | break 없이 정상 범위 종료 |
| break 실행 | 건너뜀 | 찾음 등 별도 중단 |
| 처음부터 거짓 | 실행 | 본문을 돌지 않아도 break 없음 |

while의 else는 바로 안의 if에 붙은 else와 다르다. 들여쓰기 수준과 연결 대상을 먼저 본다. 예외나 return으로 흐름을 떠난 경우까지 무조건 실행되는 정리 구문은 아니다.

원본의 random.randint(1,6)은 양끝을 포함한 정수를 뽑는다. 같은 코드라도 뽑힌 값과 3이 나올 때까지의 횟수는 달라질 수 있다. 반복 구조의 설명을 위해 고정값을 쓰면 가상 입력이라고 명시한다.

> 📚 **출처 · 본문 설명 확인:** [Python while 문](https://docs.python.org/ko/3/reference/compound_stmts.html#the-while-statement), [반복의 break·else](https://docs.python.org/ko/3/tutorial/controlflow.html#break-and-continue-statements). 실제 배운 문법의 의미를 확인한 근거다. 예제·표·풀이 자체는 수업 자료를 바탕으로 새로 구성했다. 외부 문장을 직접 인용하지 않았다. 이번 문법 확인 기간: 2026-10-28~29.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 전체 코드.** [실행 파일](실습/책형_복습/09-02_Python_while과_반복제어.py)을 제공한다. Python이 설치된 환경에서 새 .py 파일로 저장해 실행한다. 터미널은 그 파일이 있는 폴더에서 열고 `python 파일이름.py`를 실행한다. VS Code의 Python 실행 기능을 사용해도 된다. 결과는 터미널에 표시된다.



```python
rolls = [1, 5, 3]  # 실제 난수가 아닌 설명용 뽑기 순서
count = 0
dice = 0
while dice != 3:
    dice = rolls[count]
    count += 1
    print('뽑기', count, dice)
print('끝', count)
for target in [2, 20]:
    index = 0
    while index < 4:
        if index == target:
            print('찾음', target)
            break
        index += 1
    else:
        print('못찾음', target)
```

처음 dice=0이라 본문에 들어가 첫 가상 값 1을 받는다. 다음 5, 다음 3을 받고 각각 count를 늘린다. 3을 출력한 뒤 다시 조건을 검사해 거짓이면 종료한다. 이 순서는 실제 난수 발생을 재현한 것이 아니라 흐름을 예측하기 위한 고정 목록이다. 뒤의 검색은 target=2에서 break하여 else를 건너뛰고, 20은 0~3 범위에 없어 조건 종료 뒤 못찾음을 출력한다.

**예상 출력 또는 관찰:**

```text
뽑기 1 1
뽑기 2 5
뽑기 3 3
끝 3
찾음 2
못찾음 20
```

아래는 원본 발췌다. 주석의 잘못된 설명도 원문을 보존하고 풀이에서 교정한다. 필요한 선언·호출·다른 파일의 정의는 다음 절까지 연결해 읽는다.

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_python/09_for.py` 25–46행

```python
import random
print( random.random() )
print( random.randint(1, 6) )

# 주사위 3이 몇 번만에 나오는지 출력하시오

```

**발췌 바로 풀이:** `random.randint(1, 6)`은 여기서 1부터 6까지의 정수를 하나 고른다. `dice != 3`인 동안 한 번 뽑을 때마다 `count`를 늘리고, 3이 나오면 그 횟수를 출력한다. 강사님은 `dice=-1`, 나는 `dice=0`으로 시작하지만 둘 다 처음에는 3이 아니므로 루프에 진입한다. 내 파일의 위쪽 주석 처리된 `while` 시도에는 정의되지 않은 `result`가 등장한다. **실행되는 것은 그 아래 `dice`를 사용한 버전**이다.

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_python/09_for.py` 101–110행

```python
a = 20
i = 0
while i < 10 :
    if i == a :
        print('찾음')
        break
    i += 1
else :
    print('못찾음')
# while의 else는 break를 만나지 않고 조건식에 의해 종료되는 경우 else문 실행 됨
```

**발췌 바로 풀이:** 두 파일 모두 `a=20`을 찾지만 `i`는 0부터 9까지만 검사한다. `i == a`가 참이 되는 때가 없으므로 `break`를 만나지 않고 `while` 조건이 거짓이 된다. 그 결과 `else`에서 **`못찾음`**을 출력한다. 여기서 `else`는 `if`의 `else`가 아니라 **`while`에 붙은 `else`**다. 반대로 찾은 순간 `break`로 나가면 그 `else`는 실행하지 않는다.

양쪽은 randint를 호출하여 3을 받을 때까지 count를 올린다. 강사님 dice=-1과 내 dice=0은 둘 다 처음 3이 아니므로 같은 조건으로 진입한다. 내 앞쪽 주석 버전의 result는 정의되지 않았지만 실제로 실행되는 버전은 dice를 사용한다. 마지막 a=20 검색은 i가 0~9까지만 움직여 break하지 못하고 못찾음을 출력한다.

## 5. 선언·호출·파일이 연결되는 흐름

random 모듈 import → randint 함수 호출 → 새 정수를 dice에 대입 → count 증가 → 현재 값이 3이면 횟수 출력 → 다음 while 검사 순서다. random은 Python이 제공하는 모듈이고 실제 난수 생성 함수의 내부 구현을 내가 작성한 것은 아니다. 새 예제는 모듈 호출 대신 목록 조회로 값을 준비한 별도 설명이다. 원본 turtle 호출은 그래픽 창을 열 수 있어 이번 검수에서는 실행하지 않고 실제 사용 범위만 읽었다.

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 내 코드는 count를 뽑기 한 번마다 늘리고 종료한 값 3의 횟수를 출력한다. **교정:** dice=0과 -1의 시작 차이를 결과 횟수 차이의 근거로 삼지 않는다. 실제 뽑힌 순서가 횟수를 결정한다. **원본 한계:** 난수 반복에 최대 횟수 제한이 없고, 가상 목록 예제는 3이 그 안에 있다는 조건이 있다. **학습 범위:** 주석의 while True는 활성 반복이 아니며 이 파일이 그 줄에서 무한 출력하는 것으로 설명하지 않는다.

개선안은 D 드라이브 원본을 수정한 결과가 아니다. 실제 오류·수업용 단순화·목적에 따른 선택을 구별한다.

## 8. 결과를 추적하고 한 가지 바꾸기

| 가상 뽑기 전 | 받은 값 | count | 다음 조건 |
| --- | --- | --- | --- |
| dice=0 | 1 | 1 | 1!=3, 계속 |
| dice=1 | 5 | 2 | 5!=3, 계속 |
| dice=5 | 3 | 3 | 3!=3은 거짓, 종료 |

본문 안에서 3을 받았다고 그 아래 모든 문장을 자동으로 건너뛰는 것은 아니다. 원본은 횟수 출력까지 한 뒤 다음 조건 검사에서 끝난다. break를 넣는 다른 구현과 현재 구조를 구별한다. while에 붙은 else는 조건이 단 한 번 참이었다는 사실보다 break 없이 종료했는지가 핵심이다.

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| 가상 첫 값을 3으로 | 한 번 만에 종료 | 다음 검사에서 거짓 |
| target 20을 3으로 | 찾음 3, else 없음 | 범위 안에서 break |
| count 증가 제거 | 첫 값만 계속 읽을 수 있음 | 상태 진행이 사라짐 |
| 처음 dice를 3으로 | 뽑기 없이 끝 0 | 첫 조건부터 거짓 |

무한 반복이면 조건에 쓰이는 값이 실제로 바뀌는지 본다. 가상 목록에 3을 없애면 목록 범위 오류도 날 수 있어 실제 난수와 다르다는 조건을 유지한다. 못찾음이 예상과 다르면 while 범위와 break 위치, else 들여쓰기를 확인한다.
