# 20. Python 종합실습 — 주문 자료를 읽고 판단하고 설명하기

[Python 목차](README.md) · [실무 스타일](19_Python_실무_코딩스타일.md) · [장별 문제](실습/연습문제/README.md)

## 1. 목적과 출발점

이미 배운 문자열·리스트·조건·반복·함수·예외를 연결하는 **새 종합실습**이다. 실제 내 [주문 평가](실습-02_Python_주문파일_평가실습.md)에서 처리 흐름을 가져왔지만 데이터·함수 구조는 교재에서 재구성했다. 강사님의 대응 주문 정답이 있는 것으로 소개하지 않는다.

학습 목표는 합계만 출력하는 데 있지 않다. 문자열을 왜 숫자로 바꾸는지, 어느 항목을 제외하는지, 함수가 무엇을 반환하는지 처음 보는 사람에게 설명할 수 있어야 한다.

## 2. 요구사항과 먼저 적을 예상

| 조건 | 정한 규칙 | 확인 예 |
| --- | --- | --- |
| 형식 | 상품·수량·가격 세 칸 | 쉼표로 나눔 |
| 공백 | 각 칸 앞뒤 제거 | 사과 앞뒤 공백 |
| 숫자 | 수량·가격 정수 변환 | 3000원에서 원 제거 |
| 범위 | 수량≥0, 0≤가격≤10000 | 음수 제외·0 허용 |
| 결과 | 정상 주문 목록과 매출 | 목록·숫자 두 결과 |
| 실패 | 형식·정수·범위 오류는 제외 | None 반환 |

새 함수 parse_order는 한 줄을 받아 정상 주문 목록 또는 None을 반환한다. collect_orders는 여러 줄을 받아 정상 목록과 합계의 튜플을 반환한다. 빈 상품명·쉼표가 포함된 상품명 등까지 처리하는 완성형 CSV 프로그램은 아니다.

기본 입력은 사과 2개×3000원, 배 -1개×4000원, 귤 3개×2000원이다. 실행 전에 남길 목록과 전체 매출을 종이에 적는다.

## 3. 직접 구현할 순서

1. 한 줄을 나누고 각 칸을 정리한다.
2. 칸 수를 확인한 다음 수량·가격을 변환한다. 실패한 줄은 None으로 구분한다.
3. 범위를 검사하고 정상일 때만 자료를 반환한다.
4. 바깥 함수에서 각 줄의 결과를 받아 정상 자료만 저장·누적한다.
5. 목록과 합계를 반환하고 호출한 곳에서 출력한다.

함수 이름만 분리하지 말고 각 인자·반환 경로를 실제로 적는다. None이 돌아온 줄을 바로 order[1]로 읽으면 실패한다. 조건을 통과한 경우만 읽도록 순서를 정한다.

## 4. 전체 풀이와 실행

Python 표준 기능만 필요하다. [전체 파일](실습/책형_복습/20_Python_종합실습.py)을 새 폴더에서 실행한다. 외부 파일·서비스·패키지와 입력 대기는 없다.

<details>
<summary>전체 풀이 — 예상과 자신의 코드를 적은 뒤 펼치기</summary>

```python
def parse_order(line):
    parts = [part.strip() for part in line.split(',')]
    if len(parts) != 3:
        return None
    try:
        quantity = int(parts[1])
        price = int(parts[2].replace('원', ''))
    except ValueError:
        return None
    if quantity < 0 or price < 0 or price > 10000:
        return None
    return [parts[0], quantity, price]

def collect_orders(lines):
    accepted = []
    sales = 0
    for line in lines:
        order = parse_order(line)
        if order is None:
            continue
        accepted.append(order)
        sales += order[1] * order[2]
    return accepted, sales

rows = [' 사과 , 2, 3000원', '배, -1, 4000원', '귤, 3, 2000원']
orders, total = collect_orders(rows)
print(orders)
print(total)
```

```text
[['사과', 2, 3000], ['귤', 3, 2000]]
12000
```

collect_orders가 첫 줄을 parse_order에 넘기면 사과·2·3000의 목록이 돌아온다. 이를 accepted에 넣고 6000을 더한다. 배는 범위 검사에서 None을 반환하므로 continue로 건너뛴다. 귤을 처리한 뒤 두 결과를 튜플로 돌려주고 바깥에서 orders·total에 나눠 받는다. 함수 안에서는 출력하지 않아 계산 결과를 다른 코드에서도 사용할 수 있다. 원본 과제를 새 함수로 재구성한 개선 예제이며 당시 코드가 아니다.

## 5. 단계별 결과와 함수 연결

| 호출 | 중간 판정 | 반환 뒤 처리 | 누적 매출 |
| --- | --- | --- | --- |
| 사과 한 줄 | 3칸·정수·범위 정상 | 목록 추가 | 6000 |
| 배 한 줄 | 수량 -1 | None이므로 건너뜀 | 6000 |
| 귤 한 줄 | 정상 | 목록 추가 | 12000 |
| collect_orders 종료 | 순회 끝 | 두 항목 튜플 반환 | 12000 |

collect_orders는 parse_order를 실제로 호출한다. parse_order의 매개변수 line은 그때 전달한 한 줄이고, 내부 parts는 그 한 줄을 나눈 새 목록이다. return 목록이 돌아오면 호출자 order가 이를 받는다. None이면 현재 줄에서 누적을 하지 않는다. 함수 안 지역 이름을 바깥에서 직접 읽는 방식이 아니다.

print는 맨 마지막에 있다. 함수가 숫자·목록을 반환하므로 다음에는 화면 표시 대신 다른 계산에 사용할 수도 있다. 함수 내부 print만으로 같은 반환 계약을 대신할 수 없다.

## 6. 한 번에 하나씩 확인할 실험

| 시나리오 | 바꿀 입력 | 예상 |
| --- | --- | --- |
| 빈 입력 | rows=[] | 빈 목록·0 |
| 경계 | 물, 0, 10000원 | 목록 유지·매출 0 |
| 상한 초과 | 물, 1, 10001원 | 제외 |
| 정수 실패 | 물, 두개, 1000원 | 제외 |
| 칸 수 실패 | 상품만 | 제외 |
| 정상 전체 | 배 수량을 1 | 세 주문·16000 |

각 시나리오는 원래 기본 입력 대신 독립적으로 실행한다. 실패 입력을 하나 섞었을 때 나머지 정상 행이 계속 처리되는지도 본다. 제외 사유를 화면에서 구별하지 않는 것은 현재 예제의 단순화다. 0을 허용하는 조건과 상품명 검증의 누락도 따로 설명한다.

## 7. 내 원본과 비교하고 스스로 검토하기

| 비교 대상 | 실제 처리 | 새 풀이와 차이 |
| --- | --- | --- |
| 내 exam.py | 파일 읽기·칸별 strip·조건·누적 | 함수로 분리하지 않음 |
| 내 99_try.py | 칸별 strip | 바깥 목록의 빈 문자열 검사 한계 |
| 내 991_try.py | 줄 전체 strip | 칸별 공백 요구를 완전히 대신하지 못함 |
| 새 풀이 | 한 줄 해석 함수·전체 집계 함수 | 칸 수·숫자 실패 처리 추가 |

실제 원본 데이터는 남는 네 항목·19,000원이고 새 기본 예제는 두 항목·12,000원이다. 숫자가 다르다는 이유만으로 둘 중 하나를 오류라고 판단하지 않는다. 입력과 요구를 먼저 비교한다. 새 구조가 더 길어져도 실패 경로와 반환값을 설명하기 쉽다는 이점이 있다. 다만 작고 한 번 쓰는 예제까지 무조건 함수를 늘리는 규칙은 아니다.

채점할 때는 결과값, 경계 조건, 함수 계약, 정상 입력과 실패 입력의 구분, 설명의 정확성을 각각 본다. 왜 그 순서로 처리했는지 말할 수 없으면 해당 본문의 개념·작은 예제로 돌아간다.
