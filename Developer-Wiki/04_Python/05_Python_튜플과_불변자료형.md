## 개요

튜플은 여러 값을 순서대로 저장하는 자료형이다.

리스트와 비슷하지만 생성한 뒤 원소를 추가·삭제·변경할 수 없다는 차이가 있다.

```text
여러 값 저장
    ↓
순서 유지
    ↓
인덱스로 조회
    ↓
생성 후 원소 변경 불가
```

튜플은 다음과 같은 데이터를 표현할 때 사용할 수 있다.

- 좌표
- RGB 색상
- 날짜의 연·월·일
- 함수에서 반환하는 여러 값
- 변경하지 않을 설정값 묶음

```python
position = (10, 20)
rgb = (255, 128, 0)
date = (2026, 8, 6)
```

> [!IMPORTANT]
> 튜플은 “괄호로 만든 리스트”가 아니다.
>
> 순서가 있는 여러 값을 저장하지만, 원소 구성을 변경할 수 없는 별도의 자료형이다.

## 개념에서 실제 실행까지 — 튜플이란? — 불변 컨테이너와 내부 객체

### 무엇이며 왜 배워야 할까?

튜플은 요소의 참조를 순서대로 담되 생성 후 그 위치를 교체하거나 요소 수를 변경할 수 없는 시퀀스다. 좌표나 여러 반환값처럼 하나의 묶음으로 다룰 때 유용하다. 빈 튜플 ()는 정상 문법이며 내 코드의 ‘빈 튜플 선언 불가’ 메모는 바로잡아야 한다.

원소 하나는 (3,)처럼 쉼표가 필요하다. (3)은 괄호로 묶은 정수 표현식이므로 int이고, 괄호 없이 3,도 튜플이다. 언패킹은 오른쪽의 요소를 왼쪽 이름에 나누어 연결하며 개수가 맞지 않으면 ValueError가 난다.

불변은 튜플 자체의 요소 배치를 고칠 수 없다는 뜻이지 내부 객체까지 얼린다는 뜻은 아니다. 튜플 안의 리스트에는 append할 수 있지만 t[0]=새값으로 자리 자체를 교체할 수 없다. 이 차이를 알아야 ‘튜플이니까 어디서든 안전한 상수’라는 오해를 피한다. 튜플도 모든 요소가 해시 가능해야 dict 키나 set 원소가 될 수 있다.

### 독립 실행 예제: 입력에서 결과까지

다음 코드는 앞 문서의 변수 없이 새 .py 파일에서 실행할 수 있는 보충 예제다. 직접 적은 입력값을 사용하므로 같은 조건에서 아래 출력과 비교할 수 있다.

```python
empty = ()
single = (3,)
not_tuple = (3)
pair = ([1], '좌표')
pair[0].append(2)
print(empty, type(single).__name__, type(not_tuple).__name__)
print(pair)
x, y = (10, 20)
print(x, y)
```

예상 출력:

```text
() tuple int
([1, 2], '좌표')
10 20
```

### 실행 순서를 한 단계씩 따라가기

1. (), (3,), (3)을 각각 평가하여 빈 튜플·한 원소 튜플·정수로 연결한다.
2. pair는 리스트와 문자열 참조를 담은 튜플이다.
3. pair[0]을 조회한 결과 리스트에 append하여 내부 목록만 변경한다.
4. 언패킹이 오른쪽 튜플의 두 요소를 x,y에 각각 연결한다.

### 원본에서 어디에 사용했을까?


#### 내 코드: `05_tuple.py` 6~12행

문맥 확인용 원본 발췌다. 이 조각만 독립 실행할 수 있다는 뜻은 아니다. 주석의 설명은 아래 실제 동작 해설과 대조한다.

```python
# tuple은 ()없이도 선언해서 사용할 수 있음
b = 1,2,3
print(b, type(b))

# 값이 1개인 tuple을 선언하기 위해서는 ','를 써줘야 함

print(c, type(c))
```

### 실무에서 판단할 기준과 디버깅

## 1. 튜플 선언

### 1-1. 내 코드

```python
a = (1, 2, 3)

print(a, type(a))
```

### 1-2. 강사님 코드

```python
a = (1, 2, 3)

print(a, type(a))
```

두 코드는 동일하다.

### 1-3. 출력 결과

```text
(1, 2, 3) <class 'tuple'>
```

### 1-4. 구성

| 요소 | 의미 |
| --- | --- |
| `a` | 튜플을 저장하는 변수 |
| `(1, 2, 3)` | 세 개의 정수를 가진 튜플 |
| `type(a)` | 자료형 확인 |

### 1-5. 동작 과정

```text
1, 2, 3 준비
    ↓
하나의 튜플로 묶음
    ↓
변수 a에 저장
```

## 2. 괄호 없는 튜플

### 2-1. 내 코드와 강사님 코드

```python
b = 1, 2, 3

print(b, type(b))
```

### 2-2. 출력 결과

```text
(1, 2, 3) <class 'tuple'>
```

괄호가 없어도 쉼표로 값을 나열하면 튜플이 만들어진다.

```text
1, 2, 3
→ 튜플
```

> [!IMPORTANT]
> 튜플을 결정하는 핵심은 괄호보다 쉼표다.

## 3. 괄호는 왜 사용할까?

다음 두 코드는 같은 튜플을 만든다.

```python
a = (1, 2, 3)
b = 1, 2, 3
```

하지만 괄호를 사용하면 값들이 하나의 튜플이라는 점이 더 명확하게 보인다.

```python
user_info = (
    "Kim",
    21,
    True,
)
```

여러 줄로 작성할 때도 괄호를 사용하면 읽기 쉽다.

> [!TIP]
> 괄호 없이 만들 수 있더라도, 함수 호출·연산식·여러 줄 데이터에서는 괄호를 사용해 의도를 명확하게 표현한다.

## 4. 원소 하나인 튜플

### 4-1. 내 코드

```python
c = (3,)
d = 4,

print(c, type(c))
print(d, type(d))
```

### 4-2. 강사님 코드

```python
c = (3,)
d = 4,

print(d, type(d))
```

내 코드는 괄호를 사용한 방식과 괄호 없는 방식을 모두 출력해 확인한다.

### 4-3. 출력 결과

```text
(3,) <class 'tuple'>
(4,) <class 'tuple'>
```

### 4-4. 왜 쉼표가 필요할까?

다음 코드는 튜플이 아니다.

```python
value = (3)

print(type(value))
```

출력:

```text
<class 'int'>
```

괄호는 단순히 계산 우선순위를 묶는 역할로 해석된다.

원소 하나인 튜플:

```python
value = (3,)
```

```text
(3)
→ 정수 3

(3,)
→ 원소 하나인 튜플
```

## 5. 빈 튜플

내 코드 주석에는 빈 튜플을 만들 수 없다고 기록되어 있지만, Python에서는 빈 튜플을 만들 수 있다.

```python
empty_tuple_1 = ()
empty_tuple_2 = tuple()

print(empty_tuple_1)
print(empty_tuple_2)
```

### 5-1. 출력 결과

```text
()
()
```

### 5-2. 원본 메모 바로잡기

기존 메모:

```text
a = ()처럼 빈 것으로 선언 불가
```

정확한 설명:

```text
()
→ 빈 튜플 생성 가능

(3)
→ 정수

(3,)
→ 원소 하나인 튜플
```

> [!IMPORTANT]
> 빈 튜플은 만들 수 있다.
>
> 쉼표가 반드시 필요한 경우는 원소가 하나인 튜플이다.

## 6. 튜플의 자료형

```python
values = (
    10,
```

## 10. 튜플은 불변 자료형

내 코드에서는 튜플을 `readonly list`라고 표현했다.

학습 관점에서는 리스트처럼 여러 값을 저장하지만 변경할 수 없다는 의미로 이해할 수 있다.

정확하게는 튜플은 **불변(immutable) 자료형**이다.

```python
numbers = (
    1,
    2,
    3,
)
```

다음 작업은 사용할 수 없다.

- 원소 대입
- `append()`
- `remove()`
- `pop()`
- `sort()`

## 11. 튜플 원소 변경 오류

```python
    2,

```

### 11-1. 발생 결과

```text

```

### 11-2. 오류 원인

튜플은 생성 후 특정 위치의 원소를 다른 값으로 바꿀 수 없다.

```text
numbers[0]
→ 조회 가능

numbers[0] = 100
→ 변경 불가
```

## 29. 튜플 안의 리스트

튜플 자체는 불변이지만, 튜플 안에 저장된 가변 객체는 변경될 수 있다.

```python
data = (
    "Python",
    [1, 2, 3],
)

data[1].append(4)

print(data)
```

### 29-1. 출력 결과

```text
('Python', [1, 2, 3, 4])
```

### 29-2. 왜 가능할까?

```text
튜플의 두 번째 원소
→ 같은 리스트 객체를 계속 가리킴

리스트 내부 값
→ 변경 가능
```

튜플의 원소 자체를 다른 객체로 바꾼 것은 아니다.

> [!WARNING]
> 튜플이라고 해서 내부 데이터 전체가 항상 완전히 변경 불가능한 것은 아니다.
>
> 내부에 리스트·딕셔너리 같은 가변 객체가 있으면 그 객체의 내용은 바뀔 수 있다.

```python

    1,
    [2, 3],
)
```

이 튜플은 딕셔너리 키로 사용할 수 없다.

## 31. 리스트와 튜플 비교

| 구분 | 리스트 | 튜플 |
| --- | --- | --- |
| 기호 | `[]` | `()` 또는 쉼표 |
| 변경 가능 | 가능 | 불가능 |
| 값 추가·삭제 | 가능 | 불가능 |
| 인덱싱·슬라이싱 | 가능 | 가능 |
| 중복 값 | 가능 | 가능 |
| 순서 유지 | 예 | 예 |
| 주요 사용 | 변경되는 목록 | 고정된 값 묶음 |

### 31-1. 리스트가 적합한 경우

- 상품 목록이 계속 추가됨
- 사용자 목록을 삭제·수정함
- 정렬과 변경이 자주 필요함
- 반복 처리 결과를 누적함

### 31-2. 튜플이 적합한 경우

- 좌표처럼 값의 의미와 개수가 고정됨
- 함수에서 여러 값을 반환함
- 변경하지 않을 설정값 묶음
- 딕셔너리 키로 사용할 고정 조합

## 32. 내 코드와 강사님 코드 비교

| 항목 | 내 코드 | 강사님 코드 |
| --- | --- | --- |
| 기본 선언 | `(1, 2, 3)` | `(1, 2, 3)` |
| 괄호 없는 선언 | `1, 2, 3` | `1, 2, 3` |
| 원소 하나 | 괄호·괄호 없는 방식 모두 출력 | 두 방식 선언 후 `d` 출력 |
| 빈 튜플 | 생성 불가라고 메모 | 별도 설명 없음 |
| 리스트 변환 | 리스트→튜플, 튜플→리스트 모두 실습 | 별도 변환 예제 없음 |
| 불변성 | `readonly list`, 값 변경 불가 메모 | 기본 선언 중심 |

### 32-1. 내 코드의 장점

- 원소 하나인 튜플에 쉼표가 필요한 점을 정확히 기록했다.
- 괄호 없이 튜플을 만들 수 있다는 점을 확인했다.
- 리스트와 튜플의 상호 변환을 직접 실습했다.
- 튜플이 변경 불가능하다는 핵심 특징을 메모했다.

### 32-2. 내 코드의 개선점

- 빈 튜플은 `()` 또는 `tuple()`로 만들 수 있다.
- 튜플은 `readonly list`라기보다 불변 시퀀스라고 설명하는 것이 정확하다.
- 튜플 내부에 가변 객체가 있으면 그 객체 내용은 바뀔 수 있다.
- 튜플도 `count()`와 `index()` 같은 조회 메서드를 제공한다.

### 32-3. 강사님 코드의 장점

- 튜플 선언의 세 가지 핵심 형태를 간결하게 보여 준다.
- 원소 하나인 튜플의 쉼표 문법을 학습할 수 있다.
- 첫 튜플 학습 파일로 필요한 최소 개념이 명확하다.

### 32-4. 강사님 코드의 보충점

- 빈 튜플 생성 방법이 필요하다.
- 불변성 오류 예제가 있으면 리스트와 차이를 이해하기 쉽다.
- 인덱싱·언패킹·변환 사용법을 보충할 필요가 있다.
- 실제 활용 상황을 연결하면 튜플 선택 기준이 명확해진다.

## 33. 기존 코드에서 개선 코드로 바꾼 이유

### 33-1. 빈 튜플 설명 수정

기존 이해:

```text
()
→ 선언 불가
```

개선된 이해:

```python
empty_tuple = ()
```

```text
()
→ 정상적인 빈 튜플
```

### 33-2. 용어 개선

기존:

```text
readonly list
```

개선:

```text
불변 시퀀스 자료형
```

이유:

- 리스트와 튜플은 서로 다른 자료형이다.
- 튜플은 리스트의 읽기 전용 모드가 아니다.

### 33-3. 의미 있는 변수명

기존:

```python
a = (1, 2, 3)
```

개선:

```python
coordinates = (
    10,
    20,
    30,
)
```

학습 예제에서는 `a`도 가능하지만 실제 코드에서는 값의 역할을 드러내는 이름이 좋다.

## 34. 실무형 예제: 사용자 검색 조건

검색 조건은 한 번 정한 뒤 변경하지 않는 값 묶음으로 표현할 수 있다.

```python
search_condition = (
    "개발",
    19,
    True,
)

department, minimum_age, active_only = (
    search_condition
)

print("부서:", department)
print("최소 나이:", minimum_age)
print("활성 사용자만:", active_only)
```

### 34-1. 출력 결과

```text
부서: 개발
최소 나이: 19
활성 사용자만: True
```

### 34-2. 코드에서 무엇을 사용하는 걸까?

| 코드 | 사용하는 이유 |
| --- | --- |
| `search_condition` | 고정된 검색 조건 묶음 저장 |
| 튜플 | 값의 순서와 개수를 유지 |
| 언패킹 | 각 조건을 의미 있는 변수로 분리 |

### 34-3. 주의점

튜플 원소가 많아지면 위치만으로 의미를 이해하기 어려워질 수 있다.

복잡한 데이터 구조라면 다음을 검토한다.

- 딕셔너리
- `NamedTuple`
- `dataclass`
- 클래스

> [!TIP]
> 튜플은 작고 의미가 명확한 고정 값 묶음에 적합하다.

## 36. 자주 하는 실수

### 36-1. 괄호만 있으면 튜플이라고 생각

`(3)`은 정수이고 `(3,)`이 튜플이다.

### 36-2. 빈 튜플을 만들 수 없다고 생각

`()`와 `tuple()` 모두 가능하다.

### 36-3. 튜플을 읽기 전용 리스트라고만 이해

둘은 서로 다른 자료형이다.

<a id="index-section-114"></a>

### 36-4. 튜플에 `append()`나 `remove()` 사용

튜플은 원소 구성을 변경할 수 없다.

### 36-5. 튜플 결합이 원본을 변경한다고 생각

`+`는 새 튜플을 만든다.

### 36-6. 언패킹 변수 개수를 맞추지 않음

원소 개수와 변수 개수가 다르면 오류가 발생한다.

### 36-7. 확장 언패킹 결과도 튜플이라고 생각

`*middle`로 받은 값은 리스트다.

### 36-8. 튜플 내부 가변 객체도 변경되지 않는다고 생각

내부 리스트나 딕셔너리는 변경될 수 있다.

### 36-9. 고정되지 않은 목록까지 튜플로 작성

추가·삭제가 필요하면 리스트가 더 적합하다.

### 36-10. 의미가 다른 값을 너무 많이 튜플에 저장

위치만으로 의미를 파악하기 어려워질 수 있다.

## 마무리

튜플의 핵심은 단순히 값을 여러 개 묶는 것이 아니다.

```text
여러 값을 순서대로 저장하고
    ↓
원소의 위치와 개수를 유지하며
    ↓
생성 후 구성을 변경하지 않고
    ↓
언패킹으로 각각의 값에 의미를 부여하는 것
```

값의 추가·삭제가 필요한 목록은 리스트를 사용하고, 작고 고정된 값 묶음은 튜플을 고려한다.

## V3 동작 백과 보강 — 튜플 생성과 언패킹

튜플을 만드는 핵심 문법은 괄호가 아니라 쉼표다. `(1)`은 정수지만 `(1,)`은 원소 하나인 튜플이다. 튜플은 생성 후 원소의 위치를 바꿀 수 없으므로 좌표, RGB, 함수가 반환하는 고정 묶음처럼 구조가 유지되어야 하는 값에 적합하다.

```python
point = (10, 20)
x, y = point
print(type((10)))
print(type((10,)))
print(x, y)
```

```text
<class 'int'>
<class 'tuple'>
10 20
```

언패킹할 변수 수와 원소 수가 다르면 `ValueError`다. 튜플 자체는 불변이지만 내부 원소가 리스트라면 그 리스트 내용은 변경될 수 있으므로 “튜플 안의 모든 것이 절대 변하지 않는다”로 이해하면 안 된다.
