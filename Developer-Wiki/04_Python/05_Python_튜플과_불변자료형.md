# 05. 튜플 — 순서 있는 묶음과 요소 대입의 제한

[Python 목차](README.md) · [읽기 안내](00-00_Python_V3_동작_백과_읽기법.md)

리스트와 튜플은 모두 여러 값을 순서대로 읽을 수 있지만 값을 바꾸는 방식은 다르다. 튜플을 읽기 전용 리스트라는 별명으로만 외우지 말고, 무엇을 만들었고 어떤 대입이 가능한지 코드로 구별해 보자.

## 1. 이 장에서 배울 것

빈 튜플·한 항목 튜플·여러 항목 튜플을 구분한다. 쉼표와 괄호의 역할, 리스트·튜플 변환이 원래 변수를 바꾸지 않는다는 점, 재대입과 요소 변경의 차이를 설명한다.

실제 원본·새 예제·개선안·선택 학습을 구분하고 입력·실행 순서·반환값·출력을 연결한다.

<a id="concepts"></a>

## 2. 무엇이며, 왜 필요한가

튜플은 순서가 있는 값 묶음이며 요소 자리에 새 값을 대입할 수 없는 자료형이다. point=(10,20)은 두 값을 묶어 위치로 읽게 한다. point[0]은 10이지만 point[0]=30처럼 기존 튜플의 위치를 수정할 수는 없다.

| 표현 | 실제 값·종류 | 핵심 |
| --- | --- | --- |
| () | 빈 튜플 | 정상 생성 가능 |
| (3) | 정수 3 | 괄호로 식을 묶은 것 |
| (3,) | 항목 하나인 튜플 | 쉼표가 필요 |
| 3, | 같은 한 항목 튜플 | 대입 오른쪽에서 사용 |
| (1,2,3)·1,2,3 | 여러 항목 튜플 | 이 문맥에서 같은 묶음 |

튜플 생성에서 핵심은 쉼표다. 괄호만 보고 무조건 튜플이라고 읽지 않는다. 빈 튜플은 별도로 ()를 사용한다.

tuple(리스트)나 list(튜플)는 다른 종류의 새 바깥 값을 만든다. 결과를 출력했다고 원래 변수의 자료형이 자동 변경되는 것은 아니다. 변수에 새 튜플을 다시 대입하는 것과 기존 튜플 내부 위치를 수정하는 것도 다르다. 불변성은 이름이 영원히 같은 값만 가리킨다는 뜻이 아니다.

> 📚 **출처 · 본문 설명 확인:** [Python 공식 자료 구조: 튜플과 시퀀스](https://docs.python.org/ko/3/tutorial/datastructures.html#tuples-and-sequences). 실제 배운 문법의 의미를 확인한 근거다. 예제·표·풀이 자체는 수업 자료를 바탕으로 새로 구성했다. 외부 문장을 직접 인용하지 않았다. 이번 문법 확인 기간: 2026-10-28~29.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 전체 코드.** [실행 파일](실습/책형_복습/05_Python_튜플과_불변자료형.py)을 제공한다. Python이 설치된 환경에서 새 .py 파일로 저장해 실행한다. 터미널은 그 파일이 있는 폴더에서 열고 `python 파일이름.py`를 실행한다. VS Code의 Python 실행 기능을 사용해도 된다. 결과는 터미널에 표시된다.



```python
empty = ()
single_number = (3)
single_tuple = (3,)
point = 10, 20
print(empty, type(empty))
print(single_number, type(single_number))
print(single_tuple, type(single_tuple))
print(point[0], point[1])
values = [1, 2, 3]
converted = tuple(values)
print(converted, type(values))
editable = list(converted)
editable[0] = 100
print(converted, editable)
point = (30, 40)
print(point)
```

(3)과 (3,)의 type을 나란히 읽는다. values에서 converted를 만들어도 values는 리스트다. 다시 만든 editable 리스트의 첫 항목을 바꿔도 converted의 요소를 대입한 것은 아니다. 마지막 point=(30,40)은 이름을 새 튜플에 연결하는 정상 재대입이며 처음 튜플의 요소를 바꾼 작업이 아니다.

**예상 출력 또는 관찰:**

```text
() <class 'tuple'>
3 <class 'int'>
(3,) <class 'tuple'>
10 20
(1, 2, 3) <class 'list'>
(1, 2, 3) [100, 2, 3]
(30, 40)
```

## 4. 내가 작성한 코드를 따라 읽기

아래는 원본 발췌다. 주석의 잘못된 설명도 원문을 보존하고 풀이에서 교정한다. 필요한 선언·호출·다른 파일의 정의는 다음 절까지 연결해 읽는다.

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_python/05_tuple.py` 1–20행

```python
# 선언 (readonly list)
# a = () 처럼 빈 것으로 선언 불가하며, 값은 바꾸지 못 함
a = (1,2,3)
print(a, type(a))

# tuple은 ()없이도 선언해서 사용할 수 있음
b = 1,2,3
print(b, type(b))

# 값이 1개인 tuple을 선언하기 위해서는 ','를 써줘야 함
c = (3,)
print(c, type(c))
d = 4,
print(d, type(d))

# 아래와 같이 tuple > list , list > tuple 변경 가능
e = [1,2,3]
print(tuple(e))
f = (1,2,3)
print(list(f))
```

**발췌 바로 풀이:** 괄호를 생략한 쉼표 묶음도 튜플이고 한 항목일 때 쉼표가 중요하다. ()는 빈 튜플로 정상이다. tuple(e) 출력 뒤 e는 여전히 리스트이며 list(f) 출력 뒤 f도 튜플 그대로다.

내 원본은 a=(1,2,3)과 b=1,2,3을 만들고 c=(3,)·d=4,로 한 항목 튜플을 확인한다. tuple(e)·list(f)는 변환 결과를 바로 출력한다. 내 주석의 빈 튜플을 선언할 수 없다는 설명은 틀리며 ()는 가능하다. readonly list는 차이를 기억하는 비유로만 쓰고 같은 자료형이라고 설명하지 않는다.

<a id="connections"></a>

## 5. 선언·호출·파일이 연결되는 흐름

값들을 쉼표로 묶음 → 튜플에 이름 연결 → 인덱스로 요소 읽기 → 변환 함수에 전달 → 새 값 반환 → 출력 또는 별도 변수에 연결 순서다. 이 원본에는 사용자 정의 함수가 없으며 tuple·list·type·print는 Python에서 제공한다. 같은 변환 함수 호출을 보여 주는 것과 원래 이름에 그 결과를 대입하는 것을 구분한다.

<a id="review"></a>

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 내 코드는 한 항목 쉼표와 양방향 변환을 출력하여 비교했다. **실제 주석 오류:** 빈 튜플 불가라는 문구를 교정해야 한다. **표현 개선:** 불변성은 요소 대입 제한을 먼저 뜻하며 이름의 재대입 금지와 섞지 않는다. **작성 선택:** 짧은 값 묶음은 괄호로 명확히 적으면 처음 읽을 때 경계를 찾기 쉽다.

개선안은 D 드라이브 원본을 수정한 결과가 아니다. 실제 오류·수업용 단순화·목적에 따른 선택을 구별한다.

## 8. 결과를 추적하고 한 가지 바꾸기

| 단계 | 원래 이름 | 새 결과 |
| --- | --- | --- |
| e=[1,2,3] | 리스트 | 아직 없음 |
| tuple(e) | e는 리스트 유지 | (1,2,3) |
| f=(1,2,3) | 튜플 | 아직 없음 |
| list(f) | f는 튜플 유지 | [1,2,3] |

함수의 반환값과 대입을 나누어 읽으면 “변환했으니 원래 변수도 바뀐다”는 오해를 피할 수 있다. 이후 여러 값을 반환하는 함수도 튜플로 묶여 전달되는 문맥과 연결할 수 있지만, 지금은 생성·읽기·변환 결과를 먼저 확인한다.

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| (3,)에서 쉼표 제거 | 정수 | 묶인 식 |
| point[0]=30을 실행 | TypeError | 튜플 요소 대입 불가 |
| converted를 values에 다시 대입 | values도 새 튜플을 가리킴 | 변환과 재대입을 함께 수행 |

한 항목인데 정수로 나오면 쉼표를 확인한다. 변환 뒤 type이 안 바뀌면 반환값을 저장했는지 본다. 요소 대입 오류를 이름 자체 재사용이 금지된 것으로 확대하지 않는다.
