# 16. 이터레이터 — 반복할 때 다음 값을 받는다는 뜻

[Python 목차](README.md) · [읽기 안내](00-00_Python_V3_동작_백과_읽기법.md)

학습 범위는 개념과 간단한 사용이다. 직접 이터레이터 클래스를 만드는 상세 구현을 배운 것으로 확대하지 않는다. for로 이미 사용한 반복을 “값을 차례로 꺼낸다”는 관점에서 복습한다.

## 1. 이 장에서 배울 것

반복할 수 있는 자료와 현재 꺼내는 위치를 가진 객체를 구분한다. 끝까지 읽으면 반복이 끝난다는 뜻을 설명한다. 직접 __iter__·__next__를 구현하는 문제는 필수 학습으로 내지 않는다.

실제 원본·새 예제·개선안·선택 학습을 구분하고 입력·실행 순서·반환값·출력을 연결한다.

<a id="concepts"></a>

## 2. 무엇이며, 왜 필요한가

책의 페이지 목록과 지금 읽는 책갈피를 구분해 생각해 보자. 리스트에는 요소들이 있고, 반복하는 동안에는 다음에 읽을 위치가 필요하다. 반복 가능한 객체에서 값을 차례로 얻는 객체를 이터레이터라고 한다. 이 비유는 순서를 이해하기 위한 것이며 리스트 자체에 책갈피가 하나만 저장된다는 뜻은 아니다.

| 용어 | 이 장에서 이해할 수준 | 혼동하지 않을 것 |
| --- | --- | --- |
| 반복 가능한 객체 | for로 값을 얻을 수 있는 대상 | 모두 리스트인 것은 아님 |
| 이터레이터 | 다음 값을 얻는 진행 상태를 가짐 | 자료 전체를 뜻하지 않음 |
| 다음 값 | 다음 반복에 사용할 요소 | 항상 인덱스 1이라는 뜻 아님 |
| 소진 | 더 꺼낼 값이 없음 | 원본 리스트 요소 삭제와 다름 |

for는 다음 값을 얻어 반복 본문을 실행하고 더 얻을 값이 없으면 끝난다. 원본 메모의 StopInteration은 StopIteration의 오타다. 이것은 반복이 끝남을 알리는 이름이며 평소 for를 쓸 때 매번 직접 잡는 코드를 작성할 필요는 없다. 여기서는 내부 메서드를 직접 작성하지 않는다.

> 📚 **출처 · 본문 설명 확인:** [Python 자습서 · 이터레이터](https://docs.python.org/ko/3/tutorial/classes.html#iterators). 실제 배운 문법의 의미를 확인한 근거다. 예제·표·풀이 자체는 수업 자료를 바탕으로 새로 구성했다. 외부 문장을 직접 인용하지 않았다. 이번 문법 확인 기간: 2026-10-28~29.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 전체 코드.** [실행 파일](실습/책형_복습/16_Python_이터레이터.py)을 제공한다. Python이 설치된 환경에서 새 .py 파일로 저장해 실행한다. 터미널은 그 파일이 있는 폴더에서 열고 `python 파일이름.py`를 실행한다. VS Code의 Python 실행 기능을 사용해도 된다. 결과는 터미널에 표시된다.



```python
values = [10, 20]
for value in values:
    print('첫 순회', value)
for value in values:
    print('다시 순회', value)
print('남은 원본', values)
```

첫 for는 10과 20을 얻은 뒤 끝난다. 두 번째 for는 리스트를 새로 순회하므로 다시 10과 20을 읽는다. 리스트에서 요소를 꺼내 읽었다는 말이 pop으로 삭제했다는 뜻은 아니다. 마지막 출력으로 원본이 유지됐음을 확인한다. 이 예제는 for의 동작을 설명하기 위한 새 코드다.

**예상 출력 또는 관찰:**

```text
첫 순회 10
첫 순회 20
다시 순회 10
다시 순회 20
남은 원본 [10, 20]
```

### 내 코드 — 원본 발췌

```python
# *이터레이터와 제너레이터 구분 법 및 차이 설명 필요
```

**발췌 바로 풀이:** 독립 구현 코드가 아니라 복습이 필요하다고 적은 개인 메모다. 메서드 이름과 끝 신호를 개념 수준에서 연결한다. 이 주석만으로 상세 사용자 정의 구현을 실습했다고 판단하지 않는다.

## 5. 선언·호출·파일이 연결되는 흐름

이 장의 새 예제에는 import나 직접 만든 함수가 없다. 리스트 준비 → for에서 값 얻기 → 본문 출력 → 끝 → 별도 for에서 새 순회 순서다. 메모의 내부 프로토콜을 사용자 정의 클래스로 옮기는 내용은 아래 TIP에 둔다.

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 반복 종료와 예외 이름을 연결해 복습할 질문을 남겼다. **교정:** StopIteration 철자를 바로잡고, 메서드 이름을 아는 것과 직접 구현한 것을 구별한다. **범위:** 상세 클래스 구현을 메인 예제로 추가하면 당시 배운 내용과 섞이므로 현재 반복 사용의 의미만 확인한다.

개선안은 D 드라이브 원본을 수정한 결과가 아니다. 실제 오류·수업용 단순화·목적에 따른 선택을 구별한다.

## 8. 결과를 추적하고 한 가지 바꾸기

| 순서 | 현재 값 | 리스트 자체 |
| --- | --- | --- |
| 첫 순회 1회 | 10 | [10, 20] |
| 첫 순회 2회 | 20 | [10, 20] |
| 첫 순회 끝 | 더 없음 | [10, 20] |
| 다음 for 시작 | 다시 10 | [10, 20] |

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| 빈 리스트로 | 순회 본문 출력 없음 | 얻을 값 없음 |
| 30 추가 | 두 순회 모두 한 줄 증가 | 자료에 요소 추가 |
| 첫 순회에 break | 첫 순회만 일찍 종료 | 두 번째 for는 별개 |

반복 횟수와 목록 길이가 다르면 break·continue·조건을 먼저 본다. 반복 가능한 대상이라고 모두 인덱스로 읽을 수 있다고 추측하지 않는다. 상세 메서드 구현을 몰라 for를 사용할 수 없는 것은 아니다.

## 9. 추가로 알면 좋은 것과 출처

> 💡 **TIP · 수업 범위 밖:** iter(values)로 이터레이터를 얻고 next로 한 값씩 읽는 직접 관찰, __iter__·__next__를 갖춘 사용자 정의 클래스 작성은 선택 학습이다. 위 공식 자습서의 뒤쪽 구현 예시를 참고한다. 같은 이터레이터를 끝까지 읽은 뒤 다시 사용하는 상황은 리스트에 새 for를 쓰는 본문 예제와 구분해야 한다.

TIP은 기본 문제의 필수 조건이 아니다. 배운 문법을 확인한 📚 출처와 선택 확장을 구별한다.
