# Python 읽기 안내 — 코드보다 먼저 입력과 목적 보기

[Python 목차](README.md)

## 1. 이 교재에서 읽을 순서

각 본문의 처음에는 해결할 문제가 있다. 개념을 읽고 작은 예제의 결과를 예상한 뒤 실행한다. 그 다음 실제 내 코드로 넘어간다. 원본은 여러 실습이 같은 파일에 이어져 있으므로 앞에서 바뀐 변수와 정의를 확인해야 한다. 원본 일부를 떼어 실행해 이름 오류가 나면 발췌의 누락과 원본 오류를 구별한다.

## 2. 한 줄을 읽을 때의 질문

| 질문 | 적어 볼 것 | 예 |
| --- | --- | --- |
| 어디서 왔나? | 입력·초기값·매개변수 | input은 문자열 |
| 무엇인가? | 자료형·이름이 가리키는 값 | 목록과 그 안의 요소 |
| 무엇이 바뀌나? | 대입·객체 변경·반환 | append는 목록 변경 |
| 다음에 어디로 가나? | 분기·반복·호출 | return은 함수 종료 |
| 무엇이 보이나? | print·파일·예외 | 반환값과 화면 출력 구분 |

함수는 정의 → 인자 전달 → 본문 → 반환 → 호출한 곳의 사용을 연결한다. import는 가져온 이름만 보지 말고 정의 파일의 함수·클래스와 함께 읽는다. [모듈 장](15_Python_모듈과_import.md)은 보조 파일 전체를 제공한다.

## 3. 예제와 원본을 혼동하지 않기

새 설명 예제는 실행 조건·전체 코드·예상 출력을 제공한다. 실제 내 코드는 경로·행 범위를 표시한 원본 발췌다. 새 개선안은 당시 코드가 아니다. 강사님 코드는 비교에 필요한 경우에만 인용한다. 같은 동작을 양쪽에서 전부 반복하지 않는다.

원본 전체에는 사용자 입력·창 표시·파일 변경·외부 요청이 섞일 수 있다. 이 교재의 자동 확인은 분리한 새 예제를 새 임시 폴더에서 수행했다. 외부 요청 성공이나 거북이 그래픽 창 작동까지 확인했다고 확대하지 않는다.

## 4. 실수에서 배우는 방법

예상 결과를 적고 실행한 뒤, 다르면 입력·현재 자료형·실행 경로를 하나씩 확인한다. 한 번에 여러 줄을 바꾸면 원인을 찾기 어렵다. 본문 8절의 한 가지 변경 실험을 하나씩 하고 원래 상태로 돌아간다. 오류는 종류와 발생 위치를 함께 읽고, 수업용 단순화와 실제 요구 불충족을 구별한다.

## 5. 복습과 이후의 나

각 장 문제는 예상 → 설명 → 수정 순서다. 원래 퀴즈는 실습- 페이지에서 당시 해결 방식과 함께 읽는다. [스타일](19_Python_실무_코딩스타일.md)에서는 왜 나누고 이름 붙였는지 판단하고, [종합실습](20_Python_종합실습.md)에서는 여러 장을 연결한다. 나중에 실력이 늘면 결과뿐 아니라 처리 범위·실패 정책·입력 가정도 다시 검토한다.

💡 TIP의 선택 확장은 필수 문제의 선행 조건이 아니다. 외부 출처와 실제 학습 근거는 별개이며, 정의를 풍부하게 설명하는 것과 배운 범위를 넓히는 것은 다르다.
