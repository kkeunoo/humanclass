## 1. 이 장에서 배울 것

키·값·쌍과 중첩 조회를 설명한다. 없는 키의 []·get 차이, 갱신·삭제의 효과와 반환값, items 순회를 연결한다. 실제 원본의 간단 set 사용은 중복 제거 관찰로 구분한다.

실제 원본·새 예제·개선안·선택 학습을 구분하고 입력·실행 순서·반환값·출력을 연결한다.

## 2. 무엇이며, 왜 필요한가

딕셔너리는 키와 값을 연결하는 자료형이다. {'가격':1000,'수량':2}에서 가격은 키이고 1000은 값이다. 리스트의 인덱스 0처럼 위치 약속으로 읽지 않고 해당 키로 찾는다. 같은 키를 다시 대입하면 기존 값을 바꾸고, 새 키면 항목을 추가한다.

| 표현 | 결과·효과 | 없는 키라면 |
| --- | --- | --- |
| item['가격'] | 값 조회 | KeyError |
| item.get('가격') | 값 조회 | None |
| item.get('가격',0) | 값 조회 | 기본값 0 |
| '가격' in item | 키 포함 검사 | False |
| item.pop('가격') | 삭제 후 값 반환 | 기본값 없으면 오류 |
| item.items() | 키·값 쌍을 보는 뷰 | 각 쌍 순회에 사용 |

get이 기본값을 돌려주는 것은 키가 없을 때다. 키는 있는데 값이 None이면 기본값으로 자동 대체하지 않는다. item.get('스킬',{}).get('공격',0)도 스킬 키가 없을 때는 빈 딕셔너리에서 다시 읽지만, 스킬 값 자체가 None인 데이터까지 항상 안전하게 만드는 것은 아니다.

딕셔너리 in은 바깥 키를 검사한다. '공격'이 안쪽 스킬 딕셔너리의 키라면 '공격' in b와 '공격' in b['스킬']의 결과는 다르다. len도 현재 바깥 키 수를 센다. 안쪽 키까지 자동으로 모두 더하지 않는다.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 전체 코드.** [실행 파일](실습/책형_복습/07_Python_딕셔너리.py)을 제공한다. Python이 설치된 환경에서 새 .py 파일로 저장해 실행한다. 터미널은 그 파일이 있는 폴더에서 열고 `python 파일이름.py`를 실행한다. VS Code의 Python 실행 기능을 사용해도 된다. 결과는 터미널에 표시된다.



```python
item = {'가격': 1000, '수량': 2, '상세': {'이름': '공책'}}
print(item['가격'])
print(item.get('쿠폰'))
print(item.get('쿠폰', 0))
print('이름' in item, '이름' in item['상세'])
item['수량'] = 3
item['색상'] = '파랑'
print(len(item))
for key, value in item.items():
    print(key, value)
item.update(수량=4, 할인=100)
discount = item.pop('할인')
print(discount, item.get('할인'))
print(item.pop('할인', 0))
pair = item.popitem()
```

쿠폰 키가 없으므로 get의 기본 None과 지정한 0을 각각 받는다. 수량은 기존 값 변경, 색상은 새 항목이다. 할인도 나중 추가하지만 pop으로 먼저 지워 popitem 때에는 남아 있는 마지막 추가 항목인 색상이 제거된다. 임의의 항목을 무작위로 고르는 기능이 아니다. set에는 hello의 l 중복이 합쳐져 네 종류가 있지만 표시 순서에 의존하지 않도록 개수와 포함 여부만 출력했다.

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_python/07_dict.py` 98–116행

```python
a = ['a', 'b', 'c']
b = {
    'a' : 0, 
    'b' : 0, 
    'c' : 0, 
}
b = {}
b[a[0]] = 0
b[a[1]] = 0
```

**발췌 바로 풀이:** `dict.fromkeys(['a','b','c'])`는 각 키의 값을 `None`으로 둔 새 딕셔너리를 만든다. `for i in c`는 **키**를 차례대로 돌고, `c[i]`로 그 키의 값을 찾는다. `for key, value in c.items()`는 한 쌍을 바로 나누어 받는다. 내 파일은 `b = {}`로 앞의 딕셔너리를 다시 지정하므로 그 아래에서 실제로 들어간 것은 `'a'`와 `'b'` 두 키다. 강사님 파일에는 `b.clear()`가 있는데, 바로 앞에서 새 빈 딕셔너리로 다시 지정한 상태이므로 지울 항목은 없다.

내 원본은 이름·직업·스킬을 중첩 딕셔너리로 만들고 조회·갱신·삭제·순회를 실습한다. 문자열 키를 직접 쓰려면 따옴표로 이름을 적지만 모든 키가 문자열이어야 한다는 뜻은 아니다. dict(a=10,b=20)은 문자열 키 a·b를 만든다. 내 값은 이름 홍길동·직업 도적이고 강사님 값과 다르다. 두 원본 모두 get의 기본값과 안쪽 딕셔너리 접근을 확인한다.

## 5. 선언·호출·파일이 연결되는 흐름

b에서 스킬 키 조회 → 안쪽 딕셔너리 반환 → 공격 키 조회 순서다. b의 스킬 항목을 받아 둔 d는 같은 안쪽 객체를 가리키며 독립 복사를 요청한 것은 아니다. keys·values·items는 현재 딕셔너리를 보는 뷰이고, 원본은 values를 list로 바꿔 첫 값을 읽는다. for key,value in c.items()는 각 쌍을 두 이름으로 나누어 받는다. dict.fromkeys(a)는 키 목록으로 새 딕셔너리를 만들며 기본값은 None이다.

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 내 코드는 없는 키의 예외와 get 기본값, 중첩 조회 실패 가능성을 주석으로 비교한다. **교정:** dict의 pop은 인덱스가 아니라 키로 찾는다. popitem은 현재 Python에서 마지막 추가 항목을 꺼낸다. JSON 키가 set으로 관리되어 중복이 없다는 주석은 이 실습의 근거가 아니다. **기본값 조건:** get이면 언제나 안전하다고 확대하지 않고 중간 값의 실제 종류까지 확인한다.

개선안은 D 드라이브 원본을 수정한 결과가 아니다. 실제 오류·수업용 단순화·목적에 따른 선택을 구별한다.

## 7. 강사님 코드가 도움이 되는 비교

| pop 나이 반환 | 20 | '30' |
| 다시 pop 기본값 | 0 | 0 |

직업2를 추가한 시점의 바깥 키는 이름·직업·스킬·직업2의 4개다. 안쪽 스킬 항목 수는 따로다. set('hello')는 중복 글자를 제거하지만 출력 순서는 고정하지 않는다. dict의 삽입 순서와 set의 순서 보장을 같은 규칙으로 묶지 않는다.

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| 없는 쿠폰을 []로 조회 | KeyError | get과 실패 정책 차이 |
| 쿠폰 값을 None으로 미리 추가 | get('쿠폰',0)도 None | 키가 있는 상태 |
| 할인 pop 제거 | popitem이 할인을 꺼냄 | 마지막 항목 변경 |
| in 대상만 안쪽으로 변경 | 검사 키 범위 변경 | 중첩 단계 차이 |

없는 키 오류는 정확한 철자와 어느 단계인지 확인한다. None의 get 오류는 앞 단계 조회 결과를 본다. 삭제한 값이 필요한데 사라지면 pop의 반환값을 저장한다. values[0]을 바로 읽지 말고 원본처럼 list 변환 여부를 확인한다.

## 10. 복습과 빠른 정리

1. 없는 키의 []와 get 차이는?
2. get의 기본값은 값이 None이어도 대신 쓰이는가?
3. in은 값과 키 중 무엇을 검사하는가?
4. pop과 popitem은 무엇을 돌려주는가?

<details>
<summary>풀이 — 먼저 자신의 답을 적은 뒤 펼치기</summary>

[]는 KeyError, get은 기본 None 또는 지정값이다. 키가 있고 값이 None이면 그 None을 받는다. 딕셔너리 in은 키를 검사한다. pop은 지정 키의 값, popitem은 마지막 항목의 키·값 쌍을 돌려준다.
