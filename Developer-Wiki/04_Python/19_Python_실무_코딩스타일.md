## 1. 이 장에서 배울 것

값을 계산하는 함수와 출력 위치를 구분한다. 의미 있는 이름·작은 처리 단계·일관된 공백으로 읽기 쉽게 만들고, 스타일 변경과 입력 검증 추가처럼 동작이 바뀌는 변경을 나눈다.

실제 원본·새 예제·개선안·선택 학습을 구분하고 입력·실행 순서·반환값·출력을 연결한다.

## 2. 무엇이며, 왜 필요한가

코딩스타일은 실행 결과를 맞히는 문법과 다르게, 같은 목적의 코드를 사람이 읽고 관리하기 쉽게 표현하는 약속이다. quantity라는 이름을 count보다 언제나 우월하다고 할 수는 없다. 이 주문에서는 무엇의 개수인지 바로 드러나므로 수량이라는 역할을 읽기 좋다.

| 판단 | 질문 | 예 |
| --- | --- | --- |
| 이름 | 무엇을 담는지 알 수 있나? | order_total, quantity |
| 함수 경계 | 한 작업을 설명할 수 있나? | 한 줄을 주문 자료로 변환 |
| 반환 | 호출한 곳이 결과를 재사용하나? | return한 주문을 누적 |
| 출력 | 화면 표시를 어디서 하나? | 마지막 처리 결과 출력 |
| 검사 | 어떤 입력까지 처리하나? | 칸 수·정수·범위 |
| 주석 | 코드 반복 대신 이유를 주나? | 가격 칸에만 원 제거 |

짧은 함수라도 이름과 인자·반환값을 읽어야 한다. 아래 parse_order는 한 줄 문자열을 받아 정상 주문 목록 또는 None을 반환한다. collect_orders는 여러 줄을 순회하고 목록·합계 튜플을 반환한다. 반환값 None은 이 예제에서 제외할 행을 나타내기로 정한 약속이며 Python이 모든 오류를 None으로 바꿔 주는 것은 아니다.

> 📚 **출처 · 본문 설명 확인:** [Python 함수 정의](https://docs.python.org/ko/3/tutorial/controlflow.html#defining-functions). 실제 배운 문법의 의미를 확인한 근거다. 예제·표·풀이 자체는 수업 자료를 바탕으로 새로 구성했다. 외부 문장을 직접 인용하지 않았다. 이번 문법 확인 기간: 2026-10-28~29.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 전체 코드.** [실행 파일](실습/책형_복습/19_Python_실무_코딩스타일.py)을 제공한다. Python이 설치된 환경에서 새 .py 파일로 저장해 실행한다. 터미널은 그 파일이 있는 폴더에서 열고 `python 파일이름.py`를 실행한다. VS Code의 Python 실행 기능을 사용해도 된다. 결과는 터미널에 표시된다.



```python
def parse_order(line):
    parts = [part.strip() for part in line.split(',')]
    if len(parts) != 3:
        return None
    try:
        quantity = int(parts[1])
        price = int(parts[2].replace('원', ''))
    except ValueError:
        return None
    if quantity < 0 or price < 0 or price > 10000:
        return None
    return [parts[0], quantity, price]

def collect_orders(lines):
    accepted = []
    sales = 0
    for line in lines:
        order = parse_order(line)
        if order is None:
            continue
        accepted.append(order)
        sales += order[1] * order[2]
    return accepted, sales

rows = [' 사과 , 2, 3000원', '배, -1, 4000원', '귤, 3, 2000원']
orders, total = collect_orders(rows)
print(orders)
print(total)
```

collect_orders가 첫 줄을 parse_order에 넘기면 사과·2·3000의 목록이 돌아온다. 이를 accepted에 넣고 6000을 더한다. 배는 범위 검사에서 None을 반환하므로 continue로 건너뛴다. 귤을 처리한 뒤 두 결과를 튜플로 돌려주고 바깥에서 orders·total에 나눠 받는다. 함수 안에서는 출력하지 않아 계산 결과를 다른 코드에서도 사용할 수 있다. 원본 과제를 새 함수로 재구성한 개선 예제이며 당시 코드가 아니다.

**예상 출력 또는 관찰:**

```text
[['사과', 2, 3000], ['귤', 3, 2000]]
12000
```

## 5. 선언·호출·파일이 연결되는 흐름

rows → collect_orders(lines) → 각 line을 parse_order(line)로 전달 → 목록/None 반환 → 유효 목록과 매출 누적 → (accepted, sales) 반환 → 튜플 언패킹 → 출력이다. 외부 파일 import는 없다. 파일 입력을 붙일 때에는 읽은 문자열 목록을 전달하는 부분부터 연결하고 계산 함수를 다시 쓸 수 있다.

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 원본은 조건을 주석으로 남기고 출력 위치를 반복 밖에 두어 중간 처리와 결과 표시를 나눴다. **이름 개선:** delBlank·delOne은 제거 작업을 표현하지만 결과에 무엇이 담겼는지 바로 보이지 않을 수 있다. parts·quantity·price처럼 다음 계산에서 맡는 역할을 드러낼 수 있다.

**판단할 점:** 작은 수업 예제에서 함수가 많아지면 정의를 오가는 부담도 있다. 한 번만 쓰는 두 줄을 무조건 함수로 만드는 규칙은 아니다. 반복해서 확인할 한 줄 해석과 전체 누적을 나누는 이 예제에서는 각 책임을 독립적으로 읽기 쉽다.

**동작 변경과 구별:** 이름·공백만 바꾸는 것과 칸 수·정수 오류를 처리하는 것은 다르다. 새 예제의 잘못된 행 제외는 기능 보완이다. 제외 사유를 반환하지 않는 현재 단순화도 한계로 남는다.

개선안은 D 드라이브 원본을 수정한 결과가 아니다. 실제 오류·수업용 단순화·목적에 따른 선택을 구별한다.

## 7. 강사님 코드가 도움이 되는 비교



강사님 함수 수업도 반환값을 계산에 연결한다. 같은 print·return을 재인용하기보다 내 코드에서 그 차이를 짚었다. 주문 평가의 직접 대응 강사님 정답은 없으므로 이 함수 구조가 강사님 구현이라고 소개하지 않는다.

## 8. 결과를 추적하고 한 가지 바꾸기

| 호출 | 입력 | 반환 | 다음 처리 |
| --- | --- | --- | --- |
| parse_order | 사과 한 줄 | [사과,2,3000] | 저장·6000 누적 |
| parse_order | 배 음수 수량 | None | 다음 줄 |
| parse_order | 귤 한 줄 | [귤,3,2000] | 저장·6000 누적 |
| collect_orders | 세 줄 | 목록과 12000 | 나눠 받아 출력 |

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| rows를 빈 목록으로 | 빈 주문·0원 | 누적 초기값 유지 |
| 배 수량을 1로 | 배도 유지·합계 16000 | 조건 통과 |
| parse_order의 정상 return을 print로 | 호출 결과 None | 계산 결과 전달이 끊김 |
| quantity 이름만 일관되게 변경 | 출력 동일 | 이름 변경 |

NoneType 관련 오류면 반환이 빠진 경로를 본다. 함수 안에서 print가 나왔다고 호출한 곳에 값이 전달됐다고 판단하지 않는다. 이름을 바꿀 때 정의만 바꾸고 사용 부분을 남기지 않았는지 확인한다. 예외를 전부 숨기기보다 숫자 변환처럼 실패가 예상되는 작은 범위에서 처리한다.

## 9. 추가로 알면 좋은 것과 출처
