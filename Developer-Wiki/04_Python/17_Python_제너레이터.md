## 1. 이 장에서 배울 것

리스트 컴프리헨션과 제너레이터 표현식의 괄호·결과를 구분한다. list로 감싸면 최종 리스트가 만들어지는 순서를 설명한다. 제너레이터가 언제나 더 빠르다는 식으로 일반화하지 않는다.

실제 원본·새 예제·개선안·선택 학습을 구분하고 입력·실행 순서·반환값·출력을 연결한다.

<a id="concepts"></a>

## 2. 무엇이며, 왜 필요한가

[식 for ...]은 결과를 리스트로 만든다. (식 for ...)은 제너레이터 표현식이며, 필요한 다음 값을 차례로 계산하게 한다. 둘 다 반복과 조건을 짧게 표현할 수 있지만 결과 객체의 종류와 값을 준비하는 시점은 다르다.

| 코드 모양 | 만든 것 | 결과 읽기 |
| --- | --- | --- |
| [i for i in range(4)] | 리스트 | 요소들을 반복해서 읽을 수 있음 |
| (i for i in range(4)) | 제너레이터 | 다음 값을 차례로 소비 |
| list(i for i in range(4)) | 제너레이터를 소비한 리스트 | 최종적으로 리스트 확보 |

내 원본은 마지막 형태를 썼다. 중간 제너레이터를 쓰더라도 list로 감싸면 최종 항목은 모두 리스트에 담는다. 따라서 이 한 줄을 보고 메모리를 쓰지 않는다고 설명하면 틀린다. 값을 한 번씩 생산하는 구조가 어떤 의미인지 이해하는 것이 이번 범위다.

> 📚 **출처 · 본문 설명 확인:** [Python 자습서 · 제너레이터 표현식](https://docs.python.org/ko/3/tutorial/classes.html#generator-expressions). 실제 배운 문법의 의미를 확인한 근거다. 예제·표·풀이 자체는 수업 자료를 바탕으로 새로 구성했다. 외부 문장을 직접 인용하지 않았다. 이번 문법 확인 기간: 2026-10-28~29.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 전체 코드.** [실행 파일](실습/책형_복습/17_Python_제너레이터.py)을 제공한다. Python이 설치된 환경에서 새 .py 파일로 저장해 실행한다. 터미널은 그 파일이 있는 폴더에서 열고 `python 파일이름.py`를 실행한다. VS Code의 Python 실행 기능을 사용해도 된다. 결과는 터미널에 표시된다.



```python
numbers = (i for i in range(6) if i % 2 == 0)
first = list(numbers)
second = list(numbers)
print(first)
print(second)
print([i for i in range(6) if i % 2 == 0])
```

numbers에 제너레이터를 연결한 뒤 첫 list가 짝수 값을 끝까지 소비한다. 같은 numbers를 두 번째 list에 넘기면 남은 값이 없으므로 빈 리스트다. 마지막 줄은 새로운 리스트 컴프리헨션을 계산하므로 [0, 2, 4]가 된다. 첫 리스트가 빈 것으로 바뀐 것은 아니다. “자료를 다시 사용한다”와 “소진된 생산 과정을 다시 요청한다”를 구분한다.

**예상 출력 또는 관찰:**

```text
[0, 2, 4]
[]
[0, 2, 4]
```

## 5. 선언·호출·파일이 연결되는 흐름

원본 list(표현식) → 범위의 값을 조건으로 고름 → 통과한 값을 list가 모음 → a에 결과 리스트 연결 → print(a) 순서다. DB의 yield session은 자원을 사용하는 함수 흐름에 속하므로 [FastAPI 목차](../06_FastAPI/README.md)에서 실제 세션 정의와 호출 구조를 함께 복습한다.

<a id="review"></a>

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 짝수 목록을 반복문 외의 표현으로도 작성했다. **설명 보완:** list로 감싼 최종 결과는 리스트임을 말해야 한다. **주의:** 소진된 제너레이터를 다시 읽으면 원래 값이 자동 재생된다고 기대하지 않는다. **범위:** 메모의 코루틴 중요도 평가는 보편적 실무 결론이 아니므로 이 장의 학습 목표로 사용하지 않는다.

개선안은 D 드라이브 원본을 수정한 결과가 아니다. 실제 오류·수업용 단순화·목적에 따른 선택을 구별한다.

## 8. 결과를 추적하고 한 가지 바꾸기

| 단계 | numbers | first | second |
| --- | --- | --- | --- |
| 생성 | 아직 소비 전 | 없음 | 없음 |
| 첫 list 후 | 소진 | [0, 2, 4] | 없음 |
| 두 번째 list 후 | 소진 | [0, 2, 4] | [] |

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| 조건을 홀수로 | [1, 3, 5] | 조건 변경 |
| second에 새 표현식 전달 | 다시 세 값 | 새 제너레이터 생성 |
| numbers를 리스트로 생성 | 두 list에 같은 값 | 기존 리스트 재순회 |

두 번째 결과가 비면 원래 리스트가 변한 것인지 제너레이터가 소진된 것인지 본다. 괄호만 보고 함수 호출로 판단하지 말고 안에 for 표현식이 있는지 읽는다. 성능·메모리는 데이터 크기와 최종 소비 방식도 함께 고려해야 한다.

## 9. 추가로 알면 좋은 것과 출처

TIP은 기본 문제의 필수 조건이 아니다. 배운 문법을 확인한 📚 출처와 선택 확장을 구별한다.
