## 1. 이 장에서 배울 것

if·elif·else와 들여쓰기·pass를 설명한다. 빈 값의 진리값, 범위와 평균 검사 순서, match의 간단 상수 패턴, 한 줄 조건식을 실제 출력과 연결한다.

실제 원본·새 예제·개선안·선택 학습을 구분하고 입력·실행 순서·반환값·출력을 연결한다.

<a id="concepts"></a>

## 2. 무엇이며, 왜 필요한가

조건문은 조건이 참일 때 실행할 블록을 고른다. 블록은 콜론 뒤 들여쓰기로 표시한다. if·elif·else 연결에서는 먼저 참이 된 한 갈래를 실행하고 나머지는 건너뛴다. 독립 if를 여러 개 쓰는 것과 다르다.

| 구성 | 역할 | 읽는 질문 |
| --- | --- | --- |
| if | 첫 조건 검사 | 지금 참인가? |
| elif | 앞이 거짓이면 다음 검사 | 앞에서 선택되지 않았나? |
| else | 아무 조건도 맞지 않을 때 | 나머지 경우인가? |
| 중첩 if | 선택한 갈래 안의 추가 조건 | 바깥 조건을 먼저 통과했나? |
| pass | 문법상 블록을 채우되 아무 일 없음 | 아직 넣을 동작이 없나? |

False·None·숫자 0·빈 문자열과 컨테이너는 조건에서 거짓으로 평가된다. [] 자체가 boolean False로 바뀌어 저장되는 것은 아니다. 조건에서 어떻게 해석하는지와 값의 자료형은 구분한다.

검사 순서는 결과를 바꾼다. 네 점수를 쓰는 코드라면 먼저 항목 개수가 맞는지, 그 다음 숫자로 읽을 수 있는지, 범위가 맞는지, 그 다음 평균 기준을 통과하는지 질문을 나눌 수 있다. 원본은 이 중 일부만 구현했다. 아래 새 예제는 개수 검사를 앞에 두지만 숫자 형식 전체 검증까지 넣지는 않는다.

> 📚 **출처 · 본문 설명 확인:** [Python if·match 입문](https://docs.python.org/ko/3/tutorial/controlflow.html), [진리값 검사](https://docs.python.org/ko/3/library/stdtypes.html#truth-value-testing). 실제 배운 문법의 의미를 확인한 근거다. 예제·표·풀이 자체는 수업 자료를 바탕으로 새로 구성했다. 외부 문장을 직접 인용하지 않았다. 이번 문법 확인 기간: 2026-10-28~29.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 전체 코드.** [실행 파일](실습/책형_복습/08_Python_조건문.py)을 제공한다. Python 3.10 이상에서 새 .py 파일로 실행한다. 이 예제의 match 문법에 필요한 조건이다. 터미널에서 `python --version`으로 현재 버전을 확인할 수 있다. 아래 값들은 실행 흐름을 예측하도록 코드에 고정해 둔 설명용 입력이다.



```python
text = '90 80 70 80'
parts = text.split()
if len(parts) != 4:
    print('점수 개수 확인')
else:
    a, b, c, d = int(parts[0]), int(parts[1]), int(parts[2]), int(parts[3])
    if 0 <= a <= 100 and 0 <= b <= 100 and 0 <= c <= 100 and 0 <= d <= 100:
        average = (a + b + c + d) / 4
        if average >= 80:
            print('합격', average)
        else:
            print('불합격', average)
    else:
        print('점수 범위 확인')
button = 2
if button == 1:
    print('콜라')
elif button == 2:
    print('사이다')
else:
    print('다른 번호')
month = 7
match month:
    case 6 | 7 | 8:
        print('여름')
    case _:
        print('다른 계절')
print('있음' if parts else '없음')
```

네 문자열을 숫자로 바꾼 뒤 범위를 통과하여 평균 80.0을 구한다. 기준을 >=80으로 정했으므로 합격이다. button=2는 사이다 한 갈래만 실행한다. 새 예제는 month라는 의미를 부여하여 7을 여름으로 표현했다. 원본의 a=7과 출력 문구 차이는 아래 비교에서 별도로 다룬다. 마지막 조건식은 parts가 비어 있지 않아 있음이라는 값을 반환하여 print에 넘긴다.

**예상 출력 또는 관찰:**

```text
합격 80.0
사이다
여름
있음
```

### 내 코드 — 원본 발췌

```python

# match , case문 / break 필요 없고 default 대신 case _ : 를 씀
# ~또는(or) 는 |로 구분해서 써줘야 함
# a = '여름' 
a = 7 
match a :
    case 6 | 7 | 8 :
        print('봄')
    case '여름' :
        print('여름')
    case _ :
        print('그 외')

# 값이 3 > 2 이면 3 출력, 아니라면 2 출력
print( 3 if 3 > 2 else 2)
```

**발췌 바로 풀이:** `match a`에서 `case 6 | 7 | 8`의 `|`는 **여러 패턴 중 하나**를 뜻한다. `a=7`이라 첫 번째 `case`가 실행된다. 강사님 파일은 `여름`, 내 파일은 `봄`을 출력하도록 써 두었으므로 두 코드의 **출력 문자열은 다르다**. 어느 계절이 맞는지는 이 숫자 범위만으로 결정되지 않는다. `case _`는 앞의 어느 패턴에도 맞지 않을 때 실행되는 자리다. 이 예제의 `match`에는 `break`가 필요하지 않다.

내 처음 주석의 들여쓰기 오류 예시는 주석이어서 현재 실행 오류가 아니다. 점수 부분은 네 번 따로 받는 초안이 여러 줄 문자열 안에 있고, 실제 활성 코드는 공백 구분 입력이다. 양쪽은 개수와 형식 확인 전에 scores[0]~[3]을 int로 바꾸어 평균을 구한다. 값 세 개나 숫자가 아닌 입력은 범위 안내 이전에 오류가 난다. split 한 칸과 split()의 연속 공백 처리 차이도 입력 조건에 영향을 준다.

## 5. 선언·호출·파일이 연결되는 흐름

입력 → split 결과 목록 → 각 위치 조회·int → 합계·평균 → 네 범위 검사 → 평균 분기 → 출력 순서가 원본이다. 새 예제는 개수 검사만 앞에 옮긴 별도 개선이다. 일반 함수 정의는 없고 input·int·print의 반환과 호출을 사용한다. 원본 sum이라는 변수 이름은 내장 sum 이름을 가리므로 새 예제는 average와 개별 값처럼 역할을 드러내는 이름을 사용한다.

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 내 점수 코드는 네 범위를 and로 묶고 범위 통과 뒤 합격 기준을 나눴다. **공통 한계:** 개수·숫자 형식 오류까지 잘못된 입력 갈래가 처리하지 않는다. **설명 교정:** 설명 문자열 속 초안을 활성 코드처럼 실행하지 않는다. **개선:** 개수부터 확인하고, 형식 오류의 상세 처리는 뒤 예외 장과 연결한다. match를 고급 구조 분해 전체로 확장하지 않고 실제 상수 선택부터 읽는다.

개선안은 D 드라이브 원본을 수정한 결과가 아니다. 실제 오류·수업용 단순화·목적에 따른 선택을 구별한다.

## 7. 강사님 코드가 도움이 되는 비교



양쪽 메뉴 선택 규칙은 같고 안내 문구가 다르므로 중복 인용하지 않는다. a=7의 case 6|7|8은 양쪽 모두 첫 갈래를 선택하지만 강사님은 여름, 나는 봄을 출력한다. 단순 패턴 실험의 출력 문구와 달력 의미를 부여한 새 예제를 구별한다. 월별 계절 판정 의도라면 7월과 문구가 맞는지도 요구사항에 따라 평가해야 한다.

| 입력·상태 | 원본에서 먼저 일어나는 것 | 결과 |

| 점수 네 개·범위 정상·평균 80 | 숫자 변환·평균 후 검사 | 합격 |
| 점수 세 개 | 네 번째 위치 조회 | 범위 안내 전 IndexError |

| 빈 a 리스트 | if a 검사 | 거짓 갈래 |

한 줄 조건식은 값1 if 조건 else 값2이며 선택된 값만 평가한다. 여러 조건을 한 줄에 겹치면 읽기 어려울 수 있으므로 새 예제에서는 단순한 한 단계만 사용했다. pass는 반복 중단이나 함수 반환을 대신하지 않는다.

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| 점수 하나를 79로 내려 평균 80 미만 만들기 | 불합격 | 평균 조건 변경 |
| 네 값 중 하나를 101로 | 범위 안내 | 평균 합격보다 범위가 먼저 |
| 점수를 세 개로 변경 | 새 예제는 개수 안내 | 개선한 검사 순서 |
| button을 9로 | 다른 번호 | 어떤 앞 갈래도 안 맞음 |

원하지 않은 줄까지 실행되면 들여쓰기 범위를 본다. 입력 안내가 아니라 예외가 나면 안내 조건에 도달하기 전 계산을 확인한다. 공백 여러 칸 문제는 split 인수를 본다. match 문법 오류는 먼저 Python 버전 조건을 확인한다.
