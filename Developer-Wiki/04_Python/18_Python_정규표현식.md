## 1. 이 장에서 배울 것

문자열을 고정 구분자로 나누는 것과 규칙으로 나누는 차이를 설명한다. 현재 원본 패턴이 적용되는 입력·적용되지 않는 입력을 작은 문자열로 확인한다.

실제 원본·새 예제·개선안·선택 학습을 구분하고 입력·실행 순서·반환값·출력을 연결한다.

<a id="concepts"></a>

## 2. 무엇이며, 왜 필요한가

정규표현식은 찾고 싶은 문자열의 형태를 규칙으로 적는 방법이다. Python에서는 표준 모듈 re를 사용한다. split은 문자열 메서드에도 있고 re 모듈에도 있다. 이름만 같다고 두 구분자 인자를 같은 뜻으로 해석하면 안 된다.

| 사용 | 구분 기준 | 이 장의 예 |
| --- | --- | --- |
| text.split('.') | 마침표 글자 자체 | 그 글자는 결과에서 빠짐 |
| re.split(패턴, text) | 패턴에 맞는 부분 | 원본은 문장부호 뒤 공백 |
| text.strip() | 문자열 앞뒤 공백 제거 | 문장 내부 구분과 별개 |

현재 패턴 r"(?<=[.!?])\s+"는 바로 앞이 마침표·느낌표·물음표인 공백 묶음을 구분자로 삼는다. 그래서 문장부호는 결과에 남는다. 상세 패턴을 스스로 설계하는 수업으로 넓히지 않고 이 한 사용의 효과와 한계를 읽는다. 문장 의미를 이해하는 언어 분석기가 아니므로 모든 문장 경계를 정확히 찾지는 않는다.

> 📚 **출처 · 본문 설명 확인:** [Python 정규표현식 HOWTO](https://docs.python.org/ko/3/howto/regex.html), [re.split](https://docs.python.org/ko/3/library/re.html#re.split). 실제 배운 문법의 의미를 확인한 근거다. 예제·표·풀이 자체는 수업 자료를 바탕으로 새로 구성했다. 외부 문장을 직접 인용하지 않았다. 이번 문법 확인 기간: 2026-10-28~29.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 전체 코드.** [실행 파일](실습/책형_복습/18_Python_정규표현식.py)을 제공한다. Python이 설치된 환경에서 새 .py 파일로 저장해 실행한다. 터미널은 그 파일이 있는 폴더에서 열고 `python 파일이름.py`를 실행한다. VS Code의 Python 실행 기능을 사용해도 된다. 결과는 터미널에 표시된다.



```python
import re
text = ' 고양이입니다.  반갑습니다! 다음입니다? 끝 '
sentences = re.split(r'(?<=[.!?])\s+', text.strip())
print(sentences)
print(re.split(r'(?<=[.!?])\s+', '하나.둘'))
```

먼저 strip이 전체 앞뒤 공백을 없앤다. re.split은 문장부호 뒤의 두 칸·한 칸 공백을 찾아 나눈다. 둘째 문자열은 마침표 뒤 공백이 없으므로 그대로 한 항목이다. 원본 패턴의 작은 동작만 검증하며 Elasticsearch·AI 서비스는 호출하지 않는다.

**예상 출력 또는 관찰:**

```text
['고양이입니다.', '반갑습니다!', '다음입니다?', '끝']
['하나.둘']
```

```python
def split_text(text):
    # print('text : ', text)
    sentences = re.split(
        r"(?<=[.!?])\s+",   # . ! ? 다음에 공백(\s+)이 있으면 분리하는 정규표현식
        text.strip()        # 문자의 앞/뒤 공백 제거한 것을 대상으로
    )
    # print('sentences : ', sentences)
    # return sentences

    # 혹시 몰라서 각 리스트 요소의 양쪽 공백 제거
    sentences2 = []
    for s in sentences :
        if s.strip(): # 공백 제거 후에도 글이 있으면
            sentences2.append(s.strip()) # 그 글로 리스트에 추가

    sentences = sentences2
```

**발췌 바로 풀이:** 실제 split_text 정의의 앞부분이다. 분리한 항목마다 strip하고 빈 항목을 제외한다. 함수의 뒤쪽 청크 묶기와 최종 반환은 이 발췌에 포함되지 않으며 아래 연결에서 해당 본문으로 이어 본다.

메모만 있던 주제가 이후 07_elastic의 split_text에서 실제로 사용됐다. 원본 함수 전체는 문장을 청크로 묶는 작업까지 이어진다. re.split 한 줄의 결과를 함수 전체의 최종 반환값과 혼동하지 않는다. 여기서 새로 추가한 둘째 입력은 적용 한계를 확인하기 위한 실험이다.

## 5. 선언·호출·파일이 연결되는 흐름

라우터 split(text) → split_text(text) 호출 → re.split 결과 sentences → 공백·빈 항목 정리 → 뒤쪽 청크 조합 → 최종 목록 반환이다. 함수 뒤쪽까지는 [영화 CSV·청크와 임베딩](../09_영화CSV_청크와_임베딩/README.md)의 전체 흐름에서 이어 본다. 이 장은 외부 import된 AI 함수의 동작을 대신 설명한 것이 아니라 로컬 문자열 분리만 떼어 확인한 것이다.

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 분리 뒤 빈 문장을 제외해 다음 청크 계산의 재료를 정리했다. **한계:** 문장부호 다음 공백이 있어야 하며 약어·소수점·줄바꿈의 문맥을 이해하지 않는다. **설계 선택:** 복잡한 의미 분석 대신 간단 규칙을 쓰는 실습용 선택이다. 같은 문자열 처리를 무조건 정규식으로 바꿔야 한다는 뜻은 아니다.

개선안은 D 드라이브 원본을 수정한 결과가 아니다. 실제 오류·수업용 단순화·목적에 따른 선택을 구별한다.

## 8. 결과를 추적하고 한 가지 바꾸기

| 입력 | 구분하는 부분 | 결과의 특징 |
| --- | --- | --- |
| 하나. 둘 | 마침표 뒤 공백 | 하나. / 둘 |
| 하나! 둘 | 느낌표 뒤 공백 | 하나! / 둘 |
| 하나.둘 | 없음 | 한 항목 |
| 앞뒤 공백 | 먼저 strip | 바깥 공백 제거 |

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| 문장부호 뒤 공백 제거 | 그 경계에서 안 나눔 | 공백 조건 불충족 |
| 공백을 여러 개로 | 여전히 나눔 | 공백 묶음 |
| 마침표를 쉼표로 | 그 경계에서 안 나눔 | 지정 부호에 없음 |

분리되지 않으면 문장부호 뒤 공백이 있는지 본다. 문자열 split과 re.split을 바꿔 썼다면 인자의 의미부터 다시 확인한다. import re를 빠뜨리면 이름 오류가 난다. 같은 결과가 나왔다고 모든 문장 입력에서도 같은 정확도를 낸다고 판단하지 않는다.
