## 1. 분류 기준

현재 양쪽 수업 소스와 사용자 확인을 우선한다. BACKUP은 “무엇인가·어떻게 쓰나”를 풀어 설명하는 방식과 좋은 문제 구성을 참고한다. 그곳에만 등장하는 새 기능은 실제로 배운 내용의 증거가 아니다. 같은 주제 이름이 있어도 상세 구현까지 배웠다고 확대하지 않는다.

## 2. 포함한 범위

| 수준 | 내용 | 위치 |
| --- | --- | --- |
| 수업 구현 | 출력·자료형·문자열·조건·반복·파일·함수·클래스·상속·예외·모듈 | 각 00–15 본문 |
| 원래 과제 | 자료형 퀴즈·주문 평가 | 실습- 페이지 |
| 개념·간단 사용 | 이터레이터·제너레이터·정규식 | 16–18, 상세 확장은 TIP |
| 새 복습 | 스타일·통합 문제·장별 연습 | 실제 코드와 구분 |

정규식은 메모 외에도 이후 07_elastic의 re.split 사용이 확인된다. 해당 패턴의 작은 결과를 설명하되 상세 문법 전체를 본문으로 승격하지 않는다. DB의 yield 사용도 그 호출 구조에서 읽고 고급 제너레이터 구현과 혼동하지 않는다.

## 3. 추가로 알면 좋은 것

선택 확장은 별도 폴더로 보내지 않고 각 본문 하단의 💡 TIP에 둔다. 사용자 정의 이터레이터·제너레이터 상세 구현, 복잡한 정규식 작성, 깊은 복사·고급 패키지 설계·자동 검사 도구 등이 해당한다. 새 예제에 쓴 개선 동작은 당시 원본과 명시적으로 구분한다.

📚 공식 출처는 배운 문법의 의미를 확인하는 근거이며, 출처가 있다는 이유로 모두 추가 학습인 것은 아니다. 반대로 공식 문서에 나온다고 수업에서 배웠다고 판단하지도 않는다.

## 4. 제외와 이후 첨부

GPT를 이용한 바이브코딩 시험과 개인 CSS 실험, 설치 생성물은 학습 근거에서 제외했다. 실제 작성 소스가 가상환경 폴더 안에 있으면 파일별로 확인한다. 현재 workspace에서 대응 실습을 찾지 못한 개인 메모는 근거를 보류하고 이후 첨부 때 다시 판단한다. D 드라이브 원본은 수정하지 않았다.
