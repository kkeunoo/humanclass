## 1. 이 장에서 배울 것

조건에 맞는 항목 모으기와 숫자 누적을 나눈다. 중첩 딕셔너리의 같은 항목에서 가격·개수를 읽고, 아이디 존재 검사 뒤 해당 비밀번호를 비교하는 이유를 설명한다.

실제 원본·새 예제·개선안·선택 학습을 구분하고 입력·실행 순서·반환값·출력을 연결한다.

<a id="concepts"></a>

## 2. 무엇이며, 왜 필요한가

집계는 여러 항목을 보고 결과를 모으는 작업이다. 목록에 넣는 append와 숫자를 더하는 +=는 다른 결과를 만든다. 짝수 목록이 필요하면 목록을, 홀수 합계가 필요하면 0에서 시작한 누적값을 준비한다.

| 문제 | 반복 대상 | 검사·계산 | 결과 |
| --- | --- | --- | --- |
| 짝수·홀수 | numbers의 각 값 | 2로 나눈 나머지 | 목록·합계 |
| 장바구니 | 각 과일 키 | 그 과일의 가격×개수 | 총액 |
| 계정 비교 | 검사 ID 한 개 | 키 존재 뒤 그 값 비교 | 안내 |

로그인 모양 문제는 “이 비밀번호가 딕셔너리 어디엔가 있는가”가 아니다. 사용자가 말한 ID와 그 ID에 저장한 값이 한 쌍으로 맞아야 한다. 존재 여부를 먼저 보면 없는 키를 []로 읽는 오류도 피할 수 있다. 이 실습은 메모리의 문자열 비교이며 실제 인증 시스템은 아니다.

> 📚 **출처 · 본문 설명 확인:** [Python 딕셔너리·순회](https://docs.python.org/ko/3/tutorial/datastructures.html#dictionaries). 실제 배운 문법의 의미를 확인한 근거다. 예제·표·풀이 자체는 수업 자료를 바탕으로 새로 구성했다. 외부 문장을 직접 인용하지 않았다. 이번 문법 확인 기간: 2026-10-28~29.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 전체 코드.** [실행 파일](실습/책형_복습/실습-01a_Python_자료형_퀴즈_집계와_로그인.py)을 제공한다. Python이 설치된 환경에서 새 .py 파일로 저장해 실행한다. 터미널은 그 파일이 있는 폴더에서 열고 `python 파일이름.py`를 실행한다. VS Code의 Python 실행 기능을 사용해도 된다. 결과는 터미널에 표시된다.



```python
numbers = [3, 7, 10, 15, 22, 8, 13]
even = []
odd_total = 0
for number in numbers:
    if number % 2 == 0:
        even.append(number)
    else:
        odd_total += number
print(even, odd_total)
cart = {'사과': {'가격': 1000, '개수': 3}, '바나나': {'가격': 2000, '개수': 4}}
total = 0
for fruit in cart:
    total += cart[fruit]['가격'] * cart[fruit]['개수']
print('작은 장바구니', total)
users = {'admin': '1234', 'guest': 'guest'}
user = 'guest'
password = '1234'
if user not in users:
    print('아이디 없음')
elif users[user] != password:
    print('그 아이디의 비밀번호와 다름')
else:
    print('일치')
```

홀수 3+7+15+13의 합은 38이다. 새 작은 장바구니는 두 과일만 넣어 3000+8000=11000이다. 아래 원본 네 과일의 25000과 다른 입력 조건이다. guest에 admin의 비밀번호 1234를 넣으면 다른 계정에 존재하더라도 guest의 값과 달라 통과하지 않는다.

**예상 출력 또는 관찰:**

```text
[10, 22, 8] 38
작은 장바구니 11000
그 아이디의 비밀번호와 다름
```

## 4. 내가 작성한 코드를 따라 읽기

아래는 원본 발췌다. 주석의 잘못된 설명도 원문을 보존하고 풀이에서 교정한다. 필요한 선언·호출·다른 파일의 정의는 다음 절까지 연결해 읽는다.

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_python/quiz/01_quiz.py` 8–25행

```python
print('\n문제1','- - '*10)
numbers = [3, 7, 10, 15, 22, 8, 13]
# print(len(numbers))

double = []
single = []
singleResult = 0

for i in range(len(numbers)) :
    if numbers[i] % 2 == 0 :
        double.append(numbers[i])
    else :
        single.append(numbers[i])
        singleResult += numbers[i]

print(f'짝수 : {double}, {type(double)}')
print(f'홀수 : {single}, {type(single)}')
print(f'홀수의 합 : {singleResult}')
```

**발췌 바로 풀이:** 두 코드는 같은 `numbers`에서 짝수 `[10,22,8]`과 홀수 합 **38**을 만든다. 강사님은 먼저 반복문으로 짝수를 담고 그 아래 **리스트 컴프리헨션으로 같은 결과를 다시** 만들었다. 홀수 합도 목록을 만든 뒤 `sum`하거나 반복문으로 누적하는 두 방식을 실행한다. `print(123, sum(odd))`의 `123`은 합계에 더해진 값이 아니라 함께 출력한 별도 숫자다. 내 코드는 `range(len(numbers))`로 위치를 읽어 짝수·홀수 목록을 만들고, 홀수는 `singleResult`에 누적한다. 어느 쪽이든 `% 2`가 짝수·홀수를 나누는 조건이다.

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_python/quiz/01_quiz.py` 50–82행

```python
print('\n문제2','- - '*10)
cart = {
    '사과': {
        '가격': 1000,
        '개수': 3
    },
    '바나나': {
        '가격': 2000,
        '개수': 4
    },
    '복숭아': {
        '가격': 1500,
        '개수': 2
    },
    '키위': {
        '가격': 2200,
        '개수': 5
    }
}

fruitPrice = 0

# for i in cart.keys() 라고 한다면, i에 key값이 모두 저장이 되기 때문에
# 개수와 가격이라는 것은 동일해서 사과,바나나,복숭아,키위만 반복된다면 
# price에 누적으로 저장시키면 됨
for i in cart.keys() :
    fruitPrice += cart[i]['가격'] * cart[i]['개수']
    # fruitPrice += cart['사과']['가격'] * cart['사과']['개수']
    # fruitPrice += cart['바나나']['가격'] * cart['바나나']['개수']
    # fruitPrice += cart['복숭아']['가격'] * cart['복숭아']['개수']
    # fruitPrice += cart['키위']['가격'] * cart['키위']['개수']

print(f'총액 : {fruitPrice}')
```

**발췌 바로 풀이:** 각 과일의 `가격 × 개수`를 더하면 **25,000**이다. 강사님은 `for fruit in cart`로 키를 순회하고, 나는 `for i in cart.keys()`로 같은 키를 순회한다. `cart[i]['가격']`과 `cart[i]['개수']`는 **같은 과일의 안쪽 딕셔너리**에서 읽는다. 내 코드의 과일별 계산 줄들은 주석이라 실제 합계에는 중복 반영되지 않는다. 강사님은 사과·바나나만 별도 변수로도 계산하지만, 전체 합계는 마지막 반복문으로 구한다.

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_python/quiz/01_quiz.py` 149–169행

```python
users = {
    "admin": "1234",
    "guest": "guest",
    "user1": "abcd"
}

logID = str(input('ID를 입력하세요 : '))
logPW = str(input('PW를 입력하세요 : '))

# logID를 쳤을 때 users에 있는 키값이 동일했을 경우 밸류값은 예시로 admin이라고 치면
# 자동적으로 user[logID]의 밸류기 때문에, '1234'라는 value를 받아올 수 있어 그걸로
# 입력받은 PW값과 비교하면 해결 됨
if logID in users.keys() :
    # print(users[logID])
    if logPW == users[logID] :
        print('로그인 성공!')
    else :
        print('비밀번호가 틀렸습니다.')
else :
    print('아이디가 틀렸습니다.')

```

**발췌 바로 풀이:** 둘 다 **검사 대상 아이디가 딕셔너리의 키인지 먼저** 확인하고, 그 아이디의 값인 비밀번호와 검사 대상 비밀번호를 비교한다. 강사님은 `id='admin'`, `pw='1234'`를 변수에 고정하고, 나는 `input()`으로 두 값을 받는다. 내 위쪽의 계정별로 분기하던 긴 시도는 주석이며, 위 발췌가 실제 실행되는 풀이이다. `비밀번호`가 다른 계정에 존재하기만 하면 통과하는 검사가 아니라, **해당 아이디의 비밀번호와 일치해야** 성공한다.

내 첫 문제는 위치를 range로 읽어 짝수·홀수 목록과 홀수 합을 한 번의 반복에 만든다. 과일별 계산 줄의 여러 주석은 실제로 중복 계산하지 않는다. 내 계정 비교는 input으로 받고 강사님은 고정값으로 시험한다. str(input())에서 input은 이미 문자열을 반환하므로 이 실습의 추가 str 변환은 필요하지 않다. 계정별 긴 분기 초안은 주석이며 현재 키 기반 비교가 활성이다.

## 5. 선언·호출·파일이 연결되는 흐름

numbers[i] → 나머지 검사 → 목록 추가 또는 합계 누적이다. cart의 fruit 키 → 안쪽 딕셔너리 → 가격·개수 → 곱셈 → 누적이다. logID 존재 → users[logID] → 입력 logPW와 비교 순서다. 내 함수 정의 없이도 각 변수의 준비·순회·계산·출력 연결을 따라갈 수 있다.

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 내 코드는 홀수 목록과 합을 함께 만들고 계정의 키·값 대응을 먼저 생각했다. **간결화:** 값만 필요하면 for number in numbers로 위치 조회를 줄일 수 있다. **오류와 선택 구분:** keys() 순회도 정상이며 for fruit in cart와 같은 키를 읽는 현재 사용이다. **범위:** 평문 계정 비교 예제를 실제 서비스 비밀번호 저장 방식으로 옮기지 않는다.

개선안은 D 드라이브 원본을 수정한 결과가 아니다. 실제 오류·수업용 단순화·목적에 따른 선택을 구별한다.

## 7. 강사님 코드가 도움이 되는 비교



강사님 컴프리헨션·sum은 같은 결과를 다른 표현으로 보여 준다. print(123,sum(odd))의 123은 합계의 일부가 아니라 별도로 출력한 값이다. 네 과일 총액은 양쪽 25000이며 표현 차이로 틀린 코드라고 평가하지 않는다. 고정 계정 값과 사용자 입력의 확인 범위도 다르다.

## 8. 결과를 추적하고 한 가지 바꾸기

| 원본 과일 | 계산 | 누적 |
| --- | --- | --- |
| 사과 | 1000×3=3000 | 3000 |
| 바나나 | 2000×4=8000 | 11000 |
| 복숭아 | 1500×2=3000 | 14000 |
| 키위 | 2200×5=11000 | 25000 |

홀수 합 38과 짝수 목록 [10,22,8]은 원본에서 확인하는 고정 입력 결과다. 반복 순서를 바꾸면 목록 순서는 달라질 수 있어도 같은 수들의 합계는 같다. 로그인에서는 잘못된 ID의 키 조회보다 존재 검사를 먼저 한다.

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| numbers에 짝수 하나 추가 | 짝수 목록만 증가 | 홀수 합은 그대로 |
| 사과 개수를 1 늘림 | 총액 1000 증가 | 같은 항목의 가격×개수 |
| user를 없는 값으로 | 아이디 없음 | 키 검사 먼저 |
| guest 비밀번호를 guest로 | 일치 | 해당 계정 값과 같음 |

합이 두 배면 누적 초기화와 활성 계산 줄을 확인한다. 가격이 이상하면 같은 과일의 수량인지 본다. 비밀번호가 맞는데 실패하면 어느 ID의 값과 비교하는지 확인한다. 주석의 긴 초안을 실행 경로에 넣지 않는다.
