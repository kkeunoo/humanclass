## 문제 1. 결과와 실행 순서 예상



```python
values = list(range(10))
print(values[1:4])
print(values[1:9:2])
print(values[7:3])
print(values[7:3:-1])
print(values[-4:-2])
print(values[4:100])
piece = values[2:5]
piece[0] = 100
print(values[2], piece)
values[2:5] = [10, 20, 30, 40, 50]
print(values, len(values))
word = '안녕'
encoded = word.encode('utf-8')
print(len(word), len(encoded))
print('hello'[::-1])
ko = ['책', '알약']
en = ['book', 'pill']
view = ko
view = en
print(view[0])
```

<summary>힌트와 풀이</summary>

입력·현재 값·실행 순서·반환값·출력 위치를 따로 표시한다.

```text
[1, 2, 3]
[1, 3, 5, 7]
[]
[7, 6, 5, 4]
[6, 7]
[4, 5, 6, 7, 8, 9]
2 [100, 3, 4]
[0, 1, 10, 20, 30, 40, 50, 5, 6, 7, 8, 9] 12
2 6
olleh
book
```

처음 여섯 출력은 원래 values를 바꾸지 않는 조회다. piece는 슬라이스로 만든 새 바깥 리스트라 그 첫 숫자를 바꿔도 values[2]는 2다. 이어 세 항목 구간에 다섯 항목을 대입하여 길이가 10에서 12가 된다. 안녕은 이 예제의 한글 두 글자이며 UTF-8로 인코딩하면 6바이트다. 마지막 view는 ko 뒤 en으로 다시 대입했으므로 book을 읽는다.

</details>

## 문제 2. 이유를 자신의 말로 설명

1. a[7:3]과 a[7:3:-1]이 다른 이유는?
2. 세 항목 구간을 다섯 항목으로 바꾸면 길이는?
3. view=ko 다음 view=en이면 view[0]은?
4. len(안녕 문자열)과 인코딩 후 길이는 같은 단위인가?

<details>
<summary>풀이</summary>

기본은 앞 방향이고 -1은 뒤 방향이다. 전체 길이는 2 늘어난다. book이다. 문자열 글자 수와 UTF-8 바이트 수로 단위가 다르다.

| 식 | 결과를 만드는 규칙 |
| --- | --- |
| a[4:-1] | 뒤의 마지막 위치는 제외 |
| a[:7] | 처음부터 7 직전 |
| a[5:] | 5부터 끝까지 |
| a[:] | 전체의 새 바깥 리스트 |
| a[-4:8] | 현재 길이 10에서 6부터 8 직전 |

이 표는 길이가 10인 초기값 조건이다. 앞에서 슬라이스 대입으로 길이가 바뀌면 음수 위치가 가리키는 지점도 다시 계산한다. 원본 상태를 바꾸어 놓고 초기 조건의 정답을 그대로 적용하지 않는다. a[::-1]을 출력한 것과 a에 그 결과를 다시 대입한 것도 별개다.

</details>

## 문제 3. 한 가지만 바꾸기

본문의 다음 실험에서 한 행만 골라 결과를 먼저 예상한다. 실행 후 원래 예제로 돌아가 다음 변경을 확인한다.

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| 7:3:-1에서 -1 제거 | 빈 결과 | 앞으로는 끝 조건에 못 감 |
| 구간 대입 항목 수를 3개로 | 길이 유지 | 세 자리 대체 |
| view=en 제거 | 책 | 마지막 연결이 ko |
| 슬라이스 대신 없는 단일 인덱스 조회 | IndexError | 하나의 요소는 없음 |

<details>
<summary>막힐 때 확인할 것</summary>

예상과 다르면 시작·끝·간격을 각각 적고 끝 제외를 확인한다. 음수 인덱스를 계산할 때 현재 길이를 사용한다. 길이가 달라졌으면 앞의 구간 대입을 본다. 문자열 길이 문제는 인코딩 전후 중 무엇을 세는지 확인한다.

</details>
