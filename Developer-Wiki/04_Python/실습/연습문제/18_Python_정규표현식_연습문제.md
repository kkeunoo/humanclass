## 목표와 실행 조건

문자열을 고정 구분자로 나누는 것과 규칙으로 나누는 차이를 설명한다. 현재 원본 패턴이 적용되는 입력·적용되지 않는 입력을 작은 문자열로 확인한다.

[전체 Python 파일](../책형_복습/18_Python_정규표현식.py)을 새 파일로 실행한다. 입력·준비 파일·import 조건은 [본문 3절](../../18_Python_정규표현식.md#example)을 먼저 확인한다. 의도적으로 예외를 관찰하는 예제는 오류 종류와 그 전에 나온 출력도 답에 적는다.

## 문제 1. 결과와 실행 순서 예상



```python
import re
text = ' 고양이입니다.  반갑습니다! 다음입니다? 끝 '
sentences = re.split(r'(?<=[.!?])\s+', text.strip())
print(sentences)
print(re.split(r'(?<=[.!?])\s+', '하나.둘'))
```

<details>
<summary>힌트와 풀이</summary>

입력·현재 값·실행 순서·반환값·출력 위치를 따로 표시한다.

```text
['고양이입니다.', '반갑습니다!', '다음입니다?', '끝']
['하나.둘']
```

먼저 strip이 전체 앞뒤 공백을 없앤다. re.split은 문장부호 뒤의 두 칸·한 칸 공백을 찾아 나눈다. 둘째 문자열은 마침표 뒤 공백이 없으므로 그대로 한 항목이다. 원본 패턴의 작은 동작만 검증하며 Elasticsearch·AI 서비스는 호출하지 않는다.

</details>

## 문제 2. 이유를 자신의 말로 설명

1. 원본 결과에 마침표가 남는 이유는?
2. 하나.둘이 나뉘는가?
3. re는 별도 설치 패키지인가?
4. re.split 결과가 원본 함수의 최종 청크 목록과 언제나 같은가?

<details>
<summary>풀이</summary>

구분 대상이 문장부호 뒤 공백이기 때문이다. 공백이 없어 나뉘지 않는다. 표준 모듈이다. 뒤에서 문장을 다시 조합하므로 같다고 볼 수 없다.

| 입력 | 구분하는 부분 | 결과의 특징 |
| --- | --- | --- |
| 하나. 둘 | 마침표 뒤 공백 | 하나. / 둘 |
| 하나! 둘 | 느낌표 뒤 공백 | 하나! / 둘 |
| 하나.둘 | 없음 | 한 항목 |
| 앞뒤 공백 | 먼저 strip | 바깥 공백 제거 |

</details>

## 문제 3. 한 가지만 바꾸기

본문의 다음 실험에서 한 행만 골라 결과를 먼저 예상한다. 실행 후 원래 예제로 돌아가 다음 변경을 확인한다.

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| 문장부호 뒤 공백 제거 | 그 경계에서 안 나눔 | 공백 조건 불충족 |
| 공백을 여러 개로 | 여전히 나눔 | 공백 묶음 |
| 마침표를 쉼표로 | 그 경계에서 안 나눔 | 지정 부호에 없음 |

<details>
<summary>막힐 때 확인할 것</summary>

분리되지 않으면 문장부호 뒤 공백이 있는지 본다. 문자열 split과 re.split을 바꿔 썼다면 인자의 의미부터 다시 확인한다. import re를 빠뜨리면 이름 오류가 난다. 같은 결과가 나왔다고 모든 문장 입력에서도 같은 정확도를 낸다고 판단하지 않는다.

</details>
