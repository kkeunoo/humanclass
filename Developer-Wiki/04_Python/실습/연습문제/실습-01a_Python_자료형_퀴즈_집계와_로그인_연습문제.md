## 문제 1. 결과와 실행 순서 예상



```python
numbers = [3, 7, 10, 15, 22, 8, 13]
even = []
odd_total = 0
for number in numbers:
    if number % 2 == 0:
        even.append(number)
    else:
        odd_total += number
print(even, odd_total)
cart = {'사과': {'가격': 1000, '개수': 3}, '바나나': {'가격': 2000, '개수': 4}}
total = 0
for fruit in cart:
    total += cart[fruit]['가격'] * cart[fruit]['개수']
print('작은 장바구니', total)
users = {'admin': '1234', 'guest': 'guest'}
user = 'guest'
password = '1234'
if user not in users:
    print('아이디 없음')
elif users[user] != password:
    print('그 아이디의 비밀번호와 다름')
else:
    print('일치')
```

<details>
<summary>힌트와 풀이</summary>

입력·현재 값·실행 순서·반환값·출력 위치를 따로 표시한다.

```text
[10, 22, 8] 38
작은 장바구니 11000
그 아이디의 비밀번호와 다름
```

홀수 3+7+15+13의 합은 38이다. 새 작은 장바구니는 두 과일만 넣어 3000+8000=11000이다. 아래 원본 네 과일의 25000과 다른 입력 조건이다. guest에 admin의 비밀번호 1234를 넣으면 다른 계정에 존재하더라도 guest의 값과 달라 통과하지 않는다.

</details>

## 문제 2. 이유를 자신의 말로 설명

1. 원본 홀수 합과 네 과일 총액은?
2. 다른 ID의 올바른 비밀번호도 통과해야 하는가?
3. 내 keys 순회는 값 순회인가?
4. 작은 새 예제 총액이 다른 이유는?

<details>
<summary>풀이</summary>

38과 25000이다. 해당 ID의 값과 맞아야 한다. 딕셔너리 키를 순회한다. 두 과일로 줄인 별도 입력이라 11000이다.

| 원본 과일 | 계산 | 누적 |
| --- | --- | --- |
| 사과 | 1000×3=3000 | 3000 |
| 바나나 | 2000×4=8000 | 11000 |
| 복숭아 | 1500×2=3000 | 14000 |
| 키위 | 2200×5=11000 | 25000 |

홀수 합 38과 짝수 목록 [10,22,8]은 원본에서 확인하는 고정 입력 결과다. 반복 순서를 바꾸면 목록 순서는 달라질 수 있어도 같은 수들의 합계는 같다. 로그인에서는 잘못된 ID의 키 조회보다 존재 검사를 먼저 한다.

</details>

## 문제 3. 한 가지만 바꾸기

본문의 다음 실험에서 한 행만 골라 결과를 먼저 예상한다. 실행 후 원래 예제로 돌아가 다음 변경을 확인한다.

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| numbers에 짝수 하나 추가 | 짝수 목록만 증가 | 홀수 합은 그대로 |
| 사과 개수를 1 늘림 | 총액 1000 증가 | 같은 항목의 가격×개수 |
| user를 없는 값으로 | 아이디 없음 | 키 검사 먼저 |
| guest 비밀번호를 guest로 | 일치 | 해당 계정 값과 같음 |

<details>
<summary>막힐 때 확인할 것</summary>

합이 두 배면 누적 초기화와 활성 계산 줄을 확인한다. 가격이 이상하면 같은 과일의 수량인지 본다. 비밀번호가 맞는데 실패하면 어느 ID의 값과 비교하는지 확인한다. 주석의 긴 초안을 실행 경로에 넣지 않는다.

</details>
