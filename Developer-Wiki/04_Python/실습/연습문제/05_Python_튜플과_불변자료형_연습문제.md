## 목표와 실행 조건

빈 튜플·한 항목 튜플·여러 항목 튜플을 구분한다. 쉼표와 괄호의 역할, 리스트·튜플 변환이 원래 변수를 바꾸지 않는다는 점, 재대입과 요소 변경의 차이를 설명한다.

[전체 Python 파일](../책형_복습/05_Python_튜플과_불변자료형.py)을 새 파일로 실행한다. 입력·준비 파일·import 조건은 [본문 3절](../../05_Python_튜플과_불변자료형.md#example)을 먼저 확인한다. 의도적으로 예외를 관찰하는 예제는 오류 종류와 그 전에 나온 출력도 답에 적는다.

## 문제 1. 결과와 실행 순서 예상



```python
empty = ()
single_number = (3)
single_tuple = (3,)
point = 10, 20
print(empty, type(empty))
print(single_number, type(single_number))
print(single_tuple, type(single_tuple))
print(point[0], point[1])
values = [1, 2, 3]
converted = tuple(values)
print(converted, type(values))
editable = list(converted)
editable[0] = 100
print(converted, editable)
point = (30, 40)
print(point)
```

<details>
<summary>힌트와 풀이</summary>

입력·현재 값·실행 순서·반환값·출력 위치를 따로 표시한다.

```text
() <class 'tuple'>
3 <class 'int'>
(3,) <class 'tuple'>
10 20
(1, 2, 3) <class 'list'>
(1, 2, 3) [100, 2, 3]
(30, 40)
```

(3)과 (3,)의 type을 나란히 읽는다. values에서 converted를 만들어도 values는 리스트다. 다시 만든 editable 리스트의 첫 항목을 바꿔도 converted의 요소를 대입한 것은 아니다. 마지막 point=(30,40)은 이름을 새 튜플에 연결하는 정상 재대입이며 처음 튜플의 요소를 바꾼 작업이 아니다.

</details>

## 문제 2. 이유를 자신의 말로 설명

1. (3), (3,), ()의 종류는?
2. tuple(e)를 출력하면 e도 튜플인가?
3. point=(30,40)은 기존 요소 수정인가?

<details>
<summary>풀이</summary>

각각 정수·한 항목 튜플·빈 튜플이다. 변환 결과를 대입하지 않았다면 e는 그대로다. point 재대입은 새 값에 이름을 연결하는 작업이다.

| 단계 | 원래 이름 | 새 결과 |
| --- | --- | --- |
| e=[1,2,3] | 리스트 | 아직 없음 |
| tuple(e) | e는 리스트 유지 | (1,2,3) |
| f=(1,2,3) | 튜플 | 아직 없음 |
| list(f) | f는 튜플 유지 | [1,2,3] |

함수의 반환값과 대입을 나누어 읽으면 “변환했으니 원래 변수도 바뀐다”는 오해를 피할 수 있다. 이후 여러 값을 반환하는 함수도 튜플로 묶여 전달되는 문맥과 연결할 수 있지만, 지금은 생성·읽기·변환 결과를 먼저 확인한다.

</details>

## 문제 3. 한 가지만 바꾸기

본문의 다음 실험에서 한 행만 골라 결과를 먼저 예상한다. 실행 후 원래 예제로 돌아가 다음 변경을 확인한다.

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| (3,)에서 쉼표 제거 | 정수 | 묶인 식 |
| point[0]=30을 실행 | TypeError | 튜플 요소 대입 불가 |
| converted를 values에 다시 대입 | values도 새 튜플을 가리킴 | 변환과 재대입을 함께 수행 |

<details>
<summary>막힐 때 확인할 것</summary>

한 항목인데 정수로 나오면 쉼표를 확인한다. 변환 뒤 type이 안 바뀌면 반환값을 저장했는지 본다. 요소 대입 오류를 이름 자체 재사용이 금지된 것으로 확대하지 않는다.

</details>
