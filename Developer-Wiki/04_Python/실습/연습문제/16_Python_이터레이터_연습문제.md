# 16. 이터레이터 — 반복할 때 다음 값을 받는다는 뜻 — 연습문제

[본문](../../16_Python_이터레이터.md) · [문제 목차](README.md)

실제 수업 내용을 바탕으로 **새로 구성한 연습문제**다. 원래 수업 퀴즈·당시 내 풀이와 구별한다. 실행 전 예상 → 이유 설명 → 한 가지 수정 순서로 풀어 본다.

## 목표와 실행 조건

반복할 수 있는 자료와 현재 꺼내는 위치를 가진 객체를 구분한다. 끝까지 읽으면 반복이 끝난다는 뜻을 설명한다. 직접 __iter__·__next__를 구현하는 문제는 필수 학습으로 내지 않는다.

[전체 Python 파일](../책형_복습/16_Python_이터레이터.py)을 새 파일로 실행한다. 입력·준비 파일·import 조건은 [본문 3절](../../16_Python_이터레이터.md#example)을 먼저 확인한다. 의도적으로 예외를 관찰하는 예제는 오류 종류와 그 전에 나온 출력도 답에 적는다.

## 문제 1. 결과와 실행 순서 예상



```python
values = [10, 20]
for value in values:
    print('첫 순회', value)
for value in values:
    print('다시 순회', value)
print('남은 원본', values)
```

<details>
<summary>힌트와 풀이</summary>

입력·현재 값·실행 순서·반환값·출력 위치를 따로 표시한다.

```text
첫 순회 10
첫 순회 20
다시 순회 10
다시 순회 20
남은 원본 [10, 20]
```

첫 for는 10과 20을 얻은 뒤 끝난다. 두 번째 for는 리스트를 새로 순회하므로 다시 10과 20을 읽는다. 리스트에서 요소를 꺼내 읽었다는 말이 pop으로 삭제했다는 뜻은 아니다. 마지막 출력으로 원본이 유지됐음을 확인한다. 이 예제는 for의 동작을 설명하기 위한 새 코드다.

</details>

## 문제 2. 이유를 자신의 말로 설명

1. for로 읽으면 리스트 요소가 삭제되는가?
2. 메모의 종료 예외 이름의 올바른 철자는?
3. 이 장에서 사용자 정의 이터레이터를 구현했는가?

<details>
<summary>풀이</summary>

삭제하지 않는다. StopIteration이다. 구현하지 않았으며 개념과 기존 반복 사용만 연결했다.

| 순서 | 현재 값 | 리스트 자체 |
| --- | --- | --- |
| 첫 순회 1회 | 10 | [10, 20] |
| 첫 순회 2회 | 20 | [10, 20] |
| 첫 순회 끝 | 더 없음 | [10, 20] |
| 다음 for 시작 | 다시 10 | [10, 20] |

</details>

## 문제 3. 한 가지만 바꾸기

본문의 다음 실험에서 한 행만 골라 결과를 먼저 예상한다. 실행 후 원래 예제로 돌아가 다음 변경을 확인한다.

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| 빈 리스트로 | 순회 본문 출력 없음 | 얻을 값 없음 |
| 30 추가 | 두 순회 모두 한 줄 증가 | 자료에 요소 추가 |
| 첫 순회에 break | 첫 순회만 일찍 종료 | 두 번째 for는 별개 |

<details>
<summary>막힐 때 확인할 것</summary>

반복 횟수와 목록 길이가 다르면 break·continue·조건을 먼저 본다. 반복 가능한 대상이라고 모두 인덱스로 읽을 수 있다고 추측하지 않는다. 상세 메서드 구현을 몰라 for를 사용할 수 없는 것은 아니다.

</details>

## 채점과 복습
