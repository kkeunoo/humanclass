## 목표와 실행 조건

리스트 컴프리헨션과 제너레이터 표현식의 괄호·결과를 구분한다. list로 감싸면 최종 리스트가 만들어지는 순서를 설명한다. 제너레이터가 언제나 더 빠르다는 식으로 일반화하지 않는다.

[전체 Python 파일](../책형_복습/17_Python_제너레이터.py)을 새 파일로 실행한다. 입력·준비 파일·import 조건은 [본문 3절](../../17_Python_제너레이터.md#example)을 먼저 확인한다. 의도적으로 예외를 관찰하는 예제는 오류 종류와 그 전에 나온 출력도 답에 적는다.

## 문제 1. 결과와 실행 순서 예상



```python
numbers = (i for i in range(6) if i % 2 == 0)
first = list(numbers)
second = list(numbers)
print(first)
print(second)
print([i for i in range(6) if i % 2 == 0])
```

<details>
<summary>힌트와 풀이</summary>

입력·현재 값·실행 순서·반환값·출력 위치를 따로 표시한다.

```text
[0, 2, 4]
[]
[0, 2, 4]
```

numbers에 제너레이터를 연결한 뒤 첫 list가 짝수 값을 끝까지 소비한다. 같은 numbers를 두 번째 list에 넘기면 남은 값이 없으므로 빈 리스트다. 마지막 줄은 새로운 리스트 컴프리헨션을 계산하므로 [0, 2, 4]가 된다. 첫 리스트가 빈 것으로 바뀐 것은 아니다. “자료를 다시 사용한다”와 “소진된 생산 과정을 다시 요청한다”를 구분한다.

</details>

## 문제 2. 이유를 자신의 말로 설명

1. 원본 list(...)의 최종 자료형은?
2. 같은 제너레이터의 두 번째 list가 빈 이유는?
3. 괄호를 대괄호로 바꾸면 무엇을 만드는가?

<details>
<summary>풀이</summary>

리스트다. 첫 소비에서 끝까지 읽었기 때문이다. 리스트 컴프리헨션이 되어 처음부터 리스트를 만든다.

| 단계 | numbers | first | second |
| --- | --- | --- | --- |
| 생성 | 아직 소비 전 | 없음 | 없음 |
| 첫 list 후 | 소진 | [0, 2, 4] | 없음 |
| 두 번째 list 후 | 소진 | [0, 2, 4] | [] |

</details>

## 문제 3. 한 가지만 바꾸기

본문의 다음 실험에서 한 행만 골라 결과를 먼저 예상한다. 실행 후 원래 예제로 돌아가 다음 변경을 확인한다.

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| 조건을 홀수로 | [1, 3, 5] | 조건 변경 |
| second에 새 표현식 전달 | 다시 세 값 | 새 제너레이터 생성 |
| numbers를 리스트로 생성 | 두 list에 같은 값 | 기존 리스트 재순회 |

<details>
<summary>막힐 때 확인할 것</summary>

두 번째 결과가 비면 원래 리스트가 변한 것인지 제너레이터가 소진된 것인지 본다. 괄호만 보고 함수 호출로 판단하지 말고 안에 for 표현식이 있는지 읽는다. 성능·메모리는 데이터 크기와 최종 소비 방식도 함께 고려해야 한다.

</details>
