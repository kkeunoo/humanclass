## 목표와 실행 조건

while의 반복 전 검사와 상태 변경을 추적한다. 조건 종료·break·while의 else 차이를 설명한다. 난수 결과를 고정 횟수로 외우지 않고 실제 활성 코드와 주석 속 시도를 구별한다.

[전체 Python 파일](../책형_복습/09-02_Python_while과_반복제어.py)을 새 파일로 실행한다. 입력·준비 파일·import 조건은 [본문 3절](../../09-02_Python_while과_반복제어.md#example)을 먼저 확인한다. 의도적으로 예외를 관찰하는 예제는 오류 종류와 그 전에 나온 출력도 답에 적는다.

## 문제 1. 결과와 실행 순서 예상



```python
rolls = [1, 5, 3]  # 실제 난수가 아닌 설명용 뽑기 순서
count = 0
dice = 0
while dice != 3:
    dice = rolls[count]
    count += 1
    print('뽑기', count, dice)
print('끝', count)
for target in [2, 20]:
    index = 0
    while index < 4:
        if index == target:
            print('찾음', target)
            break
        index += 1
    else:
        print('못찾음', target)
```

<details>
<summary>힌트와 풀이</summary>

입력·현재 값·실행 순서·반환값·출력 위치를 따로 표시한다.

```text
뽑기 1 1
뽑기 2 5
뽑기 3 3
끝 3
찾음 2
못찾음 20
```

처음 dice=0이라 본문에 들어가 첫 가상 값 1을 받는다. 다음 5, 다음 3을 받고 각각 count를 늘린다. 3을 출력한 뒤 다시 조건을 검사해 거짓이면 종료한다. 이 순서는 실제 난수 발생을 재현한 것이 아니라 흐름을 예측하기 위한 고정 목록이다. 뒤의 검색은 target=2에서 break하여 else를 건너뛰고, 20은 0~3 범위에 없어 조건 종료 뒤 못찾음을 출력한다.

</details>

## 문제 2. 이유를 자신의 말로 설명

1. 본문에서 3을 받으면 언제 조건을 다시 검사하는가?
2. break로 나가도 while else가 실행되는가?
3. 실제 주사위 횟수가 매번 3으로 고정되는가?
4. dice 초기값이 3이면 본문을 도는가?

<details>
<summary>풀이</summary>

본문을 마친 뒤 다시 검사한다. break면 else를 건너뛴다. 실제 횟수는 난수 순서에 따라 달라진다. 처음부터 조건이 거짓이라 본문을 돌지 않는다.

| 가상 뽑기 전 | 받은 값 | count | 다음 조건 |
| --- | --- | --- | --- |
| dice=0 | 1 | 1 | 1!=3, 계속 |
| dice=1 | 5 | 2 | 5!=3, 계속 |
| dice=5 | 3 | 3 | 3!=3은 거짓, 종료 |

본문 안에서 3을 받았다고 그 아래 모든 문장을 자동으로 건너뛰는 것은 아니다. 원본은 횟수 출력까지 한 뒤 다음 조건 검사에서 끝난다. break를 넣는 다른 구현과 현재 구조를 구별한다. while에 붙은 else는 조건이 단 한 번 참이었다는 사실보다 break 없이 종료했는지가 핵심이다.

</details>

## 문제 3. 한 가지만 바꾸기

본문의 다음 실험에서 한 행만 골라 결과를 먼저 예상한다. 실행 후 원래 예제로 돌아가 다음 변경을 확인한다.

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| 가상 첫 값을 3으로 | 한 번 만에 종료 | 다음 검사에서 거짓 |
| target 20을 3으로 | 찾음 3, else 없음 | 범위 안에서 break |
| count 증가 제거 | 첫 값만 계속 읽을 수 있음 | 상태 진행이 사라짐 |
| 처음 dice를 3으로 | 뽑기 없이 끝 0 | 첫 조건부터 거짓 |

<details>
<summary>막힐 때 확인할 것</summary>

무한 반복이면 조건에 쓰이는 값이 실제로 바뀌는지 본다. 가상 목록에 3을 없애면 목록 범위 오류도 날 수 있어 실제 난수와 다르다는 조건을 유지한다. 못찾음이 예상과 다르면 while 범위와 break 위치, else 들여쓰기를 확인한다.

</details>
