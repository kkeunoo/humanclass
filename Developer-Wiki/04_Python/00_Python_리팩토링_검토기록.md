## 코드 대조에서 확인한 핵심 사항

- 02: e의 최종값은 내 코드 256, 강사님 코드 289다. 교환 예제를 두 번 이어 실행하면 원래 값으로 돌아온다.
- 04: clear는 공유 객체를 비우고 [] 재대입은 이름 연결을 바꾼다. copy는 바깥 목록만 복사한다. 강사님 연속 컴프리헨션·append는 중복 결과를 만든다.
- 05: ()는 유효한 빈 튜플이다. 내부 리스트까지 불변인 것은 아니다.
- 07: dict 뷰와 누락 기본값을 구분했다. fromkeys의 공유 가변값도 재현했다.
- 08: 내 코드의 여름 가지 출력은 봄으로 적혀 있어 강사님과 다르다.
- 09: 내 FizzBuzz는 0~99이며 강사님 별도 fizzbuzz.py는 1~100이다. GUI turtle 호출도 있어 파일 전체를 일괄 실행하지 않았다.
- 10: read 커서·문자/바이트·파일 모드·pickle 신뢰 조건을 구분했다.
- 11: 타입 힌트는 자동 검증이 아니다. *args 뒤 키워드 전용 매개변수는 유효하다. 내 ref 반환은 None이며 강사님은 목록을 반환한다.
- 12: hello 문자열 속성이 같은 이름 메서드를 가리는 오류를 직접 재현했다.
- 13: 자식이 __init__을 정의하지 않으면 부모 메서드를 그대로 상속한다. super는 MRO상 다음 구현을 찾는다.
- 14: try의 return은 else를 건너뛰고 finally를 거친다.
- 15: 실제 강사님 파일명 _15_module.py를 메타데이터에 반영했다. fn helper는 기능상 같은 구현이다.
- 18: [A-z]는 알파벳 이외 문자도 포함하고 [a-Z]는 잘못된 범위다. 검색과 전체 일치를 구분했다.
- Quiz: 정답 회차 미포함과 최다 득표 키 선택 오류를 추적했다.
- 20: 991_try.py의 줄 전체 strip은 필드별 strip과 다르다. 빈 줄·필드 수·숫자 형식·범위 검사를 누적 전 분리했다.

1. 새 독립 예제 24개와 추가 재현 예제 8개, 총 32개의 표준 출력을 실제 실행해 예상 출력과 비교했다. 32개 모두 일치했다.
2. 기존 26개 Markdown의 코드·출력 블록 2,899개가 결과에 그대로 남는지 내용·중복 횟수 기준으로 확인했다. 교육용 오류 코드도 지우지 않았다.
3. 기존 번호형 본문 순서 887개를 비교했다. 원래의 주제 순서·실습 순서를 보존했다.
4. 코드 펜스, details 태그, 파일 링크, 명시적 목차 앵커, 깨진 인코딩 문자를 검사했다.
5. 기존에 존재하지 않는 다섯 참조 파일명을 실제 현재 문서명으로 수정했다.
6. 패키지 내부 경로·Markdown 개수·한글 파일명과 최종 압축을 확인했다.

추가로 내·강사님 fn/fn_15_1.py의 실제 add·sub·Hero.attack을 안전하게 호출해 동작을 확인했다. Wiki_test.py의 실제 함수도 정상 입력과 숫자가 아닌 나이 입력에서 반환·ValueError를 확인했다. 이 두 파일은 외부 요청이나 파일 쓰기가 없는 정의만 실행했다.

README는 읽기 안내를 보강했고 학습 목표는 짧게 정리했다. 그 밖의 상세 학습 본문·실습·정답을 축약하지 않았다. 이전의 V3 보강 설명도 번호형 상세 본문 뒤에서 복습 자료로 유지했다.

## 검증하지 않은 것과 한계

기존 모든 코드 블록을 개별 실행했다는 뜻은 아니다. 문맥 발췌, 의도적인 문법·실행 오류, GUI·키보드 입력·네트워크·디스크 저장 예제는 전체 실행 대상이 아니다. 새 예제의 출력 일치로 사용자의 Python 버전·패키지·VSCode 설정이나 실제 파일 권한을 보장하지 않는다.

원본 한글 경로 일부는 보관본에서 인코딩이 손상되어 13_*.py와 강사님 자료형 퀴즈처럼 확인 가능한 범위로 표시했다. 손상된 파일명을 추정해 새로운 출처 이름을 만들지 않았다. 파일 내부 내용은 읽을 수 있어 개념별 비교에 사용했다.

Markdown 링크 중 다른 파트로 이동하는 상위 경로는 전체 Developer-Wiki에 적용한 후 사용하는 링크다. 이번 Python 단독 압축에 다른 파트를 끼워 넣지 않았다. 전체 용어색인과 최상위 안내는 모든 파트 승인 뒤 통합 검토 단계에서 점검한다.
