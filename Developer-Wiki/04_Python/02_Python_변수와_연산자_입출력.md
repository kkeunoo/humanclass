## 1. 이 장에서 배울 것

대입과 계산 순서를 추적하고 입력 문자열을 숫자로 변환한다. /·//·int의 차이, 교환 두 번의 결과, sep·end, 논리 연산과 is의 의미를 실제 원본에 맞춰 설명한다.

실제 원본·새 예제·개선안·선택 학습을 구분하고 입력·실행 순서·반환값·출력을 연결한다.

## 2. 무엇이며, 왜 필요한가

대입은 오른쪽 식을 먼저 계산한 뒤 왼쪽 이름에 값을 연결한다. total=price*count는 두 값이 같은지를 묻는 문장이 아니다. 같은 이름에 다시 대입하면 이후 읽는 값이 달라진다. 이미 계산해 저장한 다른 값이 자동으로 다시 계산되는 것은 아니다.

| 표현 | 역할 | 예 |
| --- | --- | --- |
| / | 일반 나눗셈 | 5/2는 2.5 |
| // | 아래 방향으로 내린 몫 | -5//2는 -3 |
| int(실수) | 0 방향으로 소수 부분 제거 | int(-2.4)는 -2 |
| ** | 거듭제곱 | 4**2는 16 |
| input | 입력한 글자 읽기 | 3을 입력해도 문자열 |
| == | 값이 같은지 비교 | 1==1.0은 True |
| is | 같은 객체인지 비교 | 엄격 타입 비교의 대체재 아님 |

문자열 '3'과 정수 3은 모양이 비슷해도 다른 종류다. input의 반환값을 곱하면 문자열 반복이 될 수 있다. 숫자 계산은 int나 float로 해석한 뒤 한다. 해석할 수 없는 '가'를 int에 넣으면 ValueError이며 JavaScript의 NaN과 같은 결과값으로 생각하지 않는다.

print의 sep은 여러 값 사이에, end는 전체 출력 끝에 넣을 내용이다. 기본 sep은 공백, end는 줄바꿈이다. 두 옵션을 따로 생각해야 여러 print가 붙어 보이는 이유를 알 수 있다.

> 📚 **출처 · 본문 설명 확인:** [Python 공식 입문: 숫자·대입](https://docs.python.org/ko/3/tutorial/introduction.html), [input·int·print](https://docs.python.org/ko/3/library/functions.html), [비교와 논리식](https://docs.python.org/ko/3/reference/expressions.html#comparisons). 실제 배운 문법의 의미를 확인한 근거다. 예제·표·풀이 자체는 수업 자료를 바탕으로 새로 구성했다. 외부 문장을 직접 인용하지 않았다. 이번 문법 확인 기간: 2026-10-28~29.

## 5. 선언·호출·파일이 연결되는 흐름

input 호출 → 입력 문자열 반환 → typed 대입 → int 호출 → 정수 반환 → count 대입 → 곱셈 → total 대입 → print 순서다. 대입은 오른쪽 계산 뒤에 일어난다. a,b=b,a는 오른쪽의 이전 값들을 먼저 읽어 왼쪽 이름에 연결한다. 이미 a를 바꾼 뒤 b가 새 a를 읽는 순차 두 문장과 다르다.

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 내 음수 몫 주석과 변환·출력을 직접 비교한 시도는 개념 차이를 드러낸다. **교정:** //는 나머지를 내리는 연산이 아니라 나눗셈의 몫을 아래쪽 정수 방향으로 구한다. is는 값과 타입까지 비교하는 === 대응이 아니다. float가 소수점 16자리까지 언제나 정확하다는 주석도 일반화할 수 없다. **실습 조건:** 숫자가 아닌 입력의 검증은 아직 넣지 않았으므로 3 같은 정수 입력 조건을 지킨다.

개선안은 D 드라이브 원본을 수정한 결과가 아니다. 실제 오류·수업용 단순화·목적에 따른 선택을 구별한다.

| e**=2 뒤 | 289 | 256 |
| 두 교환 뒤 a·b | 10·오백원 | 10·오백원 |

4.3-2.7은 이진 부동소수점 표현 때문에 1.6과 정확히 같은 값 비교가 아닐 수 있으며 원본 결과는 False다. 단순 소수점 자리 수 규칙으로 보장하지 않는다. and가 or보다 우선하고 not이 더 먼저 적용된다. 논리식은 항상 boolean만 돌려주는 것도 아니다. a or '쉬는시간'은 a가 참으로 평가되면 그 값 자체를 돌려주므로 a='글씨'일 때 결과는 글씨다.

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| 수량에 4 입력 | 총액 4000 | 입력을 정수로 변환 |
| 둘째 교환 줄 제거 | 오백원·10 유지 | 교환 한 번만 실행 |
| 마지막 첫 print의 end를 줄바꿈으로 | 12와 3이 다른 줄 | 출력 끝 처리 변경 |
| a or 식의 a를 빈 문자열로 | 쉬는시간 | 거짓으로 평가된 첫 값 대신 뒤 값 |

숫자가 반복되거나 자료형 오류가 나면 input 결과와 변환 결과를 구분한다. 교환 값이 예상과 다르면 교환을 몇 번 실행했는지 본다. 출력이 붙으면 sep뿐 아니라 이전 print의 end도 확인한다. 실수의 정확 비교와 is를 같은 해결책으로 묶지 않는다.
