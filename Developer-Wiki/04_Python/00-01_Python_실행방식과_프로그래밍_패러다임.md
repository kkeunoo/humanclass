# 1. 프로그램 실행 과정

사람이 작성한 소스 코드는 컴퓨터가 처리할 수 있는 형태로 번역되거나 해석되어야 합니다.

```text
소스 코드
   ↓
번역 또는 해석
   ↓
실행 결과
```

대표적인 실행 방식으로 컴파일러 방식과 인터프리터 방식이 있습니다.

---

# 2. 컴파일러란?

컴파일러는 소스 코드를 실행 전에 다른 형태의 코드로 변환하는 프로그램입니다.

```text
소스 코드
   ↓ 컴파일
실행 파일 또는 중간 코드
   ↓ 실행
결과
```

일반적인 특징:

- 실행 전에 번역 과정이 필요합니다.
- 변환된 결과물을 반복 실행할 수 있습니다.
- 많은 오류를 컴파일 과정에서 확인할 수 있습니다.
- 언어와 실행 환경에 따라 실행 파일 또는 중간 코드가 만들어집니다.

---

# 3. 인터프리터란?

인터프리터는 프로그램을 실행하는 동안 코드를 해석하여 동작시키는 프로그램입니다.

```text
소스 코드
   ↓ 해석과 실행
결과
```

일반적인 특징:

- 코드를 작성한 뒤 빠르게 실행할 수 있습니다.
- 실행 중 도달한 코드에서 오류가 발견될 수 있습니다.
- 대화형 실행 환경을 제공하기 쉽습니다.

다만 “인터프리터는 반드시 한 줄씩만 실행한다”라고 단정하면 실제 구현을 정확히 설명하기 어렵습니다.

---

# 4. 컴파일러와 인터프리터 비교

| 구분 | 컴파일러 중심 방식 | 인터프리터 중심 방식 |
| --- | --- | --- |
| 변환 시점 | 실행 전 | 실행 중 |
| 결과물 | 실행 파일 또는 중간 코드 | 실행 결과 |
| 오류 확인 | 변환 과정에서 다수 확인 | 실행 중 도달한 위치에서 확인 가능 |
| 장점 | 실행 효율과 배포 | 빠른 실험과 개발 편의성 |

현대 프로그래밍 언어는 두 방식을 함께 사용하는 경우가 많습니다.

---

# 5. Python의 일반적인 실행 흐름

Python은 일반적으로 인터프리터 언어라고 부릅니다. 대표 구현인 CPython은 소스 코드를 바이트코드로 변환한 뒤 Python 가상 머신에서 실행합니다.

```text
Python 소스 코드(.py)
        ↓
문법 분석
        ↓
바이트코드
        ↓
Python 가상 머신 실행
        ↓
결과
```

따라서 다음처럼 이해하는 것이 좋습니다.

> Python은 인터프리터 방식으로 사용되지만, 대표 구현체는 내부적으로 바이트코드 변환 과정도 사용합니다.

---

# 6. 소스 코드와 바이트코드

## 6.1 소스 코드

개발자가 직접 작성하는 `.py` 파일입니다.

```python
print("hello world")
```

## 6.2 바이트코드

Python 실행 환경이 처리하는 중간 명령 형태입니다.

```text
사람이 직접 작성하는 코드가 아님
기계어와도 다름
Python 실행 환경을 위한 중간 표현
```

일부 환경에서는 `__pycache__` 폴더와 `.pyc` 파일이 생성될 수 있습니다.

---

# 7. Python 가상 머신

Python 가상 머신은 바이트코드 명령을 읽고 실행합니다.

```text
.py 파일
   ↓
바이트코드
   ↓
Python Virtual Machine
   ↓
실행 결과
```

여기서 가상 머신은 별도의 화면이 있는 가상 컴퓨터가 아니라 Python 명령을 처리하는 실행 구조를 의미합니다.

---

# 8. 절차 지향 프로그래밍

절차 지향 프로그래밍은 작업의 순서와 절차를 중심으로 코드를 구성합니다.

```python
price = 1000
count = 3
result = price * count
print(result)
```

```text
값 준비 → 계산 → 결과 출력
```

작은 프로그램이나 순차적인 작업을 표현할 때 이해하기 쉽습니다.

---

# 9. 객체지향 프로그래밍

객체지향 프로그래밍은 데이터와 그 데이터를 다루는 기능을 객체 단위로 묶어 구성합니다.

```python
class Product:
    def __init__(self, name, price):
        self.name = name
        self.price = price

    def show(self):
        print(self.name, self.price)

product = Product("사과", 1000)
product.show()
```

객체는 일반적으로 상태와 행동을 함께 가질 수 있습니다.

```text
상태 → 속성
행동 → 메서드
```

---

# 10. 절차 지향과 객체지향 비교

| 항목 | 절차 지향 | 객체지향 |
| --- | --- | --- |
| 중심 | 처리 순서와 함수 | 객체와 객체의 관계 |
| 구성 | 데이터와 처리 절차 | 상태와 행동을 함께 구성 |
| 장점 | 단순한 흐름을 빠르게 작성 | 역할 분리와 확장에 유리 |
| 주의점 | 규모가 커지면 흐름이 복잡해질 수 있음 | 작은 문제에도 과도한 구조를 만들 수 있음 |

두 방식 중 하나만 항상 옳은 것은 아닙니다.

---

# 11. Python은 다중 패러다임 언어

Python은 하나의 방식만 강제하지 않습니다.

```text
절차 지향
객체지향
함수 중심 스타일
```

문제의 크기와 역할에 따라 적절한 방식을 선택할 수 있습니다.

---

# 12. Python과 들여쓰기

Python은 중괄호 대신 들여쓰기로 코드 블록을 구분합니다.

```python
if True:
    print("실행")
```

잘못된 예:

```python
print("hello")
    print("world")
```

블록을 시작한 문장이 없는데 두 번째 줄만 들여쓰기되어 `IndentationError`가 발생할 수 있습니다.

---

# 13. 권장 들여쓰기

Python에서는 공백 4칸을 기본 들여쓰기 단위로 사용하는 것이 일반적입니다.

```python
def hello():
    print("hello")
```

주의 사항:

- 한 블록 안에서 깊이를 일정하게 유지합니다.
- 탭과 공백을 섞지 않습니다.
- 보기 위한 임의의 들여쓰기를 하지 않습니다.
- 콜론으로 끝나는 블록 문장 다음에는 하위 코드를 들여씁니다.

# V3 동작 백과 보강 — 소스가 실행되기까지

| 단계 | 실제로 일어나는 일 | 관찰 방법 |
|---|---|---|
| 입력 | 개발자가 `.py` 파일에 소스 코드를 저장한다 | 편집기에서 코드 확인 |
| 해석 준비 | Python이 문법을 분석하고 실행 가능한 바이트코드 형태로 다룬다 | 문법이 틀리면 실행 전에 `SyntaxError` |
| 실행 | Python 가상 머신이 위에서 아래로 문장을 수행한다 | `print()` 결과와 상태 변화 |
| 종료 | 처리하지 않은 예외가 없으면 정상 종료한다 | 종료 코드와 터미널 결과 |

`python 01_hello.py`라고 실행하면 파일명이 입력이 되고, Python 실행기가 그 파일을 읽는다. 함수와 클래스는 정의 문장을 만날 때 객체로 만들어지지만 본문 전체가 즉시 실행되는 것은 아니다. 함수 본문은 호출할 때, 클래스의 인스턴스 초기화 코드는 객체를 만들 때 실행된다. 들여쓰기는 보기 좋게 만드는 장식이 아니라 조건문·반복문·함수에 속하는 범위를 결정한다.

**원본 연결:** 실행 순서는 내 코드 `workspace_python/01_hello.py`와 강사님 코드 `workspace_python/_01_hello.py`부터 확인한다. 절차 지향·객체지향·함수형 비교는 여러 번호형 파일을 이해하기 위한 Wiki 확장 설명이다.

```python
print("A")
def hello():
    print("B")
print("C")
hello()
```

```text
A
C
B
```

정의 시점에는 `B`가 출력되지 않고, `hello()` 호출 시점에 출력되는 것이 핵심이다.
