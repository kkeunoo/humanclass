# 00-01. Python 실행 — 파일의 글자에서 화면의 결과까지

처음에는 언어 분류를 외우기보다 내가 쓴 파일의 어느 줄이 실행되는지 설명하는 것이 먼저다. 코드는 파일에 저장한 글자이고, 실행 결과는 Python이 그 코드를 읽어 실제 작업한 뒤 터미널에 남긴 값이다.

## 1. 이 장에서 배울 것

파일 저장·실행·출력을 구별하고 위에서 아래로 진행하는 흐름을 읽는다. 주석과 실행 문장을 나누고, 화면에 보이지 않았다는 이유로 모든 줄을 오류라고 판단하지 않는다.

실제 원본·새 예제·개선안·선택 학습을 구분하고 입력·실행 순서·반환값·출력을 연결한다.

<a id="concepts"></a>

## 2. 무엇이며, 왜 필요한가

Python 소스 파일은 보통 .py 확장자로 저장한다. 편집기에서 글자를 입력하고 저장하는 것과 그 파일을 실행하는 것은 다른 동작이다. 실행할 때는 Python이 파일 내용을 읽고 명령을 수행한다. 이 첫 예제의 독립 문장들은 위에서 아래로 진행한다. 나중에 조건문·반복문·함수를 배우면 선택하거나 되풀이하거나 호출하는 흐름이 더해진다.

| 구분 | 예 | 의미 |
| --- | --- | --- |
| 소스 코드 | print('시작') | 실행할 작업을 적은 문장 |
| 주석 | # 실행하지 않을 메모 | 사람이 읽는 설명 |
| 문자열 | '시작' | 글자 값 |
| 출력 | 터미널의 시작 | print를 호출한 결과 |

print('시작')은 문자열 값을 출력 함수에 전달한다. 괄호를 포함한 전체 문장은 코드이고 괄호 안의 따옴표로 묶은 부분은 값이다. 터미널 결과에는 따옴표와 print라는 이름까지 그대로 나타나는 것이 아니다.

파일 실행과 대화형 실행도 구분한다. 대화형 환경에서는 식의 값이 자동으로 보이는 경우가 있지만, .py 파일에서 문자열만 한 줄 적었다고 print처럼 출력되지는 않는다. 이 책의 기본 실행 조건은 .py 파일이다.

> 📚 **출처 · 본문 설명 확인:** [Python 공식 입문: 주석·계산과 값](https://docs.python.org/ko/3/tutorial/introduction.html). 실제 배운 문법의 의미를 확인한 근거다. 예제·표·풀이 자체는 수업 자료를 바탕으로 새로 구성했다. 외부 문장을 직접 인용하지 않았다. 이번 문법 확인 기간: 2026-10-28~29.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 전체 코드.** [실행 파일](실습/책형_복습/00-01_Python_실행방식과_프로그래밍_패러다임.py)을 제공한다. Python이 설치된 환경에서 새 .py 파일로 저장해 실행한다. 터미널은 그 파일이 있는 폴더에서 열고 `python 파일이름.py`를 실행한다. VS Code의 Python 실행 기능을 사용해도 된다. 결과는 터미널에 표시된다.



```python
print('첫째')
# print('실행하지 않는 줄')
'화면에 출력하지 않은 문자열'
print('둘째')
```

첫 print가 첫째를 출력하고 줄을 바꾼다. 둘째 줄은 # 뒤의 메모여서 호출하지 않는다. 셋째 줄은 문자열 표현식이지만 파일에서는 화면 출력이 없다. 마지막 print가 둘째를 출력한다. 네 줄 중 화면에 두 줄만 생긴 이유를 실행 오류가 아니라 문장의 역할로 설명한다.

**예상 출력 또는 관찰:**

```text
첫째
둘째
```

## 4. 내가 작성한 코드를 따라 읽기

아래는 원본 발췌다. 주석의 잘못된 설명도 원문을 보존하고 풀이에서 교정한다. 필요한 선언·호출·다른 파일의 정의는 다음 절까지 연결해 읽는다.

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_python/01_hello.py` 1–4행

```python
# 'indent' err는 들여쓰기를 잘못했다는 것
# 아래처럼 진행하면 IndentationError: unexpected indent 가 나옴
print('hello world');
    # print('hello world'); 
```

**발췌 바로 풀이:** 첫 두 줄만 비교해도 실행 문장과 주석의 차이를 볼 수 있다. **전체 파일의 두 번째 `print`와 실제 출력**은 [01 출력과 주석](01_Python_출력과_주석.md)에서 확인한다. 들여쓴 `# print(...)`도 주석이므로 현재 원본 실행에서 `IndentationError`를 일으키지 않는다. 내 주석은 그 줄을 실행 코드로 바꾸어 잘못 들여썼다면 오류가 날 수 있음을 설명한다.

내 첫 파일은 print의 세미콜론과 들여쓴 # 주석을 포함한다. 실행 문장을 갑자기 들여쓰면 오류가 날 수 있지만 현재 들여쓴 줄은 주석이다. 실제 오류가 발생한 파일처럼 설명하지 않는다. 아래는 첫 부분만 인용했으며 파일 전체에 있는 두 번째 print와 여러 줄 문자열은 다음 출력 장에서 다룬다.

<a id="connections"></a>

## 5. 선언·호출·파일이 연결되는 흐름

저장한 .py 파일 → Python 실행 → 첫 실행 문장 → 다음 문장 → print가 터미널에 출력 → 파일 끝 순서다. 지금 예제는 다른 파일을 import하거나 직접 만든 함수를 호출하지 않는다. print는 Python에서 제공하는 함수다. 먼저 파일 경로와 실행 결과 위치를 확인하고 편집기 자체가 계산 결과를 저장한다고 생각하지 않는다.

<a id="review"></a>

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 내 주석은 들여쓰기 오류를 미리 의식하고 실행 줄을 구분하려는 기록이다. **교정:** 주석에 오류 이름이 적혀 있다고 현재 실행에서 그 오류가 난 것은 아니다. **작성 선택:** 줄 끝 세미콜론은 여기서 허용되지만 필수는 아니다. 한 줄에 한 문장으로 읽기 쉽게 쓰는 편이 첫 복습에 좋다. **확인:** 편집 후 저장하지 않으면 실행한 파일 내용과 화면에서 보고 있는 내용이 달라질 수 있다.

개선안은 D 드라이브 원본을 수정한 결과가 아니다. 실제 오류·수업용 단순화·목적에 따른 선택을 구별한다.

## 7. 강사님 코드가 도움이 되는 비교



양쪽 첫 print는 같은 글자를 출력하므로 강사님 코드를 반복하지 않는다. 강사님은 세미콜론 없이 썼고 내 코드는 붙였지만 이 자리의 결과는 같다. 언어가 다른 것이 아니라 같은 Python 문장의 작성 선택이다.

<a id="results"></a>

## 8. 결과를 추적하고 한 가지 바꾸기

| 줄 | 읽는 것 | 터미널 변화 |
| --- | --- | --- |
| 1 | print 호출 | 첫째 한 줄 |
| 2 | # 주석 | 없음 |
| 3 | 문자열 표현식 | 파일 실행에서는 없음 |
| 4 | print 호출 | 둘째 한 줄 |

편집기의 실행 버튼을 눌렀는데 다른 결과라면 코드 내용만 보지 말고 실행 파일 경로도 확인한다. 이전 파일·다른 폴더의 같은 이름을 실행했을 수 있다. 실행 위치를 알아야 이후 파일 입출력의 상대 경로도 이해할 수 있다.

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| 둘째 줄의 # 제거 | 중간 문구도 출력 | 주석에서 호출로 변경 |
| 셋째 줄을 print로 감싸기 | 해당 문자열 출력 | 값 계산과 출력의 차이 |
| 두 print 줄 순서 교환 | 둘째 다음 첫째 | 실행 순서 변경 |

출력이 안 보이면 저장 여부·실행 파일·터미널을 먼저 확인한다. 주석인지 실행 줄인지 구별한다. Python 실행 명령을 찾지 못하는 환경 문제와 코드 문법 오류를 같은 문제로 읽지 않는다. 이후 오류 장에서 메시지의 파일·줄·종류를 읽는다.

## 10. 복습과 빠른 정리

1. 소스를 저장하면 바로 출력도 만들어지는가?
2. .py 파일에서 문자열만 한 줄 적으면 print와 같은가?
3. 들여쓴 주석이 있다는 사실만으로 오류인가?

<details>
<summary>풀이 — 먼저 자신의 답을 적은 뒤 펼치기</summary>
