# 14. 동기와 비동기 — 예약한 순서와 실행하는 차례

[JavaScript 목차](README.md) · [읽기 안내](00_JavaScript_V3_동작_백과_읽기법.md)

함수를 호출하면 그 안의 일을 끝내고 돌아오는 경우와, 나중에 할 일을 등록한 뒤 다음 문장으로 진행하는 경우를 구별해야 한다. 타이머0ms도 현재 줄에서 콜백을 즉시 호출하는 문법은 아니다.

## 1. 이 장에서 배울 것

현재 함수 호출의 흐름과 타이머 콜백의 실행을 나눈다. 원본의 활성 코드·이전 주석 실험을 구분하고 출력 순서를 설명한다.

입력·현재 상태·실행 순서·결과를 분리해 설명한다. 실제 수업 원본은 아래에 표시하고, 원본에 없는 선택 학습은 9절 TIP에 둔다.

<a id="concepts"></a>

## 2. 무엇이며, 왜 필요한가

여기서 동기는 호출한 함수의 일을 실행한 뒤 돌아와 다음 문장으로 진행하는 흐름이다. outer가inner를 부르면 inner 본문이 끝난 뒤 outer의 다음 줄로 돌아온다. 함수가 안쪽으로 연결되어 있다고 동시에 실행되는 것은 아니다.

타이머는 콜백을 등록하고 현재 코드를 계속 실행한다. 지연값0은 ‘지금 함수 안으로 들어가라’가 아니라 실행할 수 있는 차례를 기다리는 예약이다. 따라서 A출력 → 타이머B등록 → C출력이면 A·C가 먼저고 B가 뒤다. 정확한 벽시계 시각을 약속하는 값도 아니다.

```text
현재 호출: outer → inner → outer복귀 → 나머지문장
예약 처리: 현재 실행이 끝남 → 실행 가능한 콜백의 차례
```

이벤트 루프는 이런 실행 차례를 이어 주는 구조로 우선 이해한다. 두 타이머가 차례로 출력되었다는 사실만으로 동기 함수 호출로 바뀌거나 동시에 실행된 것은 아니다. Promise와 내부 큐 전체는 이 원본보다 뒤 학습과 TIP에서 구분한다.

> 📚 **출처 · 본문 설명 확인:** [MDN setTimeout과 지연](https://developer.mozilla.org/en-US/docs/Web/API/Window/setTimeout) 및 [실행 모델](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Execution_model). 배운 기능의 뜻을 확인한 근거다. 예제·표·풀이 흐름은 수업 코드를 바탕으로 새로 작성했으며 외부 문장을 직접 인용하지 않았다. 확인일: 2026-10-28.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 전체 스크립트.** [HTML 실행 파일](실습/책형_복습/14_JavaScript_동기비동기와_이벤트루프.html)과 같은 폴더의 [JS 파일](실습/책형_복습/14_JavaScript_동기비동기와_이벤트루프.js)을 함께 내려받는다. HTML을 브라우저로 열고 Console에서 결과를 확인한다. script는 필요한 HTML 뒤에 연결한다. 콘솔 출력은 페이지 본문에 자동으로 쓰이지 않는다.

```javascript
function inner() {
    console.log('안쪽');
}
function outer() {
    console.log('바깥 시작');
    inner();
    setTimeout(function () {
        console.log('예약 첫째');
    }, 0);
    setTimeout(function () {
        console.log('예약 둘째');
    }, 0);
    console.log('바깥 끝');
}
outer();
console.log('현재 코드 끝');
```

outer와inner의 정의를 먼저 준비한다. 호출하면 바깥 시작과 안쪽을 출력하고 타이머 두 개를 등록한다. 그 자리에서 콜백 본문을 실행하지 않아 바깥 끝·현재 코드 끝까지 먼저 진행한다. 그 뒤 이 예제에서 같은 지연으로 순서대로 등록한 두 콜백을 관찰한다.

**예상 출력 또는 관찰:**

```text
바깥 시작
안쪽
바깥 끝
현재 코드 끝
예약 첫째
예약 둘째
```

## 4. 내가 작성한 코드를 따라 읽기

아래는 원본의 일부다. 원본에 의존하는 앞 선언·HTML·함수는 다음 절의 연결까지 읽는다. 주석의 잘못된 표현도 원문대로 보존하고 설명에서 교정한다.

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_html/javascript/14_async.html` 11–46행

```javascript
            function fn1() {
                console.log('fn1 실행')

                fn2()
            }
            function fn2() {
                console.log('fn2 실행')

                fn3()
                fn3()

                console.log('1')
                // 3이 먼저 나오는 이유는 setTimeout은 '0초 이후' 라는 개념이기 때문에,
                // 1-3-2 순서로 출력되게 됨 (이 모습이 동기화가 안 되어있는 것)
                // setTimeout( function() {
                //     console.log('2')
                // }, 0)
                // console.log('3')

                // 아래와 같이 주었을 때는 같은 setTimeout이기 때문에,
                // '마지막'이 먼저 나오고 2, 3 순으로 나오게 됨
                // 이러한 것 때문에 지연함수라고 부르며, 두 번째 인자값을 주는 것
                // 같은 setTimeout 0 이라면 두개는 동기화가 된 것
                setTimeout( function() {
                    console.log('2')
                }, 0)
                setTimeout( function() {
                    console.log('3')
                }, 0)
                console.log('마지막')
            }
            function fn3() {
                console.log('fn3 실행')
            }

            fn1()
```

**발췌 바로 풀이:** 실제로 활성화된 문장은 양쪽이 같은 흐름이다. 내 주석에는 이전 실험인 1→3→2 설명도 있지만 그 부분의 코드 두 줄은 주석 처리되어 있다. **현재 활성 코드와 이전 실험의 주석을 구분**해야 한다.

내 fn1은 fn2를 부르고 fn2는 fn3를 두 번 부른다. 현재 활성 코드에서는 1을 출력한 뒤 2와 3을 각각 타이머로 등록하고 마지막을 일반 문장으로 출력한다. 앞의 1→3→2 설명은 3을 일반 문장으로 출력하던 주석 속 실험이다. 같은 파일에 두 설명이 있어도 실제 실행하는 줄을 먼저 골라야 한다.

## 5. 선언·호출·파일이 연결되는 흐름

fn1 정의 → fn1 호출 → fn2 호출 → fn3 두 번 호출과 복귀 → 1 출력 → 2·3 콜백 등록 → 마지막 출력 → 현재 호출 종료 → 예약 콜백 순서다. 같은 지연값의 타이머 둘도 각자의 콜백이다. 타이머 등록 순서와 현재 문장 순서를 나누어 적는다. 08-03장의 식별자·해제와 같은 기능을 쓰지만 이 장의 질문은 출력 시점이다.

<a id="review"></a>

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 내 주석은 이전 실험과 두 타이머 실험을 비교하려는 기록이다. **교정:** 같은 setTimeout 0이면 동기화된다는 표현은 실행 차례가 같아 보이는 것과 동기 호출을 혼동한다. **개선 방향:** 현재 실행할 줄을 고르고 등록과 실행을 다른 칸에 적는다. 구현 내부의 큐 이름을 먼저 외우지 않아도 이 출력은 설명할 수 있다.

개선안은 원본을 수정한 결과가 아니다. 실제 오류, 수업용 단순화, 목적에 따른 선택을 구별해 판단한다.

## 7. 강사님 코드가 도움이 되는 비교



양쪽 활성 코드는 같은 흐름이어서 중복 인용하지 않는다. 강사님·내 파일 모두 fn1 → fn2 → fn3 두 번 → 1 → 마지막 → 2 → 3의 흐름을 만든다. 예전 주석이 현재 결과와 다르게 보이는 것은 그 실험과 현재 코드가 모두 활성화되어서가 아니다.

## 8. 결과를 추적하고 한 가지 바꾸기

| 원본 단계 | 당장 출력 | 예약 |
| --- | --- | --- |
| fn1 | fn1 실행 | 없음 |
| fn2·fn3 두 번 | fn2 실행·fn3 실행·fn3 실행 | 없음 |
| 일반 출력 | 1 | 없음 |
| 타이머 둘 등록 | 없음 | 2·3 콜백 |
| fn2 마지막 | 마지막 | 유지 |
| 현재 실행 뒤 | 2·3 | 콜백 차례 |

주석 속 짧은 실험을 따로 꺼내 1 → 타이머 2 → 일반 3으로 실행하면 1·3·2다. 3을 다시 두 번째 타이머에 넣으면 그 짧은 예제는 1·2·3이다. 전체 원본에는 fn 출력과 마지막 문장이 별도로 남아 있으므로 짧은 예제와 전체 로그를 섞지 않는다.

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| 첫 타이머를 일반 console.log로 | 예약 첫째가 바깥 끝보다 먼저 | 현재 실행으로 변경 |
| 첫 지연만 100ms로 | 둘째 콜백이 첫째보다 먼저 될 수 있음 | 동일 지연 조건 변경 |
| inner 호출만 제거 | 안쪽 출력 없음 | 정의만으로 실행하지 않음 |

출력 순서가 예상과 다르면 콜백의 정의와 등록, 실제 호출을 구분한다. 오래 걸리는 동기 작업 뒤의 지연을0ms설정 실패로 설명하지 않는다. 다른 파일의 console.log변경 실험과 섞지 말고 독립 파일에서 확인한다.

## 10. 복습과 빠른 정리

1. 마지막이 2보다 먼저 출력되는 이유는?
2. 0ms는 즉시 호출인가?
3. 2→3 순서가 동기 호출을 뜻하는가?

<details>
<summary>짧은 풀이 — 먼저 답한 뒤 확인</summary>

마지막은 현재 실행 문장이고 2는 예약 콜백이다. 0ms도 현재 실행이 끝난 뒤의 차례를 기다린다. 순서가 있다는 것과 동기 호출은 같은 말이 아니다.

</details>

| --- | --- |
| 일반 호출 | 실행을 끝내고 복귀 |
| 등록 | 함수 값을 전달 |
| 콜백 실행 | 나중 차례 |
| 주석 실험 | 현재 활성 코드와 분리 |
