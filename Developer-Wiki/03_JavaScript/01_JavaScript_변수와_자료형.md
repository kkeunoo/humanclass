# 01. 변수와 자료형 — 이름·값·변환을 나누어 읽기

## 1. 이 장에서 배울 것

선언·대입·출력을 구분하고 let·const·var의 기본 차이를 설명한다. 문자열과 숫자 변환을 추적하며 실제 회식비 풀이를 몫·나머지로 확인한다.

입력·현재 상태·실행 순서·결과를 분리해 설명한다. 실제 수업 원본은 아래에 표시하고, 원본에 없는 선택 학습은 9절 TIP에 둔다.

## 2. 무엇이며, 왜 필요한가

`let score = 60;`은 score라는 이름을 선언하고 60을 초기값으로 넣는다. `score = 65;`는 기존 변수에 새 값을 저장한다. 여기서 =는 ‘같은가?’를 묻는 기호가 아니다. `console.log(score)`는 그 순간의 값을 Console로 보여 주며 페이지 본문에 자동으로 쓰지 않는다.

변수를 이름표에 비유할 수 있지만, 이름표에 ‘숫자만’이라고 고정한 것은 아니다. let으로 선언한 변수에 숫자를 넣었다가 문자열을 대입할 수 있다. const는 값의 자료형 때문이 아니라 **그 이름에 다른 값을 다시 대입하는 것을 막는 선언**이다. 객체 내부까지 모두 고정한다는 뜻은 뒤 객체 장에서 구별한다.

| 선언 | 같은 범위의 재선언 | 재대입 | 범위의 기본 구분 |
| --- | --- | --- | --- |
| var | 가능 | 가능 | 함수 범위 |
| let | 불가 | 가능 | 블록 범위 |
| const | 불가 | 불가 | 블록 범위 |

범위는 이름을 사용할 수 있는 영역이다. 중괄호와 함수의 관계는 뒤 반복·함수 장에서 다시 실험한다. 지금은 선언 전에 사용하거나 선언 키워드를 빼는 방식을 새 예제의 기본 습관으로 삼지 않는다.

값에는 숫자·문자열·참거짓 등이 있다. 따옴표 안의 '10'은 숫자처럼 보여도 문자열이다. +는 문자열 연결도 하므로 Number('10')로 변환한 뒤 더하는 것과 결과가 다르다. Number는 전체 값을 숫자로 바꾸려 하고 parseInt는 앞에서부터 정수로 읽을 수 있는 부분을 해석한다. 그래서 Number('10개')는 NaN, parseInt('10개')는10이다. parseInt는 입력 전체가 유효한 숫자인지 검사하는 함수가 아니다.

> 📚 **출처 · 본문 설명 확인:** [MDN 선언과 자료형](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Grammar_and_types), [Number](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number), [parseInt](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/parseInt). 배운 기능의 뜻을 확인한 근거다. 예제·표·풀이 흐름은 수업 코드를 바탕으로 새로 작성했으며 외부 문장을 직접 인용하지 않았다. 확인일: 2026-10-28.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 전체 스크립트.** [HTML 실행 파일](실습/책형_복습/01_JavaScript_변수와_자료형.html)과 같은 폴더의 [JS 파일](실습/책형_복습/01_JavaScript_변수와_자료형.js)을 함께 내려받는다. HTML을 브라우저로 열고 Console에서 결과를 확인한다. script는 필요한 HTML 뒤에 연결한다. 콘솔 출력은 페이지 본문에 자동으로 쓰이지 않는다.

```javascript
let score = 60;
score = 65;
console.log(score);
const text = '10.1';
console.log(text + 2);
console.log(Number(text) + 2);
console.log(parseInt(text));
console.log(Number('10개'));
```

score는60에서65로 바뀐 뒤 출력된다. text의 초기값은 문자열이고 재대입하지 않는다. 문자열에2를 연결하면10.12, 숫자 변환 뒤 더하면12.1이다. Console에서는 문자열과 숫자가 비슷하게 보일 수 있으므로 글자 모양만 보지 말고 typeof와 계산 과정을 함께 확인한다.

**예상 출력 또는 관찰:**

```text
65
10.12
12.1
10
NaN
```

## 4. 내가 작성한 코드를 따라 읽기

아래는 원본의 일부다. 원본에 의존하는 앞 선언·HTML·함수는 다음 절의 연결까지 읽는다. 주석의 잘못된 표현도 원문대로 보존하고 설명에서 교정한다.

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_html/javascript/01_var.html` 43–59행

```javascript
        // 선언 방법 3
        let d = 60
        console.log('d : '+ d);

        // 같은 변수 명으로 다시 선언하는 것을 막아준다
        // let d = 70
        d = 65
        console.log('d : '+ d);

        // 선언 방법 4
        const e = 70
        console.log('e : '+ e)
        // const e = 80
        // e = 75

        d = '문자'
        console.log('d : '+ d);
```

**발췌 바로 풀이:** 이 부분은 양쪽이 같다. 강사님 방식으로 바꿀 필요가 없다. 실행되는 줄과 주석 처리한 오류 실험을 구분하며 읽으면 된다.

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_html/javascript/01_var.html` 96–108행

```javascript
        let strA = "10.1"
        let strB = "10개"
        console.log( strA + 2 ) // "10.12"
        let numA = Number(strA) + 2
        console.log(numA)
        console.log( Number(strB) )

        numA = parseInt( strA )
        console.log('numA :', numA)
        console.log( parseInt(strB) )

        console.log( String(numA) )
        console.log( ''+numA )
```

**발췌 바로 풀이:** strA는 문자열10.1이라 +2는 연결이다. Number로 바꾼 뒤에는12.1이고 parseInt는10을 만든다. strB의10개는 전체 숫자가 아니어서 Number 결과는NaN이지만 parseInt는 앞부분10을 읽는다. 여기서 numA는 parseInt 뒤10으로 바뀌어 마지막 String 변환도 문자열10이다.

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_html/javascript/01_var.html` 135–142행

```javascript
        // `
        // 9명이 회식을 했고 비용이 100,000원이 나왔다
        // `
        
        console.log( '나머지 : ', 100000 % 9 )
        console.log( '인당 : ', parseInt(100000 / 9) )

        console.log( '주최자 : ', parseInt(100000 / 9) + (100000 % 9) )
```

**발췌 바로 풀이:** 9명 중 8명은 11,111원씩, 주최자는 11,112원을 내면 합계 100,000원이 된다. 몫과 나머지를 실제 답까지 연결한 점이 좋다. `parseInt(100000 / 9)`가 각자의 기본 부담이고 `% 9`의 결과 1원이 주최자에게 더해진다. 여기서는 강사님 파일의 빈 계산보다 내 풀이가 더 완성되어 있다.

첫 발췌에서 d는60 →65 →'문자'로 바뀐다. e는70이며 주석 속 재선언·재대입은 실행하지 않는다. 두 번째는 strA='10.1'·strB='10개'의 변환 실험이다. numA는 처음12.1이었다가 parseInt 결과10으로 다시 바뀐다. 마지막 String(numA)와 ''+numA는 이10을 문자열로 만든다.

마지막 회식비 풀이에서는 총100,000원·9명이 조건이다. 기본 부담은 parseInt(100000/9)=11,111원이고 나머지는1원이다. 주최자에게 그1원을 더하면11,112원, 나머지8명은11,111원이다. 11,111×8+11,112=100,000으로 합계까지 검산한다. 출력에 원·인당 같은 의미를 붙이면 숫자만 있을 때보다 다시 읽기 좋다.

## 5. 선언·호출·파일이 연결되는 흐름

이 장은 script 안의 선언 → 대입 → 호출 순서다. console.log의 괄호 안 식을 먼저 계산해 인자로 전달한다. Number·parseInt·String은 수업에서 호출한 내장 함수이며 별도의 내 파일 import가 필요하지 않다. 원본 앞부분의 c=50은 선언 키워드 없는 대입이지 값의 ‘타입 없음’이 아니다. 값50은number다. a의 경우 뒤 var선언이 있다는 조건까지 달라 같은 사례로 묶지 않는다.

let y만 선언하면 값은undefined, 선언하지 않은 z를 읽으면ReferenceError, 7/0은Infinity,7*'문자'는NaN이다. console.error는 오류처럼 보이는 메시지를 출력하는 호출이며 그 자체가 예외를 던져 다음 실행을 중단한다는 뜻은 아니다.

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 회식비는 강사님 파일의 빈 계산을 실제 답과 합계까지 연결했다. **교정:** 선언 없는 대입을 ‘타입 없음’으로 외우지 않는다. **수업용 단순화:** 작은 양수 계산에서 parseInt를 몫 얻기에 썼지만 모든 수 크기의 소수 버림 도구로 일반화하지 않는다. **개선 방향:** 이름·입력 단위·중간 계산을 밝혀 둔다. 원본 잔고의 `잔고=잔고+번돈`과 `잔고+=번돈`을 둘 다 실행하면 한 번이 아닌 두 번 입금되어215,000원이 된다.

개선안은 원본을 수정한 결과가 아니다. 실제 오류, 수업용 단순화, 목적에 따른 선택을 구별해 판단한다.

## 7. 강사님 코드가 도움이 되는 비교



선언·변환 부분은 양쪽이 같아 강사님 원문을 중복 인용하지 않는다. 회식비는 강사님 문제의 주석이100000만원이고 내 조건은100,000원이라 먼저 단위를 맞춰야 한다. 계산이 비어 있는 강사님 파일보다 내 풀이는 이 조건에서 완성되어 있다. 짧은 원문을 권장 풀이인 것처럼 대신하지 않는다.

## 8. 결과를 추적하고 한 가지 바꾸기

| 실행 | 사용 값 | 결과 | 값의 종류 |
| --- | --- | --- | --- |
| text+2 | '10.1',2 | '10.12' | 문자열 |
| Number(text)+2 | 10.1,2 |12.1 | 숫자 |
| parseInt(text) | '10.1' |10 | 숫자 |
| Number('10개') | 전체 변환 불가 |NaN | 숫자 계산 실패 표현 |

원본 alert는 안내, confirm은true/false, prompt는문자열 또는 취소null을 돌려준다. 상당수 호출은 주석이다. Number(null)과Number('')는0이므로 취소·빈 입력을 구분하려면 변환 전 값을 확인한다. 원본 평 환산은1평=3.3㎡인 수업용 근사이며10평→33㎡,82㎡→82/3.3평처럼 단위도 함께 읽는다.

| 한 가지 변경 | 예상 | 이유 |
| --- | --- | --- |
| text만 '10'으로 | 연결102·덧셈12 | 입력 변경 |
| Number('10개')를 parseInt로 |10 | 전체 변환과 부분 해석 차이 |
| score 재대입만 제거 |60 출력 | 초기값 유지 |

숫자 계산이 이상하면 따옴표·입력 함수의 반환형·변환 시점을 확인한다. NaN은 문자열 "NaN"과 구분한다. 같은 범위의 let 재선언을 실험할 때는 별도 파일에서 확인하고, 정상 예제에 오류 줄을 함께 켜 두지 않는다.
