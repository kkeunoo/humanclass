# 08-03. 타이머와 취소 — 예약과 실행을 구분하기 — 연습문제

[본문](../../08-03_JavaScript_타이머와_취소.md) · [문제 목차](README.md)

실제 수업 기능을 바탕으로 **새로 구성한 연습문제**다. 강사님 원본 퀴즈와 구분한다. 예상 → 이유 → 수정 순서로 풀고, 정답은 먼저 답한 뒤 펼친다.

## 목표와 실행 조건

setTimeout·setInterval·해제를 연결한다. 함수를 전달하는 것과 즉시 호출하는 것을 구별하고 정확한 실행 시각을 보장하지 않음을 설명한다.

[전체 실행 HTML](../책형_복습/08-03_JavaScript_타이머와_취소.html)과 같은 폴더의 JS를 함께 준비한다. Console을 열고 새로고침하면 처음부터 실행한다. 원본과 별도 파일이므로 기존 변수·타이머·출력 변경 실험의 영향을 섞지 않는다. 실제 입력·현재 시각·난수는 고정 결과와 구별한다.

입력·버튼·키보드·스크롤 예제는 [본문의 3절](../../08-03_JavaScript_타이머와_취소.md#example)에 적힌 조작 순서대로 결과를 예상한다. 통신 예제는 해당 절의 가상 JSON 파일과 로컬 웹 실행 준비가 필요하며 HTML을 직접 여는 조건과 다르다. Console 출력이 없는 문제는 화면의 값·개수·선택 상태를 답한다.

## 문제 1. 실행 순서와 결과 예상

다음은 **새 설명 예제**다. 출력 전에 어떤 값이 어떤 순서로 만들어지는지 적는다.

```javascript
const cancelled = setTimeout(function () {
    console.log('취소된 작업');
}, 100);
clearTimeout(cancelled);
let count = 0;
const interval = setInterval(function () {
    count++;
    console.log(count);
    if (count === 3) {
        clearInterval(interval);
        console.log('끝');
    }
}, 30);
console.log('예약 완료');
```

<details>
<summary>힌트와 풀이</summary>

**힌트:** 입력·현재 상태·실행 시점·반환값을 따로 표시한다.

```text
예약 완료
1
2
3
끝
```

첫 타이머는 즉시 취소해서 ‘취소된 작업’을 출력하지 않는다. 반복은3회 실행한 뒤 자기 id로 해제한다. 현재 호출이 끝나기 전 ‘예약 완료’가 먼저 출력된다.30ms는 이 예제를 짧게 관찰하려는 설정이며 정확히30·60·90ms에 실행된다고 계약하지 않는다.

</details>

## 문제 2. 개념을 자신의 말로 설명

1. clearTimeout은 모든 예약을 취소하는가?
2. fn()을 전달하면 언제 호출되는가?
3. 정의에 문제가 있는데 원본이 즉시 멈추지 않는 이유는?

<details>
<summary>풀이</summary>

해당 id만 취소한다. fn()은 인수를 계산할 때 먼저 호출한다. 문제의 함수가 원본에서 호출되지 않아 오류 경로가 실행되지 않았다.

| 단계 | 저장·호출 상태 | 출력 |
| --- | --- | --- |
| 첫예약·즉시해제 |cancelled취소 |없음 |
| 반복예약·현재코드 |interval유지 |예약완료 |
| 반복1·2회 |count1·2 |1·2 |
| 반복3회 |count3·clearInterval |3·끝 |

숫자 식별자를 시험 정답으로 쓰지 않는다. 유한한 콜백 횟수 조건으로 끝내는 새 예제와 시간만으로 해제하는 원본은 검증 조건이 다르다.

</details>

## 문제 3. 한 가지를 바꾸어 확인

먼저 **count종료값만2**를 바꾸면 무엇이 달라질지 적는다. 그다음 실행 파일에 해당 변경만 적용해 실제 결과와 비교한다. 나머지 실험도 원래 예제로 돌아가 하나씩 수행한다.

<details>
<summary>변경 결과와 막힐 때 확인</summary>

| 한 가지 변경 | 예상 | 이유 |
| --- | --- | --- |
| count종료값만2 |1·2·끝 |실행횟수조건 |
| 원래간격만100ms |출력순서같고더늦게 |시간변경 |
| 첫clearTimeout만제거 |취소된작업도출력가능 |독립예약남음 |

예약했는데 아직 안 나오면 현재 동기 작업이 끝났는지 본다. 타이머가 안 멈추면 해제한 id와 반복 id가 같은지 확인한다. 문구가 안 나왔다고 예약 함수의 반환이 작업 결과라고 생각하지 않는다.

</details>
