# 05. while과 do-while — 검사·처리·다음 입력·종료 — 연습문제

[본문](../../05_JavaScript_While과_DoWhile.md) · [문제 목차](README.md)

실제 수업 기능을 바탕으로 **새로 구성한 연습문제**다. 강사님 원본 퀴즈와 구분한다. 예상 → 이유 → 수정 순서로 풀고, 정답은 먼저 답한 뒤 펼친다.

## 목표와 실행 조건

while의 사전 검사와 do-while의 사후 검사를 구분한다. 원본의 주석 상태·도달하지 못하는 종료 문구·숫자 변환과 횟수 증가 위치를 설명한다.

[전체 실행 HTML](../책형_복습/05_JavaScript_While과_DoWhile.html)과 같은 폴더의 JS를 함께 준비한다. Console을 열고 새로고침하면 처음부터 실행한다. 원본과 별도 파일이므로 기존 변수·타이머·출력 변경 실험의 영향을 섞지 않는다. 실제 입력·현재 시각·난수는 고정 결과와 구별한다.

입력·버튼·키보드·스크롤 예제는 [본문의 3절](../../05_JavaScript_While과_DoWhile.md#example)에 적힌 조작 순서대로 결과를 예상한다. 통신 예제는 해당 절의 가상 JSON 파일과 로컬 웹 실행 준비가 필요하며 HTML을 직접 여는 조건과 다르다. Console 출력이 없는 문제는 화면의 값·개수·선택 상태를 답한다.

## 문제 1. 실행 순서와 결과 예상

다음은 **새 설명 예제**다. 출력 전에 어떤 값이 어떤 순서로 만들어지는지 적는다.

```javascript
let first = 0;
while (first > 0) {
    console.log('while 본문');
    first--;
}
console.log('while 끝', first);
let second = 0;
do {
    console.log('do 본문', second);
    second--;
} while (second > 0);
console.log('do 끝', second);
```

<details>
<summary>힌트와 풀이</summary>

**힌트:** 입력·현재 상태·실행 시점·반환값을 따로 표시한다.

```text
while 끝 0
do 본문 0
do 끝 -1
```

첫 조건0>0은 거짓이어서 while 본문은 건너뛴다. do는0을 출력하고 second를-1로 바꾼 뒤 조건을 검사해 끝난다. 실행 횟수의 차이를 보기 위해 입력 창과 난수를 제거한 새 예제다. 실제 메뉴 원본에 이 출력이 있었다는 뜻은 아니다.

</details>

## 문제 2. 개념을 자신의 말로 설명

1. 처음 조건이 거짓이면 두 반복은 몇 번 실행하는가?
2.0이상 검사는 정수 검사인가?
3.업다운 정답은 반복 안에서 계속 바꾸는가?

<details>
<summary>풀이</summary>

while은0회, do-while은 최소1회다.0이상은 소수도 통과한다. 업다운은 같은 문제를 맞혀야 하므로 정답을 밖에서 한 번 정한다.

| 원본 while 메뉴 입력 | 결과 | 이유 |
| --- | --- | --- |
| '1' |커피 후 다음 입력 |본문 실행 |
| '0' |본문 진입 안 함 |느슨한 비교로0과 같음 |
| 취소null |안내 후 재입력 가능 |null은0과 동등하지 않음 |
| 빈문자열 |종료 조건으로 빠짐 |빈문자열과0의 느슨한 비교 |

**새 개선 흐름:** menu를문자열로 두고 null 또는'0'을 먼저 종료 처리하면 취소와 빈값을 구별할 수 있다. 업다운에서는 변환 전null·''확인 → Number →0종료 → isNaN·1~100·나머지%1로정수검사 →count++ →정답/UP/DOWN 순서다. 정답50에'abc'→'30'→'50'이면 안내→UP→정답2회다. 공백만 입력한 경우를 다루려면 뒤 문자열 장의 trim을 배운 뒤 별도 정책을 정한다.

</details>

## 문제 3. 한 가지를 바꾸어 확인

먼저 **first만1로**를 바꾸면 무엇이 달라질지 적는다. 그다음 실행 파일에 해당 변경만 적용해 실제 결과와 비교한다. 나머지 실험도 원래 예제로 돌아가 하나씩 수행한다.

<details>
<summary>변경 결과와 막힐 때 확인</summary>

| 한 가지 변경 | 예상 | 이유 |
| --- | --- | --- |
| first만1로 |while 본문1회 |감소 후0 |
| 원래second만2로 |do 본문2·1 출력 |두번 실행 |
| 원래while 조건만first>=0으로 |본문0에서1회 |감소해-1로종료 |

화면이 멈춘다면 종료 조건에 도달하는 값 변경이 있는지 본다. 무한 반복을 시험하려고 안전한 예제의 증감식을 무턱대고 지우지 않는다. 메뉴가 종료 문구 없이 끝났다면 본문 전 검사인지부터 확인한다. 입력 유효성·성공 횟수·반복 종료는 서로 다른 조건이다.

</details>
