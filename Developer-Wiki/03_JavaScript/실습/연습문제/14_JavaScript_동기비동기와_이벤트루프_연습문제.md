# 14. 동기와 비동기 — 예약한 순서와 실행하는 차례 — 연습문제

[본문](../../14_JavaScript_동기비동기와_이벤트루프.md) · [문제 목차](README.md)

실제 수업 기능을 바탕으로 **새로 구성한 연습문제**다. 강사님 원본 퀴즈와 구분한다. 예상 → 이유 → 수정 순서로 풀고, 정답은 먼저 답한 뒤 펼친다.

## 목표와 실행 조건

현재 함수 호출의 흐름과 타이머 콜백의 실행을 나눈다. 원본의 활성 코드·이전 주석 실험을 구분하고 출력 순서를 설명한다.

[전체 실행 HTML](../책형_복습/14_JavaScript_동기비동기와_이벤트루프.html)과 같은 폴더의 JS를 함께 준비한다. Console을 열고 새로고침하면 처음부터 실행한다. 원본과 별도 파일이므로 기존 변수·타이머·출력 변경 실험의 영향을 섞지 않는다. 실제 입력·현재 시각·난수는 고정 결과와 구별한다.

입력·버튼·키보드·스크롤 예제는 [본문의 3절](../../14_JavaScript_동기비동기와_이벤트루프.md#example)에 적힌 조작 순서대로 결과를 예상한다. 통신 예제는 해당 절의 가상 JSON 파일과 로컬 웹 실행 준비가 필요하며 HTML을 직접 여는 조건과 다르다. Console 출력이 없는 문제는 화면의 값·개수·선택 상태를 답한다.

## 문제 1. 실행 순서와 결과 예상

다음은 **새 설명 예제**다. 출력 전에 어떤 값이 어떤 순서로 만들어지는지 적는다.

```javascript
function inner() {
    console.log('안쪽');
}
function outer() {
    console.log('바깥 시작');
    inner();
    setTimeout(function () {
        console.log('예약 첫째');
    }, 0);
    setTimeout(function () {
        console.log('예약 둘째');
    }, 0);
    console.log('바깥 끝');
}
outer();
console.log('현재 코드 끝');
```

<details>
<summary>힌트와 풀이</summary>

**힌트:** 입력·현재 상태·실행 시점·반환값을 따로 표시한다.

```text
바깥 시작
안쪽
바깥 끝
현재 코드 끝
예약 첫째
예약 둘째
```

outer와inner의 정의를 먼저 준비한다. 호출하면 바깥 시작과 안쪽을 출력하고 타이머 두 개를 등록한다. 그 자리에서 콜백 본문을 실행하지 않아 바깥 끝·현재 코드 끝까지 먼저 진행한다. 그 뒤 이 예제에서 같은 지연으로 순서대로 등록한 두 콜백을 관찰한다.

</details>

## 문제 2. 개념을 자신의 말로 설명

1. 마지막이 2보다 먼저 출력되는 이유는?
2. 0ms는 즉시 호출인가?
3. 2→3 순서가 동기 호출을 뜻하는가?

<details>
<summary>풀이</summary>

마지막은 현재 실행 문장이고 2는 예약 콜백이다. 0ms도 현재 실행이 끝난 뒤의 차례를 기다린다. 순서가 있다는 것과 동기 호출은 같은 말이 아니다.

| 원본 단계 | 당장 출력 | 예약 |
| --- | --- | --- |
| fn1 | fn1 실행 | 없음 |
| fn2·fn3 두 번 | fn2 실행·fn3 실행·fn3 실행 | 없음 |
| 일반 출력 | 1 | 없음 |
| 타이머 둘 등록 | 없음 | 2·3 콜백 |
| fn2 마지막 | 마지막 | 유지 |
| 현재 실행 뒤 | 2·3 | 콜백 차례 |

주석 속 짧은 실험을 따로 꺼내 1 → 타이머 2 → 일반 3으로 실행하면 1·3·2다. 3을 다시 두 번째 타이머에 넣으면 그 짧은 예제는 1·2·3이다. 전체 원본에는 fn 출력과 마지막 문장이 별도로 남아 있으므로 짧은 예제와 전체 로그를 섞지 않는다.

</details>

## 문제 3. 한 가지를 바꾸어 확인

먼저 **첫 타이머를 일반 console.log로**를 바꾸면 무엇이 달라질지 적는다. 그다음 실행 파일에 해당 변경만 적용해 실제 결과와 비교한다. 나머지 실험도 원래 예제로 돌아가 하나씩 수행한다.

<details>
<summary>변경 결과와 막힐 때 확인</summary>

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| 첫 타이머를 일반 console.log로 | 예약 첫째가 바깥 끝보다 먼저 | 현재 실행으로 변경 |
| 첫 지연만 100ms로 | 둘째 콜백이 첫째보다 먼저 될 수 있음 | 동일 지연 조건 변경 |
| inner 호출만 제거 | 안쪽 출력 없음 | 정의만으로 실행하지 않음 |

출력 순서가 예상과 다르면 콜백의 정의와 등록, 실제 호출을 구분한다. 오래 걸리는 동기 작업 뒤의 지연을0ms설정 실패로 설명하지 않는다. 다른 파일의 console.log변경 실험과 섞지 말고 독립 파일에서 확인한다.

</details>
