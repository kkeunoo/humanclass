# 09-02. TV 상태 관리 — 함수 호출 뒤 남는 값 — 연습문제

[본문](../../09-02_JavaScript_TV상태관리.md) · [문제 목차](README.md)

실제 수업 기능을 바탕으로 **새로 구성한 연습문제**다. 강사님 원본 퀴즈와 구분한다. 예상 → 이유 → 수정 순서로 풀고, 정답은 먼저 답한 뒤 펼친다.

## 목표와 실행 조건

저장 상태와 출력 문구를 구분한다. 전원 검사·경계 제한·음소거 해제를 어떤 순서로 처리하는지 비교하고 내 전원 토글의 장점을 설명한다.

[전체 실행 HTML](../책형_복습/09-02_JavaScript_TV상태관리.html)과 같은 폴더의 JS를 함께 준비한다. Console을 열고 새로고침하면 처음부터 실행한다. 원본과 별도 파일이므로 기존 변수·타이머·출력 변경 실험의 영향을 섞지 않는다. 실제 입력·현재 시각·난수는 고정 결과와 구별한다.

입력·버튼·키보드·스크롤 예제는 [본문의 3절](../../09-02_JavaScript_TV상태관리.md#example)에 적힌 조작 순서대로 결과를 예상한다. 통신 예제는 해당 절의 가상 JSON 파일과 로컬 웹 실행 준비가 필요하며 HTML을 직접 여는 조건과 다르다. Console 출력이 없는 문제는 화면의 값·개수·선택 상태를 답한다.

## 문제 1. 실행 순서와 결과 예상

다음은 **새 설명 예제**다. 출력 전에 어떤 값이 어떤 순서로 만들어지는지 적는다.

```javascript
let power = false;
let lastVol = 5;
let muted = true;
const VOL_MAX = 5;
function powerOne() {
    power = !power;
    console.log(power ? '켜짐' : '꺼짐');
}
function volumeUp() {
    if (!power) {
        console.log('전원 꺼짐');
        return;
    }
    muted = false;
    lastVol++;
    if (lastVol > VOL_MAX) {
        lastVol = VOL_MAX;
    }
    console.log(lastVol, muted);
}
volumeUp();
powerOne();
volumeUp();
powerOne();
```

<details>
<summary>힌트와 풀이</summary>

**힌트:** 입력·현재 상태·실행 시점·반환값을 따로 표시한다.

```text
전원 꺼짐
켜짐
5 false
꺼짐
```

이 새 예제는 경계 사례를 바로 보려고 볼륨5·음소거true에서 시작했다. 원본의 초기값0·false와 구별한다. 꺼졌을 때는 값을 바꾸지 않고 돌아간다. 켠 뒤에는 최대 볼륨이어도 먼저 음소거를 해제하고5로 제한해 상태를 출력한다. 두 번의 powerOne은 처음 전원 상태로 돌아온다. 사용한 함수 정의가 모두 위에 있다.

</details>

## 문제 2. 개념을 자신의 말로 설명

1.음소거할때 저장볼륨을 반드시0으로 지워야 하는가?
2.대문자let은 상수인가?
3.최대볼륨에서 음소거해제가 안되면 어떤 순서를 바꾸는가?

<details>
<summary>풀이</summary>

별도 상태를 두어 기존 볼륨을 기억할 수 있다. 대문자는 이름 약속이고let값은 바뀐다. 해제를 먼저 하고 범위 보정과 출력을 별도로 처리한다.

| 시작 상태·호출 | 원본 또는 개선 판단 |
| --- | --- |
| 꺼짐에서 조작 |값 유지·안내 |
| channel(10) 뒤올림 |0으로순환 |
| channel(0) 뒤내림 |10으로순환 |
| 정상채널 뒤-50 |이전채널유지,주석의0아님 |
|5·음소거에서올림 |강사님은해제·5출력,내원본은해제건너뜀 |
| powerOne 두번 |처음전원으로복귀 |

이 표는 호출 전 상태를 맞춰 비교하는 기준이다. 이미 다른 테스트로 값이 바뀐 상태에서 연속 실행하면 결과도 달라질 수 있다.

</details>

## 문제 3. 한 가지를 바꾸어 확인

먼저 **새 예제 초기power만true**를 바꾸면 무엇이 달라질지 적는다. 그다음 실행 파일에 해당 변경만 적용해 실제 결과와 비교한다. 나머지 실험도 원래 예제로 돌아가 하나씩 수행한다.

<details>
<summary>변경 결과와 막힐 때 확인</summary>

| 한 가지 변경 | 예상 | 이유 |
| --- | --- | --- |
| 새 예제 초기power만true |첫조작5false·다음토글꺼짐 |시작상태변경 |
| 원래 muted=false 줄만제거 |켜도음소거true유지 |문구아닌대입필요 |
| 원래 초기lastVol만3 |켜고올리면4 |경계전상태 |

메시지는 맞는데 다음 동작이 이상하면 상태 대입을 확인한다. 최대·최소에서 출력이 사라지면 else if로 서로 다른 책임을 묶었는지 본다. 테스트마다 power·lastVol·음소거 초기값을 적는다.

</details>
