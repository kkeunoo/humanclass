## 2. 코드를 읽을 때 네 가지 질문

입력은 어디서 오는가? 현재 값은 무엇인가? 언제 함수가 실행되는가? 결과가 어디에 남는가? 이 네 가지를 적으면 함수 정의만 읽고 이미 실행됐다고 생각하거나, 화면과 Console 출력을 혼동하는 일을 줄일 수 있다.

예를 들어 addEventListener는 실행할 함수를 연결한다. 클릭 전에는 그 본문이 실행되지 않는다. value를 읽어 변수에 저장한 뒤 입력 칸이 바뀌어도 그 변수가 자동으로 다시 읽지는 않는다. 요청을 보낸 뒤 응답도 아직 오지 않았을 수 있다. 서로 다른 장에 반복되는 이 시점의 차이를 연결해 읽는다.

## 3. 실제 원본과 새 자료를 구분하는 표시

| 표시 | 의미 |
| --- | --- |
| 내 코드 — 원본 발췌 | D 드라이브의 실제 코드·주석과 행 범위 |
| 발췌 바로 풀이 | 해당 코드의 동작·조건·주석 교정 |
| 새 설명 예제 | 개념을 독립 실행하도록 새로 작성 |
| 개선안 | 원본의 오류·한계를 보완한 별도 작성 |
| 개인 학습 메모 | 당시 적은 관찰·질문, 코드 자체와 별도 |
| 📚 출처 · 본문 설명 확인 | 실제 배운 기능의 의미를 공식 자료로 확인 |
| 💡 TIP · 수업 범위 밖 | 선택 학습, 기본 문제의 필수 조건 아님 |

강사님 코드는 차이를 설명할 때 필요한 부분만 인용한다. 양쪽이 같은데 두 코드를 매번 붙이는 방식을 피한다. 내 원본의 오류도 그대로 보존하고 바로 뒤에서 고친 설명과 구별한다.

## 4. 실행 조건과 결과의 신뢰 범위

[책형 복습 파일](실습/README.md)은 장마다 HTML·JS를 함께 제공한다. DOM 예제는 필요한 HTML·CSS도 본문에 있다. 20장 통신 예제는 가상 JSON 파일을 같은 폴더에 두고 로컬 웹으로 제공해야 한다. 경로는 해당 장의 준비 절차를 따른다.

시간·난수·사용자 입력은 환경에 따라 결과가 달라진다. 가상 데이터는 가상이라고 표시하고 실제 서비스 응답과 혼동하지 않는다. 이번 브라우저 검증은 별도의 headless Chrome에서 진행했으며 외부 날씨·AI·웹훅을 실행하지 않았다. 최신 확인 범위는 [검증 기록](../편집기록/03_JavaScript_최종_검증기록.md)에 있다.

## 5. 복습과 이후의 활용

먼저 예측하고, 실행해서 차이를 찾고, 이유를 쓰고, 한 조건만 바꾸어 다시 확인한다. 문제는 [장별 연습문제](실습/연습문제/README.md), 실제 수업 문제의 풀이 비교는 해당 본문 03·04·05·06·12·17장 등에서 읽는다. [실무 스타일](23_JavaScript_실무_코딩스타일.md)과 [종합실습](24_JavaScript_종합실습.md)은 그 배운 문법을 다시 적용하는 새 연습이다.

취업 후 다시 볼 때는 10절의 빠른 정리에서 시작하되 API 이름만 복사하지 않는다. 입력 조건·실행 시점·반환값·변경 대상을 확인한 뒤 현재 프로젝트에 적용한다. 수업 밖 기능이 필요해졌을 때 같은 페이지의 TIP을 다음 학습 목록으로 사용한다.
