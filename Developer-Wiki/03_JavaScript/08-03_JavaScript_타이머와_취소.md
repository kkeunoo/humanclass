# 08-03. 타이머와 취소 — 예약과 실행을 구분하기

[JavaScript 목차](README.md) · [읽기 안내](00_JavaScript_V3_동작_백과_읽기법.md)

함수를 잠시 뒤 한 번 실행하거나 일정 간격으로 반복하도록 예약할 수 있다. 예약 함수의 반환값은 작업 결과가 아니라 그 예약을 취소할 때 쓰는 식별자다.

## 1. 이 장에서 배울 것

setTimeout·setInterval·해제를 연결한다. 함수를 전달하는 것과 즉시 호출하는 것을 구별하고 정확한 실행 시각을 보장하지 않음을 설명한다.

입력·현재 상태·실행 순서·결과를 분리해 설명한다. 실제 수업 원본은 아래에 표시하고, 원본에 없는 선택 학습은 9절 TIP에 둔다.

<a id="concepts"></a>

## 2. 무엇이며, 왜 필요한가

setTimeout(함수,지연)은 한 번 실행을 예약하고 바로 식별자를 반환한다. setInterval은 반복 실행을 예약한다. 지연 단위는 밀리초이며1000ms=1초다. 현재 코드를 멈추고 기다리는 호출이 아니며 실행 중 작업·환경 때문에 더 늦게 실행될 수 있다.

| 예약 | 취소 | 기억할 것 |
| --- | --- | --- |
| setTimeout |clearTimeout(id) |해당한번예약 |
| setInterval |clearInterval(id) |해당반복예약 |

이 장의 식별자 설명은 브라우저 환경 기준이다. 숫자 자체는 예약 순서·환경에 따라 달라져 고정 정답이 아니다. 특정id를 취소해도 다른id의예약까지 모두 취소하지 않는다. 이미 실행한 일을 되돌리는 기능도 아니다.

setTimeout(fn,1000)은 함수 값을 전달한다. setTimeout(fn(),1000)은 인수를 만드는 동안 fn을 먼저 호출하고 그 반환값을 넘긴다. 반복 호출이 안쪽에 있으면 예약하기 전에 동기 재귀가 계속될 수 있다. 이전 장의 함수 참조와 연결되는 핵심이다.

> 📚 **출처 · 본문 설명 확인:** [MDN setTimeout](https://developer.mozilla.org/en-US/docs/Web/API/Window/setTimeout)과 [setInterval](https://developer.mozilla.org/en-US/docs/Web/API/Window/setInterval). 배운 기능의 뜻을 확인한 근거다. 예제·표·풀이 흐름은 수업 코드를 바탕으로 새로 작성했으며 외부 문장을 직접 인용하지 않았다. 확인일: 2026-10-28.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 전체 스크립트.** [HTML 실행 파일](실습/책형_복습/08-03_JavaScript_타이머와_취소.html)과 같은 폴더의 [JS 파일](실습/책형_복습/08-03_JavaScript_타이머와_취소.js)을 함께 내려받는다. HTML을 브라우저로 열고 Console에서 결과를 확인한다. script는 필요한 HTML 뒤에 연결한다. 콘솔 출력은 페이지 본문에 자동으로 쓰이지 않는다.

```javascript
const cancelled = setTimeout(function () {
    console.log('취소된 작업');
}, 100);
clearTimeout(cancelled);
let count = 0;
const interval = setInterval(function () {
    count++;
    console.log(count);
    if (count === 3) {
        clearInterval(interval);
        console.log('끝');
    }
}, 30);
console.log('예약 완료');
```

첫 타이머는 즉시 취소해서 ‘취소된 작업’을 출력하지 않는다. 반복은3회 실행한 뒤 자기 id로 해제한다. 현재 호출이 끝나기 전 ‘예약 완료’가 먼저 출력된다.30ms는 이 예제를 짧게 관찰하려는 설정이며 정확히30·60·90ms에 실행된다고 계약하지 않는다.

**예상 출력 또는 관찰:**

```text
예약 완료
1
2
3
끝
```

## 4. 내가 작성한 코드를 따라 읽기

아래는 원본의 일부다. 원본에 의존하는 앞 선언·HTML·함수는 다음 절의 연결까지 읽는다. 주석의 잘못된 표현도 원문대로 보존하고 설명에서 교정한다.

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_html/javascript/08_function.html` 218–225행

```javascript
            // setTimeout의 return은 예약번호이고, clearTimeout으로 해당 번호를 받아 취소할 수 있음
            let idx = setTimeout(
                function() { console.log("야호!!!!!!!!!!!")}, 
                1000
            )
            console.log(idx)
            // 예약 취소 clearTimeout
            clearTimeout(idx)
```

**발췌 바로 풀이:** 둘 다 1초 예약의 식별자를 idx에 저장한 뒤 즉시 clearTimeout으로 취소한다. 따라서 해당 느낌표 많은 야호는 출력되지 않는다. 앞에서 따로 예약한 3초·4초의 야호까지 모두 취소되는 것은 아니다. 예약마다 식별자가 다르기 때문이다. 식별자 숫자 자체는 환경·예약 순서에 따라 달라져 고정 정답으로 적지 않는다.

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_html/javascript/08_function.html` 243–252행

```javascript
            // 지정한 시간마다 자동으로 반복되게끔 할 수 있음
            let idx2 = setInterval(function() {
                console.log('인터발')
            }, 1000*2)
            // clearInterval(idx2)
            // 10초 있다가 '인터발' 출력 끄기
            // 전달인자 안에 함수를 넣을 수 있으므로, clearInterval을 함수로 하여 초와 같이 넣음
            setTimeout(function(){
                clearInterval(idx2)
            }, 1000*10)
```

**발췌 바로 풀이:** 같은 구조다. 2초 간격의 반복 예약을 만들고 10초 후 해제를 예약한다. 일반적으로 2·4·6·8초 무렵의 실행을 기대하지만, 실제 실행 지연과 10초 경계의 예약 처리 때문에 정확한 출력 횟수를 계약처럼 단정하지 않는다. clearInterval은 이후 반복을 중지하며 이미 실행된 일을 되돌리지 않는다. [MDN setInterval](https://developer.mozilla.org/en-US/docs/Web/API/Window/setInterval)

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_html/javascript/08_function.html` 233–241행

```javascript
            // 리커시브, 재귀호출이라고 함(반복)
            function 기계_1초후_한번더( 함수 ) {
                함수()
                
                setTimeout(
                    기계_1초후_한번더( 함수 ),
                    1000
                )
            }
```

**발췌 바로 풀이:** 양쪽 모두 같은 문제다. setTimeout에 넘길 인수를 계산하면서 `기계_1초후_한번더(함수)`를 즉시 다시 호출한다. 이를 호출하면 1초 간격 예약이 아니라 동기 재귀가 계속되어 호출 스택 한계를 만날 수 있다. **원본 파일에는 이 함수의 바깥 호출이 없으므로 파일을 여는 것만으로 이 오류가 발생하는 것은 아니다.**

내 idx는1초 예약 후 즉시 취소하므로 느낌표 많은 야호가 실행되지 않는다. 앞서 따로 예약한3·4초 타이머까지 취소되는 것은 아니다. idx2는2초 간격의 인터발을 만들고10초 후 해제를 따로 예약한다. 현재 상태와 이미 취소된 예약을 구분한다. 마지막 재귀 정의는 setTimeout 인수에 자기 호출을 넣었지만 원본에는 바깥 호출이 없어 파일을 열자마자 오류 경로가 실행되지는 않는다.

## 5. 선언·호출·파일이 연결되는 흐름

콜백 정의 → 예약 함수 호출 → 식별자 저장 → 현재 코드 계속 → 예약된 콜백 실행 또는 해제 순서다. 원본 rc(cb)는 cb()를 즉시 한 번 호출하고 setTimeout(cb,1000)으로 한 번 더 예약하며 끝없는 재귀가 아니다. rc도 선언만 된 상태다. 원본 기계 함수는 인수 평가 중 자기 호출이 이어지므로 호출하면1초 반복이 아닌 호출 스택 한계를 만날 수 있다.

<a id="review"></a>

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 예약 번호와 해제를 함께 메모했고 반복 종료도 별도 예약으로 연결했다. **실제 오류 경로:** 재귀 함수를 호출하면 함수 참조 대신 즉시 호출한 결과를 전달하는 문제가 발생한다. **개선 방향:** 기본 복습은 setInterval·clearInterval로 유한하게 끝내고 예약마다 id를 구분한다. 호출되지 않은 문제를 현재 파일 전체가 즉시 실패한 것처럼 평가하지 않는다.

개선안은 원본을 수정한 결과가 아니다. 실제 오류, 수업용 단순화, 목적에 따른 선택을 구별해 판단한다.

<a id="teacher"></a>

## 7. 강사님 코드가 도움이 되는 비교



양쪽 예약·취소와 잘못된 재귀 구조가 같아 중복 인용하지 않는다. 정확한 횟수를 단정하기보다 원본의 시간 조건과 경계 실행 순서를 본다.2·4·6·8초 무렵은 기대할 수 있지만10초 해제 경계까지 항상 정확히 몇 회라고 보장하지 않는다.

## 8. 결과를 추적하고 한 가지 바꾸기

| 단계 | 저장·호출 상태 | 출력 |
| --- | --- | --- |
| 첫예약·즉시해제 |cancelled취소 |없음 |
| 반복예약·현재코드 |interval유지 |예약완료 |
| 반복1·2회 |count1·2 |1·2 |
| 반복3회 |count3·clearInterval |3·끝 |

숫자 식별자를 시험 정답으로 쓰지 않는다. 유한한 콜백 횟수 조건으로 끝내는 새 예제와 시간만으로 해제하는 원본은 검증 조건이 다르다.

| 한 가지 변경 | 예상 | 이유 |
| --- | --- | --- |
| count종료값만2 |1·2·끝 |실행횟수조건 |
| 원래간격만100ms |출력순서같고더늦게 |시간변경 |
| 첫clearTimeout만제거 |취소된작업도출력가능 |독립예약남음 |

예약했는데 아직 안 나오면 현재 동기 작업이 끝났는지 본다. 타이머가 안 멈추면 해제한 id와 반복 id가 같은지 확인한다. 문구가 안 나왔다고 예약 함수의 반환이 작업 결과라고 생각하지 않는다.

3. 정의에 문제가 있는데 원본이 즉시 멈추지 않는 이유는?

<details>
<summary>짧은 풀이 — 먼저 답한 뒤 확인</summary>
