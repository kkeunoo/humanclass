# 09. 화살표 함수 — 줄여 써도 반환을 확인하기

[JavaScript 목차](README.md) · [읽기 안내](00_JavaScript_V3_동작_백과_읽기법.md)

화살표 함수는 함수 값을 표현하는 문법이다. 짧게 쓸 수 있지만 괄호·중괄호·return의 역할을 생략해서 이해하면 결과가 달라질 수 있다. 별도 TV 실습의 일반 function을 모두 화살표로 바꾸는 것이 목표는 아니다.

## 1. 이 장에서 배울 것

블록 본문과 식 본문의 반환을 구분한다. 쉼표 반환과 여러값 출력, 원본 문장 경계 오류를 설명한다.

입력·현재 상태·실행 순서·결과를 분리해 설명한다. 실제 수업 원본은 아래에 표시하고, 원본에 없는 선택 학습은 9절 TIP에 둔다.

<a id="concepts"></a>

## 2. 무엇이며, 왜 필요한가

const add=(a,b)=>a+b는 두 값을 받아 더한 결과를 반환하는 함수 값을 add에 담는다. (a,b)=>{return a+b;}처럼 블록으로도 쓸 수 있다. 블록을 쓰면서 return을 지우면 내부 계산값이 자동 반환되지 않는다.

| 형태 | 읽는 법 |
| --- | --- |
| (a,b)=>{return a+b;} |블록의 명시적 반환 |
| (a,b)=>a+b |식 결과를 반환 |
| a=>a+100 |단순 매개변수 하나라 괄호 생략 |
| ()=>{...} |매개변수가 없어도 괄호 필요 |

return a,b는 두 값 묶음을 반환하는 문법이 아니라 쉼표 연산자의 마지막 값 b를 반환한다. console.log(a,b)의 여러 인자 출력과 다르다. 여러 값을 묶어 돌려주려면 이미 배운 배열을 사용하는 return[a,b] 같은 새 재구성을 생각할 수 있다.

조건에 따라 return을 여러 곳에 적을 수 있다. 한 호출은 실행 중 return을 만나면 끝나므로 그 뒤 같은 경로가 실행되지 않는다는 뜻이지 함수 안에 return을 한 번만 써야 한다는 규칙은 아니다.

> 📚 **출처 · 본문 설명 확인:** [MDN 화살표 함수](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Functions/Arrow_functions)와 [쉼표 연산자](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Comma_operator). 배운 기능의 뜻을 확인한 근거다. 예제·표·풀이 흐름은 수업 코드를 바탕으로 새로 작성했으며 외부 문장을 직접 인용하지 않았다. 확인일: 2026-10-28.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 전체 스크립트.** [HTML 실행 파일](실습/책형_복습/09_JavaScript_화살표함수와_TV상태관리.html)과 같은 폴더의 [JS 파일](실습/책형_복습/09_JavaScript_화살표함수와_TV상태관리.js)을 함께 내려받는다. HTML을 브라우저로 열고 Console에서 결과를 확인한다. script는 필요한 HTML 뒤에 연결한다. 콘솔 출력은 페이지 본문에 자동으로 쓰이지 않는다.

```javascript
const block = (a, b) => {
    return a + b;
};
const expression = (a, b) => a + b;
const noReturn = (a, b) => {
    a + b;
};
console.log(block(2, 3));
console.log(expression(2, 3));
console.log(noReturn(2, 3));
```

세 함수는 같은2·3을 받지만 마지막은 계산만 하고 반환하지 않는다. 짧은 식 본문과 return이 있는 블록은5를 반환한다. 함수 정의만 있을 때는 결과 출력이 없으므로 아래 호출까지 함께 읽는다.

**예상 출력 또는 관찰:**

```text
5
5
undefined
```

## 4. 내가 작성한 코드를 따라 읽기

아래는 원본의 일부다. 원본에 의존하는 앞 선언·HTML·함수는 다음 절의 연결까지 읽는다. 주석의 잘못된 표현도 원문대로 보존하고 설명에서 교정한다.

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_html/javascript/09_arrow.html` 45–51행

```javascript
            const fn5 = (a, b) => {
                return a + b
            }
            // 실행문 안에 return만 있는 경우 실행 블럭의 {}중괄호, return 생략 가능
            // {}를 생략한 경우 return도 반드시 생략해야 함
            const fn6 = (a, b) => a + b
            const fn7 = a => a + 100
```

**발췌 바로 풀이:** 같은 실험이다. fn5와 fn6를 (2,3)으로 호출하면 5, fn7을 (2)로 호출하면 102다. 이 발췌에는 선언만 있으며 결과를 보기 위해서는 호출이 필요하다.

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_html/javascript/09_arrow.html` 12–24행

```javascript
            const fn1 = function(a, b) {
                console.log(a, b)
                return a, b
                // return은 1번만 써야 한다
                // return a, b
            }
            fn1(1, 2)
            
            // 아래와 같은 형태로 변수 선언 없이 실행하게도 할 수 있음
            (function(a, b) {
                console.log(a, b)
                return a, b
            })(1, 2) // ()는 실행의 괄호이기 때문에 앞에 있는 것 실행
```

**발췌 바로 풀이:** 두 파일 모두 fn1(1,2) 다음 문장이 괄호로 시작한다. 앞 호출 뒤 세미콜론이 없어 줄바꿈만으로 문장이 끝나지 않고, 반환값 2를 다시 함수처럼 호출하려 한다. 따라서 TypeError로 중단되어 뒤의 화살표 선언까지 정상적으로 진행하지 못한다. **fn1(1,2);처럼 세미콜론을 붙여 경계를 명시하면 교정된다.** 수정 파일의 성공 결과와 원본 실패를 구분한다.

내 fn5·fn6는 위 두 올바른 반환 형태이며 (2,3)으로 호출하면5다. fn7(2)는102다. 발췌에는 선언만 있어 호출을 추가해야 관찰된다. 앞 원본 fn1·fn2의 return a,b는 b를 반환한다. 내 ‘return은1번’ 주석은 조건별 반환과 호출 종료를 구분해 교정한다.

<a id="connections"></a>

## 5. 선언·호출·파일이 연결되는 흐름

함수 표현식 → 변수에 함수 값 저장 → 인수 전달 → 본문 식 또는 return → 호출 결과 순서다. 원본 앞부분의 fn1(1,2) 뒤에는 세미콜론 없이 괄호로 시작하는 즉시 호출 문장이 이어진다. 줄바꿈만으로 문장이 끝나지 않아 반환된2를 다시 함수처럼 호출하려고 하며 TypeError로 중단될 수 있다. 앞 호출 뒤에 세미콜론을 넣어 문장 경계를 명시하는 것은 새 개선안이다.

<a id="review"></a>

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 축약 형태와 호출 괄호의 뜻을 주석으로 남겼다. **실제 오류:** 원본 전체는 문장 경계 때문에 뒤의 화살표 선언까지 정상 진행하지 못한다. **별도 오류 경로:** fn4는 매개변수 없이 외부 a를 읽는데 이 파일에 a가 없어 앞 오류를 고친 뒤 호출하면ReferenceError다. 현재 fn4는 선언만 되어 있다. **개선 방향:** 축약 전 정상 반환을 확인하고 원본 실패와 교정본 성공을 분리한다.

개선안은 원본을 수정한 결과가 아니다. 실제 오류, 수업용 단순화, 목적에 따른 선택을 구별해 판단한다.

<a id="teacher"></a>

## 7. 강사님 코드가 도움이 되는 비교



양쪽의 축약 형태와 앞 문장 경계 문제가 같아 중복 인용하지 않는다. 강사님 코드도 같은 조건에서 검토한다. 함수가 짧다는 이유만으로 본문이 더 명확해지는 것은 아니며, 상태 변경이 많으면 여러 문장으로 풀어 쓰는 것이 적합할 수 있다.

<a id="results"></a>

## 8. 결과를 추적하고 한 가지 바꾸기

| 코드 | (2,3) 호출 결과 | 이유 |
| --- | --- | --- |
| return a+b |5 |합 반환 |
| 식 본문 a+b |5 |식 결과 반환 |
| 블록 안 a+b만 |undefined |반환 없음 |
| return a,b |3 |마지막 표현 값 |

원본 fn1(1,2)의 반환은2다. 숫자를 출력한 것, 숫자를 반환한 것, 반환한 숫자를 다시 호출하려다 실패한 것은 서로 다른 단계다.

| 한 가지 변경 | 예상 | 이유 |
| --- | --- | --- |
| noReturn에return 추가 |마지막5 |명시적 반환 |
| expression의+만*로 |두번째6 |식 계산 변경 |
| block 인수만4,3으로 |첫번째7 |해당 호출 입력 변경 |

undefined이면 중괄호 안 return을 확인한다. 뒤 함수 선언이 보이는데 사용할 수 없다면 앞에서 실행이 중단되었는지 본다. 줄바꿈이 모든 문장의 끝을 보장하는 것은 아니다.

## 9. 추가로 알면 좋은 것과 출처

> 💡 **TIP · 수업 범위 밖:** this·arguments·생성자와 일반 함수의 상세 차이, 고급 즉시 실행 패턴은 추가 학습이다. 모든 function을 화살표로 바꿔도 동작이 같다는 뜻은 아니다.



이 절의 확장은 기본 문제의 필수 조건이 아니다. 📚 출처가 있다는 것과 수업 밖 기능이라는 것은 다른 구분이다.

2. return a,b는 두 값 반환인가?
3. 괄호 시작 문장 앞에서 어떤 경계를 확인하는가?

<summary>짧은 풀이 — 먼저 답한 뒤 확인</summary>

명시적 반환이 없으면undefined다. 쉼표의 마지막 값만 반환한다. 앞 호출 끝의 세미콜론 등 문장 경계를 확인한다.
