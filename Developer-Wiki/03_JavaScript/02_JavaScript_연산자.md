# 02. 연산자 — 식이 내놓는 값과 변수 변화

[JavaScript 목차](README.md) · [읽기 안내](00_JavaScript_V3_동작_백과_읽기법.md)

## 2. 무엇이며, 왜 필요한가

+·-·*·/·%는 수업의 산술 연산이다. /는 정수끼리도 소수 결과를 낼 수 있고,%는 나머지를 구한다. +=는 기존 값에 더해 다시 저장한다. +는 문자열 연결도 하므로 앞 장의 자료형 구분을 함께 쓴다.

`k++`는 현재 값을 식에 제공하고 k를1늘린다. `++k`는 k를1늘린 값을 식에 제공한다. **둘 다 변수를 즉시 바꾸며**, 후위가 식 전체 종료까지 변경을 미룬다는 뜻은 아니다. 전위·후위는 위치의 구분이고 둘 다 피연산자가 하나인 단항 연산자다.

| 종류 | 결과의 역할 | 예 |
| --- | --- | --- |
| 대입 | 변수 저장 | price+=20 |
| 비교 | 참거짓 | 3==='3'은false |
| 논리 | 조건 결합·반전 | true&&false는false |
| 삼항 | 조건에 따른 값 선택 | 짝수?'짝':'홀' |

==는 이 예제의 숫자·문자열을 변환해 비교하지만===는 자료형이 다르면 같다고 하지 않는다. &&·||는 불리언끼리 사용하면 참거짓을 조합하며, 모든 값에서 반드시true/false만 반환하는 것으로 일반화하지 않는다. 삼항은 출력 함수가 아니라 선택한 값을 만드는 식이다.

> 📚 **출처 · 본문 설명 확인:** [MDN 증감](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Increment)와 [엄격 동등](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Strict_equality). 배운 기능의 뜻을 확인한 근거다. 예제·표·풀이 흐름은 수업 코드를 바탕으로 새로 작성했으며 외부 문장을 직접 인용하지 않았다. 확인일: 2026-10-28.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 전체 스크립트.** [HTML 실행 파일](실습/책형_복습/02_JavaScript_연산자.html)과 같은 폴더의 [JS 파일](실습/책형_복습/02_JavaScript_연산자.js)을 함께 내려받는다. HTML을 브라우저로 열고 Console에서 결과를 확인한다. script는 필요한 HTML 뒤에 연결한다. 콘솔 출력은 페이지 본문에 자동으로 쓰이지 않는다.

```javascript
let k = 10;
let before = k++;
console.log(before, k);
k = 10;
let after = ++k;
console.log(after, k);
console.log(3 == '3', 3 === '3');
let num = 7;
let result = num % 2 === 0 ? '짝수' : '홀수';
console.log(result);
```

before에는 증가 전 10이 들어가지만 첫 출력 시 k는 이미 11이다. 다시 10으로 초기화한 뒤 after에는 증가 후 11을 넣는다. 숫자 3도 문자열 3과 엄격 비교하면 false다. num 7의 나머지는 1이어서 삼항은 홀수를 선택하고, 그 값을 result에 저장한 뒤 출력한다.

**예상 출력 또는 관찰:**

```text
10 11
11 11
true false
홀수
```

```javascript
            //단항(++k_더하기를 먼저 함), 이항(k++_더하기를 뒤에 함)연상자의 차이
            // ex) -5(단항), 7-5(이항)
            k = 10;

            console.log('k', k)

            k = 10;
            console.log('++k', ++k)
            console.log('k', k)

            k = 10;
            let m = k++ + 1;

            //++k에서 k가 11이 된 이후에 값이 뒤로 넘어가기때문에 뒤에 있는 k도 11이 되어있고
            //k가 11인 상태에서 ++하기 떄문에 12가 출력됨
            k = 10;
            m = ++k + k++
            console.log(`m: ${m}, k: ${k}`)
            
            //--나 ++는 계산할 때 우선으로 바로 적용하고, 뒤에++ 또는 --는 계산 후 그 다음값에 적용
            //k가 10에서 뒷--가 되어 9로 넘어간 상태에서 앞++하여 10, 그 다음에 앞--되어 9가 됨
            k = 10;
            m = k-- + ++k - --k
            10 + 10 - 9
            console.log(`m: ${m}, k: ${k}`)
```

**발췌 바로 풀이:** 내 주석은 계산 과정을 따라가려는 점이 좋다. 다만 25행의 ‘단항/이항 차이’는 **전위/후위 차이**로 바로잡아야 한다. ++k와 k++는 둘 다 피연산자가 하나인 단항 연산자다. 또한 후위도 변수를 즉시 변경한다. 다만 식에 제공하는 값이 변경 전 값이다. 식 전체가 끝날 때까지 변수 변경을 미루는 것으로 이해하면 틀린다. [MDN 증감 연산자](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Increment)


**발췌 바로 풀이:** 17,000원에서는5천원3장·천원2장으로 맞다. 다만17,500원으로 바꾸면 천원 부분이2.5가 되어 장수의 정수 조건을 지키지 못한다. 원래 입력의 정답과 확장 입력의 한계를 나누고, 천원 몫과 최종 잔액도 따로 구한다.

첫 발췌의 `m=++k+k++`는 k가 10일 때 왼쪽이 11을 주고 k는 11, 오른쪽이 11을 주고 k는 12가 된다. 따라서 m=22·k=12다. 다시 k=10으로 시작한 `k--+ ++k- --k`는 식에 10·10·9를 제공해 m=11·k=9다. 내 별도 줄 `10+10-9`는 값을 계산만 하며 저장·출력하지 않는다. 메모라면 주석으로 표시하는 편이 의도가 명확하다.

비교 발췌는 n=3·o='3'에서 typeof가 number·string임을 확인하고, 짝수 2와 홀수 1의 양쪽 삼항 결과를 출력한다. ‘숫자와 문자여도 값이 같음’은 이 입력의 느슨한 비교를 설명한 말이지 모든 값이 같다는 뜻은 아니다.

나머지 원본 계산은 10,000원/4,800원→2잔·400원, 8,000원 15% 할인→6,800원, 1234의 백 단위 버림→1200, 1000/794를 소수 둘째 자리까지 남겨 버림→1.25다. 마지막 17,000원의 지폐 풀이에서는 5천원 3장·천원 2장을 구한다. 이 문제들은 입력 단위와 몫·나머지를 연결한다.

## 5. 선언·호출·파일이 연결되는 흐름

선언된 값 → 각 피연산자 평가 → 연산 결과 → 대입 또는 출력 순서다. 원본 k는 앞에서 선언되어 있고 발췌는 그 뒤 대입부터 시작한다. 그 부분만 별도 파일로 옮길 때는 let k를 준비한다. 계산식이 console.log 괄호 안에 있어도 먼저 식이 평가되고 그 결과가 출력 인자가 된다.

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 내 풀이에는 잔·원·장 단위와 짝수·홀수 양쪽 시험이 있다. **교정:** 단항/이항 메모를 전위/후위로 바꿔 이해한다. **한계:** 17,500원으로 바꾸면 내 천원 계산은 2.5장을 만들 수 있다. 원래 17,000원 조건의 정답과 다른 입력의 한계를 분리한다. **개선 방향:** 실제 코드에서는 복합 증감식보다 변화 단계를 나누고 천원 몫·최종 잔액도 구한다.

개선안은 원본을 수정한 결과가 아니다. 실제 오류, 수업용 단순화, 목적에 따른 선택을 구별해 판단한다.

```javascript
        // 문제3
        // 1234를 10의 자리 이하 버림
        // 결과 : 1200
        let q3_value = 1234
        let q3_1 = q3_value / 100 // 12.34
        let q3_2 = parseInt(q3_1) // 12
        let q3_3 = q3_2 * 100
        let q3_4 = parseInt(q3_value / 100) * 100
        console.log(q3_3)

        // 문제4
        // 두 값 1000, 794가 있을 때
        // 1000 / 794의 결과를 소수점 2자리 까지만 출력
        // 결과 : 1.25
```

위 강사님 발췌는 버림 계산을 중간 변수로 나누어 보여 주어 처음 읽을 때 도움이 된다. 같은 결과를 내 한 줄 식으로 바꿀 수 있지만 오류가 나면 중간값을 확인하는 방식이 유익하다. 구매·할인 코드는 결과가 같아 중복 인용하지 않는다. 짧은 식과 긴 식 중 어느 쪽이 항상 우수한 것이 아니라 독자가 단계를 찾을 수 있는지가 기준이다.

## 8. 결과를 추적하고 한 가지 바꾸기

| 단계 | 식에 제공한 값 | 그 직후 k |
| --- | --- | --- |
| k=10에서 ++k |11 |11 |
| 이어서 k++ |11 |12 |
| 둘을 더해 m 저장 |22 |12 |

할인 계산은 할인액 8,000×15/100=1,200원을 먼저 구하고 원가에서 뺀다. 소수 둘째 자리 예제는 반올림이 아닌 버림이다. 각각 다른 요구사항이므로 결과만 외우지 않는다.

| 한 가지 변경 | 예상 | 이유 |
| --- | --- | --- |
| 작은 예제 k초기값만20 |20·21 /11·11 | 두 번째는다시10으로초기화 |
| num만8 |짝수 |나머지0 |
| 3==='3'의문자열만숫자로 |true |같은숫자값·자료형 |

전위·후위를 식 전체 전후의 변경으로 기억하면 복합식이 틀린다. 각 표현을 평가한 직후의 변수값을 적는다. 17,500원 지폐 복습은 5천원 3장·천원 2장·잔액 500원이며 소수 장수를 정답으로 쓰지 않는다.
