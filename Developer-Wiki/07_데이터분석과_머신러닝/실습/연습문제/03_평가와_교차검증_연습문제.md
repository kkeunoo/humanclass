# 03. 평가와 교차 검증 — 어떤 자료로 얻은 점수인지 끝까지 구별하기 — 연습문제

[본문](../../03_평가와_교차검증.md) · [문제 목차](README.md)

실제 수업 내용을 바탕으로 **새로 구성한 연습문제**다. 원본·당시 내 코드·새 개선안을 구별한다. 예상 → 이유 → 한 가지 변경 순서로 푼다.

## 목표와 준비

F1과 ROC AUC에 들어가는 자료를 구별하고 작은 표로 결과를 계산한다. 교차 검증의 반복 학습, 후보 조합 수와 fold 수의 차이, best_score_와 독립 시험 점수의 차이를 설명한다. 원본 주석보다 실제 인자를 기준으로 평가 범위를 읽는다.

[본문 3절](../../03_평가와_교차검증.md#example)의 폴더·설치·입력·실행 조건부터 확인한다. 아래 필요한 파일 전체를 같은 구조로 저장한다. 가져오는 함수·모델 정의도 빠뜨리지 않는다.

## 문제 1. 실행 결과 예상

**example.py**

```python
from sklearn.metrics import f1_score, roc_auc_score

y_true = [0, 0, 1, 1]
pred = [0, 1, 1, 0]
positive_scores = [0.1, 0.8, 0.9, 0.4]
print('F1:', f1_score(y_true, pred))
print('AUC:', roc_auc_score(y_true, positive_scores))
print('모두 0의 F1:', f1_score(y_true, [0, 0, 0, 0]))
print('동점 점수의 AUC:', roc_auc_score(y_true, [0.5, 0.5, 0.5, 0.5]))
```

실행 전에 결과를 먼저 적는다. 자료의 모양·분류 결과·확률·점수·현재 변수의 대상을 구별한다.

<details>
<summary>풀이</summary>

```text
F1: 0.5
AUC: 0.75
모두 0의 F1: 0.0
동점 점수의 AUC: 0.5
```

같은 y_true를 두 함수에 전달하되 비교 대상은 다르게 준다. 첫 F1은 최종 0·1 답, 첫 AUC는 클래스 1 점수다. 세 번째 출력은 실제 양성 두 행을 전부 놓쳐 F1이 0이다. 네 번째는 모든 행의 점수가 같아 순서로 클래스를 구별하지 못한 경우다.

한 지표만 올리는 요령을 찾는 예제가 아니다. 실제 양성의 정의와 어떤 예측 표현을 평가하는지를 먼저 설명하기 위한 예제다. 여기에는 학습 코드가 없으므로 새 모델을 만든 결과라고 부르지 않는다.

새 4행 표의 정답을 바꾸지 않고 추적한다.

| 개수 | 해당 행 | 값 |
| --- | --- | ---: |
| 진짜 1을 1로 찾음 | C | 1 |
| 실제 0을 1로 고름 | B | 1 |
| 실제 1을 놓침 | D | 1 |
| 정밀도 | C / (B+C) | 0.5 |
| 재현율 | C / (C+D) | 0.5 |
| F1 | 두 비율의 조화평균 | 0.5 |
| AUC | 양성·음성 점수 4쌍 비교 | 0.75 |

**원본 사본의 현재 실행 기록:** 기본 시험 F1은 양쪽 모두 0.75, AUC는 약 0.955419다. GridSearchCV의 선택 평균은 내 cv=5에서 약 0.523452, 강사님 cv=3에서 약 0.483615다. 둘 다 이번에는 max_depth=None·나무 50개를 골랐지만 비교 조건은 다르다. 마지막 전체 자료 skf 평균은 약 0.600428이며 기본 시험 F1이나 선택 평균과 같은 대상의 점수가 아니다. 이 숫자들은 실제 수업 자료와 현재 환경의 기록이지 모든 환경의 고정 정답은 아니다.

</details>

## 문제 2. 이유 설명

1. 새 4행 표에서 F1과 AUC는 각각 얼마이며 왜 다른가?
2. 후보 6개·cv=5면 후보 비교 학습은 몇 번인가?
3. 원본 마지막 점수와 앞 점수를 그대로 비교할 수 없는 이유는?

<details>
<summary>풀이</summary>

1. 0.5와 0.75다. 최종 답의 양성 탐지와 점수 순위가 다르다.
2. 30번이며 기본 refit의 마지막 재학습은 별도다.
3. 학습 부분에서 전체 자료로 대상이 바뀌고 분할·선택 이력도 달라졌다.

</details>

## 문제 3. 한 가지만 바꾸기

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| 최종 답만 모두 0으로 | F1 0 | 실제 양성을 못 찾음 |
| 확률 점수를 모두 동점으로 | AUC 0.5 | 순위를 구분하지 못함 |
| 후보는 유지·cv를 3으로 | 후보 6개 그대로, 비교 학습 18번 | 후보 수와 fold 수는 다름 |
| 기본 refit을 False로 | best_estimator_를 기본처럼 사용 못 함 | 선택 후 전체 재학습을 하지 않음 |
| 마지막 입력을 학습 부분으로 유지 | 평가 대상이 일관됨 | 처음 시험 행을 선택에 다시 넣지 않음 |

<details>
<summary>막힐 때 확인</summary>

한 클래스만 있는 평가 부분은 AUC를 정의하기 어렵다. 실제 0·1 개수를 먼저 확인한다. 확률 배열 모양 오류라면 두 열 전체를 전달했는지 살핀다. best_estimator_가 없다면 fit 여부와 refit 설정을 확인한다. 오래 걸리면 후보 수×fold 수×나무 수가 만드는 일을 계산하고 무조건 병렬 옵션부터 추가하지 않는다.

</details>

## 채점과 복습

정상 출력뿐 아니라 입력 열·정답·분할·평가 대상의 차이도 설명한다. 새 예제는 독립 실행이며 실제 와인 점수와 구별한다. TIP 확장은 필수 조건이 아니다. 정의→입력→호출→반환→다음 평가의 흐름을 연결한다.
