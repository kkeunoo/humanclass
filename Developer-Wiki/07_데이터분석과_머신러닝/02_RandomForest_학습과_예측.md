## 1. 이 장에서 배울 것

모델 생성·학습·예측을 구별한다. 나무 수·깊이·난수 상태가 서로 다른 설정임을 설명하고 한 와인도 2차원 표로 보내는 이유를 이해한다. predict의 클래스와 predict_proba의 클래스별 점수를 읽되 맞았다는 증거로 혼동하지 않는다.

## 2. 무엇이며, 왜 필요한가

### 모델은 답을 저장하는 변수와 어떻게 다른가?

일반 함수는 개발자가 조건을 직접 적을 수 있다. 예를 들어 알코올 값이 특정 수 이상이면 1이라는 규칙을 작성하는 식이다. 지도 학습 모델은 입력과 정답 쌍을 보고 예측에 사용할 관계를 맞춘다. 여기서 지도라는 말은 정답 y를 제공한다는 뜻이다. 아무 자료나 넣으면 의미를 스스로 이해하는 프로그램이라는 뜻은 아니다.

결정나무는 입력 값에 관한 조건을 차례로 적용해 가지를 나누는 모델이다. “알코올이 어떤 경계보다 큰가?” 같은 질문 뒤 다음 질문으로 이동한다고 떠올릴 수 있다. 이 질문과 경계를 학습 자료로 정한다. 이는 구조를 설명하는 비유이며 아래 숲에 실제로 그 질문이 들어갔다고 단정한 것은 아니다.

### 왜 나무를 여러 개 사용할까?

한 나무가 특정 학습 자료의 작은 차이에 민감할 수 있다. RandomForest는 무작위성을 사용해 여러 나무를 만들고 그 결과를 모은다. scikit-learn의 이 분류기는 나무들의 클래스별 확률을 평균하여 최종 분류에 사용한다. “100명이 투표한다”는 비유는 이해의 출발점이지만 언제나 단순한 딱딱한 표 수와 같다고 계산하면 안 된다.

| 설정 | 묻는 질문 | 뜻 |
| --- | --- | --- |
| n_estimators=100 | 몇 나무를 만들까? | 나무 개수 |
| max_depth | 질문을 얼마나 깊게 이어 갈까? | 한 나무의 최대 깊이 |
| random_state=42 | 무작위 선택을 어떻게 되풀이할까? | 비교를 위한 난수 상태 |

나무를 늘리면 여러 판단을 모으는 변동을 줄이는 데 도움이 될 수 있지만 계산도 늘어난다. 입력이 잘못되었거나 평가 대상이 달라졌거나 같은 자료만 외우기 쉬운 설정이라면 나무 수 증가가 그 문제를 해결하지 않는다. 그러므로 **많을수록 무조건 높은 점수**라는 규칙은 없다. random_state는 이 실험을 같은 조건에서 비교하기 위한 것이며 좋은 모델을 골라 주는 번호가 아니다.

### fit·predict·predict_proba는 다른 단계다

생성자는 아직 학습 전인 모델 객체를 만든다. `fit(X_train, y_train)`을 호출하면 그 객체가 학습되어 이후 예측에 쓸 상태를 가진다. predict는 새 입력의 분류 결과를, predict_proba는 각 클래스의 확률 형태 점수를 돌려준다. 예측을 호출했다고 새 와인의 정답으로 모델을 다시 학습한 것은 아니다.

확률 배열의 열 순서는 학습한 클래스 목록 `classes_`로 확인한다. 이 수업의 0·1이면 보통 0, 1 순서다. 예를 들어 `[[0.7, 0.3]]`은 한 행에 클래스 0 점수 0.7, 클래스 1 점수 0.3이라는 뜻이다. 이것만으로 실제 좋은 와인일 확률이 완벽하게 보정되었다거나 정답을 70% 맞혔다고 말할 수는 없다.

> 📚 **출처 · 본문 설명 확인:** [RandomForestClassifier](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.RandomForestClassifier.html) · [숲 모델 설명](https://scikit-learn.org/stable/modules/ensemble.html#forest). 배운 의미 확인 근거다. 아래 표·전체 예제·풀이를 외부 문장 그대로 옮기지 않았다. 확인일: 2026-10-30.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 필요한 파일 전체.** 같은 장의 폴더 구조를 유지한다. pandas와 scikit-learn이 있는 환경에서 example.py를 실행한다. 외부 CSV 없이 구조를 확인하는 가상 자료이며 실제 와인 품질을 설명하는 모델이 아니다. 원본과 같은 나무 100개·random_state=42를 사용한다.



**[example.py](실습/책형_복습/02_RandomForest_학습과_예측/example.py) — 새 예제 전체 파일**

```python
import pandas as pd
from sklearn.ensemble import RandomForestClassifier

X_train = pd.DataFrame({'alcohol': [8, 8, 8, 8, 13, 13, 13, 13]})
y_train = [0, 0, 0, 0, 1, 1, 1, 1]
model = RandomForestClassifier(n_estimators=100, random_state=42)
learned = model.fit(X_train, y_train)
new_wines = pd.DataFrame({'alcohol': [8, 13]})
pred = model.predict(new_wines)
proba = model.predict_proba(new_wines)
print('같은 모델:', learned is model)
print('클래스:', model.classes_.tolist())
print('입력 모양:', new_wines.shape)
print('분류:', pred.tolist())
print('확률 모양:', proba.shape)
print('각 행 합:', proba.sum(axis=1).round(6).tolist())
```

학습 자료는 두 알코올 값과 정답을 반복해 만든 작은 예제다. 이 값으로 실제 와인의 좋은 기준을 주장하지 않는다. fit의 반환을 learned에 받아 같은 모델인지 확인했다. 별도 모델을 새로 만든 것이 아니라 학습된 model 자신을 돌려준다.

새 와인은 두 행·한 열이다. predict 결과에는 두 답이 있고 확률 배열에는 두 행·두 클래스 열이 있다. sum(axis=1)은 한 행 안의 클래스 점수 합을, round는 표시를 단순하게 하는 새 확인 도구다. 원본에서 사용했다고 인용하지 않는다. 같은 자료와 같은 값으로 만든 학습 예제의 성공은 독립 성능 평가가 아니다.

**실행 결과:**

```text
같은 모델: True
클래스: [0, 1]
입력 모양: (2, 1)
분류: [0, 1]
확률 모양: (2, 2)
각 행 합: [1.0, 1.0]
```

## 5. import·함수·입력·출력이 연결되는 흐름

| 단계 | 정의·입력 | 상태 또는 반환 | 뒤에서 쓰는 곳 |
| --- | --- | --- | --- |
| import | sklearn.ensemble의 클래스 | 모델 생성자를 사용 가능하게 함 | 생성 |
| 생성 | 나무 수·난수 상태 | 학습 전 model | fit |
| fit | 학습 입력과 정답 | 학습된 model 자신 | 예측 |
| DataFrame | 한 행 값·열 이름 | 입력 표 wine_df | 두 예측 메서드 |
| predict | 같은 입력 구조 | 행당 한 클래스 | 새 입력 설명·F1 |
| predict_proba | 같은 입력 구조 | 행 × 클래스 점수 | 설명·ROC AUC |

메서드는 객체에 속한 함수다. model.fit과 model.predict는 같은 model의 학습 상태를 연결한다. pandas와 sklearn에서 import한 것은 라이브러리의 공개 도구이며 이 원본에 숨겨진 사용자 def가 있는 것은 아니다. 다음 평가 장에서는 wine_df가 아니라 X_test를 예측해 y_test와 비교한다.

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** fit 전에 입력과 정답을 나눴고 새 입력에도 열 이름을 붙였다. predict와 확률의 출력도 따로 메모했다. 원본의 주석이 새 와인 한 행을 읽는 출발점이 된다.

**아쉬운 점:** 나무 수 증가와 재현성 메모가 섞였고 예전 확률 수치가 언제나 나오는 답처럼 보일 수 있다. 생성·학습·새 입력·성능 평가를 이름과 출력 제목으로 더 분명히 나누면 좋다.

**개선 방향:** 새 입력을 만든 뒤 열 이름·순서·행 수를 먼저 확인한다. 확률 열은 classes_를 함께 보고 해석한다. 주석의 출력 옆에 데이터·환경·설정 조건을 기록한다. 당시 모델을 바꾸지 않고 아래 실험과 새 예제에서 이 확인을 보완했다.

원본 오류·수업용 단순화·목적에 따른 설계를 나눈다. 새 개선안은 당시 내 코드나 D 드라이브 수정본이 아니다.

## 8. 결과를 추적하고 한 가지 바꾸기

| 원본의 흐름 | 자료 모양 | 의미 |

| wine_pred | (1,) | 한 클래스 |
| wine_prob | (1, 2) | 한 행의 두 클래스 점수 |

행 수는 입력과 출력에 연결되지만 출력 열 수는 입력 특성 수와 다르다. 11개 특성을 넣었다고 확률이 11개 나오는 것은 아니다.

**실제 원본을 사본으로 재실행한 값 — 2026-10-30, pandas 3.0.5·scikit-learn 1.9.1:**

| 원본의 수동 와인 | predict | predict_proba: 0, 1 순서 |
| --- | --- | --- |
| 내 값 | [0] | [[0.59, 0.41]] |
| 강사님 값 | [1] | [[0.34, 0.66]] |

동일한 학습 자료·기본 모델로 학습했지만 새 입력 값은 다르다. 이 표는 현재 사본 실행 기록이며 위 작은 가상 표의 출력과 별개다. 두 답 중 하나가 더 좋은 구현이라는 평가도 아니다. 실제 이 새 와인의 정답을 여기서 측정한 것은 아니다.

| 한 가지만 변경 | 확인할 것 | 결론을 내릴 때 주의 |
| --- | --- | --- |
| 새 입력을 두 행으로 | 분류 2개·확률 2행 | 행별 결과가 늘어남 |
| n_estimators를 50으로 | 학습 시간·시험 점수 | 반드시 점수가 내려가지는 않음 |
| 열 이름 하나 변경 | 입력 구조 검사 | 숫자 개수만 같아도 의미가 다름 |
| fit 전에 predict | 미학습 오류 | 생성과 학습은 다른 단계 |
| random_state만 변경 | 나무와 예측의 변화 가능성 | 항상 모든 답이 바뀌는 것은 아님 |

2차원 입력을 요구하는 오류라면 한 행을 [값들]로만 보냈는지 본다. 열 수·이름 오류라면 X의 열과 새 표를 비교한다. 미학습 오류라면 실제 같은 객체에 fit을 호출했는지 본다. 높은 확률이 틀렸다면 확률 값만으로 정답이 보장되는 것은 아니므로 정답이 있는 별도 평가 자료를 확인한다.

**확인 범위:** 작은 새 예제를 임시 폴더에서 독립 실행해 위 출력을 확인한다. 원본 CSV의 모양·분할·모델 결과 검사는 별도 보고서에 기록한다. 원본 주석의 옛 점수와 이번 실행값을 구별한다. 기존 수업 가상환경과 D 드라이브 소스는 읽기만 하며 새 패키지나 생성물을 쓰지 않는다.

## 9. 추가로 알면 좋은 것과 출처

> 💡 **TIP · 수업 범위 밖:** 확률 보정, 각 특성의 기여도 해석, 모델 저장·배포, 다른 분류기 비교는 추가 학습이다. 숲의 표본 추출·특성 무작위 선택 원리를 더 깊이 공부하고 싶다면 위 공식 숲 모델 설명을 읽는다. 현재 복습의 기본 목표는 생성→학습→같은 입력 구조의 예측이다.

확인한 라이브러리 의미와 수업 밖 확장을 구분한다. 위 출처는 본문의 설명 근거이며 TIP에 적힌 새 주제를 이미 배운 것으로 간주하지 않는다.

## 10. 복습과 빠른 정리

1. 나무 100개와 random_state=42는 같은 목적의 설정인가?
2. 한 행의 입력 특성 11개와 확률 열 2개는 왜 다른가?
3. 새 와인 한 개의 확률만으로 모델 성능을 판단할 수 있는가?

<details>
<summary>풀이 — 먼저 결과와 이유를 적은 뒤 펼치기</summary>

1. 나무 수와 무작위 선택을 되풀이하는 조건은 다르다.
2. 입력 열은 측정 항목이고 확률 열은 학습한 클래스에 해당한다.
3. 정답이 있는 여러 평가 행과 비교해야 한다. 확률이 높아도 틀릴 수 있다.

</details>
