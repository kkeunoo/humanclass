## 2. 무엇이며, 왜 필요한가

### 무엇을 맞혔는지 먼저 세어 본다

이 수업에서 양성은 good=1이다. 좋은 와인이라고 예측한 것 중 실제 좋은 와인이 얼마나 되는가를 **정밀도**, 실제 좋은 와인 중 얼마를 찾아냈는가를 **재현율**이라고 한다. 서로 분모가 다르다. F1은 이 두 비율의 조화평균이며 둘 중 하나만 높게 만들었을 때를 구별하는 데 쓴다. 전체 행 중 맞힌 비율인 정확도와 같은 수식은 아니다.

| 새 설명용 4행 | 실제 y | 예측 pred | 클래스 1 점수 |
| --- | ---: | ---: | ---: |
| A | 0 | 0 | 0.1 |
| B | 0 | 1 | 0.8 |
| C | 1 | 1 | 0.9 |
| D | 1 | 0 | 0.4 |

1이라고 고른 B·C 중 맞은 것은 C 하나이므로 정밀도는 1/2다. 실제 1인 C·D 중 찾은 것은 C 하나이므로 재현율도 1/2다. 따라서 F1은 0.5다. 일반식은 `2 × 정밀도 × 재현율 / (정밀도 + 재현율)`이며, 양성 자체가 없거나 전혀 고르지 않은 경우 같은 경계는 지표 함수의 설정도 확인한다.

### ROC AUC에는 왜 확률을 넣을까?

F1은 이번에 최종 선택한 0·1 답을 본다. ROC AUC는 양성과 음성을 점수로 얼마나 잘 순서 지었는지 보는 지표다. 위 표에서 실제 양성 C·D를 각각 음성 A·B와 비교하면 4쌍 중 3쌍에서 양성 점수가 더 높다. 이 자료에서는 AUC가 0.75다. 같은 예측에 F1 0.5와 AUC 0.75가 나와도 모순이 아니다. 두 숫자의 목적이 다르다.

수업은 `predict_proba(X_test)[:, 1]`로 클래스 1 열을 가져왔다. `:`는 모든 행, `1`은 두 번째 열이다. 이 배열은 pandas의 열 이름 선택과 다른 2차원 NumPy 인덱싱이다. 확률 대신 최종 클래스만 넣으면 점수 순서 정보가 크게 줄어든다. AUC 0.5는 무작위 순위 수준의 기준이고 한 번 실행하면 항상 정확히 0.5가 나온다는 보장은 아니다.

### 교차 검증은 같은 모델에 계속 덧붙여 학습하는 것일까?

cross_val_score는 각 분할에서 모델의 새 사본을 학습하고 그 분할의 검증 부분으로 점수를 얻는다. cv=5이면 다섯 부분을 번갈아 검증용으로 사용해 점수 다섯 개를 얻는다. 반환 배열의 mean은 그 평균이다. 이미 fit한 model을 넘겨도 그 학습 상태를 그대로 시험만 하는 절차가 아니다.

분류기이고 y가 이진·다중 클래스일 때 정수 cv는 기본적으로 StratifiedKFold 방식의 분할을 사용한다. 따라서 원본 후반의 “이제 처음으로 비율을 맞춘다”는 메모는 정확하지 않다. 명시적으로 만든 skf의 차이에는 `shuffle=True`와 고정 난수 상태, 전달 자료를 전체 X·y로 바꾼 점도 있다.

### 설정 후보를 고르는 점수와 마지막 시험은 다르다

GridSearchCV는 후보 설정을 교차 검증으로 비교한다. 수업의 나무 수 2개 × 깊이 3개는 6개 조합이다. 학생 cv=5면 후보 비교에서 30번 학습하고, 기본 refit=True로 고른 설정을 전달한 학습 자료 전체에 다시 학습한다. 강사님 cv=3은 비교 18번과 마지막 재학습이다. cv는 후보 조합의 수가 아니라 분할 수다.

best_params_는 선택한 설정, best_score_는 선택 과정의 평균 점수, best_estimator_는 고른 설정으로 다시 학습한 모델이다. 후보 중 가장 좋았다는 뜻이지 가능한 모든 모델 중 최고라는 보장이 아니다. 최종 판단에는 선택에 사용하지 않은 시험 자료의 역할을 별도로 남겨야 한다.

```python
from sklearn.metrics import f1_score, roc_auc_score

y_true = [0, 0, 1, 1]
pred = [0, 1, 1, 0]
positive_scores = [0.1, 0.8, 0.9, 0.4]
print('F1:', f1_score(y_true, pred))
print('AUC:', roc_auc_score(y_true, positive_scores))
print('모두 0의 F1:', f1_score(y_true, [0, 0, 0, 0]))
print('동점 점수의 AUC:', roc_auc_score(y_true, [0.5, 0.5, 0.5, 0.5]))
```

같은 y_true를 두 함수에 전달하되 비교 대상은 다르게 준다. 첫 F1은 최종 0·1 답, 첫 AUC는 클래스 1 점수다. 세 번째 출력은 실제 양성 두 행을 전부 놓쳐 F1이 0이다. 네 번째는 모든 행의 점수가 같아 순서로 클래스를 구별하지 못한 경우다.

# 단지 답만 점검하는 것이 아니라, 실제 양성(참/좋은 와인[1]) 데이터를 잘 찾았는지도 고려한다

proba = model.predict_proba(X_test)[:, 1]
# 슬라이싱 [:, 1] 은 전체 행에서 두 번째 컬럼(좋은 와인의 확률)만 추출

# 1 : 완벽 / 0.5 : 랜덤 / 0.5 미만 : 좋지 않음
auc = roc_auc_score(y_test, proba)
print('rod_auc 평가 점수 : ', auc) # 정답에 가까운 지표 rod_auc 평가 점수 :  0.9554193602552262
```

```

**발췌 바로 풀이:** 명시한 skf는 비율을 가깝게 유지하면서 섞어 다섯 fold를 만든다. 호출은 앞선 학습용 부분이 아닌 전체 X와 y다. 따라서 앞 점수보다 높다는 사실만으로 일반화가 개선됐다고 비교할 수 없다. 비교 자료와 설정, 선택 이력이 동시에 달라졌다.

먼저 model의 시험 예측으로 F1과 AUC를 계산한다. 다음에는 X_train·y_train 안에서 cross_val_score를 돌린다. 그 뒤 같은 학습 부분을 GridSearchCV로 비교한다. 마지막에는 best_estimator_를 전체 X·y의 skf 교차 검증에 전달한다. 변수 scores를 재사용했으므로 마지막 print의 scores가 앞 배열과 같은 대상이라고 생각하면 안 된다.

원본은 분할·지표·조합 탐색을 여러 방식으로 실습했다는 근거다. 다만 마지막 전체 자료 평가에는 처음 떼어 둔 시험 행도 다시 들어간다. 선택 이력이 있는 설정을 전체 자료에서 다시 평가한 수치를 “끝까지 건드리지 않은 시험의 최종 점수”로 부를 수 없다. 이 한계는 TIP으로 숨길 새 기능이 아니라 현재 코드의 결과를 정확히 읽기 위한 본문 설명이다.

“train과 test를 모두 학습하면 다 맞힌다”는 메모도 보장으로 읽지 않는다. 핵심은 시험 자료를 선택·학습에 사용하면 독립 평가의 목적을 잃는다는 것이다. 학습 자료조차 설정·자료에 따라 100% 맞히지 못할 수 있다.

## 5. import·함수·입력·출력이 연결되는 흐름

| 순서 | 입력 | 내부 작업 | 나오는 것 |
| --- | --- | --- | --- |
| 기본 평가 | X_test와 y_test | 이미 학습한 model 예측·비교 | F1·AUC |
| 단순 교차 검증 | model, X_train, y_train | fold마다 새 학습·검증 | 점수 5개·평균 |
| 후보 탐색 | 기본 모델·params·학습 부분 | 후보마다 교차 검증 | 설정·평균·고른 모델 |
| 원본 마지막 평가 | grid_model, 전체 X, y | skf별 새 학습·검증 | 다른 대상의 점수 |

`grid.best_estimator_`는 예측 메서드를 가진 학습 모델이다. `best_params_`는 설정 dict이고 그 자체에 predict가 있는 것은 아니다. cross_val_score·GridSearchCV·지표 함수는 sklearn에서 import한 도구다. 사용자 정의 함수가 생략된 구조는 아니며 새로운 모듈 분리는 스타일 장에서 전체 정의를 제공한다.

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 최종 답과 클래스 1 점수를 따로 구했고 F1과 AUC를 같은 점수로 비교하지 말자는 메모도 남겼다. 학습 자료만 후보 탐색에 사용한 점은 보존할 가치가 있다.

**아쉬운 점:** 주석과 활성 인자가 일부 다르고 마지막에는 평가 자료와 분할 방식이 함께 바뀌었다. 이때 점수 상승을 한 설정의 효과로 해석하면 근거가 부족하다. cv=5가 언제나 최선이라는 메모도 모든 자료에 적용하는 규칙은 아니다.

**이렇게 개선하면 좋다:** 각 출력에 사용 자료·분할 방식·지표를 적고, 후보 탐색은 학습 부분에서 끝낸 뒤 남겨 둔 시험 부분으로 별도 평가한다. 이 새 순서는 종합실습에서 실행 가능한 전체 코드로 보여 준다. 원본은 당시 실험의 기록으로 보존한다.

원본 오류·수업용 단순화·목적에 따른 설계를 나눈다. 새 개선안은 당시 내 코드나 D 드라이브 수정본이 아니다.

## 7. 강사님 코드가 도움이 되는 비교

출처: `D:/workspace_teacher/workspace_python/06_scikit_learn/01_main.py` 214–246행 · **원본 발췌**

```python
from sklearn.model_selection import GridSearchCV
params = {
    "n_estimators": [50, 100],
    "max_depth": [5, 10, None]
}
# 2 * 3 = 6개의 조합
# n_estimators : 의사결정나무 개수
# max_depth : 나무의 최대 깊이 (None : 제한하지 않는다)
# 하이퍼파라미터 : 개발자가 바꿀 수 있는 값

grid = GridSearchCV(
    RandomForestClassifier(random_state=42),
    params,
    cv=3,
    scoring='f1'
)
# GridSearchCV
#   첫 번째 전달인자 : 머신러닝 모델
#   두 번째 전달인자 : 시험할 하이퍼파라미터 후보
#   세 번째 전달인자 : 학습 데이터의 조합 수로 평가
#   네 번째 전달인자 : 평가 지표, 지표의 점수가 가낭 높은 조합을 찾는다

grid.fit(X_train, y_train)
# 지정한 6개의 하이퍼파라미터 조합을 각각 학습하고 평가한다

print('최적의 조합법 :', grid.best_params_)
# 6개 조합 중 가장 좋았던 조합을 출력한다

print('최고 점수 :', grid.best_score_)
# GridSearchCV가 선택한 최적의 하이퍼파라미터 조합으로 교차검증에 얻은 평균 F1 점수를 출력
# 진짜 평가는 X_test, y_test로 평하는게 좋다

grid_model = grid.best_estimator_
```

강사님 GridSearchCV는 cv=3, 내 코드는 cv=5다. 인용에서 실제 인자를 보고 비교 횟수가 달라짐을 읽는다. 강사님의 “진짜 평가는 X_test, y_test” 메모는 선택 점수와 마지막 시험을 나누는 데 도움이 된다. 양쪽 모두 단순 교차 검증 뒤 주석에 전체 X·y라고 적었지만 활성 인자는 X_train·y_train이므로 교정은 양쪽에 동일하게 적용한다.

## 8. 결과를 추적하고 한 가지 바꾸기

새 4행 표의 정답을 바꾸지 않고 추적한다.

| 개수 | 해당 행 | 값 |
| --- | --- | ---: |
| 진짜 1을 1로 찾음 | C | 1 |
| 실제 0을 1로 고름 | B | 1 |
| 실제 1을 놓침 | D | 1 |
| 정밀도 | C / (B+C) | 0.5 |
| 재현율 | C / (C+D) | 0.5 |
| F1 | 두 비율의 조화평균 | 0.5 |
| AUC | 양성·음성 점수 4쌍 비교 | 0.75 |

**원본 사본의 현재 실행 기록:** 기본 시험 F1은 양쪽 모두 0.75, AUC는 약 0.955419다. GridSearchCV의 선택 평균은 내 cv=5에서 약 0.523452, 강사님 cv=3에서 약 0.483615다. 둘 다 이번에는 max_depth=None·나무 50개를 골랐지만 비교 조건은 다르다. 마지막 전체 자료 skf 평균은 약 0.600428이며 기본 시험 F1이나 선택 평균과 같은 대상의 점수가 아니다. 이 숫자들은 실제 수업 자료와 현재 환경의 기록이지 모든 환경의 고정 정답은 아니다.

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
| 최종 답만 모두 0으로 | F1 0 | 실제 양성을 못 찾음 |
| 확률 점수를 모두 동점으로 | AUC 0.5 | 순위를 구분하지 못함 |
| 후보는 유지·cv를 3으로 | 후보 6개 그대로, 비교 학습 18번 | 후보 수와 fold 수는 다름 |
| 기본 refit을 False로 | best_estimator_를 기본처럼 사용 못 함 | 선택 후 전체 재학습을 하지 않음 |
| 마지막 입력을 학습 부분으로 유지 | 평가 대상이 일관됨 | 처음 시험 행을 선택에 다시 넣지 않음 |

한 클래스만 있는 평가 부분은 AUC를 정의하기 어렵다. 실제 0·1 개수를 먼저 확인한다. 확률 배열 모양 오류라면 두 열 전체를 전달했는지 살핀다. best_estimator_가 없다면 fit 여부와 refit 설정을 확인한다. 오래 걸리면 후보 수×fold 수×나무 수가 만드는 일을 계산하고 무조건 병렬 옵션부터 추가하지 않는다.

**확인 범위:** 작은 새 예제를 임시 폴더에서 독립 실행해 위 출력을 확인한다. 원본 CSV의 모양·분할·모델 결과 검사는 별도 보고서에 기록한다. 원본 주석의 옛 점수와 이번 실행값을 구별한다. 기존 수업 가상환경과 D 드라이브 소스는 읽기만 하며 새 패키지나 생성물을 쓰지 않는다.
