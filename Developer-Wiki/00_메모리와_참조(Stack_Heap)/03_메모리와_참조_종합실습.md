<a id="problem"></a>

## 2. 주어진 상태와 문제

### 2.1 전체 실행 코드

```python
# 새로 구성한 종합실습 · 독립 실행 가능
def append_four(values):
    values.append(4)


first = [1, 2]
same = first
other = first.copy()
append_four(same)
other[0] = 9

print(first)
print(same is first)
print(other)
print(append_four(other))
```

### 2.2 결과 예상

| 출력 줄 | 예상값 | 그 순간 무엇을 확인하는가? |
| --- | --- | --- |
| `print(first)` | 직접 작성 | 공유 리스트의 내용 |
| `print(same is first)` | 직접 작성 | 객체의 동일성 |
| `print(other)` | 직접 작성 | 복사한 리스트의 현재 내용 |
| `print(append_four(other))` | 직접 작성 | 함수 호출의 반환값 |

마지막 줄이 끝난 뒤 `other`의 **최종 상태**도 따로 적는다. 그 상태가 세 번째 출력 줄과 같을지 먼저 생각해 보자.

### 2.3 이유 설명

1. `first`, `same`, `other`는 바깥 리스트 몇 개를 사용하고 있는가?
2. `append_four(same)`은 왜 `first`에서 확인한 내용에도 영향을 주는가?
3. `other[0] = 9`는 왜 `first[0]`까지 바꾸지 않는가?
4. 마지막 `print`가 `None`이어도 `other`에는 변화가 있는가?

<a id="hints"></a>

## 3. 단계별 힌트

<details>
<summary>힌트 1 — 이름을 세는 대신 객체를 세기</summary>

`same = first`는 새 리스트를 만들지 않는다. `other = first.copy()`에서 새 바깥 리스트가 생긴다. 따라서 이름은 세 개이고, 이 단계에서 바깥 리스트는 두 개다.

</details>

<details>
<summary>힌트 2 — 호출마다 매개변수의 대상을 적기</summary>

첫 호출에서는 `values`가 `same`과 같은 객체를 가리킨다. 마지막 호출에서는 `values`가 `other`의 객체를 가리킨다. 함수 이름이 같아도 이번 호출에 어느 객체를 전달했는지 따로 본다.

</details>

<details>
<summary>힌트 3 — 출력의 시간을 구분하기</summary>

세 번째 출력 뒤에 마지막 함수 호출이 있다. 마지막 호출이 `other`를 바꾸더라도 이미 출력된 세 번째 줄의 글자가 뒤늦게 바뀌지는 않는다.

</details>

<a id="solution"></a>

## 4. 풀이와 상태 추적

<details>
<summary>정답과 자세한 해설 — 먼저 예상한 뒤 펼치기</summary>

확인한 출력:

```text
[1, 2, 4]
True
[9, 2]
None
```

| 실행 직후 | `first`와 `same`의 객체 A | `other`의 객체 B | 확인할 관계 |
| --- | --- | --- | --- |
| 세 이름 준비 | `[1, 2]` | `[1, 2]` | A와 B는 별도 바깥 리스트 |
| `append_four(same)` | `[1, 2, 4]` | `[1, 2]` | 매개변수 `values`도 A를 사용 |
| `other[0] = 9` | `[1, 2, 4]` | `[9, 2]` | B의 요소 자리만 교체 |
| 세 번째 출력까지 | 그대로 | `[9, 2]` | 이 시점의 B가 화면에 출력 |
| 마지막 함수 호출 | 그대로 | `[9, 2, 4]` | 이번 `values`는 B를 사용 |

마지막 `print`는 `other` 자체가 아니라 **`append_four(other)`의 호출 결과**를 출력한다. 함수가 B를 바꾼 뒤 명시적 반환 없이 끝나므로 그 결과는 `None`이다. 함수가 아무 일도 하지 않았다는 뜻이 아니다.

따라서 마지막 줄 다음에 `print(other)`를 추가하면 `[9, 2, 4]`가 나온다. 원본 상태, 반환값, 출력 시점을 나눠 추적해야 설명이 완성된다.

</details>

## 5. 요구사항을 바꿔 작은 수정하기

### 요구사항 A — 복사 없이 같은 목록을 써야 한다면

원래 코드에서 **`other = first.copy()` 한 줄만 `other = first`로 바꾸고** 처음부터 실행한다. 출력은 어떻게 바뀔까?

<details>
<summary>바꾼 결과와 이유</summary>

```text
[9, 2, 4]
True
[9, 2, 4]
None
```

세 이름이 모두 같은 A를 사용한다. 그래서 `other[0] = 9`가 `first`에서도 보인다. 마지막 호출이 끝난 뒤의 공통 리스트는 `[9, 2, 4, 4]`다. 네 번째 출력은 여전히 함수의 반환값 `None`이다.

</details>

### 요구사항 B — 함수에 전달한 원본을 보존해야 한다면

원본 예제로 돌아간 뒤 `append_four`를 **복사본에 4를 추가하고 그 복사본을 반환**하는 함수로 바꿔 본다. 그러면 호출부에서도 무엇을 바꿔야 새 결과를 사용할 수 있을까?

<details>
<summary>설명용 개선 코드와 풀이</summary>

다음은 함수와 호출부를 함께 다시 쓴 독립 실행 예제다. 원래 과제 코드에 적용된 원본이 아니다.

```python
def with_four(values):
    new_values = values.copy()
    new_values.append(4)
    return new_values


original = [1, 2]
result = with_four(original)
print(original)
print(result)
print(original is result)
```

확인한 출력:

```text
[1, 2]
[1, 2, 4]
False
```

복사본을 만든 것만으로 호출자가 그 결과를 사용하게 되지는 않는다. `return new_values`로 돌려주고 `result = ...`로 받아야 한다. 반환값을 무시하면 원본은 유지되지만 새 결과를 다음 코드에서 쓰지 못한다.

</details>

## 6. 흔한 실수와 확인 순서

| 잘못 해석하기 쉬운 것 | 왜 맞지 않는가? | 다시 볼 곳 |
| --- | --- | --- |
| 이름이 세 개이므로 리스트 세 개 | 대입은 별명을 연결할 수 있음 | `same = first` |
| 함수에 return이 없으니 변화 없음 | 변경과 반환은 별도 | `values.append(4)` |
| 마지막 출력이 `other` 내용 | 함수 호출 결과를 출력하고 있음 | 바깥 `print`의 인자 |
| 나중에 변경되면 이전 출력도 바뀜 | 이미 출력한 텍스트는 이전 시점 기록 | 실행 순서 |
| 새 리스트 반환이면 호출부 수정 불필요 | 반환값을 받아야 새 결과 사용 가능 | `result = ...` |

강사님과 내 함수의 반환 차이는 [본문의 필요한 비교](01_메모리와_참조%28Stack_Heap%29.md#teacher)에서 다시 읽는다. 이 실습의 풀이를 특정 수업 제출 코드라고 표시하지 않는다.
