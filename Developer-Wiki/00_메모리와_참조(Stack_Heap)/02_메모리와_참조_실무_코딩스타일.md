# 메모리와 참조 — 변경이 드러나는 함수 작성

[00 목차](README.md) · [수업 원본 비교](01_메모리와_참조%28Stack_Heap%29.md) · [종합실습](03_메모리와_참조_종합실습.md)

이 문서는 `_04_list.py`와 `_11_fn.py`의 **변경·재할당·반환 차이**를 읽기 쉽게 다시 적용한 코딩 스타일 연습이다. 아래 코드는 원본 발췌가 아니라 수업 범위 안에서 재구성했다.

```python
def add_item(items, item):
    items.append(item)  # 전달받은 리스트 자체가 바뀐다.
    return items

numbers = [1, 2]
result = add_item(numbers, 3)
print(numbers)  # [1, 2, 3]
print(result)   # [1, 2, 3]
```

함수 이름과 설명에서 **입력 리스트를 바꾸는지** 드러낸다. `return`이 없더라도 `append()`의 변경은 남으며, 위의 `return`은 결과를 쓰기 편하게 돌려줄 뿐 변경을 일으킨 원인은 아니다. 반대로 원본을 보존해야 하는 요구가 있으면 `copy()`로 새 **바깥 리스트**를 만든 다음 수정한다. 중첩 리스트 내부까지 독립된다고 일반화하지 않는다.

코드를 검토할 때는 (1) 이름이 어느 객체를 가리키는지, (2) 객체를 바꾸는지 이름을 재할당하는지, (3) 반환값이 무엇인지 순서로 확인한다. 팀에서 부작용을 줄이는 설계는 유용하지만 “모든 함수가 새 객체를 반환해야 한다”는 수업 규칙으로 소개하지 않는다.
