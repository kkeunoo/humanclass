## 1. 이번 장에서 배울 것

요구사항은 두 종류다. ‘공유한 목록에 항목을 추가한다’면 입력을 수정하는 함수가 맞을 수 있다. ‘수정 전 목록을 남겨 두고 새 목록을 얻는다’면 복사 후 새 결과를 반환해야 한다. 둘 중 하나가 언제나 좋은 스타일인 것은 아니다.

이 장에서는 함수의 **입력·입력 변경 여부·반환값·호출 방식**을 한 묶음으로 설명하는 습관을 익힌다. 리스트·함수를 배운 뒤 [본문의 변경과 반환](01_메모리와_참조%28Stack_Heap%29.md#function)을 먼저 읽는다.

| 실행 조건 | 이 장에서 사용할 것 |
| --- | --- |
| Python | Python 3, 별도 패키지 불필요 |
| 초기 자료 | 매 예제마다 새 `[1, 2]` |
| 실행 방법 | 독립 예제를 새 Python 파일에서 위에서 아래로 실행 |
| 제공된 함수 | [실습/reference_tools.py](실습/reference_tools.py) |
| 한 번에 확인 | `실습` 폴더에서 `python 참조_복습.py` |

원본 파일을 수정하는 과제가 아니라 의도를 드러내는 새 예제를 읽는 연습이다. 함수 정의만 있는 코드 조각은 호출문이 있어야 출력이나 상태 변화를 관찰할 수 있다.

## 2. 개념부터 이해하기

### 함수 사용자는 무엇을 알아야 할까?

함수 이름이 ‘항목을 추가한다’는 뜻이어도 **어느 리스트에 추가하는지**는 별도 질문이다. 호출 뒤 원본이 바뀌면 다른 코드가 그 원본을 사용하던 결과도 달라질 수 있다. 반면 새 결과를 돌려주는 함수는 그 결과를 받아 써야 한다.

| 구분 | 입력을 수정 | 새 결과 생성 |
| --- | --- | --- |
| 추가할 대상 | 전달받은 리스트 | 복사해 만든 리스트 |
| 원본을 쓰던 다른 이름 | 바뀐 내용을 봄 | 이 한 단계 리스트 예제에서는 원본 유지 |
| 반환값 | 별도 결과가 필요 없으면 `None` 가능 | 새 리스트 반환 필요 |
| 호출자의 행동 | 호출 뒤 원본 사용 | 반환값을 받아 사용 |

여기서 중요한 것은 함수가 짧은지보다 **약속한 동작과 실제 변경 대상이 같은지**다. 입력 변경이라는 관찰 가능한 효과를 보통 부수 효과라고도 부른다. 이 장에서는 용어를 외우기보다 호출 전후 원본을 나란히 적어 확인한다.

## 3. 작은 예제와 결과

**설명용 새 예제 · 독립 실행 가능.** 첫 함수는 입력을 수정하고 명시적인 반환을 하지 않는다.

```python
def append_in_place(items, item):
    items.append(item)


numbers = [1, 2]
result = append_in_place(numbers, 3)
print(numbers)
print(result)
```

확인한 출력:

```text
[1, 2, 3]
None
```

`items`와 `numbers`는 같은 리스트를 사용한다. 함수 안에서 실행한 `append`가 원본을 바꾼다. `result`는 그 리스트의 별명으로 자동 연결되지 않는다. 함수에 명시적인 반환이 없으므로 `None`이다.

**설명용 새 예제 · 독립 실행 가능.** 같은 초기 자료에서 원본을 남겨야 한다면 복사본을 바꾼다.

```python
def with_added_item(items, item):
    new_items = items.copy()
    new_items.append(item)
    return new_items


numbers = [1, 2]
result = with_added_item(numbers, 3)
print(numbers)
print(result)
print(result is numbers)
```

확인한 출력:

```text
[1, 2]
[1, 2, 3]
False
```

`copy()`로 새 바깥 리스트를 만들었으므로 추가한 대상은 `new_items`다. `return new_items`가 그 리스트를 호출자에게 전달하고, 호출자는 `result`라는 이름으로 받는다. 이제 원본과 새 결과를 함께 사용할 수 있다.

**하나만 바꿔 보는 실험:** 두 번째 함수에서 `new_items = items.copy()`만 `new_items = items`로 바꾸면 어떻게 될까? 새 이름이 생겨도 복사본은 생기지 않는다. 같은 객체에 추가하므로 `numbers`까지 `[1, 2, 3]`으로 바뀌고 마지막 `is`는 `True`가 된다. 확인할 때는 매번 초기 자료부터 다시 실행한다.

## 4. 내 코드의 선택을 읽기

내 `workspace_python/11_fn.py`의 `ref(a)`는 `a.append(4)`를 실행하고 별도 반환문이 없다. [본문의 정확한 원본 발췌](01_메모리와_참조%28Stack_Heap%29.md#function)를 기준으로 다음처럼 읽는다.

| 실제 선택 | 동작 | 이 선택이 맞는 요구사항 |
| --- | --- | --- |
| 매개변수에 바로 `append` | 입력 리스트를 변경 | 호출자가 가진 목록을 갱신 |
| 명시적인 반환 없음 | 호출 결과는 `None` | 입력 변경만 수행하고 결과는 원본에서 확인 |

이 함수를 ‘새 리스트를 만들어 주는 함수’로 기대하면 문제가 생긴다. 코드를 쓰는 쪽과 부르는 쪽의 기대가 다른 것이다. 따라서 함수 설명에 **입력 리스트를 수정한다**는 문장을 먼저 쓰는 것이 도움이 된다.

반환문을 추가하는 것만으로 입력을 보존할 수는 없다. 이미 바꾼 객체를 반환할지, 복사한 객체를 바꿀지는 요구사항을 기준으로 고른다.

## 5. 다른 파일과 연결하기

두 새 함수는 [reference_tools.py](실습/reference_tools.py)에 있고, [참조_복습.py](실습/참조_복습.py)가 import한다. 구현 전체는 [본문 5절](01_메모리와_참조%28Stack_Heap%29.md#connections)에도 실었다.

```text
실행 파일이 리스트 준비
  → 함수에 전달
  → 함수가 원본 또는 복사본에 append
  → 함수 반환값을 result에 받음
  → 실행 파일에서 원본과 result를 따로 출력
```

| 가져온 이름 | 정의 위치 | 반환 경로 |
| --- | --- | --- |
| `append_in_place` | `reference_tools.py` | 끝에 도달해 `None` |
| `with_added_item` | 같은 모듈 | `return new_items`로 새 리스트 |

호출 위치에서 함수 안이 보이지 않더라도 이 표로 약속을 확인할 수 있다. 문서에는 함수 이름만 나열하지 않고 **반환값을 무시해도 되는지, 원본이 바뀌는지**까지 적는다.

## 6. 내 코드 돌아보기

### 좋은 선택과 주의할 선택

내 원본은 변경을 일으키는 문장이 하나라 원인을 추적하기 쉽다. 원본 수정이 목표일 때 직접 `append`하는 방식은 목적에 맞는다. 그 자체를 ‘복사하지 않아 잘못됨’이라고 평가하지 않는다.

| 점검 상황 | 평가 종류 | 판단 |
| --- | --- | --- |
| 원본 갱신이 목표인데 직접 수정 | 목적에 맞는 선택 | 수정한다는 사실을 설명 |
| 원본 보존이 목표인데 직접 수정 | 요구사항과 동작 불일치 | 복사 후 변경으로 수정 |
| 입력을 수정한 뒤 같은 리스트 반환 | 선택 | 반환값도 사용할 이유가 있으면 가능 |
| 새 결과를 만들고 반환하지 않음 | 사용 방식 점검 | 호출자가 새 결과를 얻을 방법 필요 |
| 함수 이름의 `_in_place` 접미사 | 설명용 약속 | 수업의 필수 문법이나 유일한 팀 규칙은 아님 |

문법 오류와 요구사항 불일치도 나눠 본다. 코드가 실행된다는 사실만으로 ‘원본 보존’ 요구사항을 충족하는 것은 아니다.

### 개선 전후에서 확인할 것

원본 유지가 필요하다면 3절 두 번째 함수처럼 수정한다. 수정 후에는 **원본이 같은 값인가**, **결과에 새 항목이 있는가**, **원본과 결과가 같은 객체인가**를 함께 확인한다. 한 항목만 보고 성공이라고 판단하지 않는다.

## 7. 강사님 코드에서 배울 점

강사님 `ref(a)`에는 수정 뒤 `return a`가 있다. 정확한 코드는 [본문의 필요한 비교](01_메모리와_참조%28Stack_Heap%29.md#teacher)에 있고 여기서 다시 인용하지 않는다.

가져갈 점은 **수정한 같은 리스트도 반환값으로 제공할 수 있다**는 것이다. 그 선택은 원본 보존과 다르다. 반환값이 있다는 이유로 더 안전한 함수라거나, 반환이 없다는 이유로 덜 완성된 함수라고 평가하지 않는다.

| 비교할 질문 | 강사님 원본 | 내 원본 |
| --- | --- | --- |
| 입력 리스트 변경 | 있음 | 있음 |
| 호출 결과 | 수정한 같은 리스트 | `None` |
| 원본 보존 | 안 함 | 안 함 |

## 8. 결과와 확인 방법

**설명용 새 예제 · 독립 실행 가능.** 빈 리스트라는 경계 조건에서도 같은 약속이 지켜지는지 확인한다.

```python
def append_in_place(items, item):
    items.append(item)


def with_added_item(items, item):
    result = items.copy()
    result.append(item)
    return result


original = []
changed_result = append_in_place(original, 3)
print(original, changed_result)

original = []
new_result = with_added_item(original, 3)
print(original, new_result)
```

확인한 출력:

```text
[3] None
[] [3]
```

빈 목록에서도 첫 함수는 입력을 바꾸고 둘째 함수는 새 결과를 만든다. 같은 3을 추가했더라도 호출 후 사용할 이름이 다르다.

| 현상 | 먼저 볼 것 |
| --- | --- |
| 결과가 `None` | 명시적 반환이 있는지, 메서드 반환을 받았는지 |
| 원본까지 변경 | `copy()` 여부보다 실제 수정 대상의 객체 |
| 복사했는데 안쪽 변경이 함께 보임 | 얕은 복사의 범위, 중첩 자료 여부 |
| 함수 호출 뒤 화면에 아무것도 없음 | 함수가 출력하는지, 반환만 하는지; 호출자가 출력했는지 |

코드와 독립 예제의 출력은 Python 3.12.14에서 확인했다. 이 기준을 모든 자료형이나 깊은 객체 구조에 곧바로 적용하지 않는다.

> 📚 **출처 · 본문 설명 확인:** 리스트 메서드와 함수의 반환은 [Python 자습서 — 자료구조](https://docs.python.org/3/tutorial/datastructures.html), [함수 정의](https://docs.python.org/3/tutorial/controlflow.html#defining-functions)로 확인했다. 복사 범위는 [copy 문서](https://docs.python.org/3/library/copy.html)를 참고했다. 확인일: 2026-10-28. 여기의 함수 이름과 비교 예제는 새 재구성이다.

### 결과 예상 → 이유 → 작은 수정

다음 질문에 차례로 답한다.

1. `result = numbers.append(3)` 뒤 원본과 `result`는 각각 무엇인가?
2. 그 결과를 ‘추가 실패’라고 해석하면 왜 틀리는가?
3. 원본을 유지해야 한다면 수정할 대상과 반환값을 어떻게 바꿀 것인가?

<details>
<summary>풀이</summary>

초기 `numbers`가 `[1, 2]`면 호출 후 `[1, 2, 3]`이고, `result`는 `None`이다. `append`가 기존 리스트에 추가했지만 그 리스트를 반환하지 않기 때문이다. 원본을 유지하려면 복사한 바깥 리스트에 추가한 뒤 그것을 반환한다. 3절 두 번째 예제가 그 구조다.

</details>
