# 메모리와 참조 — 변경이 드러나는 함수 작성

[00 목차](README.md) · [수업 원본 비교](01_메모리와_참조%28Stack_Heap%29.md) · [종합실습](03_메모리와_참조_종합실습.md)

## 이 장의 질문

함수에 리스트를 넘긴 뒤 바깥 목록이 바뀌었다면, **함수 이름만 보고 그 사실을 예상할 수 있을까?** 이 장은 수업의 `append()`·`copy()`·`return`을 다시 사용해, 입력을 직접 바꾸는 함수와 새 리스트를 만드는 함수를 구분한다. 아래 함수 이름과 예제는 **원본 발췌가 아닌 새로 구성한 복습**이다.

**입력을 바꾸는 함수**는 전달받은 리스트 자체에 `append()` 등을 적용한다. **새 결과를 만드는 함수**는 이 장의 한 단계 리스트처럼 복사본을 만든 다음 그 복사본을 바꿔 돌려준다. 먼저 두 방식의 차이를 작은 예제로 본다.

```python
# 설명용 재구성: 두 블록을 차례로 실행
numbers = [1, 2]
alias = numbers
alias.append(3)
print(numbers)

numbers = [1, 2]
copied = numbers.copy()
copied.append(3)
print(numbers)
print(copied)
```

출력은 차례로 `[1, 2, 3]`, `[1, 2]`, `[1, 2, 3]`이다. 첫 부분은 **같은 리스트를 변경**했고, 둘째 부분은 **새 바깥 리스트를 변경**했다. 이 차이를 함수 안에서도 그대로 추적하면 된다.

## 1. 먼저 수업 코드의 결과를 다시 읽기

[원본 비교 본문 5절](01_메모리와_참조%28Stack_Heap%29.md#function)에서 강사님 `ref(a)`는 전달받은 리스트에 `4`를 붙이고 **같은 리스트를 반환**한다. 내 `ref(a)`도 리스트에 `4`를 붙이지만 **반환문은 없다**. 두 함수 모두 `print(b)`에서는 `[1, 2, 3, 4]`를 보이지만, 호출 결과를 변수에 받으면 각각 리스트와 `None`이 된다.

| 먼저 확인할 것 | 강사님 원본 | 내 원본 |
| --- | --- | --- |
| 입력 리스트를 바꾸는 문장 | `a.append(4)` | `a.append(4)` |
| 반환문 | `return a` | 없음 |
| `ref(b)` 뒤 바깥 `b` | 변경됨 | 변경됨 |
| 호출 결과를 받을 때 | 같은 리스트 | `None` |

이 표에서 **변경**의 원인은 `append()`이고, **반환값**의 차이는 `return` 때문이다. 두 동작을 한 문장으로 뭉뚱그리면 코드를 수정할 때 혼동한다.

## 2. 입력을 바꾸는 함수

다음처럼 입력 리스트 자체를 수정하려는 함수라면, 이름과 호출 위치에서 그 의도를 드러낸다.

```python
# 수업 문법으로 만든 설명용 재구성
def append_item_in_place(items, item):
    items.append(item)

numbers = [1, 2]
result = append_item_in_place(numbers, 3)
print(numbers)  # [1, 2, 3]
print(result)   # None
```

`items`와 `numbers`가 같은 리스트를 가리키므로 함수 밖의 `numbers`도 바뀐다. `result`가 `None`이어도 추가 작업은 실행됐다. 함수를 사용할 사람에게는 **입력을 수정한다는 사실**이 더 중요하다.

## 3. 원본을 남기고 새 리스트를 만드는 함수

원본 `[1, 2]`를 나중에도 그대로 써야 한다면 바깥 리스트를 복사한 뒤 새 리스트에 추가한다. `list.copy()`는 수업에서 확인한 문법이다.

```python
# 수업 문법으로 만든 설명용 재구성
def with_added_item(items, item):
    new_items = items.copy()
    new_items.append(item)
    return new_items

numbers = [1, 2]
result = with_added_item(numbers, 3)
print(numbers)  # [1, 2]
print(result)   # [1, 2, 3]
```

여기서는 `append()`도 사용했지만 **복사본**에 적용했기 때문에 원본은 그대로다. 숫자만 담긴 이 예제에서 `copy()`로 목적을 달성한다. 중첩 리스트의 안쪽 객체까지 새로 만들어진다고 확대하지 않는다.

## 4. 코드를 검토할 때의 순서

1. 함수가 받은 이름이 **기존 리스트**를 가리키는지 확인한다.
2. `append()`·요소 대입처럼 객체의 **내용을 바꾸는 문장**을 찾는다.
3. `items = [...]`처럼 이름을 **재할당**하는 문장과 구별한다.
4. 반환값을 호출한 쪽에서 실제로 사용하는지 확인한다.

<summary>점검 질문 — `return`을 지우면 무엇이 달라질까?</summary>

첫 번째 함수에는 원래 `return`이 없으므로 달라지지 않는다. 강사님 `ref(a)`에서 `return a`를 지우면 바깥 리스트의 변경은 남고, **호출 결과**만 리스트에서 `None`으로 달라진다. 원본 비교 본문의 실제 코드와 대조해 보자.

## 💡 추가로 알면 좋은 것

> [!TIP]
> 함수 이름에 `_in_place`를 붙이는 것은 이 문서의 **새 설명용 약속**이다. 수업 원본의 필수 이름 규칙은 아니다. 팀에서 어떤 이름을 택하든 입력을 바꾸는지 문서와 사용 예제로 분명히 알 수 있게 한다.

중첩 리스트의 안쪽까지 나누어야 하는 경우는 [본문의 깊은 복사 보충](01_메모리와_참조%28Stack_Heap%29.md#extra-01-4)에서 읽는다. 기본 실습의 정답에는 요구하지 않는다.
