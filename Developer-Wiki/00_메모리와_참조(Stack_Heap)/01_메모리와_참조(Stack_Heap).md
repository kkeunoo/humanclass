# Section 1.1 왜 메모리를 배워야 하는가?

## 📖 왜 이 내용을 배워야 할까?

프로그래밍을 처음 배우면 대부분 변수와 함수부터 접한다.

``` python
a = 10
b = a
```

처음에는 이 코드가 단순해 보이지만, 학습이 진행될수록 다음과 같은 질문이
생긴다.

-   `b = a`는 값을 복사하는 것일까?
-   리스트는 왜 함께 변경될까?
-   함수에 전달한 변수는 왜 원본이 바뀌기도 하고 바뀌지 않기도 할까?
-   변수는 실제로 어디에 존재할까?

이 질문들은 모두 **메모리(Memory)** 를 이해하면 하나의 흐름으로
연결된다.

------------------------------------------------------------------------

## 🤔 생각해 보기

다음 코드가 실행되면 문자열 `"HumanClass"`는 어디에 존재할까?

``` python
name = "HumanClass"
```

생각해 보자.

-   CPU가 기억할까?
-   SSD(HDD)에 계속 저장될까?
-   메모리(RAM)에 존재할까?
-   변수 안에 문자열 자체가 들어갈까?

이 Chapter를 끝낼 때쯤이면 자연스럽게 설명할 수 있게 된다.

------------------------------------------------------------------------

## 💡 메모리는 왜 필요한가?

CPU는 계산을 수행하는 장치이다.

하지만 계산에 필요한 데이터와 계산 결과를 계속 보관하는 역할은 하지
않는다.

프로그램이 실행되는 동안 필요한 정보를 저장할 작업 공간이 필요한데, 그
공간이 **메모리(RAM)** 이다.

간단히 정리하면 다음과 같다.

  구성 요소     역할
  ------------- -----------------------------
  CPU           계산 수행
  Memory(RAM)   실행 중인 데이터 보관
  SSD/HDD       프로그램과 파일을 장기 보관

------------------------------------------------------------------------

## 🧠 비유로 이해하기

사람이 문제를 푸는 모습을 떠올려 보자.

``` text
머리
 ↓
생각한다.
 ↓
책상
 ↓
메모를 올려두고 필요할 때 다시 본다.
```

컴퓨터도 매우 비슷하다.

``` text
CPU
 ↓
계산한다.
 ↓
RAM
 ↓
데이터를 보관한다.
```

RAM은 프로그램이 실행되는 동안 사용하는 **작업 공간(Workspace)** 이다.

------------------------------------------------------------------------

## ⚠️ 자주 하는 오해

많은 입문자는 다음과 같이 생각한다.

> "변수 안에 값이 들어 있다."

간단한 설명에서는 사용할 수 있는 표현이지만, 객체(Object)와
참조(Reference)를 배우기 시작하면 혼란의 원인이 된다.

이 문서에서는 더 정확한 관점으로 메모리를 설명한다.

지금은 다음 한 문장만 기억하면 된다.

> **프로그램에서 사용하는 데이터는 메모리에 존재한다.**

------------------------------------------------------------------------

-   CPU는 계산을 담당한다.
-   RAM은 작업 공간이다.
-   메모리를 이해하면 변수와 객체를 이해하기 쉬워진다.

# Chapter 1. 메모리란 무엇인가?

## Section 1.2 프로그램은 어떻게 실행될까?

------------------------------------------------------------------------

## 📖 왜 실행 과정을 알아야 할까?

Python 코드를 작성하면 화면에 결과가 출력된다.

``` python
print("Hello, HumanClass!")
```

하지만 컴퓨터 내부에서는 이 한 줄의 코드가 단순히 실행되는 것이 아니라,
여러 장치가 서로 협력하여 프로그램을 동작시킨다.

Stack과 Heap을 이해하려면 먼저 프로그램이 실행되는 전체 흐름을 이해해야
한다.

------------------------------------------------------------------------

## 💡 프로그램은 어디에서 시작될까?

Python 파일(.py)은 처음에는 **저장장치(SSD/HDD)** 에 저장되어 있다.

예를 들어 다음과 같은 파일이 있다고 하자.

``` text
hello.py
```

이 파일은 아직 실행 중인 프로그램이 아니다.

단순히 저장되어 있는 데이터일 뿐이다.

------------------------------------------------------------------------

## 실행 과정

``` text
① Python 코드 작성

        │

        ▼

② SSD(HDD)에 저장

        │

        ▼

③ 프로그램 실행

        │

        ▼

④ 운영체제가 프로그램을 RAM으로 로드

        │

        ▼

⑤ CPU가 RAM에서 명령을 하나씩 읽어 실행

        │

        ▼

⑥ 실행 결과를 다시 RAM에 저장하거나 화면에 출력
```

이 과정이 매우 빠르게 반복된다.

------------------------------------------------------------------------

## 🧠 RAM이 필요한 이유

SSD는 데이터를 오래 저장하기에는 적합하지만, 읽고 쓰는 속도는 RAM보다
느리다.

프로그램이 실행되는 동안에는 빠른 작업 공간이 필요하다.

따라서 운영체제는 프로그램을 RAM으로 가져온 뒤 CPU가 RAM을 대상으로
작업하도록 만든다.

즉,

-   SSD : 보관
-   RAM : 작업
-   CPU : 계산

이라는 역할 분담이 이루어진다.

------------------------------------------------------------------------

## 🤔 생각해 보기

프로그램을 종료하면 어떻게 될까?

실행 중 RAM에 존재하던 데이터는 대부분 사라진다.

하지만 저장장치에 있는 Python 파일은 그대로 남아 있다.

따라서 다음에 다시 실행하면 운영체제가 다시 RAM으로 프로그램을 올려
실행한다.

------------------------------------------------------------------------

## ⚠️ 자주 하는 오해

"Python 파일이 RAM에 저장된다."

→ 정확한 표현은 아니다.

Python **파일 자체는 저장장치에 존재**한다.

실행할 때 필요한 코드와 데이터가 RAM으로 복사되어 실행된다.

------------------------------------------------------------------------

## ✅ 핵심 정리

-   Python 파일은 저장장치에 저장된다.
-   실행 시 운영체제가 프로그램을 RAM으로 올린다.
-   CPU는 RAM에서 명령을 읽고 실행한다.
-   프로그램 종료 후 RAM의 데이터는 대부분 사라진다.

------------------------------------------------------------------------

## Section 1.3 CPU, RAM 그리고 저장장치의 역할

------------------------------------------------------------------------

## 📖 왜 각각의 역할을 알아야 할까?

Stack과 Heap은 모두 메모리(RAM) 안에 존재한다.

따라서 먼저 CPU, RAM, 저장장치(SSD/HDD)가 각각 어떤 역할을 하는지
이해해야 메모리 구조를 자연스럽게 받아들일 수 있다.

------------------------------------------------------------------------

## 🧠 컴퓨터의 세 가지 핵심 구성 요소

컴퓨터는 크게 다음 세 요소가 협력하여 동작한다.

  구성 요소   역할                           비유
  ----------- ------------------------------ -------------
  CPU         계산하고 명령을 실행           사람의 두뇌
  RAM         실행 중인 데이터를 임시 보관   책상
  SSD/HDD     프로그램과 파일을 장기 보관    책장

이 세 장치는 서로 역할이 명확하게 구분되어 있다.

------------------------------------------------------------------------

## 💡 CPU의 역할

CPU(Central Processing Unit)는 프로그램의 명령을 읽고 실행하는 장치이다.

예를 들어,

``` python
a = 10
b = 20
print(a + b)
```

CPU는 덧셈을 수행하고 출력 명령을 실행하지만, 결과를 오래 기억하는
역할은 하지 않는다.

즉, CPU는 **계산 담당**이다.

------------------------------------------------------------------------

## 💡 RAM의 역할

RAM(Random Access Memory)은 프로그램이 실행되는 동안 필요한 데이터를
저장하는 작업 공간이다.

프로그램이 종료되면 대부분의 데이터는 RAM에서 사라진다.

RAM은 빠른 속도를 제공하는 대신 영구적으로 데이터를 보관하지 않는다.

------------------------------------------------------------------------

## 💡 저장장치의 역할

SSD(HDD)는 프로그램과 파일을 오랫동안 보관하는 공간이다.

Python 파일(.py), 이미지, 문서, 데이터베이스 파일 등은 모두 저장장치에
기록된다.

프로그램을 실행하면 필요한 내용이 RAM으로 복사되어 사용된다.

------------------------------------------------------------------------

## 🤔 생각해 보기

다음 상황을 생각해 보자.

``` text
컴퓨터 전원을 끈다.
```

어떤 데이터가 남을까?

-   Python 파일 → 남는다.
-   Word 문서 → 남는다.
-   실행 중이던 RAM 데이터 → 대부분 사라진다.

이 차이를 이해하는 것이 메모리 학습의 시작이다.

------------------------------------------------------------------------

## ⚠️ 자주 하는 오해

"RAM이 크면 컴퓨터가 무조건 빠르다."

RAM은 작업 공간의 크기를 늘려 주지만, 프로그램의 계산 자체는 CPU가
수행한다.

따라서 CPU 성능과 RAM 용량은 서로 다른 역할을 담당한다.

------------------------------------------------------------------------

## ✅ 핵심 정리

-   CPU는 계산을 수행한다.
-   RAM은 실행 중인 데이터를 보관한다.
-   SSD/HDD는 데이터를 장기 보관한다.
-   프로그램 실행 시 저장장치의 내용이 RAM으로 올라와 CPU가 실행한다.

------------------------------------------------------------------------

# Chapter 1. 메모리란 무엇인가?

## Section 1.4 프로그램이 실행되면 메모리는 어떻게 구성될까?

------------------------------------------------------------------------

## 📖 왜 메모리 구조를 알아야 할까?

지금까지는 CPU, RAM, 저장장치가 각각 어떤 역할을 하는지 살펴보았다.

하지만 아직 중요한 질문이 하나 남아 있다.

> **RAM 안에는 모든 데이터가 아무렇게나 저장될까?**

정답은 **아니다.**

프로그램이 실행되면 메모리는 용도에 따라 여러 영역으로 나누어 사용된다.

이 구조를 이해하면 이후에 배울 **Stack**과 **Heap**을 훨씬 쉽게 이해할
수 있다.

------------------------------------------------------------------------

## 🧠 메모리는 하나의 커다란 창고가 아니다.

교육용으로 단순화하면 메모리는 다음과 같이 여러 영역으로 나누어 생각할
수 있다.

``` text
+--------------------------------------+
| Code 영역                            |
+--------------------------------------+
| Data 영역                            |
+--------------------------------------+
| Heap 영역                            |
|                                      |
|             (객체 저장)              |
|                                      |
+--------------------------------------+
|                Stack                 |
|      (함수 호출, 지역 변수 등)        |
+--------------------------------------+
```

> **참고**
>
> 위 그림은 학습을 위한 단순화된 모델이다. 실제 운영체제와 언어 구현은
> 환경에 따라 달라질 수 있다.

------------------------------------------------------------------------

## 💡 각 영역의 역할

### 1. Code 영역

프로그램의 실행 명령이 저장되는 영역이다.

Python 코드 역시 실행 가능한 형태로 준비되어 CPU가 읽어 실행한다.

------------------------------------------------------------------------

### 2. Data 영역

프로그램 실행에 필요한 일부 데이터가 저장되는 영역이다.

이번 문서에서는 세부 내용보다 **메모리가 여러 영역으로 나뉜다**는 점만
이해하면 충분하다.

------------------------------------------------------------------------

### 3. Heap 영역

프로그램에서 생성되는 **객체(Object)** 가 저장되는 공간이다.

리스트, 딕셔너리, 문자열 등 다양한 객체가 이 영역에 만들어진다.

Chapter 2부터 가장 많이 다루게 될 영역이다.

------------------------------------------------------------------------

### 4. Stack 영역

함수 호출 과정과 지역 변수 등을 관리하는 영역이다.

함수가 호출될 때 생성되고, 함수가 종료되면 함께 정리되는 특징을 가진다.

------------------------------------------------------------------------

## 🤔 아직은 Stack과 Heap을 외우지 않아도 된다.

많은 입문자가 다음처럼 암기하려고 한다.

-   Stack = 변수
-   Heap = 객체

하지만 지금 단계에서는 암기보다

> **메모리가 역할별로 나누어져 있다.**

이 사실만 이해하는 것이 중요하다.

Stack과 Heap의 정확한 동작은 다음 Chapter에서 자세히 다룬다.

------------------------------------------------------------------------

## ⚠️ 자주 하는 오해

"Stack과 Heap은 서로 다른 메모리이다."

그렇지 않다.

둘 다 **RAM 안에 존재하는 서로 다른 영역**이다.

즉,

``` text
RAM
 ├── Stack
 ├── Heap
 ├── Code
 └── Data
```

처럼 이해하면 된다.

# Chapter 2. Stack이란 무엇인가?

## Section 2.1 Stack의 개념 이해

------------------------------------------------------------------------

# 📖 왜 Stack을 먼저 배울까?

메모리를 공부하다 보면 가장 먼저 듣는 용어가 **Stack**과 **Heap**이다.

많은 입문자는 두 용어를 단순히 암기하려고 하지만, 실제로 중요한 것은
**왜 Stack이라는 공간이 필요한가**를 이해하는 것이다.

이번 Section에서는 구현 세부사항보다 **Stack이 존재하는 이유와 역할**을
중심으로 살펴본다.

------------------------------------------------------------------------

# 🤔 생각해 보기

다음 코드를 실행해 보자.

``` python
def hello():
    print("Hello")

hello()
```

이 함수는 실행이 끝난 뒤 어떻게 될까?

-   함수는 계속 메모리에 남아 있을까?
-   실행에 필요한 정보는 어디에 저장될까?

이 질문의 답이 Stack이다.

------------------------------------------------------------------------

# 💡 Stack이 필요한 이유

프로그램은 함수를 한 번만 실행하지 않는다.

``` python
login()
print_menu()
save()
logout()
```

함수는 계속 호출되고 종료된다.

컴퓨터는 현재 **어떤 함수가 실행 중인지**, **실행이 끝나면 어디로
돌아가야 하는지**, **지역 변수는 무엇인지**를 기억해야 한다.

이 정보를 관리하기 위해 사용하는 공간이 **Stack**이다.

------------------------------------------------------------------------

# 🧠 Stack은 접시를 쌓는 구조

Stack은 아래에서부터 차곡차곡 쌓이고, 가장 위의 것부터 꺼내는 구조이다.

``` text
        ┌──────────────┐
TOP →   │ save()       │
        ├──────────────┤
        │ print_menu() │
        ├──────────────┤
BOTTOM→ │ login()      │
        └──────────────┘
```

가장 나중에 들어온 것이 가장 먼저 제거된다.

이를 **LIFO(Last In, First Out)** 라고 한다.

------------------------------------------------------------------------

# 🧪 Python 예제

``` python
def hello():
    print("Hello")

print("Start")
hello()
print("End")
```

실행 순서

1.  `print("Start")`
2.  `hello()` 호출
3.  `hello()` 실행
4.  `hello()` 종료
5.  `print("End")`

------------------------------------------------------------------------

# 📦 교육용 Stack 변화

함수 호출 전

``` text
Stack

┌──────────────┐
│ (비어 있음)  │
└──────────────┘
```

`hello()` 호출

``` text
Stack

┌──────────────┐
│ hello()      │
└──────────────┘
```

`hello()` 종료

``` text
Stack

┌──────────────┐
│ (비어 있음)  │
└──────────────┘
```

> 위 그림은 학습을 위한 단순화된 모델이다.

------------------------------------------------------------------------

# ❓ Why?

왜 Stack은 위에서만 추가하고 제거할까?

현재 실행 중인 함수는 항상 **가장 최근에 호출된 함수**이다.

따라서 가장 최근 함수부터 종료하면 프로그램의 실행 순서를 자연스럽게
유지할 수 있다.

------------------------------------------------------------------------

# ⚠️ 자주 하는 오해

❌ Stack = 변수를 저장하는 공간

보다 정확하게는,

> **함수 호출 과정과 실행에 필요한 정보(예: 지역 변수 등)를 관리하는
> 메모리 영역**이다.

이후 Section에서 Stack Frame을 배우면 이 의미를 더 명확하게 이해하게
된다.

------------------------------------------------------------------------

# ✅ 핵심 정리

-   Stack은 RAM 안의 메모리 영역이다.
-   함수 호출을 관리한다.
-   가장 최근에 호출된 함수가 가장 먼저 종료된다.
-   LIFO 구조를 사용한다.

# Chapter 2. Stack이란 무엇인가?

## Section 2.2 Stack Frame(스택 프레임)

------------------------------------------------------------------------

# 📖 왜 Stack Frame을 배워야 할까?

이전 Section에서는 Stack이 **함수 호출을 관리하는 메모리 영역**이라는
것을 배웠다.

하지만 Stack에는 함수 이름만 저장되는 것이 아니다.

함수가 실행되기 위해 필요한 정보를 하나로 묶어 관리하는 공간이 있으며,
이를 **Stack Frame(스택 프레임)** 이라고 한다.

Stack을 이해하려면 반드시 Stack Frame을 이해해야 한다.

------------------------------------------------------------------------

# 🤔 생각해 보기

다음 코드를 실행해 보자.

``` python
def greet():
    message = "Hello"
    print(message)

greet()
```

`message` 변수는 어디에 저장될까?

그리고 `greet()` 함수가 종료되면 어떻게 될까?

이 질문의 답이 Stack Frame이다.

------------------------------------------------------------------------

# 💡 Stack Frame이란?

Stack Frame은 **하나의 함수 실행에 필요한 정보를 담고 있는 작업
공간**이다.

함수가 호출되면 새로운 Stack Frame이 생성되고, 함수가 종료되면 해당
Stack Frame도 함께 제거된다.

교육용으로 단순화하면 Stack Frame에는 다음과 같은 정보가 포함된다고
생각할 수 있다.

-   현재 실행 중인 함수
-   지역 변수(Local Variable)
-   함수 실행에 필요한 정보
-   함수가 종료된 뒤 돌아갈 위치

> 실제 구현은 언어와 운영체제에 따라 다를 수 있으며, 위 내용은 학습을
> 위한 단순화된 설명이다.

------------------------------------------------------------------------

# 🧪 Python 예제

``` python
def greet():
    message = "Hello"
    print(message)

print("Start")
greet()
print("End")
```

실행 순서를 따라가 보자.

1.  `print("Start")`
2.  `greet()` 호출
3.  새로운 Stack Frame 생성
4.  `message` 생성
5.  `print(message)` 실행
6.  `greet()` 종료
7.  Stack Frame 제거
8.  `print("End")`

------------------------------------------------------------------------

# 📦 Stack Frame 변화

함수 호출 전

``` text
Stack

┌────────────────────────┐
│ (비어 있음)            │
└────────────────────────┘
```

`greet()` 호출

``` text
Stack

┌────────────────────────┐
│ greet()                │
│------------------------│
│ message = "Hello"      │
└────────────────────────┘
```

함수 종료

``` text
Stack

┌────────────────────────┐
│ (비어 있음)            │
└────────────────────────┘
```

------------------------------------------------------------------------

# 🧠 메모리 변화 표

  실행 단계        Stack 상태
  ---------------- -----------------
  함수 호출 전     Frame 없음
  `greet()` 호출   Frame 생성
  `message` 생성   Frame 내부 저장
  함수 종료        Frame 제거

------------------------------------------------------------------------

# ❓ Why?

왜 지역 변수는 함수가 끝나면 사용할 수 없을까?

지역 변수는 **Stack Frame 안에서만 존재**하기 때문이다.

함수가 종료되면 Stack Frame이 제거되고, 그 안에 있던 지역 변수도 함께
사라진다.

이것이 함수 밖에서 지역 변수에 접근할 수 없는 이유이다.

------------------------------------------------------------------------

# ⚠️ 자주 하는 오해

❌ Stack Frame은 함수 자체를 저장한다.

보다 정확하게는,

> **함수를 실행하기 위한 정보들을 관리하는 실행 단위**이다.

즉, 함수 코드와 Stack Frame은 같은 개념이 아니다.

------------------------------------------------------------------------

# ✅ 핵심 정리

-   함수가 호출되면 Stack Frame이 생성된다.
-   지역 변수는 Stack Frame 안에서 관리된다.
-   함수가 종료되면 Stack Frame도 제거된다.
-   제거된 Stack Frame 안의 지역 변수는 더 이상 사용할 수 없다.

# Chapter 2. Stack이란 무엇인가?

## Section 2.3 함수 호출과 반환, Stack은 어떻게 변할까?

------------------------------------------------------------------------

# 📖 왜 여러 개의 함수를 살펴봐야 할까?

앞에서 Stack과 Stack Frame의 개념을 배웠다.

이번에는 함수가 **다른 함수를 호출하는 상황**을 통해 Stack이 실제로
어떻게 변하는지 살펴본다.

이 과정을 이해하면 **LIFO(Last In, First Out)** 구조가 왜 필요한지
자연스럽게 이해할 수 있다.

------------------------------------------------------------------------

# 🤔 생각해 보기

다음 코드를 실행하면 어떤 순서로 함수가 실행될까?

``` python
def first():
    print("first")
    second()

def second():
    print("second")

first()
```

`second()`가 끝난 뒤 프로그램은 어디로 돌아갈까?

------------------------------------------------------------------------

# 💡 함수는 서로를 호출할 수 있다.

하나의 함수 안에서 다른 함수를 호출하는 것은 매우 흔한 일이다.

``` text
main()
  └── first()
        └── second()
```

함수가 호출될 때마다 새로운 Stack Frame이 생성되고, 종료되면 가장 최근에
생성된 Stack Frame부터 제거된다.

------------------------------------------------------------------------

# 🧪 Python 예제

``` python
def second():
    print("2")

def first():
    print("1")
    second()
    print("1 end")

print("Start")
first()
print("End")
```

------------------------------------------------------------------------

# ▶ 실행 순서

1.  `print("Start")`
2.  `first()` 호출
3.  `first()`의 Stack Frame 생성
4.  `second()` 호출
5.  `second()`의 Stack Frame 생성
6.  `second()` 종료
7.  `second()`의 Stack Frame 제거
8.  `first()` 계속 실행
9.  `first()` 종료
10. `first()`의 Stack Frame 제거
11. `print("End")`

------------------------------------------------------------------------

# 📦 Stack 변화

초기 상태

``` text
Stack

┌──────────────────┐
│ (비어 있음)      │
└──────────────────┘
```

`first()` 호출

``` text
Stack

┌──────────────────┐
│ first()          │
└──────────────────┘
```

`second()` 호출

``` text
Stack

┌──────────────────┐
│ second()         │ ← TOP
├──────────────────┤
│ first()          │
└──────────────────┘
```

`second()` 종료

``` text
Stack

┌──────────────────┐
│ first()          │
└──────────────────┘
```

`first()` 종료

``` text
Stack

┌──────────────────┐
│ (비어 있음)      │
└──────────────────┘
```

> 위 그림은 학습을 위한 단순화된 메모리 모델이다.

------------------------------------------------------------------------

# 🧠 메모리 변화 표

  단계              Stack 상태
  ----------------- -----------------------
  시작              비어 있음
  `first()` 호출    `first()` Frame 생성
  `second()` 호출   `second()` Frame 추가
  `second()` 종료   `second()` Frame 제거
  `first()` 종료    `first()` Frame 제거

------------------------------------------------------------------------

# ❓ Why?

왜 `second()`가 끝나면 `first()`로 돌아갈까?

`first()`의 실행은 아직 끝나지 않았기 때문이다.

Stack에는 **어떤 함수가 실행 중인지**, **어디까지 실행했는지**에 대한
정보가 함께 관리된다.

따라서 `second()`가 종료되면 Stack의 가장 위(Frame)가 제거되고, 바로
아래에 있던 `first()`의 실행이 이어진다.

이것이 함수 호출이 자연스럽게 이어지는 이유이다.

------------------------------------------------------------------------

# ⚠️ 자주 하는 오해

❌ 함수가 끝나면 프로그램도 끝난다.

함수가 다른 함수를 호출한 경우에는 가장 최근에 호출된 함수만 종료될
뿐이다.

호출한 함수가 아직 남아 있다면 그 함수의 실행이 계속된다.

------------------------------------------------------------------------

# ✅ 핵심 정리

-   함수를 호출하면 새로운 Stack Frame이 생성된다.
-   여러 함수가 호출되면 Stack Frame이 차곡차곡 쌓인다.
-   가장 마지막에 호출된 함수가 가장 먼저 종료된다.
-   함수 종료 후에는 호출한 함수의 실행이 이어진다.

## Section 2.4 지역 변수(Local Variable)와 Stack

------------------------------------------------------------------------

# 📖 왜 지역 변수를 이해해야 할까?

함수를 배우면서 가장 많이 만나는 개념 중 하나가 **지역 변수(Local
Variable)** 이다.

많은 입문자가 다음과 같은 경험을 한다.

``` python
def hello():
    message = "Hello"

print(message)
```

실행하면 오류가 발생한다.

왜 `message`를 사용할 수 없을까?

그 이유는 **지역 변수는 Stack Frame 안에서만 존재하기 때문**이다.

------------------------------------------------------------------------

# 🤔 생각해 보기

다음 코드를 살펴보자.

``` python
def add():
    a = 10
    b = 20
    print(a + b)

add()
```

`a`와 `b`는 언제 만들어질까?

그리고 `add()`가 끝난 뒤에도 계속 존재할까?

------------------------------------------------------------------------

# 💡 지역 변수란?

지역 변수(Local Variable)는 **함수 안에서 생성되어 해당 함수 안에서만
사용할 수 있는 변수**를 말한다.

함수가 호출되면 지역 변수를 관리하기 위한 Stack Frame이 생성되고, 함수가
종료되면 Stack Frame과 함께 지역 변수도 정리된다.

------------------------------------------------------------------------

# 🧪 Python 예제

``` python
def add():
    a = 10
    b = 20
    print(a + b)

print("Start")
add()
print("End")
```

실행 순서

1.  `add()` 호출
2.  Stack Frame 생성
3.  `a` 생성
4.  `b` 생성
5.  `print(a + b)`
6.  함수 종료
7.  Stack Frame 제거
8.  `a`, `b`도 함께 정리

------------------------------------------------------------------------

# 📦 Stack 변화

함수 호출 전

``` text
Stack

┌────────────────────────┐
│ (비어 있음)            │
└────────────────────────┘
```

함수 실행 중

``` text
Stack

┌────────────────────────┐
│ add()                  │
│------------------------│
│ a = 10                 │
│ b = 20                 │
└────────────────────────┘
```

함수 종료

``` text
Stack

┌────────────────────────┐
│ (비어 있음)            │
└────────────────────────┘
```

> 위 그림은 학습을 위한 단순화된 메모리 모델이다.

------------------------------------------------------------------------

# 🧠 메모리 변화 표

  단계           Stack Frame   지역 변수
  -------------- ------------- ---------------
  함수 호출 전   없음          없음
  함수 실행      생성          `a`, `b` 생성
  함수 종료      제거          함께 제거

------------------------------------------------------------------------

# ❓ Why?

왜 함수 밖에서는 `a`와 `b`를 사용할 수 없을까?

지역 변수는 **현재 실행 중인 함수의 Stack Frame 안에서만 유효**하다.

함수가 종료되면 Stack Frame 자체가 제거되므로, 그 안에 있던 지역 변수도
더 이상 존재하지 않는다.

따라서 다음 코드는 오류가 발생한다.

``` python
def add():
    a = 10

add()

print(a)
```

`a`는 이미 제거된 Stack Frame 안에 있었기 때문이다.

------------------------------------------------------------------------

# ⚠️ 자주 하는 오해

❌ 지역 변수는 프로그램이 종료될 때 사라진다.

정확한 설명은 다음과 같다.

> **지역 변수는 함수가 종료되는 순간 Stack Frame과 함께 정리된다.**

프로그램이 계속 실행 중이어도 함수가 끝났다면 지역 변수는 사용할 수
없다.

------------------------------------------------------------------------

# ✅ 핵심 정리

-   지역 변수는 함수 안에서 생성된다.
-   지역 변수는 Stack Frame 안에서 관리된다.
-   함수가 종료되면 Stack Frame과 함께 제거된다.
-   함수 밖에서는 지역 변수에 접근할 수 없다.

## Section 3.1 Heap의 개념 이해

------------------------------------------------------------------------

# 📖 왜 Heap을 배워야 할까?

Chapter 2에서는 함수가 실행될 때 사용하는 **Stack**을 배웠다.

하지만 프로그램에는 함수만 있는 것이 아니다.

다음과 같은 데이터는 어디에 저장될까?

``` python
numbers = [1, 2, 3]
name = "HumanClass"
user = {"name": "Kim"}
```

이처럼 프로그램에서 사용하는 **객체(Object)** 를 저장하기 위한 공간이
바로 **Heap**이다.

> 이번 Chapter에서는 Heap의 개념을 이해하는 데 집중하며, 객체와 참조는
> 다음 Section부터 단계적으로 학습한다.

------------------------------------------------------------------------

# 🤔 생각해 보기

다음 코드를 실행하면 리스트는 어디에 만들어질까?

``` python
numbers = [10, 20, 30]
```

-   변수 안에 리스트가 들어갈까?
-   Stack에 저장될까?
-   Heap에 저장될까?

이 질문에 답하기 위해 Heap을 알아보자.

------------------------------------------------------------------------

# 💡 Heap이란?

Heap은 **프로그램에서 생성되는 객체(Object)를 저장하는 메모리
영역**이다.

교육용 모델에서는 다음과 같이 이해하면 된다.

-   리스트(List)
-   딕셔너리(Dictionary)
-   문자열(String)
-   기타 객체(Object)

와 같은 데이터가 Heap에 생성된다.

> 실제 메모리 관리 방식은 언어와 구현에 따라 달라질 수 있으며, 본 문서는
> 학습을 위한 단순화된 모델을 사용한다.

------------------------------------------------------------------------

# 🧠 Stack과 Heap의 역할 비교

  Stack               Heap
  ------------------- ---------------------------
  함수 호출 관리      객체 저장
  Stack Frame 생성    객체 생성
  함수 종료 시 정리   객체 생명주기에 따라 관리

Stack과 Heap은 경쟁 관계가 아니라 **서로 협력하는 메모리 영역**이다.

------------------------------------------------------------------------

# 🧪 Python 예제

``` python
numbers = [10, 20, 30]
```

교육용 메모리 모델에서는 다음과 같이 표현할 수 있다.

``` text
Stack                    Heap

numbers  ─────────────▶  [10, 20, 30]
```

현재 단계에서는 화살표의 의미를 자세히 설명하지 않는다.

지금은 **리스트 객체가 Heap에 생성된다**는 점만 이해하면 충분하다.

------------------------------------------------------------------------

# 📦 Heap의 특징

Heap은 프로그램 실행 중 필요한 만큼 객체가 생성되는 공간이다.

예를 들어,

``` python
a = [1]
b = [2]
c = [3]
```

교육용 모델에서는 Heap에 각각의 리스트 객체가 생성된다고 생각할 수 있다.

``` text
Heap

┌──────────────┐
│ [1]          │
├──────────────┤
│ [2]          │
├──────────────┤
│ [3]          │
└──────────────┘
```

------------------------------------------------------------------------

# ❓ Why?

왜 Stack이 아닌 Heap에 객체를 저장할까?

객체는 함수보다 오래 사용되거나 여러 곳에서 함께 사용할 수도 있다.

따라서 함수 실행을 위한 공간(Stack)과 객체를 위한 공간(Heap)을 구분하면

## Section 3.2 객체(Object)와 Heap

------------------------------------------------------------------------

# 📖 왜 객체(Object)를 이해해야 할까?

Heap을 이해하려면 먼저 **객체(Object)** 가 무엇인지 알아야 한다.

Python에서 다루는 대부분의 데이터는 객체로 표현된다.

``` python
number = 10
text = "Python"
scores = [90, 95, 100]
user = {"name": "Kim"}
```

겉으로는 모두 변수처럼 보이지만, 실제로는 **객체를 생성하고 사용하는
과정**이 일어난다.

이번 Section에서는 객체의 개념과 Heap의 관계를 이해하는 데 집중한다.

------------------------------------------------------------------------

# 🤔 생각해 보기

다음 코드를 보자.

``` python
fruits = ["apple", "banana"]
```

`fruits`라는 이름이 리스트 자체일까?

아니면 리스트는 다른 곳에 존재하고 `fruits`는 그것을 사용하는 것일까?

다음 Section에서 이 질문이 **참조(Reference)** 로 이어진다.

------------------------------------------------------------------------

# 💡 객체(Object)란?

객체는 **프로그램이 메모리에서 다루는 하나의 데이터**이다.

교육용으로는 다음과 같은 것들을 객체라고 생각하면 된다.

-   숫자
-   문자열
-   리스트
-   딕셔너리
-   집합
-   튜플

Python에서는 이러한 데이터를 생성하면 객체가 만들어진다.

------------------------------------------------------------------------

# 🧠 객체는 왜 Heap에 저장될까?

객체는 함수보다 오래 사용될 수도 있고, 프로그램의 여러 부분에서 활용될
수도 있다.

따라서 함수 실행을 위한 Stack과 구분하여, 객체는 Heap에서 관리하는
구조를 사용한다.

> 본 문서에서는 학습을 위해 단순화된 메모리 모델을 사용한다.

------------------------------------------------------------------------

# 🧪 Python 예제

``` python
name = "HumanClass"
numbers = [1, 2, 3]
user = {"name": "Kim"}
```

교육용 메모리 모델

``` text
Stack                         Heap

name    ───────────────▶      "HumanClass"

numbers ───────────────▶      [1, 2, 3]

user    ───────────────▶      {"name": "Kim"}
```

현재는 화살표를 **객체를 사용하는 연결** 정도로만 이해하면 된다.

참조의 정확한 의미는 Chapter 4에서 다룬다.

------------------------------------------------------------------------

# 📦 Heap에는 여러 객체가 함께 존재할 수 있다.

``` python
a = [1]
b = [2]
c = [3]
```

교육용 모델

``` text
Heap

┌────────────────────┐
│ [1]                │
├────────────────────┤
│ [2]                │
├────────────────────┤
│ [3]                │
└────────────────────┘
```

Heap에는 프로그램이 필요로 하는 다양한 객체가 함께 존재한다.

------------------------------------------------------------------------

# ❓ Why?

왜 변수 안에 데이터를 모두 넣지 않을까?

객체를 Heap에서 별도로 관리하면 프로그램은 데이터를 효율적으로 다룰 수
있다.

이 덕분에 동일한 객체를 여러 곳에서 사용할 수도 있고, 함수 호출과 객체
생명주기를 분리하여 관리할 수도 있다.

이 개념은 다음 Chapter의 **참조(Reference)** 를 이해하는 핵심이 된다.

------------------------------------------------------------------------

# ⚠️ 자주 하는 오해

> 사용하기 위한 이름이다.**

현재는 이 정도만 이해해도 충분하다.

# Chapter 4. 변수와 참조(Reference)

## Section 4.1 참조(Reference)란 무엇인가?

------------------------------------------------------------------------

# 📖 왜 참조를 배워야 할까?

지금까지 우리는 다음 두 가지를 배웠다.

-   Stack에는 함수 실행 정보가 저장된다.
-   Heap에는 객체(Object)가 생성된다.

그렇다면 하나의 의문이 생긴다.

> **Stack에 있는 변수는 Heap에 있는 객체를 어떻게 사용할까?**

이 질문에 대한 답이 바로 **참조(Reference)** 이다.

참조를 이해하면 리스트, 딕셔너리, 함수 호출에서 발생하는 다양한 현상을
자연스럽게 설명할 수 있다.

------------------------------------------------------------------------

# 🤔 생각해 보기

다음 코드를 보자.

``` python
numbers = [10, 20, 30]
```

여기서 `numbers` 안에 리스트가 들어있는 것일까?

아니면 리스트는 Heap에 있고 `numbers`는 다른 역할을 하는 것일까?

------------------------------------------------------------------------

# 💡 참조(Reference)란?

교육용 메모리 모델에서는 다음과 같이 이해하면 된다.

> **참조(Reference)는 변수와 객체를 연결하는 관계이다.**

즉,

-   객체는 Heap에 존재한다.
-   변수는 Stack에 존재한다.
-   변수는 참조를 통해 객체를 사용한다.

------------------------------------------------------------------------

# 🧠 그림으로 이해하기

``` text
Stack                         Heap

numbers  ───────────────▶     [10, 20, 30]
```

여기서 화살표가 바로 **참조**를 의미한다.

중요한 점은 변수 안에 리스트가 들어있는 것이 아니라,

**변수가 Heap의 객체를 사용할 수 있도록 연결되어 있다는 것**이다.

------------------------------------------------------------------------

# 🧪 Python 예제

``` python
message = "Hello"
```

교육용 메모리 모델

``` text
Stack                     Heap

message ─────────────▶     "Hello"
```

변수는 문자열 자체를 담는다고 생각하기보다,

문자열 객체를 사용할 수 있도록 연결되어 있다고 이해하면 이후 학습이 훨씬
쉬워진다.

------------------------------------------------------------------------

# 🧪 또 다른 예제

``` python
scores = [90, 95]
```

``` text
Stack                     Heap

scores ─────────────▶      [90, 95]
```

문자열이든 리스트든 교육용 모델에서는 동일한 방식으로 이해할 수 있다.

------------------------------------------------------------------------

# ❓ Why?

왜 참조라는 개념을 사용할까?

객체를 변수 안으로 복사해서 사용하는 방식이라면 메모리 낭비가 커질 수
있다.

객체는 Heap에 하나 두고, 필요한 변수들이 그 객체를 사용할 수 있도록
연결하면 프로그램을 효율적으로 구성할 수 있다.

다음 Section에서는 이 구조가 변수와 객체의 관계를 어떻게 설명하는지
살펴본다.

------------------------------------------------------------------------

교육용 모델에서는 다음처럼 이해하는 것이 좋다.

-   객체는 Heap에 있다.
-   변수는 Stack에 있다.
-   참조가 둘을 연결한다.

# 📖 왜 변수와 객체를 구분해야 할까?

Section 4.1에서는 **참조(Reference)** 가 변수와 객체를 연결하는 관계라는
것을 배웠다.

이번에는 한 걸음 더 나아가 **변수와 객체는 서로 다른 존재**라는 사실을
이해해 보자.

이 개념을 이해하면 이후 배우게 될 **공유(Sharing)** 와 **함수 인자
전달**을 쉽게 이해할 수 있다.

------------------------------------------------------------------------

# 🤔 생각해 보기

다음 코드를 보자.

``` python
message = "Hello"
```

다음 두 문장 중 어떤 것이 더 알맞을까?

-   변수 `message` 안에 `"Hello"`가 들어 있다.
-   변수 `message`는 `"Hello"` 객체를 사용할 수 있도록 연결되어 있다.

교육용 메모리 모델에서는 두 번째 표현을 사용한다.

------------------------------------------------------------------------

# 💡 변수와 객체는 서로 다르다.

교육용 메모리 모델에서는 다음과 같이 이해한다.

-   변수는 프로그램에서 사용하는 **이름(Name)** 이다.
-   객체는 Heap에 존재하는 **실제 데이터**이다.
-   참조가 변수와 객체를 연결한다.

-   `message`는 변수
-   `"Hello"`는 객체
-   화살표는 참조를 의미한다.

즉, 변수와 객체는 같은 것이 아니다.

------------------------------------------------------------------------

# 📖 왜 이 내용을 배워야 할까?

참조를 이해했다면 이제 가장 중요한 질문을 살펴볼 차례이다.

``` python
a = [1, 2, 3]

```

왜 `a`와 `b`를 모두 출력하면 같은 리스트가 보일까?

이 현상은 **하나의 객체를 여러 변수가 함께 사용할 수 있기 때문**이다.

# 🤔 생각해 보기

다음 코드를 실행해 보자.

``` python

b = a
```

여기서 Heap에는 리스트가 몇 개 존재할까?

-   두 개?
-   하나?

교육용 메모리 모델에서는 **하나의 리스트 객체**가 존재한다고 이해한다.

------------------------------------------------------------------------

# 💡 하나의 객체를 여러 변수가 사용할 수 있다.

다음 코드를 살펴보자.

``` python
a = [10, 20]
b = a
```

실행이 끝나면 새로운 리스트가 만들어지는 것이 아니라, `b`도 기존
리스트를 사용할 수 있게 된다.

------------------------------------------------------------------------

# 🧠 메모리 다이어그램

``` text
Stack                              Heap

a ───────────────────────────▶
                                [10, 20]
b ───────────────────────────▶
```

두 개의 변수가 **같은 객체**를 가리키고 있다.

------------------------------------------------------------------------

# 🧪 Python 예제

``` python
a = [10, 20]
b = a

print(a)
print(b)
```

출력

``` text
[10, 20]
[10, 20]
```

두 변수 모두 같은 객체를 사용하므로 같은 내용이 출력된다.

------------------------------------------------------------------------

# 🧪 객체를 수정하면?

``` python
a = [10, 20]
b = a

a.append(30)

print(a)
print(b)
```

출력

``` text
[10, 20, 30]
[10, 20, 30]
```

교육용 메모리 모델

``` text
Stack                              Heap

a ───────────────────────────▶
                                [10, 20, 30]
b ───────────────────────────▶
```

리스트 객체는 하나뿐이므로 객체를 수정하면 두 변수에서 같은 결과를
확인할 수 있다.

------------------------------------------------------------------------

# 📋 메모리 변화

  실행 코드        Stack 변화   Heap 변화
  ---------------- ------------ ------------------
  `a = [10, 20]`   `a` 생성     리스트 생성
  `b = a`          `b` 생성     변화 없음
  `a.append(30)`   변화 없음    기존 리스트 수정

------------------------------------------------------------------------

# ❓ Why?

왜 `b = a`에서 새로운 리스트가 생기지 않을까?

교육용 모델에서는 `b`가 **기존 객체를 사용할 수 있도록 연결**되었다고
이해한다.

이 덕분에 불필요하게 같은 데이터를 여러 번 만들지 않아도 된다.

------------------------------------------------------------------------

# ⚠️ 자주 하는 오해

❌ `b = a`를 실행하면 리스트가 자동으로 복사된다.

교육용 모델에서는 그렇지 않다.

-   새로운 객체 생성 ❌
-   기존 객체를 함께 사용 ⭕

(복사 방법은 이후 별도의 문서에서 다룬다.)

------------------------------------------------------------------------

-   `b = a`는 새로운 객체를 만드는 것이 아니다.
-   객체를 수정하면 같은 객체를 사용하는 모든 변수에서 변화가 보인다.

# Chapter 4. 변수와 참조(Reference)

## Section 4.4 함수 호출과 참조의 메모리 변화

------------------------------------------------------------------------

# 📖 왜 함수와 참조를 함께 배워야 할까?

앞에서는 하나의 객체를 여러 변수가 함께 사용할 수 있다는 것을 배웠다.

이번에는 그 개념을 **함수 호출**까지 확장해 보자.

함수를 호출하면 새로운 **Stack Frame**이 만들어지지만, 객체는 여전히
**Heap**에 존재한다.

그렇다면 함수의 매개변수는 객체를 어떻게 사용할까?

------------------------------------------------------------------------

# 🤔 생각해 보기

``` python
def show(data):
    print(data)

numbers = [1, 2, 3]
show(numbers)
```

함수가 호출되면 리스트가 새로 만들어질까?

아니면 기존 리스트를 그대로 사용할까?

------------------------------------------------------------------------

# 💡 함수의 매개변수도 객체를 참조한다.

교육용 메모리 모델에서는 다음과 같이 이해한다.

1.  Heap에 객체가 생성된다.
2.  호출한 쪽의 변수가 객체를 참조한다.
3.  함수가 호출되면 새로운 Stack Frame이 생성된다.
4.  매개변수도 **같은 객체**를 참조한다.

------------------------------------------------------------------------

# 🧪 Python 예제

``` python
def print_items(items):
    print(items)

numbers = [10, 20]
print_items(numbers)
```

호출 전

``` text
Stack                           Heap

numbers ───────────────▶        [10, 20]
```

함수 호출 중

``` text
Stack

┌────────────────────────────┐
│ print_items Frame          │
│                            │
│ items ───────────────┐      │
└──────────────────────┼──────┘
                       │
┌──────────────────────▼──────┐
│ Global Frame                │
│ numbers ──────────────┐      │
└────────────────────────┼─────┘
                         │

Heap
[10, 20]
```

`numbers`와 `items`는 모두 같은 객체를 사용한다.

------------------------------------------------------------------------

# 🧪 객체를 수정하는 경우

``` python
def add_value(items):
    items.append(30)

numbers = [10, 20]
add_value(numbers)

print(numbers)
```

출력

``` text
[10, 20, 30]
```

교육용 메모리 모델

``` text
Stack                           Heap

numbers ───────────────▶
                         [10, 20, 30]
items   ───────────────▶
```

함수 안에서 수정한 객체는 호출한 곳에서도 같은 객체이므로 변경 결과를
확인할 수 있다.

------------------------------------------------------------------------

# 📋 메모리 변화

  실행 단계      Stack 변화       Heap 변화
  -------------- ---------------- --------------------
  리스트 생성    `numbers` 생성   `[10, 20]` 생성
  함수 호출      `items` 생성     변화 없음
  `append(30)`   변화 없음        기존 리스트 수정
  함수 종료      `items` 제거     수정된 리스트 유지

------------------------------------------------------------------------

# ❓ Why?

왜 함수 호출 시 새로운 리스트를 만들지 않을까?

교육용 모델에서는 함수도 **기존 객체를 사용할 수 있도록 연결**된다고
이해한다.

이렇게 하면 같은 데이터를 불필요하게 여러 번 만들지 않아도 된다.

------------------------------------------------------------------------

# ⚠️ 자주 하는 오해

❌ 함수의 매개변수는 항상 새로운 객체를 만든다.

교육용 모델에서는

-   새로운 Stack Frame은 생성된다.
-   새로운 객체는 자동으로 생성되지 않는다.
-   매개변수는 기존 객체를 함께 사용한다.

------------------------------------------------------------------------

# ✅ 핵심 정리

-   함수 호출 시 새로운 Stack Frame이 생성된다.
-   매개변수도 같은 Heap 객체를 참조할 수 있다.
-   객체를 수정하면 호출한 곳에서도 변경 내용을 확인할 수 있다.
-   Stack은 변하지만 Heap의 객체는 그대로 유지된다.

## Section 5.1 코드 한 줄과 메모리 변화

------------------------------------------------------------------------

# 📖 왜 메모리 변화를 추적해야 할까?

지금까지는 Stack, Heap, 그리고 참조(Reference)를 각각 배웠다.

하지만 실제 프로그램에서는 이 개념들이 **동시에** 동작한다.

개발자는 코드를 읽을 때 단순히 실행 결과만이 아니라,

> **"이 코드가 실행되면 메모리가 어떻게 변할까?"**

를 생각하는 습관이 중요하다.

이번 Chapter에서는 코드를 한 줄씩 실행하면서 Stack과 Heap이 어떻게
변하는지 단계적으로 살펴본다.

> 본 문서의 그림은 학습을 위한 교육용 메모리 모델이다.

------------------------------------------------------------------------

# 🤔 생각해 보기

다음 코드를 실행하면 메모리는 어떻게 변할까?

``` python
name = "Python"
scores = [90, 95]
```

객체는 언제 생성되고, 변수는 언제 만들어질까?

------------------------------------------------------------------------

# 💡 코드는 한 줄씩 실행된다.

Python은 일반적으로 코드를 위에서 아래로 순서대로 실행한다.

각 줄이 실행될 때마다

-   새로운 객체가 생성될 수 있고
-   새로운 변수가 만들어질 수 있으며
-   Stack과 Heap의 상태가 달라질 수 있다.

------------------------------------------------------------------------

# 🧪 단계별 예제

``` python
name = "Python"
scores = [90, 95]
```

### ① 실행 전

``` text
Stack                 Heap

(비어 있음)           (비어 있음)
```

### ② 첫 번째 줄 실행

``` python
name = "Python"
```

``` text
Stack                          Heap

name ───────────────▶          "Python"
```

### ③ 두 번째 줄 실행

``` python
scores = [90, 95]
```

``` text
Stack                          Heap

name ───────────────▶          "Python"

scores ─────────────▶          [90, 95]
```

코드가 한 줄씩 실행될 때마다 메모리도 함께 변화한다.

------------------------------------------------------------------------

# 📋 메모리 변화 표

  실행 단계            Stack           Heap
  -------------------- --------------- ------------------
  시작                 비어 있음       비어 있음
  `name = "Python"`    `name` 생성     문자열 객체 생성
  `scores = [90,95]`   `scores` 생성   리스트 객체 생성

왜 실행 순서를 따라 메모리를 이해해야 할까?

프로그램은 모든 객체를 한꺼번에 만들지 않는다.

필요한 코드가 실행되는 시점마다 메모리가 변화한다.

이 과정을 이해하면 복잡한 프로그램도 단계적으로 분석할 수 있다.

------------------------------------------------------------------------

생성된다**고 이해하면 된다.

## Section 5.2 변수 재할당(Reassignment)과 메모리 변화

------------------------------------------------------------------------

# 📖 왜 변수 재할당을 알아야 할까?

프로그램에서는 같은 변수를 여러 번 사용하는 경우가 많다.

``` python
name = "Python"
name = "Java"
```

겉으로 보기에는 단순히 값이 바뀐 것처럼 보인다.

하지만 교육용 메모리 모델에서는 **변수가 어떤 객체를 참조하는지가
변경**된 것으로 이해한다.

이번 Section에서는 변수 재할당이 일어날 때 Stack과 Heap이 어떻게
변하는지 단계별로 살펴본다.

> 본 문서의 메모리 그림은 학습을 위한 단순화된 모델이다.

------------------------------------------------------------------------

# 🤔 생각해 보기

다음 코드를 실행하면 어떤 일이 일어날까?

``` python
name = "Python"
name = "Java"
```

-   `"Python"`이 `"Java"`로 바뀌는 것일까?
-   아니면 새로운 객체가 만들어지는 것일까?

------------------------------------------------------------------------

# 💡 재할당이란?

재할당(Reassignment)은 **이미 존재하는 변수에 새로운 값을 다시 대입하는
것**이다.

교육용 모델에서는 다음과 같이 이해한다.

1.  새로운 객체가 필요하면 Heap에 생성된다.
2.  변수는 새 객체를 참조하도록 연결이 바뀐다.

------------------------------------------------------------------------

# 🧪 단계별 예제

``` python
name = "Python"
name = "Java"
```

### ① 실행 전

``` text
Stack                Heap

(비어 있음)          (비어 있음)
```

### ② 첫 번째 줄 실행

``` text
Stack                         Heap

name ───────────────▶         "Python"
```

### ③ 두 번째 줄 실행

``` text
Stack                         Heap

name ───────────────▶         "Java"

Heap
"Python"
"Java"
```

교육용 모델에서는 `name`이 `"Java"` 객체를 참조하도록 연결이 변경된
것으로 이해한다.

------------------------------------------------------------------------

# 📋 메모리 변화 표

  실행 단계           Stack 변화    Heap 변화
  ------------------- ------------- -----------------
  시작                비어 있음     비어 있음
  `name = "Python"`   `name` 생성   `"Python"` 생성
  `name = "Java"`     참조 변경     `"Java"` 생성

------------------------------------------------------------------------

# ❓ Why?

왜 재할당을 새로운 연결로 이해할까?

변수는 데이터를 담는 상자가 아니라 **객체를 사용할 수 있는 이름**이기
때문이다.

따라서 새로운 값을 대입하면 변수는 새 객체를 사용하도록 연결이 변경된다.

------------------------------------------------------------------------

# ⚠️ 자주 하는 오해

❌ `"Python"` 객체가 `"Java"`로 변한다.

교육용 모델에서는

-   기존 객체가 직접 바뀌는 것이 아니라,
-   변수가 새로운 객체를 참조하게 된다고 이해한다.

> 실제 메모리 관리 방식은 구현에 따라 다를 수 있으며, 본 문서는 교육용
> 모델을 사용한다.

------------------------------------------------------------------------

# ✅ 핵심 정리

-   재할당은 변수에 새로운 값을 다시 대입하는 것이다.
-   변수는 새로운 객체를 참조하도록 연결이 변경될 수 있다.
-   코드 실행 순서에 따라 Stack과 Heap의 상태도 함께 변한다.

## Section 5.3 여러 변수와 재할당의 메모리 변화

------------------------------------------------------------------------

# 📖 왜 이 상황을 배워야 할까?

앞에서는 하나의 변수에 새로운 값을 대입하는 **재할당**을 살펴보았다.

이번에는 **여러 변수가 하나의 객체를 함께 사용하는 상황에서 재할당이
일어나면 어떤 일이 발생하는지** 알아보자.

이 개념은 참조(Reference)를 이해하는 가장 중요한 단계 중 하나이다.

------------------------------------------------------------------------

# 🤔 생각해 보기

다음 코드를 보자.

``` python
a = [1, 2]
b = a
a = [3, 4]
```

마지막 줄이 실행된 뒤,

-   `a`와 `b`는 같은 리스트를 사용할까?
-   Heap에는 리스트가 몇 개 존재할까?

------------------------------------------------------------------------

# 💡 재할당은 기존 객체를 변경하지 않는다.

교육용 메모리 모델에서는 다음과 같이 이해한다.

1.  `a`가 첫 번째 리스트를 참조한다.
2.  `b`도 같은 리스트를 참조한다.
3.  `a`를 재할당하면 새로운 리스트가 생성된다.
4.  `a`만 새 객체를 참조하고 `b`는 기존 객체를 계속 사용한다.

------------------------------------------------------------------------

# 🧪 단계별 예제

``` python
a = [1, 2]
b = a
a = [3, 4]
```

### ① 첫 번째 줄

``` text
Stack                     Heap

a ───────────────▶        [1, 2]
```

### ② 두 번째 줄

``` text
Stack                     Heap

a ───────────────▶
                     [1, 2]
b ───────────────▶
```

### ③ 세 번째 줄

``` text
Stack                              Heap

a ───────────────▶                 [3, 4]

b ───────────────▶                 [1, 2]
```

새로운 리스트가 생성되고 `a`의 연결만 변경된다.

------------------------------------------------------------------------

# 🧪 출력 결과

``` python
a = [1, 2]
b = a

a = [3, 4]

print(a)
print(b)
```

출력

``` text
[3, 4]
[1, 2]
```

재할당은 다른 변수가 참조하는 객체를 변경하지 않는다.

------------------------------------------------------------------------

# 📋 메모리 변화 표

  실행 단계      Stack 변화        Heap 변화
  -------------- ----------------- ---------------------
  `a = [1, 2]`   `a` 생성          첫 번째 리스트 생성
  `b = a`        `b` 생성          변화 없음
  `a = [3, 4]`   `a`의 참조 변경   두 번째 리스트 생성

------------------------------------------------------------------------

# ❓ Why?

왜 `b`도 함께 바뀌지 않을까?

재할당은 **변수의 연결을 변경하는 동작**이다.

기존 객체 자체를 수정하는 것이 아니므로 `b`는 원래 객체를 계속 사용할 수
있다.

------------------------------------------------------------------------

# ⚠️ 자주 하는 오해

❌ `a = [3, 4]`를 실행하면 기존 리스트가 `[3, 4]`로 바뀐다.

교육용 모델에서는

-   기존 리스트는 그대로 존재한다.
-   새로운 리스트가 생성된다.
-   `a`만 새로운 객체를 참조한다.

------------------------------------------------------------------------

# ✅ 핵심 정리

-   여러 변수가 하나의 객체를 참조할 수 있다.
-   재할당은 변수의 참조를 변경한다.
-   기존 객체는 자동으로 변경되지 않는다.
-   객체 수정과 재할당은 서로 다른 동작이다.

## Section 5.4 객체 수정과 재할당 비교

------------------------------------------------------------------------

# 📖 왜 둘을 비교해야 할까?

초보자가 가장 많이 헷갈리는 두 가지 동작이 있다.

-   객체 수정(Object Modification)
-   변수 재할당(Reassignment)

겉으로는 둘 다 값이 바뀌는 것처럼 보이지만, 교육용 메모리 모델에서는
**완전히 다른 동작**으로 이해한다.

------------------------------------------------------------------------

# 🤔 생각해 보기

다음 두 코드의 출력은 같을까?

``` python
a = [1, 2]
b = a
a.append(3)
```

``` python
a = [1, 2]
b = a
a = [3, 4]
```

왜 결과가 달라질까?

------------------------------------------------------------------------

# 💡 핵심 차이

-   **객체 수정**: 기존 객체의 내용이 바뀐다.
-   **재할당**: 변수가 다른 객체를 참조하도록 연결이 바뀐다.

------------------------------------------------------------------------

# 🧪 예제 1 : 객체 수정

``` python
a = [1, 2]
b = a
a.append(3)
```

메모리

``` text
Stack                          Heap

a ───────────────▶
                   [1, 2, 3]
b ───────────────▶
```

출력

``` text
[1, 2, 3]
[1, 2, 3]
```

두 변수는 같은 객체를 사용하므로 같은 결과를 본다.

------------------------------------------------------------------------

# 🧪 예제 2 : 재할당

``` python
a = [1, 2]
b = a
a = [3, 4]
```

메모리

``` text
Stack                               Heap

a ───────────────▶                  [3, 4]

b ───────────────▶                  [1, 2]
```

출력

``` text
[3, 4]
[1, 2]
```

`a`만 새로운 객체를 사용하게 된다.

------------------------------------------------------------------------

# 📋 비교 표

  구분                                  객체 수정   재할당
  ------------------------------------- ----------- ---------------
  새로운 객체 생성                      아니오      필요하면 생성
  기존 객체 변경                        예          아니오
  변수의 참조 변경                      아니오      예
  같은 객체를 참조하는 다른 변수 영향   있음        없음

------------------------------------------------------------------------

# ❓ Why?

왜 결과가 다를까?

객체 수정은 **객체 자체를 변경**한다.

재할당은 **변수가 바라보는 대상을 변경**한다.

즉, 수정 대상이 서로 다르기 때문이다.

------------------------------------------------------------------------

# ⚠️ 자주 하는 오해

❌ 재할당도 객체를 수정하는 것이다.

교육용 모델에서는

-   `append()` → 객체 수정
-   `=` → 변수의 참조 변경

으로 구분하면 된다.

------------------------------------------------------------------------

# ✅ 핵심 정리

-   객체 수정은 기존 객체를 바꾼다.
-   재할당은 변수의 연결을 바꾼다.
-   같은 객체를 참조하는 변수는 객체 수정의 영향을 함께 받는다.
-   재할당은 다른 변수가 참조하는 객체에는 영향을 주지 않는다.

> **"이 코드가 실행되면 메모리가 어떻게 변할까?"**

를 함께 생각하는 것이 목표이다.

## Section 6.2 함수 호출과 여러 변수의 메모리 분석

------------------------------------------------------------------------

# 📖 왜 함수 호출까지 분석해야 할까?

실제 프로그램은 단순한 변수 선언만으로 이루어지지 않는다.

대부분의 코드는 함수를 호출하고, 값을 전달하며, 여러 변수가 하나의
객체를 함께 사용한다.

이번 Section에서는 지금까지 학습한 내용을 이용하여 **함수 호출
전·중·후의 메모리 변화**를 단계별로 분석한다.

> 본 문서의 메모리 그림은 학습을 위한 교육용 모델이다.

------------------------------------------------------------------------

# 🤔 생각해 보기

다음 코드를 보자.

``` python
def show(data):
    print(data)

numbers = [1, 2]
alias = numbers

show(alias)
```

함수가 호출되면

-   새로운 리스트가 만들어질까?
-   `data`는 어떤 객체를 사용할까?

------------------------------------------------------------------------

# 💡 분석 순서

이 코드는 다음 순서로 분석한다.

1.  리스트 생성
2.  `alias`가 같은 객체를 참조
3.  함수 호출
4.  새로운 Stack Frame 생성
5.  매개변수가 같은 객체를 참조

------------------------------------------------------------------------

# 🧪 단계별 분석

``` python
def show(data):
    print(data)

numbers = [1, 2]
alias = numbers

show(alias)
```

### ① 리스트 생성

``` text
Stack                           Heap

numbers ───────────────▶        [1, 2]
```

### ② alias 생성

``` text
Stack                           Heap

numbers ───────────────▶
                               [1, 2]
alias ─────────────────▶
```

### ③ 함수 호출

``` text
Stack

┌────────────────────────────┐
│ show Frame                 │
│                            │
│ data ────────────────┐      │
└──────────────────────┼──────┘
                       │
┌──────────────────────▼──────┐
│ Global Frame                │
│ numbers ──────────────┐      │
│ alias ────────────────┤      │
└───────────────────────┼──────┘
                        │

Heap
[1, 2]
```

세 개의 변수(`numbers`, `alias`, `data`)가 모두 같은 객체를 사용한다.

### ④ 함수 종료

``` text
Stack                           Heap

numbers ───────────────▶
                               [1, 2]
alias ─────────────────▶
```

함수 Frame은 제거되지만 Heap의 객체는 그대로 유지된다.

------------------------------------------------------------------------

# 📋 메모리 변화 표

  실행 단계           Stack 변화       Heap 변화
  ------------------- ---------------- -------------
  리스트 생성         `numbers` 생성   리스트 생성
  `alias = numbers`   `alias` 생성     변화 없음
  함수 호출           `data` 생성      변화 없음
  함수 종료           `data` 제거      변화 없음

------------------------------------------------------------------------

# ❓ Why?

왜 함수의 매개변수도 같은 객체를 사용할까?

교육용 모델에서는 함수가 호출될 때 **객체를 새로 만드는 것이 아니라 기존
객체를 사용할 수 있도록 연결**된다고 이해한다.

이 덕분에 함수 안과 밖에서 같은 객체를 다룰 수 있다.

------------------------------------------------------------------------

# ⚠️ 자주 하는 오해

-   새로운 Stack Frame은 생성된다.
-   기존 객체는 그대로 사용된다.
-   매개변수는 같은 객체를 참조한다.

# Chapter 6. 실전 메모리 분석

## Section 6.3 함수 안에서 객체 수정과 재할당 비교

------------------------------------------------------------------------

# 📖 왜 함수 안에서의 동작을 비교해야 할까?

함수 밖에서 객체 수정과 재할당의 차이를 이해했다면, 이제는 **함수 안에서
같은 동작이 일어날 때 메모리가 어떻게 변하는지** 살펴볼 차례이다.

실무에서는 함수가 데이터를 수정하는지, 아니면 새로운 객체를 사용하도록
변경하는지를 이해하는 것이 매우 중요하다.

> 본 문서의 메모리 그림은 학습을 위한 교육용 모델이다.

------------------------------------------------------------------------

# 🤔 생각해 보기

다음 두 함수는 무엇이 다를까?

``` python
def update(items):
    items.append(3)
```

``` python
def update(items):
    items = [3]
```

두 함수 모두 `items`를 사용하지만, 메모리 변화는 같지 않다.

------------------------------------------------------------------------

# 💡 핵심 개념

-   **객체 수정**은 기존 객체의 내용을 변경한다.
-   **재할당**은 매개변수가 새로운 객체를 참조하도록 연결을 변경한다.

------------------------------------------------------------------------

# 🧪 예제 1 : 객체 수정

``` python
def update(items):
    items.append(3)

numbers = [1, 2]
update(numbers)
```

### 함수 호출 중

``` text
Stack

┌──────────────────────────┐
│ update Frame             │
│ items ───────────────┐   │
└──────────────────────┼───┘
                       │
┌──────────────────────▼───┐
│ Global Frame             │
│ numbers ──────────────┐   │
└────────────────────────┼──┘
                         │

Heap
[1, 2, 3]
```

함수 안과 밖이 같은 객체를 사용하므로 수정 내용이 함께 보인다.

출력

``` text
[1, 2, 3]
```

# 🧪 예제 2 : 재할당

``` python
def update(items):
    items = [3]

numbers = [1, 2]
update(numbers)

print(numbers)
```

### 함수 호출 중

``` text
Stack

┌──────────────────────────┐
│ update Frame             │
│ items ─────────────▶[3]  │
└──────────────────────────┘

┌──────────────────────────┐
│ Global Frame             │
│ numbers ─────────────▶   │
└──────────────────────┼───┘
                       │

Heap
[1, 2]
[3]
```

함수 안의 `items`만 새로운 객체를 참조한다.

출력

``` text
[1, 2]
```

# 📋 비교표

  항목                객체 수정       재할당
  ------------------- --------------- -----------------
  수정 대상           기존 객체       매개변수의 참조
  새로운 객체         생성하지 않음   필요 시 생성
  함수 밖 변수 영향   있음            없음

------------------------------------------------------------------------

# ❓ Why?

왜 결과가 다를까?

함수의 매개변수도 하나의 변수이다.

따라서 `=`를 사용하면 **매개변수의 참조만 변경**되고, 원래 변수가
참조하는 객체는 그대로 유지된다.

반면 `append()`는 기존 객체를 수정하므로 같은 객체를 참조하는 모든
변수가 변경된 내용을 확인할 수 있다.

------------------------------------------------------------------------

# ⚠️ 자주 하는 오해

❌ 함수 안에서 재할당하면 원래 변수도 함께 변경된다.

교육용 모델에서는 함수의 매개변수도 독립적인 변수이므로, 재할당은 그
매개변수의 연결만 변경한다고 이해한다.

------------------------------------------------------------------------

# ✅ 핵심 정리

-   함수 안에서도 객체 수정과 재할당은 서로 다른 동작이다.
-   객체 수정은 같은 객체를 사용하는 변수에 영향을 준다.
-   재할당은 매개변수의 참조만 변경한다.
-   함수 종료 후 재할당된 매개변수는 함께 사라진다.

## Section 6.4 중첩 함수 호출과 Stack Frame의 변화

------------------------------------------------------------------------

# 📖 왜 중첩 함수 호출을 배워야 할까?

프로그램은 하나의 함수만 실행하는 경우보다 함수가 다른 함수를 호출하는
경우가 훨씬 많다.

이때 **Stack Frame이 어떤 순서로 생성되고 제거되는지** 이해하면 함수
호출의 흐름을 명확하게 설명할 수 있다.

> 본 문서의 메모리 그림은 학습을 위한 교육용 모델이다.

------------------------------------------------------------------------

# 🤔 생각해 보기

다음 코드를 실행하면 Stack에는 어떤 일이 일어날까?

``` python
def second():
    print("Hello")

def first():
    second()

first()
```

------------------------------------------------------------------------

# 💡 핵심 개념

함수가 호출될 때마다 새로운 Stack Frame이 생성된다.

함수가 종료되면 **가장 마지막에 생성된 Frame부터 제거(LIFO)** 된다.

------------------------------------------------------------------------

# 🧪 단계별 분석

``` python

    print("Hello")

    second()

first()
```

``` text
└────────────────────┘
```

``` text

└────────────────────┘

┌────────────────────┐
│ first Frame        │
└────────────────────┘

┌────────────────────┐
│ Global Frame       │
└────────────────────┘
```

``` text
Stack

┌────────────────────┐
│ first Frame        │
└────────────────────┘

┌────────────────────┐
│ Global Frame       │
└────────────────────┘
```

### ④ `first()` 종료

``` text
Stack

┌────────────────────┐
│ Global Frame       │
└────────────────────┘
```

------------------------------------------------------------------------

# 📋 Stack Frame 변화 표

  실행 단계         Stack 변화
  ----------------- ---------------------
  `first()` 호출    `first Frame` 생성
  `second()` 호출   `second Frame` 생성
  `second()` 종료   `second Frame` 제거
  `first()` 종료    `first Frame` 제거

------------------------------------------------------------------------

# ❓ Why?

왜 마지막에 호출된 함수가 먼저 종료될까?

현재 실행 중인 함수가 끝나야 이전 함수가 자신의 작업을 계속할 수 있기
때문이다.

따라서 함수 호출은 **후입선출(LIFO)** 방식으로 관리된다.

------------------------------------------------------------------------

# ⚠️ 자주 하는 오해

❌ 함수가 여러 번 호출되면 하나의 Frame을 계속 사용한다.

교육용 모델에서는 함수를 호출할 때마다 새로운 Stack Frame이 생성된다고
이해한다.

------------------------------------------------------------------------

# ✅ 핵심 정리

-   함수마다 독립적인 Stack Frame이 생성된다.
-   호출이 깊어질수록 Stack Frame이 위로 쌓인다.
-   함수 종료 시 가장 위의 Frame부터 제거된다.
-   이것이 Stack 구조가 사용되는 이유이다.

# Chapter 7. 제어문과 메모리

## Section 7.1 조건문과 메모리의 흐름

------------------------------------------------------------------------

# 📖 왜 조건문을 메모리 관점에서 봐야 할까?

지금까지는 코드가 위에서 아래로 순서대로 실행되는 상황을 살펴보았다.

하지만 실제 프로그램은 조건에 따라 **실행되는 코드가 달라진다.**

조건문을 메모리 관점에서 이해하면 **어떤 코드가 실행되고, 어떤 변수와
객체가 실제로 생성되는지** 논리적으로 설명할 수 있다.

> 본 문서의 메모리 그림은 학습을 위한 교육용 모델이다.

------------------------------------------------------------------------

# 🤔 생각해 보기

다음 코드를 보자.

``` python
score = 85

if score >= 80:
    grade = "A"

print(grade)
```

다음을 생각해 보자.

-   `grade`는 언제 생성될까?
-   `if` 조건이 거짓이라면 어떻게 될까?

------------------------------------------------------------------------

# 💡 핵심 개념

조건문은 **조건식의 결과에 따라 실행할 코드를 선택**한다.

교육용 메모리 모델에서는 다음 순서로 이해한다.

1.  조건식 평가
2.  참이면 블록 실행
3.  거짓이면 블록 건너뛰기
4.  실행된 코드만 Stack과 Heap에 영향을 준다.

------------------------------------------------------------------------

# 🧪 단계별 분석

``` python
score = 85

if score >= 80:
    grade = "A"
```

### ① 첫 번째 줄

``` text
Stack                     Heap

score ─────────────▶      85
```

### ② 조건식 평가

``` text
score >= 80

결과 : True
```

조건이 참이므로 다음 줄이 실행된다.

### ③ 조건 블록 실행

``` text
Stack                     Heap

score ─────────────▶      85

grade ─────────────▶      "A"
```

------------------------------------------------------------------------

# 🧪 조건이 거짓인 경우

``` python
score = 60

if score >= 80:
    grade = "A"
```

조건 결과

``` text
False
```

조건 블록은 실행되지 않는다.

``` text
Stack                     Heap

score ─────────────▶      60
```

`grade`는 생성되지 않는다.

------------------------------------------------------------------------

# 📋 메모리 변화 표

  실행 단계      Stack 변화     Heap 변화
  -------------- -------------- ------------------
  `score = 85`   `score` 생성   숫자 객체 생성
  조건 평가      변화 없음      변화 없음
  조건 참        `grade` 생성   문자열 객체 생성
  조건 거짓      변화 없음      변화 없음

------------------------------------------------------------------------

# ❓ Why?

왜 조건이 거짓이면 `grade`가 없을까?

조건 블록이 실행되지 않았기 때문이다.

메모리는 **실제로 실행된 코드**에 의해서만 변화한다.

------------------------------------------------------------------------

# ⚠️ 자주 하는 오해

❌ `if` 안에 있는 변수는 항상 생성된다.

교육용 모델에서는 조건이 참일 때만 해당 코드가 실행되고, 그에 따라

## Section 7.2 if-else와 if-elif-else의 메모리 변화

------------------------------------------------------------------------

# 📖 왜 여러 실행 경로를 이해해야 할까?

프로그램은 하나의 경로만 실행되는 경우보다 여러 조건 중 하나를 선택하는
경우가 더 많다.

`if-else`와 `if-elif-else`는 **여러 실행 경로 중 하나만 실행**한다.

메모리 관점에서는 **실제로 선택된 경로만 Stack과 Heap에 영향을 준다.**

> 본 문서의 메모리 그림은 학습을 위한 교육용 모델이다.

------------------------------------------------------------------------

# 🤔 생각해 보기

``` python
score = 75

if score >= 90:
    grade = "A"
else:
    grade = "B"
```

-   `"A"` 객체가 생성될까?
-   `"B"` 객체가 생성될까?
-   둘 다 생성될까?

------------------------------------------------------------------------

# 💡 핵심 개념

조건문은 여러 블록이 있어도 **한 번의 실행에서 하나의 블록만 실행**된다.

교육용 메모리 모델에서는 다음 순서로 이해한다.

1.  조건식 평가
2.  실행할 블록 선택
3.  선택된 블록만 실행
4.  선택된 코드만 메모리를 변경

------------------------------------------------------------------------

# 🧪 예제 1 : if-else

``` python
score = 75

if score >= 90:
    grade = "A"
else:
    grade = "B"
```

### 조건 평가

``` text
75 >= 90

결과 : False
```

### 메모리

``` text
Stack                         Heap

score ───────────────▶        75

grade ───────────────▶        "B"
```

`if` 블록은 실행되지 않으므로 `"A"`는 생성되지 않는다.

------------------------------------------------------------------------

# 🧪 예제 2 : if-elif-else

``` python
score = 85

if score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
else:
    grade = "C"
```

### 실행 순서

``` text
90 이상?      False
80 이상?      True
else          실행 안 함
```

### 메모리

``` text
Stack                         Heap

score ───────────────▶        85

grade ───────────────▶        "B"
```

첫 번째 조건이 거짓이므로 두 번째 조건을 검사하고, 참이 되어 `"B"`만
생성된다.

------------------------------------------------------------------------

# 📋 메모리 변화 표

  실행 경로            Stack 변화   Heap 변화
  -------------------- ------------ ----------------
  if 실행              변수 생성    해당 객체 생성
  elif 실행            변수 생성    해당 객체 생성
  else 실행            변수 생성    해당 객체 생성
  실행되지 않은 블록   변화 없음    변화 없음

------------------------------------------------------------------------

# ❓ Why?

왜 `"A"`와 `"C"`는 생성되지 않을까?

조건문은 실행 경로를 하나만 선택하기 때문이다.

실행되지 않은 코드는 메모리에 영향을 주지 않는다.

------------------------------------------------------------------------

교육용 모델에서는 **실행된 블록의 변수와 객체만 생성**된다고 이해한다.

-   `if-elif-else`는 여러 경로 중 하나만 실행된다.
-   실행되지 않은 블록은 메모리를 변경하지 않는다.

# 📖 왜 반복문을 메모리 관점에서 봐야 할까?

반복문은 같은 코드를 여러 번 실행하는 제어문이다.

반복이 진행될 때마다 **반복 변수의 값이 바뀌고**, 실행되는 코드에 따라
Stack과 Heap의 상태도 달라질 수 있다.

> 본 문서의 메모리 그림은 학습을 위한 교육용 모델이다.

-   Stack은 어떻게 변할까?

# 💡 핵심 개념

교육용 메모리 모델에서는 다음 순서로 이해한다.

1.  반복 시작
2.  반복 변수에 값 대입
3.  반복 본문 실행
4.  다음 값으로 반복 변수 갱신
5.  반복 종료

반복마다 **실행 흐름은 반복되지만, 반복 변수는 새로운 값으로 갱신**된다.

# 📖 왜 반복문과 함수 호출을 함께 이해해야 할까?

실제 프로그램에서는 반복문 안에서 함수를 호출하는 코드가 매우 자주
사용된다.

이때 반복이 진행될 때마다 함수가 호출되고, 새로운 Stack Frame이
생성되었다가 함수가 종료되면 제거된다.

> 본 문서의 메모리 그림은 학습을 위한 교육용 모델이다.

------------------------------------------------------------------------

# 🤔 생각해 보기

``` python

    print(value)

    show(i)
```

다음을 생각해 보자.

-   반복할 때마다 함수는 몇 번 호출될까?
-   Stack Frame은 언제 생성되고 제거될까?

------------------------------------------------------------------------

# 💡 핵심 개념

반복문의 각 반복은 독립적으로 함수를 호출한다.

교육용 메모리 모델에서는 다음 순서로 이해한다.

1.  반복 변수에 값 대입
2.  함수 호출
3.  새로운 Stack Frame 생성
4.  함수 실행
5.  함수 종료와 Frame 제거
6.  다음 반복

------------------------------------------------------------------------

# 🧪 단계별 분석

``` python
def show(value):
    print(value)

for i in range(3):
    show(i)
```

### ① 첫 번째 반복 (`i = 0`)

``` text
Stack

┌──────────────────────┐
│ show Frame           │
│ value ─────────▶ 0   │
└──────────────────────┘

┌──────────────────────┐
│ Global Frame         │
│ i ──────────────▶ 0  │
└──────────────────────┘
```

함수가 종료되면 `show Frame`이 제거된다.

------------------------------------------------------------------------

### ② 두 번째 반복 (`i = 1`)

``` text
Stack

┌──────────────────────┐
│ show Frame           │
│ value ─────────▶ 1   │
└──────────────────────┘

┌──────────────────────┐
│ Global Frame         │
│ i ──────────────▶ 1  │
└──────────────────────┘
```

------------------------------------------------------------------------

### ③ 세 번째 반복 (`i = 2`)

``` text
Stack

┌──────────────────────┐
│ show Frame           │
│ value ─────────▶ 2   │
└──────────────────────┘

┌──────────────────────┐
│ Global Frame         │
│ i ──────────────▶ 2  │
└──────────────────────┘
```

함수는 반복마다 새롭게 호출되고, 호출이 끝날 때마다 Frame이 제거된다.

------------------------------------------------------------------------

# 📋 메모리 변화 표

  반복 단계   Stack 변화          Heap 변화
  ----------- ------------------- -----------
  반복 시작   `i` 갱신            변화 없음
  함수 호출   `show Frame` 생성   변화 없음
  함수 실행   매개변수 사용       변화 없음
  함수 종료   `show Frame` 제거   변화 없음

------------------------------------------------------------------------

# ❓ Why?

왜 같은 함수를 여러 번 호출해도 Frame을 재사용하지 않을까?

각 함수 호출은 독립적인 실행 과정이므로 호출마다 새로운 Stack Frame이
필요하다.

함수가 종료되면 해당 Frame은 제거되고, 다음 호출에서는 새로운 Frame이
생성된다.

------------------------------------------------------------------------

핵심 목표는 다음 질문에 답할 수 있는 것이다.

> **"실행되는 코드가 달라지면 Stack과 Heap은 어떻게 변할까?"**

# 💡 핵심 개념 정리

## 1. 조건문

``` python
if score >= 80:
    grade = "A"
```

-   조건이 참인 경우에만 블록이 실행된다.
-   실행된 코드만 메모리를 변화시킨다.

------------------------------------------------------------------------

## 2. if-else / if-elif-else

``` python
if score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
else:
    grade = "C"
```

-   여러 경로 중 하나만 선택된다.
-   선택된 블록만 변수와 객체를 생성한다.

------------------------------------------------------------------------

## 3. for 반복문

``` python
for i in range(3):
    print(i)
```

-   반복 변수는 반복마다 새로운 값으로 갱신된다.
-   같은 코드가 여러 번 실행된다.

------------------------------------------------------------------------

## 4. 반복문 안의 함수 호출

``` python
for i in range(3):
    show(i)
```

-   반복마다 함수가 호출된다.
-   호출마다 새로운 Stack Frame이 생성된다.
-   함수 종료 후 Frame은 제거된다.

------------------------------------------------------------------------

# 🧠 종합 비교표

  상황            Stack 변화         Heap 변화
  --------------- ------------------ -----------------------
  조건문(True)    변수 생성 가능     객체 생성 가능
  조건문(False)   변화 없음          변화 없음
  반복문          반복 변수 갱신     실행 코드에 따라 변화
  함수 호출       Stack Frame 생성   변화 없음
  함수 종료       Stack Frame 제거   참조가 있는 객체 유지

------------------------------------------------------------------------

# ❓ Why?

왜 제어문을 메모리와 함께 이해해야 할까?

프로그램은 항상 같은 경로를 실행하지 않는다.

조건과 반복에 따라 **실행되는 코드가 달라지고**, 메모리 역시 그 실행
결과에 따라 변화한다.

따라서 실행 흐름과 메모리 흐름을 함께 이해하면 프로그램의 동작 원리를
더욱 명확하게 설명할 수 있다.

# 💡 종합 분석 순서

교육용 메모리 모델에서는 항상 다음 순서로 분석한다.

1.  코드 한 줄 실행

4.  함수 호출 여부 확인

# 🧪 단계별 분석

``` python
def show(data):
    print(data)

numbers = [1, 2]

for value in numbers:
    show(value)
```

### ① 리스트 생성

``` text
Stack                    Heap

numbers ─────────▶       [1, 2]
```

------------------------------------------------------------------------

### ② 첫 번째 반복

``` text
Stack

show Frame
data ───────────▶ 1

Global Frame
numbers ────────▶ [1,2]
value ──────────▶ 1
```

`show()`가 종료되면 `show Frame`은 제거된다.

------------------------------------------------------------------------

### ③ 두 번째 반복

``` text
Stack

show Frame
data ───────────▶ 2

Global Frame
numbers ────────▶ [1,2]
value ──────────▶ 2
```

반복이 끝나면 함수 Frame도 제거된다.

------------------------------------------------------------------------

### ④ 프로그램 종료

``` text
Stack

Global Frame
(프로그램 종료)
```

------------------------------------------------------------------------

# 📋 메모리 변화 표

  단계          Stack 변화          Heap 변화
  ------------- ------------------- -------------
  리스트 생성   `numbers` 생성      리스트 생성
  반복 시작     `value` 갱신        변화 없음
  함수 호출     `show Frame` 생성   변화 없음
  함수 종료     `show Frame` 제거   변화 없음
  반복 종료     반복 종료           변화 없음

------------------------------------------------------------------------

# Chapter 8. 종합 메모리 분석

## Section 8.2 객체 공유와 함수 호출의 종합 분석

------------------------------------------------------------------------

# 📖 왜 객체 공유와 함수 호출을 함께 분석해야 할까?

실제 프로그램에서는 하나의 객체를 여러 변수가 함께 사용한 상태에서
함수를 호출하는 경우가 매우 많다.

이때 함수 안에서 객체를 수정하면 어떤 변수가 영향을 받는지, 메모리가
어떻게 변하는지를 이해하는 것이 중요하다.

> 본 문서의 메모리 그림은 학습을 위한 교육용 모델이다.

------------------------------------------------------------------------

# 🤔 생각해 보기

``` python
def add_item(items):
    items.append(3)

numbers = [1, 2]
backup = numbers

add_item(numbers)
```

다음을 생각해 보자.

-   `numbers`와 `backup`은 같은 객체를 사용할까?
-   함수 안에서 수정한 결과는 어디까지 영향을 줄까?

------------------------------------------------------------------------

# 💡 분석 순서

교육용 메모리 모델에서는 다음 순서로 분석한다.

1.  객체 생성
2.  객체 공유
3.  함수 호출
4.  매개변수 연결
5.  객체 수정
6.  함수 종료

------------------------------------------------------------------------

# 🧪 단계별 분석

``` python
def add_item(items):
    items.append(3)

numbers = [1, 2]
backup = numbers

add_item(numbers)
```

### ① 리스트 생성

``` text
Stack                          Heap

numbers ───────────────▶       [1, 2]
```

------------------------------------------------------------------------

### ② 객체 공유

``` text
Stack                          Heap

numbers ───────────────▶
                              [1, 2]
backup ────────────────▶
```

두 변수는 같은 리스트를 참조한다.

------------------------------------------------------------------------

### ③ 함수 호출

``` text
Stack

┌────────────────────────────┐
│ add_item Frame             │
│ items ────────────────┐    │
└───────────────────────┼────┘
                        │
┌───────────────────────▼────┐
│ Global Frame               │
│ numbers ──────────────┐     │
│ backup ───────────────┤     │
└────────────────────────┼────┘
                         │

Heap
[1, 2]
```

------------------------------------------------------------------------

### ④ 객체 수정

``` python
items.append(3)
```

``` text
Heap

[1, 2, 3]
```

같은 객체를 참조하므로 `numbers`, `backup`, `items` 모두 변경된 리스트를
사용한다.

------------------------------------------------------------------------

### ⑤ 함수 종료

``` text
Stack                         Heap

numbers ───────────────▶
                              [1, 2, 3]
backup ────────────────▶
```

`add_item Frame`은 제거되지만 리스트는 그대로 유지된다.

------------------------------------------------------------------------

# 📋 메모리 변화 표

  단계          Stack 변화       Heap 변화
  ------------- ---------------- --------------------
  리스트 생성   `numbers` 생성   리스트 생성
  객체 공유     `backup` 생성    변화 없음
  함수 호출     `items` 생성     변화 없음
  객체 수정     변화 없음        기존 리스트 수정
  함수 종료     Frame 제거       수정된 리스트 유지

------------------------------------------------------------------------

# ❓ Why?

왜 `backup`도 변경된 결과를 볼 수 있을까?

`backup`과 `numbers`는 같은 리스트 객체를 참조하고 있기 때문이다.

함수 안에서 수정된 것은 변수 자체가 아니라 **공유 중인 객체**이다.

------------------------------------------------------------------------

# ⚠️ 자주 하는 오해

❌ 함수 안에서만 리스트가 수정된다.

교육용 모델에서는 같은 객체를 참조하는 모든 변수는 수정된 객체를 함께
사용한다고 이해한다.

------------------------------------------------------------------------

-   여러 변수는 하나의 객체를 공유할 수 있다.
-   함수의 매개변수도 같은 객체를 참조할 수 있다.
-   객체 수정은 공유 중인 모든 참조에 영향을 준다.
-   함수 종료 후에도 객체는 계속 유지된다.

------------------------------------------------------------------------

# 📖 왜 객체 수정과 재할당을 구분해야 할까?

실무에서는 함수 안에서 객체를 변경하는 경우와 새로운 객체를 만들어
변수에 다시 대입하는 경우가 모두 사용된다.

겉보기에는 비슷하지만 **메모리의 변화는 서로 다르다.**

> 본 문서의 메모리 그림은 학습을 위한 교육용 모델이다.

------------------------------------------------------------------------

# 🤔 생각해 보기

``` python
numbers = [1, 2]
backup = numbers

numbers.append(3)
```

``` python
numbers = [1, 2]
backup = numbers

numbers = [10, 20]
```

두 코드의 마지막 상태는 왜 다를까?

------------------------------------------------------------------------

# 💡 핵심 개념

-   **객체 수정**: 기존 객체의 내용이 바뀐다.
-   **재할당**: 변수가 새로운 객체를 참조한다.

이 차이를 Stack과 Heap의 흐름으로 이해하는 것이 중요하다.

------------------------------------------------------------------------

# 🧪 예제 1 : 객체 수정

``` python
numbers = [1, 2]
backup = numbers

numbers.append(3)
```

### 수정 전

``` text
Stack                      Heap

numbers ───────▶
                │
backup ─────────┘      [1, 2]
```

### 수정 후

``` text
Stack                      Heap

numbers ───────▶
                │
backup ─────────┘      [1, 2, 3]
```

객체는 그대로이며 내용만 변경된다.

------------------------------------------------------------------------

# 🧪 예제 2 : 재할당

``` python
numbers = [1, 2]
backup = numbers

numbers = [10, 20]
```

### 재할당 전

``` text
Stack                      Heap

numbers ───────▶
                │
backup ─────────┘      [1, 2]
```

### 재할당 후

``` text
Stack                          Heap

numbers ───────────────▶       [10, 20]

backup ────────────────▶       [1, 2]
```

`numbers`만 새로운 리스트를 참조하게 된다.

------------------------------------------------------------------------

# 📋 비교표

  구분        Stack 변화   Heap 변화
  ----------- ------------ ---------------------
  객체 수정   참조 유지    기존 객체 내용 변경
  재할당      참조 변경    새로운 객체 생성

------------------------------------------------------------------------

# ❓ Why?

왜 `backup`은 재할당 후에도 기존 리스트를 사용할까?

재할당은 **변수의 참조 대상만 변경**하기 때문이다.

기존 객체를 참조하는 다른 변수는 영향을 받지 않는다.

------------------------------------------------------------------------

# ⚠️ 자주 하는 오해

❌ 재할당은 기존 객체까지 함께 변경한다.

교육용 모델에서는 재할당은 새로운 객체를 참조하는 과정이며, 기존 객체
자체는 변경되지 않는다고 이해한다.

------------------------------------------------------------------------

# ✅ 핵심 정리

-   객체 수정은 공유 중인 객체의 내용을 변경한다.
-   재할당은 변수의 참조 대상을 변경한다.
-   공유된 객체는 수정 시 함께 영향을 받는다.
-   재할당은 공유 관계를 끊을 수 있다.

------------------------------------------------------------------------

# ☑ Check List

-   [ ] 객체 수정과 재할당의 차이를 설명할 수 있다.
-   [ ] 공유 객체에서 수정 결과를 예측할 수 있다.
-   [ ] 재할당 후 각 변수가 무엇을 참조하는지 설명할 수 있다.

실제 프로그램에서는 변수, 함수, 조건문, 반복문, 객체 공유가 함께

------------------------------------------------------------------------

# 🤔 생각해 보기

``` python
def process(items):
    if len(items) < 3:
        items.append(99)

numbers = [1, 2]
backup = numbers

for _ in range(2):
    process(numbers)
```

6.  객체 수정 여부 확인

8.  다음 반복
9.  프로그램 종료

# 🧪 단계별 메모리 분석

## ① 리스트 생성

``` text
Stack                         Heap

numbers ─────────────▶        [1, 2]
```

------------------------------------------------------------------------

## ② 참조 공유

``` text
Stack                         Heap

numbers ─────────────▶
                         │
backup ──────────────▶   ┘    [1, 2]
```

두 변수는 같은 리스트를 참조한다.

------------------------------------------------------------------------

## ③ 첫 번째 반복

`process(numbers)` 호출

``` text
Stack

┌──────────────────────────┐
│ process Frame            │
│ items ───────────────┐   │
└──────────────────────┼───┘
                       │
┌──────────────────────▼───┐
│ Global Frame             │
│ numbers ─────────────┐    │
│ backup ──────────────┤    │
└──────────────────────┼────┘
                       │

Heap
[1, 2]
```

조건 `len(items) < 3`은 참이므로

``` python
items.append(99)
```

실행 후

``` text
Heap

[1, 2, 99]
```

함수가 종료되면 `process Frame`은 제거된다.

------------------------------------------------------------------------

## ④ 두 번째 반복

다시 `process(numbers)` 호출

현재 리스트

``` text
[1, 2, 99]
```

조건

``` python
len(items) < 3
```

결과는 False이다.

따라서 `append()`는 실행되지 않는다.

메모리는 변경되지 않는다.

------------------------------------------------------------------------

## ⑤ 프로그램 종료

``` text
Stack                         Heap

numbers ─────────────▶
                         │
backup ──────────────▶   ┘    [1, 2, 99]
```

------------------------------------------------------------------------

# 📋 실행 흐름 요약

  단계                실행 결과    메모리 변화
  ------------------- ------------ --------------------
  리스트 생성         객체 생성    Heap에 리스트 생성
  객체 공유           참조 추가    Stack만 변경
  첫 번째 함수 호출   조건 참      리스트 수정
  두 번째 함수 호출   조건 거짓    변화 없음
  종료                Frame 제거   수정된 리스트 유지

------------------------------------------------------------------------

# ❓ Why?

왜 `99`는 한 번만 추가될까?

첫 번째 호출 후 리스트 길이가 3이 되었기 때문이다.

두 번째 호출에서는 조건이 거짓이므로 객체는 더 이상 수정되지 않는다.

------------------------------------------------------------------------

# ⚠️ 자주 하는 오해

❌ 반복문이 두 번 실행되므로 `99`도 두 번 추가된다.

실제로는 반복마다 **조건을 다시 평가**하며, 실행 결과에 따라 메모리
변화가 달라진다.

------------------------------------------------------------------------

# ✅ 핵심 정리

-   실행 흐름은 조건과 반복에 따라 달라진다.
-   함수 호출마다 Stack Frame이 생성되고 제거된다.
-   객체를 공유하면 수정 결과도 함께 공유된다.
-   실제 메모리 변화는 실행된 코드에 의해서만 발생한다.

# 📖 왜 리스트를 메모리 관점에서 배워야 할까?

리스트(List)는 Python에서 가장 많이 사용하는 자료형 중 하나이다.

여러 개의 데이터를 하나의 객체로 관리할 수 있기 때문에 실무에서도 매우
자주 사용된다.

# 📖 왜 튜플을 메모리 관점에서 배워야 할까?

튜플(Tuple)은 여러 값을 하나로 묶는 자료형이다.

------------------------------------------------------------------------

# ❓ Why?

왜 같은 값을 다시 추가해도 집합이 바뀌지 않을까?

집합은 **중복되지 않는 요소만 저장하는 자료형**이기 때문이다.

이미 있는 값은 다시 저장하지 않는다.

------------------------------------------------------------------------

# ⚠️ 자주 하는 오해

❌ `add()`를 호출할 때마다 새로운 집합이 만들어진다.

교육용 모델에서는 `add()`는 기존 집합 객체를 수정하는 연산으로 이해한다.

------------------------------------------------------------------------

# ✅ 핵심 정리

-   집합은 Heap에 생성된다.
-   변수는 집합 객체를 참조한다.
-   `add()`는 기존 집합을 수정한다.
-   같은 요소를 다시 추가해도 집합은 변하지 않는다.

# 📚 Chapter 9 돌아보기

이번 Chapter에서는 Python에서 자주 사용하는 네 가지 자료형을 메모리
관점에서 살펴보았다.

-   List
-   Tuple
-   Dictionary
-   Set

각 자료형은 용도는 다르지만 모두 **Heap에 객체가 생성되고, Stack의
변수가 그 객체를 참조한다**는 공통점을 가진다.

> 본 문서의 메모리 그림은 학습을 위한 교육용 모델이다.

------------------------------------------------------------------------

# 🗺️ Chapter 학습 흐름

``` text
자료형 생성
    │
    ▼
Heap에 객체 생성
    │
    ▼
Stack 변수에서 객체 참조
    │
    ▼
자료형별 동작
(읽기, 추가, 수정 등)
    │
    ▼
메모리 변화 확인
```

------------------------------------------------------------------------

# 💡 핵심 개념 정리

## 1. List

``` python
numbers = [1, 2]
numbers.append(3)
```

-   요소를 추가할 수 있다.
-   기존 리스트 객체를 수정한다.

------------------------------------------------------------------------

## 2. Tuple

``` python
point = (10, 20)
```

-   요소를 읽을 수 있다.
-   교육용 관점에서 생성 후 내용을 변경하지 않는다.

------------------------------------------------------------------------

## 3. Dictionary

``` python
student = {"name": "Kim"}
student["age"] = 20
```

-   키와 값을 함께 관리한다.
-   항목 추가와 값 수정은 기존 객체를 변경한다.

------------------------------------------------------------------------

## 4. Set

``` python
fruits = {"apple"}
fruits.add("banana")
```

-   중복을 허용하지 않는다.
-   같은 요소를 다시 추가해도 객체 내용은 그대로 유지된다.

------------------------------------------------------------------------

# 🧠 자료형 비교표

  -----------------------------------------------------------------------
  자료형       Heap 생성  변수는 참조  요소 읽기  내용 변경(교육용 관점)
  ------------ ---------- ------------ ---------- -----------------------
  List             O           O           O                 O

  Tuple            O           O           O                 X

  Dictionary       O           O           O                 O

  Set              O           O           O                 O
  -----------------------------------------------------------------------

# 🖼️ 공통 메모리 구조

``` text
Stack

variable
    │
    ▼

Heap

[자료형 객체]
```

모든 자료형은 객체이며, 변수는 객체 자체가 아니라 **객체를 참조**한다.

------------------------------------------------------------------------

# ❓ Why?

왜 모든 자료형을 메모리와 함께 배워야 할까?

자료형마다 사용할 수 있는 기능은 다르지만, 객체 생성과 참조라는 기본
원리는 공통이다.

이 공통 원리를 이해하면 새로운 자료형을 만나더라도 메모리 관점에서
동작을 예측할 수 있다.

------------------------------------------------------------------------

# ⚠️ 자주 헷갈리는 내용

  ---------------------------------------------------------------------
  질문                               정리
  ---------------------------------- ----------------------------------
  리스트와 딕셔너리는 수정 가능한가? 교육용 관점에서는 가능하다.

  튜플은 생성 후 내용을 변경하는가?  교육용 관점에서는 변경하지 않는다.

  집합은 중복을 저장하는가?          저장하지 않는다.

  변수는 자료형 객체 자체를          객체를 참조한다.
  저장하는가?                        
  ---------------------------------------------------------------------

# ✅ Chapter 핵심 정리

-   모든 자료형은 Heap에 객체로 생성된다.
-   변수는 Stack에서 객체를 참조한다.
-   자료형마다 지원하는 동작은 다르다.
-   객체를 읽는 것과 수정하는 것은 메모리 변화가 다르다.
-   자료형의 특성을 메모리와 함께 이해하면 프로그램을 더 쉽게 분석할 수
    있다.
