# 변수와 참조 — 같은 리스트가 함께 바뀌는 이유

[00번 읽기 안내](README.md)

`b = a`를 실행한 뒤 `b`만 수정했는데 `a`도 바뀌었다. 함수에 리스트를 넣었더니 `return`이 없어도 바깥 리스트가 바뀌었다. 이 문서는 수업에서 작성한 두 상황을 **이름이 가리키는 대상**과 **리스트의 내용**으로 나누어 설명한다.

Python의 변수·리스트·인덱스를 배운 뒤 읽으면 된다. 함수가 아직 낯설다면 1~4절을 먼저 읽고, 함수 수업 뒤 5절부터 이어 읽는다. HTML을 시작하기 전에 이 문서를 외울 필요는 없다.

## 이 문서에서 할 수 있게 되는 것

- `b = a`와 `b = a.copy()`의 결과를 구분한다.
- 리스트의 내용을 바꾸는 것과 변수에 새 리스트를 대입하는 것을 구분한다.
- 함수의 원본 변경과 반환값을 따로 확인한다.
- 내 코드의 주석을 정확한 표현으로 고쳐 설명한다.

## 1. 이름·객체·참조를 구분하기

`a = [1, 2, 3]`에서 `a`는 **이름**, `[1, 2, 3]`은 **리스트 객체**다. 객체는 프로그램에서 다루는 값의 실체라고 생각하면 된다. 이름으로 그 객체에 접근하는 관계를 여기서는 **참조**라고 부른다.

| 표현 | 읽는 방법 |
| --- | --- |
| `a = [1, 2, 3]` | 새 리스트를 만들고 이름 `a`로 접근한다. |
| `b = a` | `a`가 가리키는 객체에 이름 `b`도 연결한다. |
| `b[0] = 10` | `b`가 가리키는 리스트의 0번 요소를 바꾼다. |
| `b = [10]` | 이름 `b`를 새 리스트에 연결한다. |

다음 그림의 화살표는 관계를 보여 준다. 실제 메모리 주소나 Stack·Heap의 물리적 배치를 그린 것은 아니다.

```text
a ──┐
    ├──> 리스트 [1, 2, 3]
b ──┘
```

두 이름이 보인다고 리스트도 두 개 생긴 것은 아니다. 리스트를 수정할 때는 **어느 이름으로 수정했는지**보다 **어느 객체를 수정했는지**를 확인한다.

## 2. `b = a`: 같은 리스트를 함께 사용하기

### 강사님 코드 — 원본 발췌

강사님 `workspace_python/_04_list.py` 102~106행

```python
a = [1,2,3,4,5]
b = a
b[2] = 30
print(b)
print(a)
```

`b[2]`의 `2`는 세 번째 요소의 인덱스다. `b = a`에서 새 리스트를 만들지 않았으므로 `b[2] = 30`은 `a`로도 접근하는 같은 리스트를 수정한다.

### 내 코드 — 원본 발췌

내 코드 `workspace_python/04_list.py` 120~124행

```python
a = [1,2,3,4,5]
b = a # 이렇게 넣으면 a = b의 주소값이 동일해지기 때문에, index값을 바꾸면 두개가 모두 바뀜
b[2] = 30
print(b)
print(a)
```

두 코드의 실행문은 같으며 출력도 같다. 내 주석의 “두 개가 모두 바뀜”은 **두 리스트가 각각 바뀌는 것**으로 오해할 수 있다. “하나의 리스트를 두 이름으로 보고 있으므로 두 출력에 같은 변경이 나타난다”라고 읽으면 정확하다.

### 두 코드의 출력

```text
[1, 2, 30, 4, 5]
[1, 2, 30, 4, 5]
```

| 실행 직후 | 이름의 연결 | 리스트 내용 |
| --- | --- | --- |
| `a = [1,2,3,4,5]` | `a` → 리스트 A | A: `[1, 2, 3, 4, 5]` |
| `b = a` | `a`, `b` → A | A: 그대로 |
| `b[2] = 30` | `a`, `b` → A | A: `[1, 2, 30, 4, 5]` |

여기서 A는 설명을 위한 표식이다. Python 코드에 새 변수를 추가한 것이 아니다.

## 3. 내용 변경과 재할당 구분하기

**변경**은 이미 있는 객체의 내용을 바꾸는 것이다. **재할당**은 이름이 가리키는 대상을 다시 정하는 것이다. 리스트를 다룰 때 둘을 구분하면 “원본이 바뀌었나?”를 판단할 수 있다.

### `append()`는 같은 리스트에 요소를 추가한다

설명용 재구성 — 수업의 `append()`와 대입을 한 블록으로 분리했다.

```python
a = [1, 2, 3]
b = a
b.append(4)
print(a)
print(b)
```

출력:

```text
[1, 2, 3, 4]
[1, 2, 3, 4]
```

`append(4)`는 그 리스트의 맨 뒤에 `4`를 붙인다. 이름 `b`의 연결은 바뀌지 않는다.

### `b = [4]`는 이름 `b`의 연결을 바꾼다

설명용 재구성:

```python
a = [1, 2, 3]
b = a
b = [4]
print(a)
print(b)
```

출력:

```text
[1, 2, 3]
[4]
```

```text
재할당 전: a, b ──> 리스트 A [1, 2, 3]

재할당 후: a ─────> 리스트 A [1, 2, 3]
           b ─────> 리스트 B [4]
```

`a`는 여전히 기존 리스트를 가리킨다. `b = [4]`가 `a`의 내용까지 덮어쓰지는 않는다.

### 내 주석 보완: `clear()`와 `a = []`는 언제 다를까?

내 원본 `workspace_python/04_list.py` 101행에는 다음 주석이 있다.

> `a.clear() # a = [] 는 동일하게 사용할 수 있음`

`a`만 출력하면 둘 다 빈 리스트로 보일 수 있다. 그러나 다른 이름도 같은 리스트를 가리킬 때는 결과가 다르다. 강사님 원본에도 `clear()`와 `a = []`가 등장하지만, 두 방법을 공유 상태에서 비교하지는 않는다.

설명용 재구성 — 두 경우를 각각 새 리스트로 시작한다.

```python
a = [1, 2, 3]
b = a
a.clear()
print(a, b)

a = [1, 2, 3]
b = a
a = []
print(a, b)
```

출력:

```text
[] []
[] [1, 2, 3]
```

| 코드 | 하는 일 | 함께 참조하던 `b`에서 보이는 값 |
| --- | --- | --- |
| `a.clear()` | 기존 리스트의 요소를 모두 제거 | `[]` |
| `a = []` | 이름 `a`를 새 빈 리스트에 연결 | 기존 `[1, 2, 3]` |

주석은 “`a`만 보면 둘 다 비어 있지만, `clear()`는 기존 리스트를 비우고 `a = []`는 새 리스트를 대입한다”로 고치는 것이 좋다.

## 4. `copy()`: 별도 리스트 만들기

### 강사님 코드 — 원본 발췌

강사님 `workspace_python/_04_list.py` 108~112행

```python
a = [1,2,3,4,5]
b = a.copy()
b[2] = 30
print(b)
print(a)
```

`a.copy()`는 바깥 리스트를 새로 만든다. 따라서 `b[2] = 30`은 복사한 리스트의 세 번째 요소를 교체하고, 원래 리스트의 세 번째 요소는 유지된다.

### 내 코드 — 원본 발췌

내 코드 `workspace_python/04_list.py` 126~130행

```python
a = [1,2,3,4,5]
b = a.copy() # copy를 이용하면 모든 요소를 아예 복사해오기 때문에, 이럴 땐 주소값이 달라져 개별 값만 바꿔짐
b[2] = 30
print(b)
print(a)
```

실행문과 결과는 강사님 코드와 같다. 내 주석의 “모든 요소를 아예 복사”는 안쪽 객체까지 모두 새로 만든다는 뜻으로 읽지 않도록 주의한다. `list.copy()`는 **얕은 복사**다.

### 두 코드의 출력

```text
[1, 2, 30, 4, 5]
[1, 2, 3, 4, 5]
```

| 방법 | 바깥 리스트 | `b[2] = 30` 뒤 `a` |
| --- | --- | --- |
| `b = a` | 같은 리스트 | 세 번째 요소도 `30`으로 보임 |
| `b = a.copy()` | 별도 리스트 | 세 번째 요소 `3` 유지 |

<a id="section-4"></a>

### 내 코드에 있는 확인 방법: `is`와 `==`

이 블록은 내 원본에만 있다. 위 복사 예제의 결과를 확인하는 데 도움이 된다.

내 코드 `workspace_python/04_list.py` 132~135행

```python
a = [1,2,3,4,5]
b = a.copy() 
print( a is b ) # False (주소값이 다르기 때문에 주소까지 전부 같지 않음)
print( a == b ) # True (안에 있는 값은 같음)
```

출력:

```text
False
True
```

- `a is b`: **같은 객체인가?** 새 바깥 리스트를 만들었으므로 `False`다.
- `a == b`: **값이 같은가?** 이 예제의 두 리스트는 같은 순서로 같은 숫자를 담으므로 `True`다.

`is`를 일반적인 값 비교에 사용하지 않는다. 여기서는 리스트 복사 여부를 확인하는 용도다. “주소가 같다”라는 표현 대신 “같은 객체다”라고 설명하면 특정 Python 구현에 의존하지 않는다.

### 얕은 복사의 범위: 안쪽 리스트는 공유할 수 있다

다음은 **설명용 재구성**이다. 수업에서 사용한 중첩 리스트와 `copy()`를 조합해 내 주석의 한계를 확인한다. 새로운 복사 함수를 배우는 예제가 아니다.

```python
a = [[1, 2], [3, 4]]
b = a.copy()
b[0].append(9)
print(a)
print(b)
print(a is b)
print(a[0] is b[0])
```

출력:

```text
[[1, 2, 9], [3, 4]]
[[1, 2, 9], [3, 4]]
False
True
```

`b[0]`은 첫 번째 안쪽 리스트 `[1, 2]`다. 바깥 리스트는 둘이지만, 안쪽 리스트는 공유하므로 그 안쪽에 `9`를 추가한 결과가 양쪽에서 보인다.

```text
a ──> 바깥 리스트 A ── 0번 ──┐
                              ├──> 안쪽 리스트 [1, 2, 9]
b ──> 바깥 리스트 B ── 0번 ──┘
```

이와 달리 `b[0] = [9]`는 바깥 리스트 B의 0번 요소 자체를 교체하므로 A의 0번 요소는 유지된다. **안쪽 객체 변경**과 **바깥 리스트의 요소 교체**를 구분한다. 깊은 복사 함수의 사용은 추가편에서 다룬다.

## 5. 함수에서 리스트가 바뀌는 이유

먼저 용어 두 개만 확인한다. `def ref(a)`의 `a`는 함수가 입력을 받는 **매개변수**다. `ref(b)`의 `b`는 함수를 호출할 때 넘기는 **인자**다. 이 호출에서는 둘이 같은 리스트를 가리킨다.

### 강사님 코드 — 원본 발췌

강사님 `workspace_python/_11_fn.py` 120~126행

```python
def ref(a) :
    a.append(4)
    return a

b = [1,2,3]
ref(b)
print(b)
```

강사님 함수는 리스트에 `4`를 추가하고 그 리스트를 반환한다. 반환값을 다른 곳에서 사용하려는 경우 `return a`가 도움이 된다. 다만 여기서는 `ref(b)`의 반환값을 변수에 받지 않는다.

### 내 코드 — 원본 발췌

내 코드 `workspace_python/11_fn.py` 116~121행

```python
def ref(a) :
    a.append(4)

b = [1,2,3]
ref(b) # 전달인자 또는 =으로 가게되면 stack의 주소값이 들어감 + 원본 변경
print(b)
```

내 함수에는 `return a`가 없지만, `a.append(4)`는 같은 리스트를 직접 수정한다. 따라서 두 원본의 `print(b)` 결과는 같다.

### 두 코드의 출력

```text
[1, 2, 3, 4]
```

| 순서 | 실행 | 상태 |
| --- | --- | --- |
| 1 | `b = [1,2,3]` | 바깥 이름 `b`가 리스트를 가리킴 |
| 2 | `ref(b)` | 함수 안 이름 `a`도 같은 리스트를 가리킴 |
| 3 | `a.append(4)` | 그 리스트가 `[1, 2, 3, 4]`로 바뀜 |
| 4 | 함수 종료 뒤 `print(b)` | 바깥 `b`로 변경된 리스트를 확인 |

내 주석의 “stack의 주소값이 들어감”은 구체적인 저장 위치를 단정한다. 이 예제에서는 “매개변수 `a`도 `b`와 같은 리스트를 참조하므로 `append()`가 원본에 반영된다”로 고치면 충분하다.

### 반환값을 받으면 두 함수의 차이가 드러난다

아래는 **설명용 재구성**이다. 동시에 비교할 수 있도록 함수 이름을 바꾸고 반환값 출력만 추가했다. 원본 함수명은 양쪽 모두 `ref`다.

```python
def teacher_ref(a):
    a.append(4)
    return a

def my_ref(a):
    a.append(4)

b = [1, 2, 3]
teacher_result = teacher_ref(b)
print(b)
print(teacher_result)
print(teacher_result is b)

b = [1, 2, 3]
my_result = my_ref(b)
print(b)
print(my_result)
```

출력:

```text
[1, 2, 3, 4]
[1, 2, 3, 4]
True
[1, 2, 3, 4]
None
```

`None`은 여기서 “함수가 별도의 결과값을 돌려주지 않았다”는 뜻이다. 함수가 아무 일도 하지 않았다는 뜻은 아니다.

| 비교 기준 | 강사님 코드 | 내 코드 |
| --- | --- | --- |
| 전달받은 리스트 수정 | 수정함 | 수정함 |
| 반환값 | 수정한 같은 리스트 | `None` |
| 적합한 의도 | 수정한 리스트를 반환값으로도 제공 | 기존 리스트를 수정하는 작업만 수행 |

따라서 `return`이 있다는 이유만으로 강사님 코드가 항상 더 좋다고 판단하지 않는다. 반환값을 사용할 목적이라면 강사님 방식이 맞고, 원본 수정만 의도했다면 내 방식도 동작 목적에 맞는다.

### 함수 안에서 재할당하면?

설명용 재구성 — `append()`와 비교하기 위해 함수 안의 문장만 재할당으로 바꿨다.

```python
def replace(a):
    a = [4]
    print(a)

b = [1, 2, 3]
replace(b)
print(b)
```

출력:

```text
[4]
[1, 2, 3]
```

함수 안의 `a`가 새 리스트를 가리키게 되었을 뿐, 바깥 `b`의 연결은 그대로다. 함수가 끝나서 변경이 “취소된 것”이 아니다. 처음부터 기존 리스트를 수정하지 않았다.

## 6. 내 주석을 다시 읽기

원본은 학습 기록으로 남기고, 설명은 다음처럼 보완한다.

| 원본에 적은 표현 | 다시 정리한 설명 | 확인할 절 |
| --- | --- | --- |
| `b = a` 뒤 두 개가 모두 바뀜 | 같은 리스트 하나를 두 이름으로 보고 있다. | 2절 |
| `clear()`와 `a = []`를 동일하게 사용 | 다른 이름이 공유하는 경우 결과가 다르다. | 3절 |
| `copy()`는 모든 요소를 아예 복사 | 바깥 리스트를 새로 만들며 안쪽 객체는 공유할 수 있다. | 4절 |
| 함수에 stack의 주소값이 들어감 | 함수의 매개변수도 전달된 같은 객체를 참조한다. | 5절 |

이 교정은 새 과목의 선행학습을 추가하는 것이 아니다. 이미 작성한 코드의 동작을 정확하게 읽기 위한 설명이다.

## 7. 복습 문제와 해설

먼저 출력과 이유를 적어 본 뒤 실행한다. 각 문제는 설명용으로 새로 만든 독립 예제다.

### 문제 1 — 같은 리스트인가, 별도 리스트인가?

```python
a = [10, 20]
b = a
c = a.copy()
b[0] = 99
print(a)
print(c)
```

<details>
<summary>정답과 이유</summary>

```text
[99, 20]
[10, 20]
```

`a`와 `b`는 같은 리스트를 가리킨다. `c`는 별도 바깥 리스트이므로 `b`의 0번 요소 교체가 반영되지 않는다.

</details>

### 문제 2 — 재할당 뒤의 `append()`

```python
a = [1, 2]
b = a
b = [3]
b.append(4)
print(a)
print(b)
```

<details>
<summary>정답과 이유</summary>

```text
[1, 2]
[3, 4]
```

`b = [3]`에서 `b`의 연결이 바뀐다. 이후 `append()`는 새 리스트에 적용된다. `a`의 리스트는 수정하지 않았다.

</details>

### 문제 3 — 원본 변경과 반환값

```python
def add_one(items):
    items.append(1)

numbers = [0]
result = add_one(numbers)
print(numbers)
print(result)
```

<details>
<summary>정답과 이유</summary>

```text
[0, 1]
None
```

함수는 `numbers`와 같은 리스트를 수정하지만 값을 명시적으로 반환하지 않는다. 리스트의 최종 상태와 함수의 반환값은 별도로 확인해야 한다.

</details>

### 문제 4 — 얕은 복사 뒤 요소 교체

```python
a = [[1], [2]]
b = a.copy()
b[0] = [9]
print(a)
print(b)
```

<details>
<summary>정답과 이유</summary>

```text
[[1], [2]]
[[9], [2]]
```

바깥 리스트는 각각 따로 있다. `b[0] = [9]`는 복사한 바깥 리스트의 요소를 교체한다. `b[0].append(9)`처럼 공유하던 안쪽 리스트의 내용을 수정한 것이 아니다.

</details>

## 8. 필요할 때 찾는 요약

| 궁금한 것 | 먼저 볼 코드 | 판단 |
| --- | --- | --- |
| 왜 두 변수에서 같은 변경이 보일까? | `b = a` | 같은 객체를 가리키는지 확인 |
| 왜 `a`는 그대로일까? | `b = [...]` | 이름의 연결만 바뀌었는지 확인 |
| 복사했는데 왜 같이 바뀔까? | `b = a.copy()` 뒤 안쪽 객체 변경 | 얕은 복사의 공유 범위 확인 |

| 값은 같은데 `is`가 왜 거짓일까? | 별도 리스트 생성 | 값의 같음과 객체의 동일성 구분 |
