# 추가로 알면 좋은 것 — Stack·Heap과 복사 확장

[00번 읽기 안내](../README.md) · [수업 본문](../01_메모리와_참조%28Stack_Heap%29.md)

이 문서는 수업 본문의 참조 개념에서 한 걸음 더 나아가는 **선택 자료**다. 아래 내부 구조와 `deepcopy()`를 수업에서 상세히 배웠다고 분류하지 않는다. 수업 예제의 출력은 기본편만으로 설명할 수 있다.

## 1. Stack·Heap 그림은 무엇을 설명하려는가?

함수의 호출과 복귀를 설명할 때 Stack이라는 말을 쓴다. 나중에 호출된 함수가 먼저 끝나고 앞선 함수로 돌아가는 일반적인 중첩 호출을, 위에 쌓은 것을 먼저 꺼내는 모습으로 이해할 수 있다. 각 호출의 실행 위치와 지역 이름 등의 정보를 다루는 단위를 **프레임**이라고 부른다.

객체 저장 공간을 설명할 때 Heap이라는 말도 쓴다. 다만 “이름은 무조건 Stack, 값은 무조건 Heap”이라고 외우면 Python의 언어 규칙과 구현을 섞게 된다. Python 코드의 결과를 판단할 때는 **이름이 어떤 객체를 가리키고 있는지**를 먼저 확인한다.

```text
수업 코드의 ref(b)를 읽는 데 필요한 관계

바깥 이름 b ──┐
              ├──> 같은 리스트 [1, 2, 3, 4]
함수 안 a ────┘
```

이 그림은 관계를 보여 주는 도식이다. 실제 저장 주소, 객체 크기, 운영체제의 메모리 배치를 표시하지 않는다. 호출 프레임·객체의 물리적 배치를 자세히 분석하려면 Python 구현과 버전을 따로 정해야 한다.

수업 리스트 파일에 나오는 **자료구조 Stack**도 구분한다. 리스트 끝에 넣고 끝에서 꺼내는 사용법을 설명하는 Stack과, 함수 호출을 설명하는 Stack은 비슷한 순서를 공유하지만 같은 대상을 가리키는 말은 아니다.

## 2. 함수가 끝나면 리스트도 사라질까?

수업 본문의 `ref(b)`가 끝난 뒤에도 바깥 이름 `b`로 리스트를 사용할 수 있다. 함수의 실행이 끝나는 일과, 그 함수에서 사용한 모든 객체가 사라지는 일은 같지 않다.

CPython은 참조 카운트와 순환 참조를 다루는 가비지 컬렉터를 사용한다. 이것은 구현 설명이다. 이 수업에서는 참조 횟수를 손으로 계산하거나 객체의 정확한 회수 시점을 예측하는 문제로 확장하지 않는다. 특정 이름과의 연결이 끊겼다는 사실만으로 즉시 메모리가 회수되었다고 결론 내리지 않는다. [Python 데이터 모델: 객체와 수명](https://docs.python.org/3/reference/datamodel.html#objects-values-and-types)

## 3. `id()`는 주소를 공부하는 도구일까?

`id()`는 객체의 식별값을 반환한다. CPython에서 이 값이 메모리 주소와 관련된다는 사실을 모든 Python 구현의 규칙으로 넓히지 않는다. 숫자 자체를 외우거나 실행마다 같은 값이 나오기를 기대하지 않는다. 같은 객체인지 확인하려는 본문 예제에는 이미 배운 `is`면 충분하다. [Python 내장 함수: id](https://docs.python.org/3/library/functions.html#id)

## 4. 깊은 복사: 안쪽 리스트까지 나누고 싶을 때

기본편의 `list.copy()`는 얕은 복사다. 중첩된 객체까지 재귀적으로 복사하는 방법 중 하나가 `copy.deepcopy()`다. **다음 함수와 import는 추가 학습 내용**이며 기본 문제의 풀이 조건이 아니다. 깊은 복사도 객체의 종류와 사용자 정의 동작에 따라 고려할 점이 있으므로 “항상 모든 것이 완전히 독립된다”라고 일반화하지 않는다. [Python 문서: copy](https://docs.python.org/3/library/copy.html)

설명용 재구성 — 숫자와 중첩 리스트만 있는 간단한 경우다.

```python
import copy

a = [[1, 2], [3, 4]]
b = copy.deepcopy(a)
b[0].append(9)
print(a)
print(b)
print(a[0] is b[0])
```

Python 3.12.14에서 확인한 출력:

```text
[[1, 2], [3, 4]]
[[1, 2, 9], [3, 4]]
False
```

이 예제에서는 안쪽 리스트도 별도 객체이므로 `b[0]`에 추가한 `9`가 `a[0]`에 나타나지 않는다. 먼저 공유가 문제인지 판단하고 필요한 복사 범위를 정한다. 단순한 숫자 리스트의 요소를 교체하는 기본편 예제에는 `list.copy()`만으로 목적을 달성한다.

## 여기서 멈추어도 되는 범위

기본편에서 `대입 → 공유`, `재할당 → 이름 연결 변경`, `append → 객체 변경`, `copy → 새 바깥 리스트`를 설명할 수 있다면 이번 수업 범위의 복습 목적은 달성한 것이다. GC 세부 알고리즘, 객체 내부 구조, 메모리 할당기, 다른 언어의 메모리 모델은 별도 심화 주제로 남긴다.
