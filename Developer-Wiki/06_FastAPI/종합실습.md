# FastAPI 종합실습 — 화면의 Todo를 SQLite에 저장하고 다시 읽기

[FastAPI 목차](README.md) · [실무 스타일](실무_코딩스타일.md)

## 1. 목적과 출발점

실제 화면Todo·SQLite·함수 분리 수업을 연결한 새 종합실습이다. 기존 내 코드를 그대로 제출한 결과가 아니라 입력·저장·화면·다음 요청을 한 번에 설명하기 위한 재구성이다. 메모리 목록 대신 새 book_todo.sqlite를 사용한다.

## 2. 요구사항과 예상

| 요구 | 확인 |
| --- | --- |
|정수ID와내용 입력 | Form타입·빈 내용 검사 |
|목록·상세 | 저장된 현재 자료 조회 |
|중복ID | 입력 화면 복귀 |
|수정 | 해당ID만변경·303뒤상세조회 |
|삭제 | POST·303뒤목록조회 |
|없는ID | 명시적404 |
|저장 유지 | 새 연결·새 앱에서같은파일조회 |

처음 목록은 비어 있다. ID1·공부를 추가하면 상세에 공부가 보이고 수정 뒤에는 복습이 보인다. 삭제 뒤 상세는404다. 이전 상세 주소에 옛 item을 붙여도 현재 DB값을 읽어야 한다.

## 3. 구현할 순서

1. HTML의 `name`과 폼 인자의 이름을 맞춘다. 입력 칸의 이름이 서버에서 받을 이름과 연결되어야 한다.
2. store.py에서 표 준비·조회·변경 함수를 정의한다. 웹 화면을 만들기 전에 저장 기능의 입력과 반환을 정한다.
3. `?` 매개변수로 SQL 문장과 값을 따로 전달한다. 사용자 입력을 SQL 문자열에 직접 이어 붙이지 않는다.
4. 변경은 `commit()`하고 연결은 `finally`에서 닫는다. 변경의 확정과 자원 정리는 서로 다른 역할이다.
5. 경로 함수는 처리 결과를 받아 HTML·404·303을 정한다. 저장 함수가 웹 응답까지 결정하지 않도록 역할을 나눈다.

이 목록의 각 단계는 아래 전체 파일에서 찾을 수 있다. 숨은 DB함수나 생략된 템플릿을 가정하지 않는다.

**[store.py](실습/책형_복습/종합실습/store.py) — 전체 파일**

```python
import sqlite3

DB_FILE = 'book_todo.sqlite'

def prepare():
    connection = sqlite3.connect(DB_FILE)
    try:
        connection.execute('CREATE TABLE IF NOT EXISTS todos(id INTEGER PRIMARY KEY,item TEXT NOT NULL)')
        connection.commit()
    finally:
        connection.close()

def read_rows(sql, parameters=()):
    connection = sqlite3.connect(DB_FILE)
    connection.row_factory = sqlite3.Row
    try:
        cursor = connection.execute(sql, parameters)
        return [dict(row) for row in cursor.fetchall()]
    finally:
        connection.close()

def find(todo_id):
    rows = read_rows('SELECT id,item FROM todos WHERE id=?', (todo_id,))
    return rows[0] if rows else None

def list_all():
    return read_rows('SELECT id,item FROM todos ORDER BY id')

def change(sql, parameters):
    connection = sqlite3.connect(DB_FILE)
    try:
        cursor = connection.execute(sql, parameters)
        connection.commit()
        return cursor.rowcount
    finally:
        connection.close()

def create(todo_id, item):
    return change('INSERT INTO todos(id,item) VALUES(?,?)', (todo_id,item))

def rename(todo_id, item):
    return change('UPDATE todos SET item=? WHERE id=?', (item,todo_id))

def delete(todo_id):
    return change('DELETE FROM todos WHERE id=?', (todo_id,))
```

**[api.py](실습/책형_복습/종합실습/api.py) — 전체 파일**

```python
from fastapi import FastAPI, Request, Form, HTTPException
from fastapi.templating import Jinja2Templates
from fastapi.responses import RedirectResponse
import store

app = FastAPI()
templates = Jinja2Templates(directory='templates')
store.prepare()

@app.get('/create')
def create_page(request: Request):
    return templates.TemplateResponse(request, 'create.html')

@app.post('/create')
def create(todo_id: int = Form(), item: str = Form()):
    item = item.strip()
    if not item or store.find(todo_id) is not None:
        return RedirectResponse('/create', status_code=303)
    store.create(todo_id, item)
    return RedirectResponse('/read', status_code=303)

@app.get('/read')
def read(request: Request):
    return templates.TemplateResponse(request, 'read.html', {'todos': store.list_all()})

@app.get('/detail/{todo_id}')
def detail(request: Request, todo_id: int):
    todo = store.find(todo_id)
    if todo is None:
        raise HTTPException(status_code=404, detail='없는 ID')
    return templates.TemplateResponse(request, 'detail.html', {'todo': todo})

@app.get('/update/{todo_id}')
def update_page(request: Request, todo_id: int):
    todo = store.find(todo_id)
    if todo is None:
        raise HTTPException(status_code=404, detail='없는 ID')
    return templates.TemplateResponse(request, 'update.html', {'todo': todo})

@app.post('/update')
def update(todo_id: int = Form(), item: str = Form()):
    if store.find(todo_id) is None:
        raise HTTPException(status_code=404, detail='없는 ID')
    if item.strip():
        store.rename(todo_id, item.strip())
    return RedirectResponse(f'/detail/{todo_id}', status_code=303)

@app.post('/delete/{todo_id}')
def delete(todo_id: int):
    store.delete(todo_id)
    return RedirectResponse('/read', status_code=303)
```

## 5. 한 요청을 끝까지 추적하기

폼에서 보낸 `todo_id` 문자열을 FastAPI가 정수 입력으로 해석한다. 경로 함수는 `store.find()`로 같은 ID가 있는지 확인하고, 없으면 `store.create()`를 호출한다. create는 내부의 change에 INSERT 문장과 값 튜플을 전달한다. change는 SQL을 실행한 뒤 commit으로 변경을 확정하고 finally에서 연결을 닫는다.

그 다음 경로 함수가 303 응답으로 `/read`를 알려 주면 브라우저가 GET 요청을 새로 보낸다. 이 요청의 list_all은 DB에서 행을 읽고 Row를 dict로 바꾼다. 마지막으로 read.html이 목록을 반복하여 화면에 표시한다. 저장 직후의 함수 반환과 다음 GET 화면을 두 단계로 구분해 읽는다.

수정에서는 `store.rename()`의 UPDATE 문장에 WHERE 조건이 있다. 이 조건이 대상 ID를 고른다. 반환되는 rowcount는 영향을 받은 행 수다. 조회할 때마다 새 DB 연결에서 읽으므로, 서버의 메모리 목록이 남아서 보이는 결과와 구별할 수 있다. 경로 파일이 import한 모든 저장 함수의 정의는 위 store.py에서 확인할 수 있다.

## 6. 확인할 시나리오

| 시나리오 | 예상 |
| --- | --- |
|빈목록 | 자료없음안내 |
|정상추가·상세 | ID1공부 |
|중복추가 |303입력화면·기존값유지 |
|숫자아닌ID |422 |
|수정·옛주소 | 현재복습표시 |
|새연결·새앱 | 같은DB값유지 |
|GET삭제 |405 |
|POST삭제뒤상세 |404 |

한 번에 하나씩 실행하고 같은 DB파일인지 확인한다. 서버 재시작과 임시 새 폴더 실행은 다르다. 새 폴더라면 다른 DB파일이 만들어진다.

## 7. 원본과 비교하고 채점

원본 학생 화면 Todo는 문자열 값을 가진 dict를 메모리 목록에 넣고 상세 내용을 주소에서 받는다. 새 실습은 정수 ID·SQLite의 현재 자료 조회·없는 대상의 404·수정 뒤 303을 선택했다. 원본에서 입력과 화면을 연결한 시도는 그대로 학습 근거로 삼되, 자료형과 응답 정책이 달라진 부분은 새 개선안으로 구분한다.

채점할 때는 입력 위치, 함수가 받는 값과 돌려주는 값, SQL 매개변수, WHERE의 대상, 확정과 닫기, 현재 화면, 다음 요청을 각각 설명할 수 있는지 본다. 화면이 한 번 정상 출력됐다는 사실만으로 모든 조건을 통과했다고 판단하지 않는다. 예를 들어 중복을 미리 조회하더라도 두 요청이 동시에 같은 ID를 추가하는 경우까지 완전히 처리한 것은 아니다. 디스크 오류·잠금·변경 중 실패에 대한 사용자 안내도 이 작은 실습의 범위에는 포함하지 않았다.
