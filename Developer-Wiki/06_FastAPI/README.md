# FastAPI — 요청·함수·화면·저장을 연결하는 나의 교재

웹 API는 주소 하나를 외우는 기술이 아니다. 요청의 값이 어느 함수에 들어가고 어디에 저장되며 다음 화면은 무엇을 읽는지 연결하는 과정이다. 현재 강사님·내 코드를 근거로 개념부터 다시 설명하고, 원본의 오해·좋은 시도·부족한 부분을 공정하게 검토했다.

## 4. 실제 학습 범위

Router·쿼리·폼·경로·Pydantic·Jinja재사용·리다이렉트·SQLite·SQLModel세션·validator·해시·파일·쿠키·SessionMiddleware는 실제 원본에 있다. response_model·request.headers직접 읽기는 사용자 확인상 미학습이므로 TIP에 둔다. yield는 실제 세션 자원 흐름을 읽는 수준이고 고급 제너레이터 구현으로 넓히지 않는다.

실제 자격 증명·세션 비밀키는 원본에서 옮기지 않았다. 파일명에 venv폴더가 포함돼도 학생이 작성한 소스는 포함하고 설치 생성물만 제외했다. 개인 CSS실험·바이브코딩 시험은 근거로 삼지 않았다.

## 5. 확인한 것과 아직 아닌 것

새 앱의 요청·응답·파일 내용·쿠키 전달·세션 분리를 임시 폴더에서 확인한다. SQLite·해시는 독립 실행한다. 원본 Todo·SQLite·입력 모델·해시도 필요한 부분만 사본·정의 추출로 검사했다. 팝업은 별도 headless Chrome을 사용해 사용자의 기존 브라우저를 제어하지 않는다.

07의 새 세션 예제는 SQLite로 재구성했으므로 실제 MariaDB접속·운영DB상태 검증은 아니다. /login은 방문 즉시 표시를 넣는 동작 실습이며 실제 비밀번호 인증이 아니다. 최신 수치와 한계는 [검토 기록](00_FastAPI_리팩토링_검토기록.md)·책형 검증 보고서에서 구분한다.
