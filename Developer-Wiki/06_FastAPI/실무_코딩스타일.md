# FastAPI 실무 코딩스타일 — 수업의 요청 흐름을 읽기 쉽게 정리하기

[FastAPI 목차](README.md) · [종합실습](종합실습.md)

강사님과 내 **실제 수업 경로**를 비교하며 새로 만든 점검 자료다. 새 예시는 당시 작성한 원본 코드가 아니다. 처음에는 [앱과 GET·POST](01_FastAPI_가상환경과_웹_API_기초.md), [폼과 Router](02_FastAPI_Router_Request_Pydantic_CRUD.md), [화면 Todo](05_FastAPI_Jinja_Todo_CRUD.md)를 먼저 읽는다.

## 1. 주소와 요청 방식으로 동작 이름 붙이기

강사님 Todo는 `GET /add`에서 입력 화면을, `POST /api/add`에서 저장을 처리한다. 나는 `GET /create`와 `POST /create`로 같은 주소를 요청 방식별로 나눴다. 두 방식 모두 작동하므로 문서에는 **주소·방식·받는 값·저장 위치·다음 응답**을 함께 적는다. 함수 이름만 보고 어떤 화면을 여는지 추측하지 않는다.

| 동작 | 강사님 원본 | 내 원본 | 결과 |
| --- | --- | --- | --- |
| 입력 화면 | `GET /add` | `GET /create` | HTML 템플릿 |
| 새 항목 | `POST /api/add` | `POST /create` | 메모리 목록에 저장 후 303 리다이렉트 |

## 2. 값을 읽는 방식과 저장 형태 구분하기

강사님은 `Todo = Form()`을 통해 모델 값을 받고 목록에는 모델 객체를 둔다. 나는 `await request.form()`에서 `id`, `item`을 꺼내 **딕셔너리**로 담았다. 템플릿이나 수정 코드에서 `todo.item`과 `todo['item']`이 달라지는 이유다. 같은 필드 이름을 HTML 폼, Python 함수, 템플릿에서 차례로 확인한다.

```python
# 내 수업 코드의 핵심 흐름을 설명용으로 재구성
data = await request.form()
item = data.get('item')
if item != '':
    todo_list.append({'item': item})
```

이 조각은 독립 실행 코드가 아니다. 내 원본의 `id` 처리와 리다이렉트는 [05장](05_FastAPI_Jinja_Todo_CRUD.md)의 발췌에서 읽는다. 두 목록 모두 서버 메모리에 있어 다시 시작하면 남아 있지 않다. [SQLite](06_Python_SQLite와_Transaction.md)와 [사원 DB CRUD](07_FastAPI_MariaDB_SQLModel_사원_CRUD.md)의 저장과 혼동하지 않는다.

## 3. 응답 뒤에 실제로 일어나는 요청 확인하기

폼 저장 뒤 `RedirectResponse(..., status_code=303)`을 반환하면 브라우저가 목록 주소로 **새 GET 요청**을 보낸다. 함수 안에서 목록 함수를 직접 부르는 것과 차이가 있다. [04장](04_FastAPI_Response_Redirect_의존성주입.md)에서 실제 코드를 비교한다. 업로드에서는 폼의 `name`과 서버 매개변수 이름이 맞는지도 [08장](08_FastAPI_파일업로드_다운로드.md)에서 확인한다.

## 추가로 알면 좋은 것

`response_model`과 `request.headers` 직접 읽기는 배우지 않았다고 확인되었으므로 이 점검 순서의 필수 항목이 아니다. 둘은 [기존 자료의 학습 범위 분류](추가편_기존자료_학습범위_분류.md)로 둔다. 팀 단위 디렉터리 설계와 배포 규칙도 수업 원본의 구현으로 표시하지 않는다.
