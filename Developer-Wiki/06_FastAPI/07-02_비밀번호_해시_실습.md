# 07-02. 해시 실습 — 저장한 글자를 복원하지 않고 입력 일치 확인하기

[FastAPI 목차](README.md) · [읽기 안내](00_FastAPI_상세백과_읽기법.md)

이 파일은 FastAPI경로가 아닌 별도 Python실습이다. 원본 파일명은 암호화지만 실제로 작성한 함수는 Argon2해시 생성과 검증이다. 원래 글자를 돌려받는 기능과 입력이 맞는지 확인하는 기능을 구별한다.

<a id="learn"></a>

## 1. 이 장에서 배울 것

CryptContext·hash·verify의 인자와 반환을 설명한다. 같은 입력의 해시 문자열을 직접 비교하지 않는 이유를 이해하고, 실제로 구현하지 않은 로그인·DB저장까지 완성했다고 확대하지 않는다.

<a id="concepts"></a>

## 2. 무엇이며, 왜 필요한가

비밀번호 검사는 “저장된 원문을 꺼내 같은지 비교”하는 방식만 있는 것이 아니다. 이 실습은 원문으로부터 해시 표현을 만들고, 다음에 들어온 입력이 그 표현과 맞는지를 검증한다. 검증 결과는 원문 문자열이 아니라 True·False다.

| 작업 | 함수 | 받는 값 | 돌려주는 값 |
| --- | --- | --- | --- |
| 준비 | CryptContext | 사용할 해시 방식 | 설정 객체 |
| 생성 | ctx_pw.hash | 입력 문자열 | 해시 문자열 |
| 검증 | ctx_pw.verify | 새 입력·저장 해시 | 참·거짓 |

같은 입력으로 두 번 hash를 호출해도 새 salt가 사용되어 해시 문자열이 달라질 수 있다. salt는 생성 때 함께 사용하는 값이며 저장된 해시 표현에 검증에 필요한 정보가 들어 있다. 처음 수준에서는 “문자열이 다르니 입력도 다르다”는 추측을 피하는 것이 중요하다. salt형식·비용 설정의 상세 구현은 아래TIP이다.

암호화의 복호화와 해시 검증은 다른 목적이다. 이 실습의 verify는 해시를 입력 원문으로 되돌리지 않는다. 또한 단방향이라는 말은 추측 가능한 입력을 자동으로 강하게 만든다는 보장이 아니다. 여기서는 실제 함수의 생성·검증 흐름을 먼저 익힌다.

> 📚 **출처 · 본문 설명 확인:** [Passlib CryptContext](https://passlib.readthedocs.io/en/stable/narr/context-tutorial.html), [Passlib Argon2](https://passlib.readthedocs.io/en/stable/lib/passlib.hash.argon2.html). 배운 의미 확인 근거다. 아래 표·전체 예제·풀이를 외부 문장 그대로 옮기지 않았다. 확인일: 2026-10-30.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 필요한 파일 전체.** 같은 장의 폴더 구조를 유지한다. hash_tools.py와 example.py를 같은 폴더에 저장한다. passlib과 Argon2백엔드가 필요하며 새 환경이면 `python -m pip install "passlib[argon2]"`를 참고한다. 이 작업에서는 기존 수업 가상환경을 읽어 실행했다. `python example.py`를 실행한다. 연습용문자는 실제 계정 정보가 아니며 원본에 적힌 예제 비밀번호도 가져오지 않았다.



**[hash_tools.py](실습/책형_복습/07-02_비밀번호_해시_실습/hash_tools.py) — 새 예제 전체 파일**

```python
from passlib.context import CryptContext

ctx_pw = CryptContext(schemes=['argon2'], deprecated='auto')

def crypt(text):
    return ctx_pw.hash(text)

def verify(original, hashed):
    return ctx_pw.verify(original, hashed)
```

**[example.py](실습/책형_복습/07-02_비밀번호_해시_실습/example.py) — 새 예제 전체 파일**

```python
from hash_tools import crypt, verify

saved_hash = crypt('연습용문자')
another_hash = crypt('연습용문자')
print(verify('연습용문자', saved_hash))
print(verify('다른문자', saved_hash))
print(verify('연습용문자', another_hash))
```

import는 hash_tools의 설정 객체와 두 함수 정의를 연결한다. crypt의 문자열 인자가 hash에 전달되어 저장할 해시가 반환된다. 첫 verify는 같은 입력이라 True, 둘째는 다른 입력이라 False다. 새로 만든 another_hash도 같은 입력에 True다. 해시 전체 값은 고정 정답으로 출력하지 않고 검증 결과를 확인한다.

**요청과 예상 결과:**

```text
True
False
True
```

해시 문자열의 모양과 값은 실행 환경·생성값에 따라 다를 수 있다. 두 해시를 다시 원문으로 바꿔 비교한 결과가 아니다.

### 내 코드 — 원본

```python
# argon2 암호화 방식(단방향)
def crypt(txt) :

```

**발췌 바로 풀이:** 두 코드 모두 `argon2` 방식의 `CryptContext`를 만들고 `ctx_pw.hash(txt)`로 입력 문자열의 해시를 생성한다. 코드의 예제 비밀번호 자체는 학습할 개념이 아니므로 옮기지 않았다. 해시 결과 문자열은 실행마다 달라질 수 있다.
### 내 코드 — 원본

출처: `D:/workspace/workspace_python/03_database/04_암호화.py` 19–21행 · **원본 발췌**

```python
# 암호화 된 대상 비교
def verify(orig, hashed) :
    return ctx_pw.verify(orig, hashed)
```

**발췌 바로 풀이:** `ctx_pw.verify(orig, hashed)`는 입력한 원본 문자열이 저장된 해시와 맞는지 확인해 참/거짓을 돌려준다. 강사님과 내 코드의 동작은 같다. **해시 문자열을 다시 비밀번호로 복원하는 함수가 아니다.**

내 crypt는 ctx_pw.hash를 그대로 반환하고 verify는 ctx_pw.verify의 결과를 반환한다. 함수 이름 crypt가 붙었다고 복호화 가능한 암호화가 되는 것은 아니다. 양쪽 모두 schemes에 argon2를 지정하고 deprecated를 auto로 설정했다. 이 옵션은 해시 관리 설정이며 입력 문자열을 자동 수정하거나 웹 로그인을 등록하는 기능이 아니다.

<a id="connections"></a>

## 5. import·함수·화면·저장이 연결되는 흐름

CryptContext설정 → crypt(text) → hash결과를 변수에 저장 → verify(새 입력,저장 해시) → True/False다. 전체 정의가 있는 hash_tools.py를 함께 제공해 숨은 함수를 가정하지 않는다. 이 실습에는 라우터·세션 쿠키·DB INSERT가 없으며 이후 로그인 본문과의 연결은 별도로 읽는다.

<a id="review"></a>

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 생성과 검증을 각각 함수로 감싸 호출자가 입력과 저장값을 구별하게 했다. **용어 교정:** 파일명 암호화보다 현재 동작은 해시·검증이라고 설명하는 것이 정확하다. **결과 교정:** 같은 입력의 새 해시끼리 문자열 비교하면 안 되고 저장 해시와 입력을 verify에 전달한다. **한계:** 인증 성공 뒤 세션 발급·로그인 실패 정책·실제 계정 저장은 이 짧은 파일에 구현되지 않았다.

원본 오류·수업용 단순화·목적에 따른 설계를 나눈다. 새 개선안은 당시 내 코드나 D 드라이브 수정본이 아니다.

<a id="teacher"></a>

## 7. 강사님 코드가 도움이 되는 비교



강사님과 내 설정·두 함수 동작이 같아 중복 인용하지 않는다. 공백과 함수 인자 이름 차이를 우열로 평가하지 않는다. 새 예제는 실제 계정 문자열을 옮기는 대신 고정 연습값으로 동작을 재현하고 반환값을 설명했다.

## 8. 결과를 추적하고 한 가지 바꾸기

| 호출 | 검사 대상 | 결과 |
| --- | --- | --- |
|crypt(연습값) | 생성 | 해시 문자열 |
|verify(같은 입력,저장값) | 일치 | True |
|verify(다른 입력,저장값) | 불일치 | False |
|verify(같은 입력,새 해시) | 새 해시도 검증 | True |

| 한 가지만 변경 | 예상 | 이유 |
| --- | --- | --- |
|검증 입력 끝에 공백 추가 | False | 입력 자체가 다름 |
|hash생성 재실행 | 같은 입력 verify True | 저장 해시로 검증 |
|검증의 두 인자 뒤바꿈 | 올바른 검증 아님·오류 가능 | 원문·해시 역할이 다름 |

모듈 없음이면 실행 환경과 설치를 본다. MissingBackendError면 Argon2백엔드가 있는지 확인한다. 불일치면 공백·대소문자까지 입력 그대로 비교하는지 본다. 임의 문자열을 저장 해시로 넣는 경우는 정상 비밀번호 불일치와 달리 형식 오류가 날 수 있다.

**확인 범위:** 독립 Python파일을 별도 임시 폴더에서 실행해 출력·DB파일·해시 검증을 확인한다. 실제 외부 서비스·운영 DB·브라우저 공개 서버에 요청한 결과와 구별한다. 원본 전체 앱을 무조건 실행하지 않으며 별도 확인한 원본 구간은 검증 보고서에 기록한다. 사용자의 가상환경은 검사에 읽기만 사용하고 파일을 설치·수정하지 않는다.

## 9. 추가로 알면 좋은 것과 출처

> 💡 **TIP · 수업 범위 밖:** 해시 비용·정책 갱신·마이그레이션·실패 횟수 제한·계정 복구·배포 환경의 알고리즘 선택은 추가 학습이다. 공식 문서의 예제가 있다는 것과 현재 서비스의 인증 설계가 완성됐다는 것은 다르다. 배운 내용은 함수의 입력·해시 생성·검증까지다.

request.headers 직접 읽기와 response_model은 미학습으로 확인된 선택 확장이다. 본문에서 이 기능을 선행 조건으로 요구하지 않는다. 응답·입력 타입 표시와 response_model 설정도 구별한다.

## 10. 복습과 빠른 정리

1. verify는 원래 비밀번호를 반환하는가?
2. 같은 입력의 새 hash끼리 문자열이 달라도 실패인가?
3. 저장 해시를 첫 번째 인자에 넣는가?
4. 이 파일에서 로그인 세션·DB저장도 완성했는가?

<details>
<summary>풀이 — 먼저 결과와 이유를 적은 뒤 펼치기</summary>

참·거짓을 반환한다. 같은 입력을 verify해 확인한다. 첫 번째는 새 원문 입력이다. 별도 구현이 없다.

</details>

|hash | 저장할 표현 생성 |
|verify | 입력과 저장 해시 검사 |
