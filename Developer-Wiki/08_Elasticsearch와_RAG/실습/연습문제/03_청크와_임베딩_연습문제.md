## 목표와 준비

청크·겹침·임베딩·차원을 구별한다. split_text의 전체 흐름과 import한 함수 정의를 읽고, 문자 수 30이 모든 결과의 상한이 아닌 이유를 설명한다. 청크마다 다른 본문·벡터·ID가 저장되도록 필요한 조건을 이해한다.

[본문 3절](../../03_청크와_임베딩.md#example)의 폴더·설치·입력·실행 조건부터 확인한다. 아래 필요한 파일 전체를 같은 구조로 저장한다. 가져오는 함수·모델 정의도 빠뜨리지 않는다.

## 문제 1. 실행 결과 예상

**chunk_tools.py**

```python
import re


def split_text(text, chunk_size=30, overlap_size=6):
    sentences = re.split(r'(?<=[.!?])\s+', text.strip())
    sentences = [s.strip() for s in sentences if s.strip()]
    chunks = []
    temp = ''
    for sentence in sentences:
        candidate = f'{temp} {sentence}' if temp else sentence
        if len(candidate) <= chunk_size:
            temp = candidate
        else:
            if temp:
                chunks.append(temp)
            temp = sentence
    if temp:
        chunks.append(temp)
    overlap_chunks = []
    for index, chunk in enumerate(chunks):
        if index == 0:
            overlap_chunks.append(chunk)
        else:
            prefix = chunks[index - 1][-overlap_size:] if overlap_size > 0 else ''
            overlap_chunks.append(f'{prefix} {chunk}'.strip())
    return overlap_chunks


def build_actions(doc, embed):
    actions = []
    for index, chunk in enumerate(split_text(doc['content'])):
        vector = embed(doc['title'], chunk)
        source = {**doc, 'content': chunk, 'chunk_index': index, 'embedding': vector}
        actions.append({'_index': 'computer_chunk', '_id': f'{doc["id"]}-{index}', '_source': source})
    return actions
```

**example.py**

```python
from chunk_tools import split_text, build_actions


def fixed_embedding(title, content):
    return [0.1, 0.2]


text = 'A' * 20 + '. ' + 'B' * 20 + '. ' + 'C' * 20 + '.'
doc = {'id': 7, 'title': '구조 예제', 'content': text}
chunks = split_text(text)
actions = build_actions(doc, fixed_embedding)
print('청크 수:', len(chunks))
print('청크 길이:', [len(c) for c in chunks])
print('둘째 앞 겹침:', chunks[1][:6])
print('ID:', [a['_id'] for a in actions])
print('본문 독립:', actions[0]['_source'] is not actions[1]['_source'])
print('원본 유지:', doc['content'] == text and 'embedding' not in doc)
print('가상 차원:', len(actions[0]['_source']['embedding']))
```

실행 전에 결과를 먼저 적는다. 자료의 모양·분류 결과·확률·점수·현재 변수의 대상을 구별한다.

split_text의 전체 정의를 제공했다. 21글자 문장 둘은 합치면 43글자여서 따로 묶이고, 둘째부터 앞 6글자와 공백 하나가 더해져 28글자가 된다. build_actions는 전달받은 embed 함수를 제목·청크로 호출한다. 여기서는 fixed_embedding의 고정값을 받으므로 의미 학습이나 벡터 유사도 성능을 확인한 것은 아니다. {**doc, ...}로 각 본문 dict를 따로 만들고 content를 실제 청크로 바꾼 부분은 원본의 결함을 고친 새 개선안이다.

| --- | --- |
|문장 3개 | 각 21글자 |
|묶기 | 두 문장 합은 43이므로 별도 |
|겹침 | 첫째 21·나머지 28글자 |

|새 _source | 청크마다 별도 dict |

## 문제 2. 이유 설명

1. 원본의 chunk_size=30은 최종 길이 상한인가?
2. doc2=doc 뒤 이전 작업도 바뀌는 이유는?
3. 차원이 같으면 모든 임베딩 모델을 섞어도 되는가?

<details>
<summary>풀이</summary>

1. 긴 한 문장과 겹침 때문에 아니다.
2. 별도 복사가 아니라 같은 dict 참조를 저장했기 때문이다.
3. 숫자 개수뿐 아니라 호환되는 모델·표현 공간이 필요하다.

</details>

## 문제 3. 한 가지만 바꾸기

| 한 가지만 변경 | 예상 |
| --- | --- |
|공백만 있는 입력 | 청크 없음 |
|40글자 한 문장 | 30보다 긴 한 청크가 남음 |
|문장부호 뒤 공백 제거 | 문장 분리가 달라짐 |
|source를 doc로 직접 지정 | 여러 작업이 같은 dict를 가리킬 수 있음 |
|차원이 다른 벡터 전송 | 실제 저장 설정과 불일치·이 예제에서는 전송하지 않음 |

<details>
<summary>막힐 때 확인</summary>

청크가 예상보다 길면 긴 단일 문장과 겹침을 확인한다. 앞선 작업의 값이 바뀌면 객체 참조를 살핀다. 적재한 본문과 질문응답의 인용이 어긋나면 chunk와 전체 content 중 무엇을 저장했는지 본다. 임베딩 오류는 모델·입력·차원·응답 존재를 단계별로 구분한다.

</details>

## 채점과 복습

정상 출력뿐 아니라 입력 열·정답·분할·평가 대상의 차이도 설명한다. 새 예제는 독립 실행이며 실제 검색·AI 서비스 성공과 구별한다. TIP 확장은 필수 조건이 아니다. 정의→입력→호출→반환→다음 평가의 흐름을 연결한다.
