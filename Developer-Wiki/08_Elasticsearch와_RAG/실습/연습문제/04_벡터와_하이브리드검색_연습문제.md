# 04 벡터와 하이브리드검색 — 연습문제

[원본 비교 본문](../../04_벡터와_하이브리드검색.md) · [연습문제 목차](README.md)

**새로 구성한 복습 문제**다. 강사님이 낸 시험이나 내 당시 구현 코드가 아니다. 본문의 강사님 코드와 내 코드를 읽고 답을 예상한다. 외부 DB·API를 실제로 호출하지 않아도 풀 수 있다.

## 문제

1. `multi_match`와 `knn`은 각각 어느 필드를 검색하는가?
2. `size=5`, `num_candidates=max(size*10, 50)`이면 각각 몇 개를 뜻하는가? 후보가 50개라면 반환 결과도 반드시 50개인가?
3. 같은 문서가 문자 검색 1위와 벡터 검색 2위라면, 원본 RRF 코드에서는 어느 두 값을 더하는가?

<details>
<summary>정답과 확인할 점</summary>

1. `multi_match`는 `title`·`content` 텍스트, `knn`은 `embedding` 숫자 벡터를 검색한다.
2. 결과 수는 5, 먼저 볼 후보 수는 50이다. 후보 수와 반환 결과 수는 다르다.
3. `1/(60+1) + 1/(60+2)`다. 두 검색의 **원점수**가 아니라 순위로 계산한다. 실제 검색 결과의 순위는 여기서 확정하지 않는다.

입력→처리→결과의 실제 원본 사례는 [본문](../../04_벡터와_하이브리드검색.md)에서 확인한다.

</details>

## 추가로 알면 좋은 것

> 💡 **TIP · 수업 범위 밖:** 상수와 후보 수를 바꾼 뒤 검색 품질을 측정하는 실험은 원본에 없다. 먼저 현재 `rank_constant=60` 계산을 이해한다.
