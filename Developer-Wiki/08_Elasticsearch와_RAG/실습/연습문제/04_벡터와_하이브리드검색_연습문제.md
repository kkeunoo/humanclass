# 04. 벡터·하이브리드 검색 — 가까운 결과를 찾고 순위로 합치기 — 연습문제

[본문](../../04_벡터와_하이브리드검색.md) · [문제 목차](README.md)

실제 수업 내용을 바탕으로 **새로 구성한 연습문제**다. 원본·당시 내 코드·새 개선안을 구별한다. 예상 → 이유 → 한 가지 변경 순서로 푼다.

## 목표와 준비

질문 벡터와 저장 벡터의 관계, k·num_candidates·size의 차이를 설명한다. 같은 _id의 순위 기여를 누적하고 정렬·잘라내기·formatter 반환까지 연결한다. 고정 순위 예제와 실제 벡터 유사도 검색을 구별한다.

[본문 3절](../../04_벡터와_하이브리드검색.md#example)의 폴더·설치·입력·실행 조건부터 확인한다. 아래 필요한 파일 전체를 같은 구조로 저장한다. 가져오는 함수·모델 정의도 빠뜨리지 않는다.

## 문제 1. 실행 결과 예상

**rank_tools.py**

```python
def fuse(text_hits, vector_hits, rank_constant=60, size=10):
    scores = {}
    for hits in [text_hits, vector_hits]:
        for rank, hit in enumerate(hits, start=1):
            doc_id = hit['_id']
            if doc_id not in scores:
                scores[doc_id] = {'score': 0.0, 'source': hit['_source']}
            scores[doc_id]['score'] += 1 / (rank_constant + rank)
    ordered = sorted(scores.items(), key=lambda item: item[1]['score'], reverse=True)
    results = []
    for doc_id, data in ordered[:size]:
        results.append({'id': doc_id, 'document': data['source'], 'score': data['score']})
    return {'results': results, 'total': len(scores)}
```

**example.py**

```python
from rank_tools import fuse

text_hits = [
    {'_id': 'A', '_source': {'title': 'A 안내'}},
    {'_id': 'B', '_source': {'title': 'B 안내'}},
]
vector_hits = [
    {'_id': 'B', '_source': {'title': 'B 안내'}},
    {'_id': 'C', '_source': {'title': 'C 안내'}},
]
result = fuse(text_hits, vector_hits)
print('순서:', [row['id'] for row in result['results']])
print('점수:', [round(row['score'], 6) for row in result['results']])
print('고유 결과:', result['total'])
short = fuse(text_hits, vector_hits, size=1)
print('상위 1개·총수:', len(short['results']), short['total'])
print('빈 입력:', fuse([], []))
```

실행 전에 결과를 먼저 적는다. 자료의 모양·분류 결과·확률·점수·현재 변수의 대상을 구별한다.

<details>
<summary>풀이</summary>

```text
순서: ['B', 'A', 'C']
점수: [0.032522, 0.016393, 0.016129]
고유 결과: 3
상위 1개·총수: 1 3
빈 입력: {'results': [], 'total': 0}
```

fuse의 전체 정의에서 두 목록을 같은 규칙으로 반복한다. 같은 B의 score가 누적되고 sorted가 내림차순으로 정렬한다. size=1이어도 고유 후보는 세 개이므로 total은 3이다. 원본 formatter는 청크 _id를 최종 결과에서 생략하지만, 새 예제는 순위 계산을 확인하기 위해 id를 함께 남긴 개선안이다.

| ID | 문자 순위 기여 | 벡터 순위 기여 | 합계·순서 |
| --- | --- | --- | --- |
|A | 1/61 | 없음 | 약 0.016393·2위 |
|B | 1/62 | 1/61 | 약 0.032522·1위 |
|C | 없음 | 1/62 | 약 0.016129·3위 |

</details>

## 문제 2. 이유 설명

1. B는 왜 A보다 앞서는가?
2. size=1이면 total도 1이어야 하는가?
3. 원본의 최종 total은 전체 인덱스의 관련 문서 수인가?

<details>
<summary>풀이</summary>

1. 두 목록의 기여를 모두 받아 점수가 더 크다.
2. 반환할 수와 고유 후보 수는 다르다.
3. 두 후보 목록에서 합친 고유 ID 수다.

</details>

## 문제 3. 한 가지만 바꾸기

| 한 가지만 변경 | 예상 |
| --- | --- |
|두 목록 모두 B를 1위로 | B에 1/61 두 번 |
|벡터 목록을 비움 | 문자 순위만 사용 |
|size를 1로 | 반환 1개·고유 총수 3 |
|원점수만 바꿈 | 새 fuse는 순위만 써 결과 동일 |
|같은 점수 발생 | 현재 정렬은 삽입 순서에 기대므로 명시 정책 검토 |

<details>
<summary>막힐 때 확인</summary>

같은 자료가 합쳐지지 않으면 _id 형식과 청크 ID를 본다. 결과가 적으면 인덱스 자료·후보 수·반환 수를 구별한다. 벡터 검색 오류는 질문과 저장의 차원·모델·필드 종류를 확인한다. RRF 숫자를 0~1 확률로 읽거나 머신러닝 시험 점수처럼 비교하지 않는다.

</details>

## 채점과 복습

정상 출력뿐 아니라 입력 열·정답·분할·평가 대상의 차이도 설명한다. 새 예제는 독립 실행이며 실제 검색·AI 서비스 성공과 구별한다. TIP 확장은 필수 조건이 아니다. 정의→입력→호출→반환→다음 평가의 흐름을 연결한다.
