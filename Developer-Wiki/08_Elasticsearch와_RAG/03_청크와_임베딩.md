# 03. 긴 텍스트를 나눠 벡터로 저장하기

[이전: 검색과 CRUD](02_검색과_CRUD.md) · [목차](README.md) · [다음: 검색 방식 비교](04_벡터와_하이브리드검색.md)

문서의 `content`를 문장 단위로 나누고 여러 문장을 약 30글자씩 묶는다. 이후 앞 청크 끝 6글자를 다음 청크에 겹쳐 넣는다. 이 수치는 **문자 길이 기준**이며 토큰 수 기준이 아니다.

## 먼저: 문서를 왜 나누나?

긴 문서 전체 대신 검색에 쓸 **작은 텍스트 조각(청크)**을 만들고, 조각마다 임베딩 값을 저장하려는 실습이다. 임베딩은 텍스트를 여러 숫자의 목록으로 바꾸는 작업이고, 이 목록을 저장하는 필드가 `dense_vector`다. 앞 장의 `text` 필드와 역할이 다르다.

| 순서 | 수업 코드의 입력과 처리 | 얻으려는 것 |
| --- | --- | --- |
| 나누기 | `content`를 문장 기준으로 나눔 | 청크 목록 |
| 겹치기 | 앞 청크의 끝 6글자를 다음 청크 앞에 덧붙임 | 경계 근처의 문맥 일부 |
| 숫자로 바꾸기 | 제목·청크를 임베딩 함수에 전달 | 384차원 벡터 응답 |
| 저장 | 문서 ID와 청크 번호로 `_id` 구성 | 청크별 검색 자료 |

표는 **실습 흐름을 새로 요약한 설명**이다. 실제 적재 성공이나 임베딩 API 응답을 재현했다는 뜻이 아니다.

## 문장 나누기와 겹침

예를 들어 `첫 문장. 다음 문장!`은 문장부호 뒤 공백에서 두 부분으로 나뉠 수 있다. 정규표현식의 전체 문법보다 **이 입력에서 어디가 갈라지는지**부터 확인한다. `chunk_size=30`은 여러 문장을 묶는 기준으로 읽고, 모든 결과가 반드시 30글자 이하라고 생각하지 않는다.

## 임베딩 함수가 하는 일

이 함수는 제목과 청크 내용을 요청 문장으로 묶어 외부 임베딩 서비스에 보낸다. 반환된 숫자 목록은 이후 질문의 벡터와 비교할 자료다. **임베딩 값 자체가 답변 문장은 아니다.**

### 강사님 코드 — 원본 발췌

출처: `D:/workspace_teacher/workspace_python/07_elastic/router/embedding_router.py` 211–235행

```python
def get_embedding_with_llm(title, content) :
    prompt = f'''
        task: retrival document\n
        title: {title}\n
        content: {content}
'''
    result = gemini.models.embed_content(
        model='gemini-embedding-2',

        # 텍스트를 임베딩한다
        contents=[
            types.Content(
                parts=[
                    types.Part.from_text(text=prompt)
                ]
            )
        ],

        # 옵션
        config=types.EmbedContentConfig(
            output_dimensionality=384
        )
    )

    return result.embeddings[0].values
```

```python
def get_embedding_with_llm(title, content):
    prompt = f'''
        task: retrival document\n
        title: {title}\n
        content: {content}
'''

    result = gemini.models.embed_content(
        model='gemini-embedding-2',
        # 텍스트를 임베딩한다
        contents=[
            types.Content(parts=[
                types.Part.from_text(text=prompt)
            ])
        ],
        #옵션
        config=types.EmbedContentConfig(
            output_dimensionality=384
        )
    )

    return result.embeddings[0].values
```

현재 적재 루프는 양쪽 모두 `get_embedding_with_llm`을 호출한다. 이 함수는 제목과 청크를 합친 요청을 Gemini 임베딩 호출에 보내고 384차원 설정의 응답 값을 꺼낸다. 코드에는 Elasticsearch inference 방식도 있지만 이 루프에서는 주석 처리돼 있다. 외부 응답, 모델명 유효성, 실제 벡터 길이는 여기서 실행 검증하지 않았다.

## 추가로 알면 좋은 것

> 💡 **TIP · 원본을 읽고 찾은 개선점:** 청크마다 `doc2 = {**doc, 'content': chunk}`처럼 별도 복사본을 만들고, 실제 청크 텍스트가 검색 결과의 `content`에 들어가는지도 확인할 수 있다. 현재 원본은 `doc2['content']`를 청크로 바꾸지 않아 **임베딩은 청크, 저장된 본문은 원래 전체 문서**일 수 있다. 이는 수업 코드에서 찾은 개선점이며 적용된 동작으로 쓰지 않는다.
