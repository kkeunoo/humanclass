# 01. 연결하고 문서를 넣기

[목차](README.md) · [다음: 검색과 CRUD](02_검색과_CRUD.md)

`api.py`는 검색과 임베딩 라우터를 FastAPI 앱에 연결한다. 연결 설정은 `config.py`가 환경변수 이름을 읽는다. 키의 **값**은 문서에 쓰지 않는다. 먼저 `computer` 인덱스의 필드 종류를 정한 다음 JSON 문서를 벌크로 넣는다.

## 먼저: 인덱스와 문서의 관계

Elasticsearch의 **문서**는 제목·분류·가격·본문 같은 필드를 가진 한 건의 JSON 자료다. **인덱스**는 이 문서를 모아 검색할 대상으로, 이번 실습의 이름은 `computer`다. **매핑**은 각 필드를 어떤 종류의 값으로 다룰지 정한다.

| 이해용 문서 예시 | 값 | 매핑에서 볼 점 |
| --- | --- | --- |
| `title` | `노트북 안내` | 문장 검색을 위한 `text` |
| `category` | `laptop` | 같은 범주값 찾기에 적합한 `keyword` |
| `price` | `900000` | 숫자 범위 검색을 위한 `integer` |

이 표는 **새로 만든 개념 예시**이며 원본 JSON의 특정 문서나 실제 검색 결과가 아니다. 아래 코드는 `computer`의 매핑을 만든 뒤 여러 문서를 적재한다.

## 인덱스의 필드 종류

`text`의 **단어 분석을 통한 검색**과 `dense_vector`의 **숫자 벡터를 이용한 검색**을 구분한다. 여기서는 아직 `dense_vector`를 만들지 않으며, 03장에서 별도 필드로 다룬다.

```python
    # indices는 index의 복수형 중에 하나

        },
    )
```

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_python/07_elastic/router/es_router.py` 47–61행

```python
    # indices는 index의 복수형 중에 하나
    es.indices.create(
        index='computer',
        mappings={
            'properties' : {
                'id':{'type':'integer'},
                'title':{'type':'text'}, # text type은 벡터로 분석해서 유연한 검색이 가능한 글씨
                'category':{'type':'keyword'}, # keyword type은 태그처럼 인식되는 것, 완전 똑같은 단어로만 검색이 가능한 글씨
                'price':{'type':'integer'},
                'rating':{'type':'float'},
                'created_at':{'type':'date'},
                'content':{'type':'text'},
            }
        }
    )
```

`text`는 검색을 위해 문장을 분석해 색인하는 필드이고, `keyword`는 정확한 값으로 보관하는 필드다. `title`·`content`가 `text`, `category`가 `keyword`다. 두 원본 주석의 “text는 벡터로 분석”이라는 표현은 부정확하다. **벡터는 03장에서 따로 만드는 `embedding` 필드**에 저장한다. SQL 표에 비유할 수 있지만 Elasticsearch의 인덱스와 SQL의 성능 인덱스는 같은 뜻이 아니다.

## 여러 문서를 한 번에 적재

`load_documents()`가 읽은 문서마다 **어느 인덱스에(`_index`), 어떤 ID로(`_id`), 어떤 내용을(`_source`)** 넣을지를 적는다. `actions`는 이런 작업들의 목록이고 `helpers.bulk`가 묶어서 보낸다.

### 강사님 코드 — 원본 발췌

출처: `D:/workspace_teacher/workspace_python/07_elastic/router/es_router.py` 74–91행

```python
def ingest_documents():
    documents = load_documents()

    actions = []
    for doc in documents:
        actions.append(
            {
                "_index": "computer",
                "_id": doc["id"],  # '_id': doc.get('id', None),
                "_source": doc,
            }
        )

    success, errors = helpers.bulk(es, actions, stats_only=False)
    print("success", success)
    print("errors", len(errors), errors)

    return {"msg": {"success": success, "errors": errors}}
```

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_python/07_elastic/router/es_router.py` 68–89행

```python
def ingest_documents():
    documents = load_documents()

    actions = []

    for doc in documents :
        actions.append({
            '_index' : 'computer',
            '_id' : doc['id'], # '_id' : doc.get('id', None),
            '_source' : doc
        })

    success, errors = helpers.bulk(es, actions, stats_only=False) # stats_only=False 를 쓰면 성공/실패 값과 에러메시지를 돌려줌
    print('success : ', success)
    print('errors : ', len(errors), errors)

    return {
        'msg' : {
            'success' : success,
            'errors' : errors
        }
    }
```

`load_documents()`가 읽은 JSON 문서마다 `_index`, `_id`, `_source`를 묶어 `actions`에 넣고 `helpers.bulk`로 전송한다. `_id`는 원본 문서의 `id`이며, 같은 ID로 다시 적재하면 이미 있던 문서에 영향을 줄 수 있다. `success`와 `errors`는 **호출 시점의 응답**으로 확인해야 한다. 코드만 보고 성공 건수를 단정하지 않는다.

`run.py`에도 연결·인덱스 생성·적재 실습이 있다. 파일 마지막에서 `ingest_documents()`를 즉시 호출하므로 실행은 서버의 문서를 변경할 수 있다. 원본을 읽는 순서와 실제 실행은 구별하자.
