# Elasticsearch·RAG 종합실습 — 한 문서가 답변에 쓰이기까지

[단원 목차](README.md) · [장별 연습문제](실습/연습문제/README.md)

실제 외부 서비스 없이 푸는 **새 추적 연습**이다. 강사님이 낸 독립 종합 과제나 내 당시 제출 코드가 아니다. 양쪽 `07_elastic` 원본에 있는 단계만 연결하고, 검색 점수·AI 답변을 만들어 내지 않는다.

## 먼저: 완성할 설명의 모양

하나의 문서가 **어느 인덱스에 어떤 필드로 들어가고, 어떻게 청크와 벡터가 되며, 검색 결과의 어느 내용이 질문과 함께 전달되는지** 단계별로 추적한다. 실행되지 않은 API 응답은 빈칸으로 두고 원본 코드에서 확실히 알 수 있는 값만 적는다.

## 문제

문서에 `title`과 `content`가 있다. 이 문서가 인덱스에 저장되고 질문응답의 근거가 되기까지 아래 빈칸을 채운다.

1. 인덱스에 저장되는 **문서와 필드**는 어디서 정하는가? [01장](01_연결과_문서적재.md)
2. `content`를 문장과 청크로 나누는 함수는 무엇을 기준으로 나누는가? [03장](03_청크와_임베딩.md)
3. 청크를 임베딩해 저장한 후 키워드와 벡터 검색이 각각 보는 것은 무엇인가? [04장](04_벡터와_하이브리드검색.md)
4. 검색된 내용을 질문과 함께 넘길 때, 답변의 **근거**는 어느 단계에서 왔는가? [05장](05_RAG_질문응답.md)

<details>
<summary>처리 순서 해설 — 먼저 직접 연결한 뒤 펼치기</summary>

```text
문서 적재 → content 분리 → 약 30글자 단위의 청크와 6글자 겹침
          → 청크 임베딩 저장 → 키워드·벡터 검색
          → 검색 결과를 질문에 덧붙여 답변 요청
```

여기서 30·6은 원본 구현의 **문자 기준**이며 모든 청크의 최대 길이를 보장하지 않는다. `text`와 `dense_vector`는 서로 다른 검색 정보다. 실제 순위와 답변 문장은 외부 서비스 없이 확정할 수 없다.

</details>

**성공 기준:** 다섯 장의 원본에서 이 단계에 대응하는 함수와 필드를 찾아 설명한다. `run.py`를 실행하거나 접속키를 준비하는 것은 이 문제의 요구가 아니다.
