## 2. 개념부터 이해하기

### 2.1 제목은 문서의 단계다

`h1`~`h6`은 제목의 수준이다. 큰 주제 아래 작은 주제를 두는 문서 구조를 표현한다. 기본 스타일이 서로 다른 크기를 붙일 수 있지만 크기를 고르기 위한 여섯 개 버튼으로 생각하지 않는다.

```html
<!-- 설명용 새 예제 · body 안에 넣을 조각 -->
<h1>HTML 학습 기록</h1>
<h2>기본 태그</h2>
<h3>문단과 줄바꿈</h3>
```

이 구조는 ‘HTML 학습 기록 안의 기본 태그, 그 안의 문단과 줄바꿈’으로 읽는다. CSS를 나중에 바꿔도 제목이 맡는 역할은 제목 요소로 표시한다. `h7`은 표준 제목 요소가 아니다.

> 📚 **출처 · 본문 설명 확인:** 여섯 제목 수준의 의미와 사용은 [MDN — h1~h6](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/Heading_Elements)로 확인했다. 원본의 h7 실험과 표준 제목 사용을 구별한다.

<a id="meaning"></a>

### 2.2 강조·표시·삭제는 같은 기능이 아니다

| 요소 | 나타낼 뜻 | 기본 표시에서 흔한 모습 | 선택할 때 묻는 질문 |
| --- | --- | --- | --- |
| `strong` | 중요성·긴급성 등 | 굵은 글자 | 중요한 내용임을 나타내려는가? |
| `em` | 문장의 강세 | 기울임 | 어느 말에 힘을 주는가? |
| `mark` | 현재 문맥에서 눈여겨볼 부분 | 배경 강조 | 여기서 주목할 부분인가? |
| `del` | 삭제된 내용 | 취소선 | 실제로 삭제된 내용을 보여 주는가? |

`<del>mark</del>`을 쓰면 태그는 `del`이다. 안에 적은 글자가 `mark`라고 해서 배경 강조 요소로 바뀌지 않는다. 태그 이름과 예제의 글자를 맞추면 실습 결과를 다시 읽기 쉽다.

기본 스타일은 이해를 도와주는 표시일 뿐, `mark`의 색이 언제나 노란색으로 고정된다는 뜻은 아니다. 취소선 모양만 필요할 때 아무 내용에나 삭제 의미를 붙이지 않고, 뒤의 CSS 장에서 표시와 의미를 나누는 방법을 배운다.

> 📚 **출처 · 본문 설명 확인:** 강조·표시 등 텍스트 의미는 [HTML 표준 — 텍스트 의미](https://html.spec.whatwg.org/multipage/text-level-semantics.html)로 확인했다. 모양만으로 의미를 동일하게 취급하지 않는다.

<a id="space"></a>

### 2.3 문단, 줄바꿈, 주제 구분

| 요소 | 쓰는 상황 | 다른 기능과의 차이 |
| --- | --- | --- |
| `p` | 하나의 문단 | 두 문단은 각각 p로 표현 |
| `br` | 같은 흐름 안에서 필요한 줄바꿈 | 문단 자체를 새로 만드는 것은 아님 |
| `hr` | 내용의 주제 전환 | 가로선 모양만이 목적은 아님 |

```html
<!-- 설명용 새 예제 · body 조각 -->
<p>첫 번째 문단이다.</p>
<p>같은 문단의 첫 줄<br>같은 문단의 다음 줄</p>
<hr>
<p>다른 주제를 시작한다.</p>
```

편집기에서 Enter를 눌렀다고 브라우저에도 같은 줄바꿈이 생기는 것은 아니다. 기본 공백 처리에서는 소스의 연속 공백과 줄바꿈이 합쳐져 표시된다. 다음 글자는 보통 `하나 둘 셋`처럼 한 흐름으로 보인다.

```html
<p>하나     둘
셋</p>
```

이것은 기본 표시의 설명이다. 모든 HTML 문맥과 CSS 설정에서 항상 똑같이 처리한다는 일반화는 피한다.

<a id="pre"></a>

### 2.4 공백을 보존할 때와 태그 글자를 보여 줄 때

`pre`는 미리 형식을 맞춘 텍스트에 사용한다. 소스에 넣은 공백·줄바꿈이 보존될 수 있으므로 들여쓰기도 결과에 영향을 준다. 하지만 **안쪽의 HTML 태그 해석까지 멈추지는 않는다.**

`<br>`라는 글자를 페이지에 보여 주려면 `&lt;br&gt;`처럼 문자 참조를 사용한다. 그 결과는 글자로 된 `<br>`이고 다시 줄바꿈 태그로 실행되는 것이 아니다.

| 표기 | 나타내는 문자·성질 | 이 장에서의 예 |
| --- | --- | --- |
| `&lt;`, `&gt;` | `<`, `>` | 태그 모양을 설명하는 글자 |
| `&amp;` | `&` | 앰퍼샌드 문자 |
| `&copy;` | `©` | 저작권 기호 |
| `&nbsp;` | 줄바꿈되지 않는 공백 | 일반 공백과 다른 처리 |

`&nbsp;` 여러 개를 넣어 페이지 전체를 정렬하려고 하면 내용과 배치가 섞인다. 수업에서는 공백의 성질을 확인하고, 간격을 정교하게 설계하는 일은 CSS로 이어 간다.

> 📚 **출처 · 본문 설명 확인:** pre의 공백 보존과 태그 해석은 [MDN — pre](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/pre), 문단·주제 구분은 [HTML 표준 — 그룹 콘텐츠](https://html.spec.whatwg.org/multipage/grouping-content.html)로 확인했다.

## 3. 작은 예제와 결과

**설명용 새 예제 · 전체 문서.** [02_기본태그_복습.html](실습/02_기본태그_복습.html)의 내용이다. 별도 CSS 없이 연다.

```html
<!DOCTYPE html>
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <title>기본 태그 복습</title>
</head>
<body>
    <h1>HTML 학습 기록</h1>
    <h2>텍스트의 역할</h2>
    <p><strong>중요한 안내</strong>와 <em>힘주어 읽을 말</em>을 구분한다.</p>
    <p><mark>확인할 부분</mark>과 <del>삭제된 내용</del>을 표시한다.</p>
    <p>같은 문단의 첫 줄<br>다음 줄</p>
    <hr>
    <p>하나     둘
셋</p>
    <pre>첫 줄
  두 칸 들여쓴 다음 줄</pre>
    <p>&lt;br&gt; &copy; &amp;</p>
    <p>1&nbsp;&nbsp;&nbsp;2</p>
</body>
</html>
```

**기본 표시 기준 예상 결과:** 제목 아래 문단들이 놓이고, strong·em·mark·del의 의미에 해당하는 기본 표시를 볼 수 있다. `pre`의 두 번째 줄 앞에는 두 칸 공백이 남으며, 그 아래 문단에는 `<br> © &`가 글자로 보인다. 정확한 픽셀 크기·색은 환경에 따라 달라질 수 있다.

**하나만 바꿔 보는 실험:** 마지막에서 두 번째 문단의 `&lt;br&gt;`를 실제 `<br>`로 바꾼다. 그러면 태그 글자가 사라지고 줄바꿈 동작이 생긴다. 문자로 표현한 것과 HTML 문법으로 작성한 것의 차이를 확인한다. 바꾼 뒤에는 원래 상태로 되돌리고 다음 실험을 한다.

## 4. 내 코드 따라 읽기

### 4.1 제목 수준을 끝까지 시험한 구간

**내 코드 · 원본 발췌** — `workspace_html/02_tag.html` 15–21행.

```html
        <h1>h1</h1>
        <h2>h2</h2>
        <h3>h3</h3>
        <h4>h4</h4>
        <h5>h5</h5>
        <h6>h6</h6>
        <h7>h7</h7><br>
```

앞의 여섯 줄은 제목 수준 실험이다. 마지막 `h7`은 글자가 보이더라도 표준 일곱 번째 제목이 된 것은 아니다. 뒤의 `br`은 그 다음 줄을 바꾸려는 별도 요소다. 화면에서 보였다는 사실과 표준 역할을 구별한다.

### 4.2 내 강조 코드와 주석

**내 코드 · 원본 발췌** — 같은 파일 26–29행.

```html
        <strong>굵어서 강조하는 글씨</strong><br>

        <!-- i tag와 동일하게 사용할 수 있지만, i는 시맨틱태그가 아니기에 em을 사용함 -->
        <em>기울여서 강조하는 글씨</em><br>
```

실제로 사용한 `strong`과 `em`은 본문에 포함한다. 다만 주석을 ‘i에는 의미가 없으므로 언제나 em으로 대체’라고 일반화하지 않는다. 기본 모양이 비슷해도 역할이 다를 수 있다. 이 장에서는 배운 두 요소의 중요성과 강세를 먼저 이해한다.

### 4.3 내 pre 안에는 br도 있다

**내 코드 · 원본 발췌** — 같은 파일 57–61행.

```html
        <Pre>1
            2<br>
            3
            4
        </Pre><br>
```

`text/html`로 여는 일반 HTML 문서에서 `<Pre>`는 pre 요소로 해석된다. 표기를 소문자로 맞추면 읽기 일관성에 도움이 되지만, 대소문자를 맞추는 선택과 공백 보존 동작은 다른 질문이다.

안에 있는 `<br>`은 여전히 줄바꿈 요소다. 소스의 실제 줄바꿈까지 같이 있어서 예상보다 빈 줄이 더 생길 수 있다. 코드 전체를 글자로 보여 주려는 목적이라면 `<br>` 자체도 문자 참조로 써야 한다.

이 장의 예제는 함수 import나 외부 파일 없이도 의미를 확인하는 독립 HTML이다. 01장에서 배운 `head`·`body` 골격 안에 **본문 태그를 채운 것**이다. 문서 구조를 새로 배우는 것이 아니라 그 구조 안의 내용 역할을 늘리고 있다.

| 앞뒤 연결 | 이번 장과의 관계 |

## 6. 내 코드 돌아보기

내 원본에는 태그별 실험과 공백·문자 참조 메모가 많다. 같은 문장 안에서 소스의 공백과 `br`을 비교한 점은 좋다. 다만 보여 주는 예제 글자와 태그 이름이 어긋나거나, 모양을 의미처럼 단정한 주석은 보완하면 복습이 더 명확해진다.

| 확인한 점 | 평가 종류 | 더 좋은 설명·사용 |
| --- | --- | --- |
| h7·사용자 이름 태그를 시험 | 실험 범위 구분 | 표준 제목으로 권장하지 않음 |
| mark를 노란색 고정으로 설명 | 설명 교정 | 문맥상 표시와 기본 모양을 구별 |
| `<del>mark</del>` | 예제 이름의 혼동 | 삭제 의미를 드러내는 내용으로 고치면 읽기 쉬움 |
| pre가 모두 그대로 출력 | 조건 누락 | 공백은 보존하되 태그는 해석 |
| 많은 br 사용 | 수업용 표시 실험 | 완성 문서의 여백 설계는 CSS와 구분 |

**개선 예시 · 원본에 미적용:** 3절처럼 제목 단계와 의미를 드러내는 문장으로 바꾸면 결과를 읽을 때 요소별 목적이 보인다. 새로운 요소를 늘리기보다 배운 요소의 선택 이유를 정확히 쓴다.

## 7. 강사님 코드에서 배울 점

강사님도 h7을 시험했고 pre 안에 br을 썼다. 이 부분은 같은 실행 원리를 설명하므로 긴 원본을 다시 인용하지 않는다. 강사님 코드라고 실험용 부분까지 완성 문서의 권장 양식으로 취급하지 않는 것이 중요하다.

강사님은 del 안에 `del`, 나는 `mark`를 적었다. 이 작은 차이에서는 **실습하려는 기능을 드러내는 예제 이름**을 쓰는 점을 참고할 수 있다. 코드를 복습할 때 태그의 역할과 예제 문구가 서로 맞으면 판단이 쉽다.

## 8. 결과와 확인 방법

| 관찰 | 기본 표시에서 예상할 결과 | 확인할 코드 |
| --- | --- | --- |
| p 안에서 Enter·여러 공백 입력 | 보통 한 흐름의 공백으로 합쳐짐 | 해당 문맥과 별도 CSS 여부 |
| p 안에 br 입력 | 같은 문단 흐름에서 줄바꿈 | br 위치 |
| pre 안의 줄바꿈·들여쓰기 | 공백·줄바꿈이 보존됨 | 소스에 실제로 적은 공백 |
| `&lt;br&gt;` 입력 | `<br>` 글자 | 문자 참조와 실제 태그 구별 |
| h7 입력 | 글자가 보여도 표준 제목 수준 없음 | 표준 요소인지 확인 |

이 개편에서는 새 문서의 요소 구조와 텍스트·문자 참조를 정적으로 확인한다. 모든 브라우저에서 화면의 글꼴·여백까지 재현한 검증은 아니다. 코드의 문자 결과와 화면의 디자인 결과를 나눠 기록한다.

<a id="tips"></a>

## 9. 추가로 알면 좋은 것

<a id="extra-02-1"></a>

> 💡 **TIP · 수업 범위 밖:** 텍스트에 더 구체적인 의미가 필요할 때 약어 `abbr`, 날짜·시간 `time`, 연락 정보 `address`, 인용 `blockquote`·`q`, 코드 `code`·입력 `kbd`를 추가로 공부할 수 있다. 각 요소는 장식만을 위한 선택이 아니며 역할에 맞게 사용한다. [출처: HTML 표준 — 텍스트 의미](https://html.spec.whatwg.org/multipage/text-level-semantics.html).

| 추가 요소 | 어떤 질문을 해결하는가? |
| --- | --- |
| `abbr` | 약어를 어떻게 풀어 설명할까? |
| `time` | 보이는 날짜와 기계가 읽을 날짜를 어떻게 연결할까? |
| `blockquote`·`q` | 인용 범위를 어떻게 표시할까? |
| `code`·`kbd` | 코드와 사용자가 누를 키를 어떻게 구별할까? |

<a id="extra-02-5"></a>

> 💡 **TIP · 수업 범위 밖:** `details`·`summary`의 접기 기능이나 `contenteditable`·`tabindex` 등의 전역 속성은 별도 확장이다. GitHub의 접힌 정답을 썼다고 HTML 수업에서 그 기능을 이미 배웠다고 판정하지 않는다. `contenteditable`은 자동 저장 기능이 아니며 초점 순서도 목적에 맞게 설계해야 한다.

`id`·`title`·`lang` 등 실제로 배운 속성은 관련 본문에서 다룬다. JavaScript의 `dataset`은 사용자가 **배웠다고 확인한 범위**이므로 여기의 추가 학습 분류와 혼동하지 않는다. 강의 자료에서 안 보이는 사용자 정의 요소의 상세 구현도 기본 문제에는 요구하지 않는다.

## 10. 복습과 다음 학습

### 결과 예상 → 이유 설명 → 작은 수정

1. `<p>&lt;h1&gt;</p>`는 제목 요소를 만들까, 태그 모양 글자를 보여 줄까?
2. 왜 pre 안의 `<br>`도 글자가 아닌 태그로 해석될까?
3. 같은 문단 안에서 줄을 바꿀 곳과 새 문단으로 나눌 곳을 골라 3절 예제를 고쳐 본다.

<details>
<summary>풀이</summary>

첫 번째는 `<h1>` 글자를 보여 준다. pre는 공백·줄바꿈을 보존하는 요소이며 HTML 파싱을 중지하는 요소가 아니다. 따라서 실제 태그를 글자로 보여 주려면 문자 참조를 사용한다. 새 문단은 p, 같은 흐름의 줄바꿈은 br로 구분한다.

</details>

| 목적 | 선택 |
| --- | --- |

| 문단 / 같은 문단 안 줄바꿈 | p / br |
| 중요성 / 강세 | strong / em |
| 문맥상 표시 / 삭제 | mark / del |
| 공백·줄바꿈 보존 | pre, 단 태그는 해석됨 |
