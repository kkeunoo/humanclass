- 주제 전환에 `hr`을 적절히 사용한다.
- `strong`, `em`, `b`, `i`의 의미 차이를 구분한다.
- `mark`, `small`, `sub`, `sup`, `del`, `ins`를 목적에 맞게 사용한다.
- HTML에서 공백과 줄바꿈이 처리되는 방식을 이해한다.
- 특수문자를 HTML 엔티티로 표현한다.
- `pre`와 `code`를 이용해 코드와 서식이 있는 텍스트를 작성한다.
- 기본 태그를 조합하여 읽기 쉬운 콘텐츠 구조를 만든다.

# 1. 태그는 모양보다 의미가 중요하다

브라우저는 각 HTML 태그에 기본 스타일을 적용합니다. 예를 들어 `h1`은 크고 굵게, `strong`은 굵게 표시되는 경우가 많습니다. 그러나 태그를 선택하는 기준은 화면 모양이 아니라 콘텐츠의 의미입니다.

```html
<h1>웹 개발 학습 기록</h1>
<p>오늘 학습한 내용을 정리합니다.</p>
<strong>제출 마감은 금요일입니다.</strong>
```

| 태그 | 기본 의미 | 대표 용도 |
| --- | --- | --- |
| `h1`~`h6` | 제목과 하위 제목 | 문서 구조와 목차 구성 |
| `p` | 하나의 문단 | 설명, 소개, 본문 |
| `strong` | 중요성·긴급성·심각성 | 경고, 핵심 안내 |
| `em` | 문맥상 강조 | 특정 단어나 문장의 강조 |

CSS를 사용하면 어떤 태그든 크기와 굵기를 바꿀 수 있습니다. 따라서 큰 글씨가 필요하다는 이유만으로 `h1`을 사용하거나, 굵게 보이게 하려고 항상 `strong`을 사용하는 방식은 피해야 합니다.

# 2. 제목 태그 `h1`~`h6`

HTML은 여섯 단계의 제목을 제공합니다.

```html
<h1>1단계 제목</h1>
<h2>2단계 제목</h2>
<h3>3단계 제목</h3>
<h4>4단계 제목</h4>
<h5>5단계 제목</h5>
<h6>6단계 제목</h6>
```

숫자가 작을수록 상위 단계의 제목입니다. 제목 태그는 글자 크기를 선택하는 도구가 아니라 문서의 계층을 나타냅니다.

## 2.1 올바른 제목 구조

```html
<h1>프론트엔드 학습 노트</h1>

<h2>HTML</h2>
<h3>문서 구조</h3>
<h3>기본 태그</h3>

<h2>CSS</h2>
<h3>선택자</h3>
<h3>박스 모델</h3>
```

구조를 트리로 표현하면 다음과 같습니다.

```text
프론트엔드 학습 노트                h1
├─ HTML                            h2
│  ├─ 문서 구조                    h3
│  └─ 기본 태그                    h3
└─ CSS                             h2
   ├─ 선택자                       h3
   └─ 박스 모델                    h3
```

## 2.2 제목 단계 사용 원칙

- 페이지의 대표 제목은 일반적으로 `h1`을 사용합니다.
- 큰 단원은 `h2`, 그 하위 단원은 `h3`처럼 단계적으로 내려갑니다.
- 글자 크기를 줄이기 위해 제목 단계를 선택하지 않습니다.
- 가능하면 제목 단계를 갑자기 건너뛰지 않습니다.
- 제목처럼 보이는 일반 문장을 `div`나 `p`로만 작성하지 않습니다.

잘못된 예시입니다.

```html
<h1>강의 안내</h1>
<h4>수업 일정</h4>
<p class="title">준비물</p>
```

제목 단계가 `h1`에서 바로 `h4`로 이동하고, 제목 역할의 내용을 `p`로 작성했습니다.

수정하면 다음과 같습니다.

```html
<h1>강의 안내</h1>
<h2>수업 일정</h2>
<h2>준비물</h2>
```

## 2.3 `h1`은 몇 개까지 사용할 수 있는가?

HTML 문법상 한 문서에 여러 개의 `h1`을 작성할 수 있습니다. 다만 일반적인 웹 페이지에서는 페이지의 대표 제목을 명확하게 전달하기 위해 하나의 `h1`을 두고, 나머지 영역을 `h2` 이하로 구성하는 방식이 이해하기 쉽고 관리하기 편합니다.

```html
<main>
  <h1>상품 상세</h1>

  <section>
    <h2>상품 설명</h2>
  </section>

  <section>
    <h2>배송 안내</h2>
  </section>
</main>
```

# 3. 문단 태그 `p`

`p`는 Paragraph의 약자로, 하나의 문단을 나타냅니다.

```html
<p>HTML은 웹 페이지의 구조와 의미를 정의합니다.</p>
<p>CSS는 HTML 요소의 디자인과 배치를 담당합니다.</p>
```

브라우저는 각각의 `p`를 독립된 문단으로 처리하고 기본 여백을 적용합니다.

## 3.1 한 문단에는 하나의 중심 내용

```html
<p>
  HTML은 콘텐츠의 구조를 정의합니다. 제목, 문단, 이미지, 링크 등의
  의미를 태그로 표시하여 브라우저와 사용자에게 전달합니다.
</p>
```

내용이 크게 달라지면 새로운 문단으로 나누는 것이 좋습니다.

```html
<p>HTML은 웹 페이지의 구조를 정의합니다.</p>
<p>CSS는 화면의 디자인과 레이아웃을 담당합니다.</p>
```

## 3.2 소스 코드의 줄바꿈과 브라우저 출력

HTML 소스에서 여러 줄로 작성하더라도 일반 텍스트 내부의 연속된 공백과 줄바꿈은 대부분 하나의 공백으로 합쳐집니다.

```html
<p>
  첫 번째 문장입니다.
  두 번째 문장입니다.
  세 번째 문장입니다.
</p>
```

브라우저에서는 보통 다음과 같이 한 문단 안에서 이어져 표시됩니다.

```text
첫 번째 문장입니다. 두 번째 문장입니다. 세 번째 문장입니다.
```

코드를 보기 좋게 줄바꿈한 것과 화면에서 실제 줄바꿈되는 것은 서로 다릅니다.

## 3.3 `p` 안에 넣으면 안 되는 대표 요소

`p` 요소는 문장과 인라인 성격의 콘텐츠를 담는 데 사용합니다. 제목, 다른 문단, 큰 구조 영역을 `p` 안에 중첩하지 않습니다.

잘못된 예시입니다.

```html
<p>
  소개 문장
  <h2>세부 제목</h2>
</p>
```

수정하면 다음과 같습니다.

```html
<p>소개 문장</p>
<h2>세부 제목</h2>
```

브라우저가 잘못된 구조를 자동으로 보정할 수 있지만, 작성한 코드와 실제 DOM 구조가 달라질 수 있으므로 올바른 중첩을 지켜야 합니다.

# 4. 줄바꿈 태그 `br`

`br`은 Line Break의 약자로, 문단을 새로 만들지 않고 현재 문장 안에서 줄만 바꿀 때 사용합니다.

```html
<p>
  서울특별시 중구 세종대로 110<br>
  대표 전화: 02-0000-0000
</p>
```

주소, 시, 노랫말처럼 줄바꿈 자체에 의미가 있는 콘텐츠에 적합합니다.

## 4.1 `p`와 `br`의 차이

| 구분 | `p` | `br` |
| --- | --- | --- |
| 의미 | 독립된 문단 | 같은 문맥 안의 줄바꿈 |
| 종료 태그 | 필요 | 없음 |
| 기본 여백 | 문단 전후에 적용될 수 있음 | 별도 문단 여백 없음 |
| 대표 용도 | 설명, 본문, 소개 | 주소, 시, 짧은 줄 구분 |

서로 다른 내용을 표현한다면 `br` 여러 개보다 `p`를 사용합니다.

잘못된 예시입니다.

```html
HTML은 구조를 담당합니다.<br><br>
CSS는 디자인을 담당합니다.<br><br>
JavaScript는 동작을 담당합니다.
```

수정하면 다음과 같습니다.

```html
<p>HTML은 구조를 담당합니다.</p>
<p>CSS는 디자인을 담당합니다.</p>
<p>JavaScript는 동작을 담당합니다.</p>
```

## 4.2 여백을 만들기 위한 `br` 사용 금지

화면에 빈 공간을 만들기 위해 `<br><br><br>`을 반복하면 콘텐츠 구조가 불분명해지고 반응형 디자인을 관리하기 어렵습니다. 시각적인 간격은 CSS의 `margin`, `padding`, `gap`으로 처리합니다.

```css
section {
  margin-bottom: 40px;
}
```

# 5. 주제 구분선 `hr`

`hr`은 문서 안에서 주제나 장면의 전환을 나타냅니다. 브라우저에서는 보통 가로선으로 표시됩니다.

```html
<h2>공지사항</h2>
<p>이번 주 수업 일정입니다.</p>

<hr>

<h2>과제 안내</h2>
<p>금요일까지 제출합니다.</p>
```

`hr`은 단순히 선을 그리기 위한 장식 요소가 아닙니다. 콘텐츠 사이에 의미 있는 주제 변화가 있을 때 사용합니다. 순수한 장식 선은 CSS의 `border`를 사용하는 편이 적절합니다.

```css
.section-title {
  border-bottom: 1px solid #ddd;
}
```

# 6. 중요성과 강조

## 6.1 `strong`

`strong`은 내용의 중요성, 긴급성, 심각성을 나타냅니다.

```html
<p><strong>주의:</strong> 제출 후에는 파일을 수정할 수 없습니다.</p>
```

## 6.2 `em`

`em`은 문맥에서 특정 부분을 강조합니다. 읽을 때 억양을 주는 것과 비슷합니다.

```html
<p>이번 과제는 <em>개별 제출</em>입니다.</p>
```

강조 위치에 따라 문장의 의미가 달라질 수 있습니다.

```html
<p><em>제가</em> 파일을 수정했습니다.</p>
<p>제가 <em>파일을</em> 수정했습니다.</p>
<p>제가 파일을 <em>수정했습니다.</em></p>
```

## 6.3 `strong`과 `em`을 함께 사용하기

두 의미가 모두 필요하면 중첩할 수 있습니다.

```html
<p>
  <strong><em>오늘 자정 전까지</em> 반드시 제출하세요.</strong>
</p>
```

과도한 강조는 오히려 핵심을 찾기 어렵게 하므로 정말 필요한 부분에만 사용합니다.

# 7. `b`, `i`와 의미 태그 비교

`b`와 `i`는 각각 굵은 모양과 기울임 모양으로 자주 설명되지만, 현대 HTML에서는 단순 장식뿐 아니라 다른 의미 태그가 적절하지 않은 특정 텍스트를 구분하는 용도로 사용합니다.

| 태그 | 주요 의미 | 예시 |
| --- | --- | --- |
| `strong` | 중요성·긴급성 | 경고, 필수 안내 |
| `em` | 문맥상 강조 | 억양이 필요한 표현 |
| `b` | 주의를 끌지만 중요성을 추가하지 않는 텍스트 | 키워드, 상품명 |
| `i` | 일반 문장과 구분되는 표현 | 용어, 외국어, 생각, 관용 표현 |

```html
<p><b>신상품</b> 목록을 확인하세요.</p>
<p><i lang="en">responsive web design</i>은 반응형 웹 디자인을 뜻합니다.</p>
```

단순히 시각적으로 굵게 또는 기울게 만들고 싶다면 의미 없는 `span`과 CSS를 사용할 수 있습니다.

```html
<p>수업은 <span class="text-bold">오후 2시</span>에 시작합니다.</p>
```

```css
.text-bold {
  font-weight: 700;
}
```

# 8. 추가 텍스트 의미 태그

## 8.1 `mark`

`mark`는 현재 문맥에서 관련성이 높아 강조 표시된 부분을 나타냅니다. 검색 결과의 검색어 표시처럼 사용할 수 있습니다.

```html
<p>검색어 <mark>HTML</mark>이 포함된 결과입니다.</p>
```

중요성을 나타내려면 `strong`, 문맥상 억양을 강조하려면 `em`이 더 적절합니다.

## 8.2 `small`

`small`은 저작권, 법적 고지, 부가 설명처럼 본문보다 중요도가 낮은 보조 정보를 나타냅니다.

```html
<p>월 이용료 19,000원</p>
<small>부가세 포함, 결제 조건에 따라 달라질 수 있습니다.</small>
```

단순히 글자를 작게 보이게 하려는 목적이라면 CSS를 사용합니다.

## 8.3 `sub`와 `sup`

`sub`는 아래 첨자, `sup`는 위 첨자를 나타냅니다.

```html
<p>물의 화학식은 H<sub>2</sub>O입니다.</p>
<p>2<sup>3</sup>은 8입니다.</p>
```

각주 번호에도 `sup`를 사용할 수 있습니다.

```html
<p>HTML은 마크업 언어입니다.<sup>1</sup></p>
```

## 8.4 `del`과 `ins`

`del`은 삭제된 내용, `ins`는 추가된 내용을 나타냅니다.

```html
<p>
  가격: <del>30,000원</del>
  <ins>24,000원</ins>
</p>
```

단순히 취소선이나 밑줄 모양이 필요하다는 이유로 사용하지 않고, 실제 변경 이력을 나타낼 때 사용합니다.

## 8.5 `s`와 `del`의 차이

| 태그 | 의미 |
| --- | --- |
| `s` | 더 이상 정확하지 않거나 유효하지 않은 내용 |
| `del` | 문서에서 삭제된 내용 |

```html
<p><s>오늘만 무료 배송</s></p>
<p><del>회의 시간: 오후 2시</del></p>
<p><ins>회의 시간: 오후 3시</ins></p>
```

# 9. 인용과 출처 표시

## 9.1 짧은 인용 `q`

문장 안에 짧은 인용을 넣을 때 사용합니다.

```html
<p>강사님은 <q>코드는 읽히도록 작성해야 한다</q>고 강조했습니다.</p>
```

브라우저가 인용 부호를 자동으로 표시할 수 있으므로 직접 따옴표를 중복해서 넣지 않습니다.

## 9.2 긴 인용 `blockquote`

하나의 독립된 인용 영역은 `blockquote`로 표현합니다.

```html
<blockquote cite="https://example.com/article">
  <p>좋은 HTML은 콘텐츠의 구조와 의미를 명확하게 전달합니다.</p>
</blockquote>
```

`cite` 속성은 인용 원문의 주소를 나타내지만 화면에 자동으로 표시되지는 않습니다. 사용자에게 출처를 보여주려면 별도의 링크나 출처 텍스트를 작성합니다.

## 9.3 작품명·자료명 `cite`

`cite` 요소는 책, 영화, 논문, 기사 등 창작물이나 자료의 제목을 나타냅니다.

```html
<p><cite>HTML Living Standard</cite> 문서를 참고했습니다.</p>
```

사람 이름을 표시하기 위한 태그는 아닙니다.

# 10. 약어와 정의

## 10.1 약어 `abbr`

약어의 전체 표현을 `title` 속성으로 제공할 수 있습니다.

```html
<p>
  <abbr title="HyperText Markup Language">HTML</abbr>은
  웹 문서의 구조를 정의합니다.
</p>
```

중요한 정보는 `title`에만 의존하지 않고 처음 등장할 때 본문에서도 함께 설명하는 것이 좋습니다.

## 10.2 정의 용어 `dfn`

문서에서 처음 정의하는 용어를 표시할 때 사용합니다.

```html
<p>
  <dfn>시맨틱 마크업</dfn>은 콘텐츠의 의미에 맞는 태그를 사용하는 방식입니다.
</p>
```

# 11. 코드와 키보드 입력 표현

## 11.1 인라인 코드 `code`

문장 안에 태그명, 속성명, 명령어, 변수명처럼 코드 성격의 텍스트를 표시합니다.

```html
<p>이미지는 <code>&lt;img&gt;</code> 태그로 삽입합니다.</p>
```

`code`는 기본적으로 연속된 공백과 줄바꿈을 보존하지 않습니다.

## 11.2 여러 줄 코드 `pre`와 `code`

`pre`는 작성한 공백과 줄바꿈을 그대로 보존합니다. 여러 줄 코드는 일반적으로 `pre` 안에 `code`를 넣습니다.

```html
<pre><code>&lt;h1&gt;HTML 학습&lt;/h1&gt;
&lt;p&gt;기본 태그를 연습합니다.&lt;/p&gt;</code></pre>
```

`pre` 내부의 들여쓰기와 줄바꿈은 그대로 출력되므로 불필요한 앞쪽 공백을 넣지 않도록 주의합니다.

```html
<!-- 불필요한 들여쓰기가 화면에도 보일 수 있음 -->
<pre><code>
    const message = 'hello';
    console.log(message);
</code></pre>
```

다음처럼 코드 내용의 시작 위치를 분명히 작성할 수 있습니다.

```html
<pre><code>const message = 'hello';
console.log(message);</code></pre>
```

## 11.3 키보드 입력 `kbd`

사용자가 입력해야 하는 키나 명령을 나타냅니다.

```html
<p>저장하려면 <kbd>Ctrl</kbd> + <kbd>S</kbd>를 누르세요.</p>
```

## 11.4 프로그램 출력 `samp`

프로그램이나 시스템이 출력한 결과를 나타냅니다.

```html
<p>콘솔에 <samp>Hello, World!</samp>가 출력됩니다.</p>
```

## 11.5 변수 `var`

수식이나 프로그래밍 문맥의 변수를 나타냅니다.

```html
<p>사각형의 넓이는 <var>w</var> × <var>h</var>입니다.</p>
```

# 12. 공백과 특수문자

## 12.1 연속된 공백은 하나로 합쳐진다

```html
<p>HTML      기본      태그</p>
```

일반적인 브라우저 출력에서는 다음과 같이 보입니다.

```text
HTML 기본 태그
```

문장 사이의 간격을 맞추기 위해 스페이스를 여러 번 입력하면 안 됩니다. 배치와 간격은 CSS로 처리합니다.

## 12.2 HTML 엔티티

HTML 문법과 충돌하거나 키보드로 직접 입력하기 어려운 문자는 엔티티로 표현할 수 있습니다.

| 표시 문자 | 엔티티 | 설명 |
| --- | --- | --- |
| `<` | `&lt;` | 작다 기호, 태그 시작 문자 |
| `>` | `&gt;` | 크다 기호, 태그 종료 문자 |
| `&` | `&amp;` | 앰퍼샌드 |
| `"` | `&quot;` | 큰따옴표 |
| `'` | `&apos;` | 작은따옴표 |
| 공백 | `&nbsp;` | 줄바꿈되지 않는 공백 |
| `©` | `&copy;` | 저작권 기호 |

HTML 코드를 글자로 보여주려면 `<`와 `>`를 엔티티로 작성해야 합니다.

```html
<p><code>&lt;h1&gt;</code>은 1단계 제목 태그입니다.</p>
```

## 12.3 `&nbsp;`를 남용하지 않는다

`&nbsp;`는 단어 사이가 줄바꿈으로 분리되지 않아야 할 때 제한적으로 사용합니다.

```html
<p>10&nbsp;km</p>
```

들여쓰기나 레이아웃을 맞추기 위해 여러 번 반복해서 사용하지 않습니다.

```html
<!-- 권장하지 않음 -->
<p>&nbsp;&nbsp;&nbsp;&nbsp;들여쓴 문장</p>
```

시각적 들여쓰기는 CSS로 처리합니다.

```css
.indent {
  padding-left: 2rem;
}
```

# 13. 블록 요소와 인라인 요소의 기본 이해

HTML 요소는 과거부터 화면 배치 특성에 따라 블록 요소와 인라인 요소로 자주 구분해 설명합니다. 실제 레이아웃은 CSS의 `display` 속성으로 바뀔 수 있지만, 기본 동작을 이해하면 태그 중첩과 문서 구조를 파악하기 쉽습니다.

| 구분 | 기본 특징 | 대표 요소 |
| --- | --- | --- |
| 블록 성격 | 새 줄에서 시작하고 가로 영역을 차지 | `h1`~`h6`, `p`, `blockquote`, `pre`, `hr` |
| 인라인 성격 | 문장 흐름 안에서 필요한 만큼 차지 | `strong`, `em`, `b`, `i`, `mark`, `code`, `small` |

```html
<p>
  HTML은 <strong>구조</strong>를 정의하고,
  CSS는 <em>표현</em>을 담당합니다.
</p>
```

`strong`과 `em`은 문단 내부 흐름에 자연스럽게 포함됩니다.

반면 제목이나 문단을 단순 인라인 요소 안에 넣는 방식은 피해야 합니다.

```html
<!-- 잘못된 구조 -->
<strong>
  <h2>중요한 제목</h2>
</strong>
```

다음처럼 제목 내부의 특정 텍스트만 강조하거나, 제목 자체가 이미 중요성을 나타내므로 추가 태그가 필요하지 않은지 판단합니다.

```html
<h2>중요한 제출 안내</h2>
```

# 14. 기본 태그 조합 예제

다음은 기본 태그를 활용한 수업 공지 예제입니다.

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>수업 공지</title>
</head>
<body>
  <main>
    <h1>HTML 수업 공지</h1>

    <p>
      이번 시간에는 제목, 문단, 강조 태그를 학습합니다.
    </p>

    <h2>학습 일정</h2>
    <p>
      수업 날짜: 2026년 7월 28일<br>
      수업 장소: 3강의실
    </p>

    <h2>준비 사항</h2>
    <p>
      <strong>수업 시작 전까지</strong>
      실습 파일을 내려받으세요.
    </p>

    <p>
      에디터에서 <kbd>Ctrl</kbd> + <kbd>S</kbd>를 눌러 저장한 뒤
      브라우저를 새로고침합니다.
    </p>

    <hr>

    <small>공지 내용은 수업 상황에 따라 변경될 수 있습니다.</small>
  </main>
</body>
</html>
```

## 14.1 구조 분석

| 코드 | 역할 |
| --- | --- |
| `h1` | 페이지의 대표 제목 |
| `h2` | 공지 내부의 하위 주제 |
| `p` | 설명과 안내 문단 |
| `br` | 날짜와 장소를 같은 문맥 안에서 줄바꿈 |
| `strong` | 반드시 확인해야 할 중요 내용 |
| `kbd` | 실제 키보드 입력 |
| `hr` | 본문과 보조 안내의 주제 구분 |
| `small` | 중요도가 낮은 부가 고지 |

# 15. 내 코드와 강사님 코드 비교

두 원본은 전체 학습 순서와 대부분의 태그가 같다.

```text
html
→ head·title
→ body
→ h1~h7 실험
→ 사용자 정의 태그
→ strong·em·mark·del
→ p·br
→ 공백·Entity
→ pre
→ hr
```

다만 주석의 상세 수준과 일부 Text·Markup에는 차이가 있다.

## 15.1 문서 제목

### 내 코드

```html
<title>정근욱</title>
```

### 강사님 코드

```html
<title>최민수</title>
```

두 코드는 학습자 이름만 다르고 `<title>`을 `<head>` 안에 배치한 구조는 같다.

## 15.2 복원 메모와 편집기 사용 설명

내 코드에는 다음 복원 메모와 VS Code 편집 방법이 추가되어 있다.

```html
<!-- 0723_HTML_tag(h1/strong/em/mark/del/p)_restore -->
```

```html
<!-- alt + shift를 누른 상태면 아래로 복사할 수 있고
     alt만 누른 상태라면 위치 이동가능 -->
```

강사님 코드에는 해당 메모가 없다.

복원 기록은 개인 작업 이력에는 유용하지만 학습 문서의 HTML 개념과 직접 관련이 없다면 Git Commit이나 별도 작업 기록으로 관리하는 편이 문서 집중도를 높인다.

## 15.3 `<head>` 설명

내 코드는 `<head>`에 들어가는 내용을 더 구체적으로 기록한다.

```html
<!-- head 태그에는 페이지의 정보가 있다
     title, style, link, script 등 메타데이터 -->
```

강사님 코드는 다음처럼 간단히 설명한다.

```html
<!-- head 태그에는 페이지의 정보가 있다 -->
```

내 코드의 방향이 더 구체적이지만 “브라우저가 이해하는 것”이라는 표현만으로는 부족하다. `<head>`에는 문서 제목, 문자 인코딩, Viewport, 외부 Resource 연결처럼 화면 본문이 아닌 문서 Metadata가 들어간다고 설명하는 편이 정확하다.

## 15.4 존재하지 않는 `<h7>`

두 코드 모두 다음 실험을 포함한다.

```html
<h7>h7</h7>
```

HTML이 제공하는 Heading Element는 `<h1>`부터 `<h6>`까지다. `<h7>`은 표준 Heading이 아니며 Browser는 알 수 없는 일반 사용자 정의 요소처럼 처리할 수 있다.

```html
<h6>6단계 제목</h6>
```

제목 단계가 더 필요하다고 `<h7>`을 만드는 것이 아니라 문서 구조를 다시 검토해야 한다.

## 15.5 사용자 정의 태그 이름

### 내 코드

```html
<jeong>
    아무 의미 없는 사용자 태그,
    개인적으로 사용할 수도 있음
</jeong>
```

### 강사님 코드

```html
<choi>아무 의미 없는 사용자 태그</choi>
```

이름만 다르고 목적은 같다. Browser가 모르는 태그도 DOM Element로 만들 수 있지만 일반 HTML에서는 의미와 호환성을 위해 표준 Element를 우선 사용한다.

Web Component의 Custom Element는 반드시 이름에 Hyphen을 포함해야 한다.

```html
<user-card></user-card>
```

단순히 개인 이름으로 `<jeong>`이나 `<choi>`를 만드는 것은 표준 Custom Element 규칙에도 맞지 않는다.

## 15.6 `strong`과 `em`

두 코드 모두 다음 태그를 사용한다.

```html
<strong>굵어서 강조하는 글씨</strong>
<em>기울여서 강조하는 글씨</em>
```

시각적 결과만 설명하면 의미가 빠진다.

```text
strong
→ 중요성·긴급성·심각성

em
→ 문맥상 강조와 억양
```

`b`와 `i`가 무조건 비시맨틱이라 사용할 수 없는 태그라는 설명도 정확하지 않다. 각각 별도의 의미가 있으므로 목적에 맞게 선택한다.

## 15.7 `mark`와 `del` Text

내 코드에는 다음 오타가 있다.

```html
적당히 <del>mark</del>태그 넣기
```

`del` 내부 Text가 `mark`로 작성되어 태그와 설명이 일치하지 않는다.

강사님 코드는 다음처럼 작성한다.

```html
적당히 <del>del</del>태그 넣기
```

의미 있는 예제로 개선하면 다음과 같다.

```html
<p>
    가격:
    <del>30,000원</del>
    24,000원
</p>
```

## 15.8 `<br>` 배치

두 코드 모두 각 Text 뒤에 `<br>`을 반복해 줄을 나눈다.

```html
<strong>중요한 내용</strong><br>
<em>강조할 내용</em><br>
```

각 내용이 독립된 문단이라면 `<p>`로 구분하는 편이 적절하다.

```html
<p><strong>중요한 내용</strong></p>
<p><em>강조할 내용</em></p>
```

`br`은 주소나 시처럼 같은 문맥 안에서 줄바꿈 자체에 의미가 있을 때 사용한다.

## 15.9 공백과 `&nbsp;`

두 코드 모두 연속된 일반 공백이 하나로 축약되는 것을 확인하고 `&nbsp;`를 반복한다.

```html
1   2&nbsp;&nbsp;&nbsp;3
```

학습 실험으로는 의미가 있지만 화면 간격을 맞추는 실무 Layout에는 적합하지 않다. `&nbsp;`는 줄바꿈되지 않아야 하는 단어 묶음에 제한적으로 사용하고, 간격은 CSS로 처리한다.

## 15.10 `<pre>` 표기

내 코드는 다음처럼 대문자가 섞인 Tag를 사용한다.

```html
<Pre>1
    2
    3
</Pre>
```

강사님 코드는 소문자를 사용한다.

```html
<pre>1
    2
    3
</pre>
```

HTML Tag 이름은 HTML 문서에서 대소문자를 엄격히 구분하지 않지만 실무에서는 일관성과 가독성을 위해 소문자로 작성한다.

## 15.11 원본 비교 요약

| 항목 | 내 코드 | 강사님 코드 | 개선 기준 |
| --- | --- | --- | --- |
| 복원 메모 | 있음 | 없음 | 학습 내용과 작업 기록 분리 |
| `<head>` 설명 | 상세 | 간단 | Metadata 역할을 정확히 설명 |
| 사용자 태그 | `<jeong>` | `<choi>` | 표준 Element 우선, Custom Element는 Hyphen 필요 |
| `<h7>` | 사용 | 사용 | Heading은 `h1`~`h6` |
| `del` Text | `mark` 오타 | `del` | 태그 의미와 Content 일치 |
| `<pre>` | `<Pre>` | `<pre>` | Tag 이름 소문자 통일 |
| `<br>` 반복 | 많음 | 많음 | 문단은 `p`, 간격은 CSS |
| `&nbsp;` 반복 | 사용 | 사용 | Layout 용도로 남용 금지 |

# 16. 자주 하는 실수

## 16.1 제목 크기만 보고 태그 선택

```html
<h4>페이지 대표 제목</h4>
```

대표 제목이라면 `h1`을 사용하고 크기는 CSS로 조정합니다.

```html
<h1 class="page-title">페이지 대표 제목</h1>
```

## 16.2 모든 텍스트를 `div`로 작성

```html
<div>공지사항</div>
<div>수업 시간이 변경되었습니다.</div>
```

```html
<h2>공지사항</h2>
<p>수업 시간이 변경되었습니다.</p>
```

## 16.3 여백을 위해 `br` 반복

```html
<p>첫 번째 문단</p>
<br><br><br>
<p>두 번째 문단</p>
```

CSS로 문단 사이의 간격을 조절합니다.

```css
p + p {
  margin-top: 1rem;
}
```

## 16.4 `strong`을 디자인 용도로만 사용

```html
<strong>메뉴 이름</strong>
```

메뉴 이름이 특별히 중요한 것이 아니라 굵게 보이기만 하면 되는 경우 CSS를 사용합니다.

```html
<span class="menu-name">메뉴 이름</span>
```

## 16.5 태그 중첩 순서 오류

잘못된 예시입니다.

```html
<strong><em>중요한 내용</strong></em>
```

나중에 연 태그를 먼저 닫아야 합니다.

```html
<strong><em>중요한 내용</em></strong>
```

## 16.6 코드 예제 안에서 태그가 실행됨

```html
<code><h1>제목</h1></code>
```

이 코드는 `<h1>`을 글자로 보여주는 것이 아니라 실제 제목 요소로 해석될 수 있습니다.

```html
<code>&lt;h1&gt;제목&lt;/h1&gt;</code>
```

여러 줄이라면 다음과 같이 작성합니다.

```html
<pre><code>&lt;h1&gt;제목&lt;/h1&gt;
&lt;p&gt;문단&lt;/p&gt;</code></pre>
```

# 17. 실무 팁

## 17.1 먼저 텍스트 구조를 설계한다

HTML을 작성하기 전에 콘텐츠를 제목과 문단으로 나눠보면 태그 선택이 쉬워집니다.

```text
페이지 제목
├─ 소개 문단
├─ 서비스 특징
│  ├─ 특징 1 설명
│  └─ 특징 2 설명
└─ 이용 안내
   └─ 주의사항
```

이를 HTML로 옮기면 다음과 같습니다.

```html
<h1>서비스 소개</h1>
<p>서비스를 소개하는 문장입니다.</p>

<h2>서비스 특징</h2>
<h3>특징 1</h3>
<p>첫 번째 특징 설명입니다.</p>

<h3>특징 2</h3>
<p>두 번째 특징 설명입니다.</p>

<h2>이용 안내</h2>
<p><strong>주의:</strong> 이용 전에 약관을 확인하세요.</p>
```

## 17.2 브라우저 기본 스타일에 의존하지 않는다

기본 스타일은 브라우저에 따라 조금씩 다를 수 있습니다. HTML에서는 의미 있는 구조를 만들고, 최종 디자인은 CSS로 통일합니다.

## 17.3 강조 태그를 최소한으로 사용한다

한 문단 전체를 굵게 만들면 중요한 부분이 구분되지 않습니다.

```html
<!-- 과도한 강조 -->
<p><strong>이 문단 전체가 모두 굵게 표시됩니다.</strong></p>
```

```html
<!-- 핵심만 강조 -->
<p>제출 전에 <strong>파일명을 반드시 확인</strong>하세요.</p>
```

## 17.4 개발자 도구로 실제 구조를 확인한다

브라우저가 잘못된 HTML 중첩을 자동으로 수정하는 경우가 있습니다. 작성한 소스와 실제 DOM이 다르게 보인다면 개발자 도구의 Elements 패널에서 구조를 확인합니다.

# 19. 정답과 해설

## 문제 1 정답

```html
<h1>웹 개발 학습</h1>
<p>HTML은 웹 페이지의 구조를 정의합니다.</p>
```

대표 제목은 `h1`, 설명 문장은 `p`로 표현합니다.

## 문제 2 정답

```html
<p>제출 마감은 <strong>금요일 오후 6시</strong>입니다.</p>
```

마감 시간은 사용자가 반드시 확인해야 하는 중요한 정보이므로 `strong`이 적절합니다.

## 문제 3 정답

```html
<p>H<sub>2</sub>O</p>
```

화학식의 아래 첨자는 `sub`를 사용합니다.

## 문제 4 정답

```html
<h1>과제 안내</h1>
<p>오늘까지 제출하세요.</p>
```

`div`로도 화면을 구성할 수 있지만, 첫 번째 내용은 대표 제목이고 두 번째 내용은 문단이므로 각각 의미에 맞는 `h1`과 `p`가 적절합니다.

## 문제 5 정답

```html
<p>HTML은 구조를 담당합니다.</p>
<p>CSS는 디자인을 담당합니다.</p>
<p>JavaScript는 동작을 담당합니다.</p>
```

세 문장은 서로 다른 주제의 독립된 설명이므로 `br`로 줄만 바꾸기보다 각각의 문단으로 구분합니다.

## 문제 6 정답

```html
<p><code>&lt;strong&gt;</code></p>
```

태그의 `<`와 `>`를 그대로 작성하면 HTML 문법으로 해석될 수 있으므로 엔티티로 변환합니다.

## 문제 7 정답

```html
<section>
  <h1>수업 일정 변경</h1>
  <p>이번 주 금요일 수업 시간이 변경되었습니다.</p>
  <p>
    변경 전: <del>오후 2시</del><br>
    변경 후: <ins>오후 3시</ins>
  </p>
  <p><strong>출석 시간을 반드시 확인하세요.</strong></p>
</section>
```

변경 이력은 `del`과 `ins`로 표현하고, 서로 연결된 전후 시간은 하나의 문단 안에서 `br`로 나눌 수 있습니다.

## 문제 8 정답

```html
<h1>개발자 노트</h1>
<h2>HTML 학습</h2>
<p>오늘은 기본 태그를 학습합니다.</p>
```

수정 내용은 다음과 같습니다.

- `h1` 다음 하위 제목을 `h2`로 구성했습니다.
- `p` 안에 제목 태그를 넣지 않고 각각 분리했습니다.
- `h2`의 하위 제목을 `h3`으로 구성했습니다.
- 중첩된 태그를 연 순서의 반대로 닫았습니다.
- 여백을 위한 반복 `br`을 제거했습니다.

# 21. 핵심 요약

```text
h1~h6  → 문서 제목의 단계와 계층
p       → 독립된 문단
br      → 같은 문맥 안의 줄바꿈
hr      → 주제 전환
strong  → 중요성·긴급성
em      → 문맥상 강조
b / i   → 중요성을 추가하지 않는 텍스트 구분
mark    → 현재 문맥에서 관련성 있는 표시
small   → 부가 설명과 고지
sub/sup → 아래 첨자와 위 첨자
code    → 코드 성격의 텍스트
pre     → 공백과 줄바꿈 보존
```

> 좋은 HTML은 화면을 꾸미기 전에 콘텐츠의 구조와 의미를 분명하게 만듭니다. 태그를 선택할 때는 “어떻게 보이는가?”보다 “이 내용은 문서에서 어떤 역할을 하는가?”를 먼저 판단하세요.
# V3 브라우저 해석 추적 카드 — 콘텐츠의 의미와 기본 구조

제목, 문단, 강조, 인용, 줄바꿈 태그는 단지 기본 모양이 아니라 콘텐츠 의미를 전달한다. `h1`~`h6`은 글자 크기 선택 도구가 아니라 문서 제목 계층이며 모양은 CSS로 조절한다.

`<strong>`은 중요성, `<em>`은 강조 의미를 제공하지만 `<b>`, `<i>`는 다른 의미를 가진다. Elements와 Accessibility Tree에서 역할·이름을 확인하고 제목 단계를 건너뛴 구조를 점검한다.

**원본 연결:** 내 코드와 강사님 코드의 `workspace_html/02_tag.html`에서 실제 DOM·요청·접근성 차이를 확인한다.
