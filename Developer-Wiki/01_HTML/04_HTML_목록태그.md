# 목록 태그 — 항목의 순서와 소속 관계를 표현하기

[HTML 목차](README.md) · [이전: 링크와 경로](03_HTML_링크와_경로.md) · [다음: 표](05_HTML_테이블.md)

준비물 세 개와 설치 단계 세 개는 모두 줄을 나열한 것처럼 보일 수 있다. 하지만 설치 단계는 순서가 바뀌면 뜻이 달라진다. 이 장은 **항목을 왜 묶는지, 순서가 중요한지, 하위 항목이 어디에 속하는지**를 기준으로 목록을 선택한다.

## 2. 개념부터 이해하기

### 2.1 세 목록을 선택하는 질문

| 구조 | 뜻 | 선택 예 |
| --- | --- | --- |
| `ul` 안의 `li` | 순서가 핵심이 아닌 항목 묶음 | 준비물·관심 과목 |
| `ol` 안의 `li` | 순서가 의미 있는 항목 묶음 | 설치·진행 단계 |
| `dl` 안의 `dt`·`dd` | 이름·용어와 설명의 관계 | 용어 풀이 |

기본 화면에서 ul에 점, ol에 번호가 붙는 것은 구조를 보여 주는 기본 표시다. ‘점을 붙이고 싶다’보다 ‘순서가 바뀌어도 내용의 의미가 같은가’를 먼저 묻는다. 번호가 필요할 때 ol을 거의 쓰지 않는다고 단정한 내 메모는 선택 규칙으로 사용하지 않는다.

```html
<!-- 설명용 새 예제 · body 조각 -->
<ul>
    <li>편집기</li>
    <li>브라우저</li>
</ul>
<ol>
    <li>파일 작성</li>
    <li>저장</li>
    <li>브라우저에서 확인</li>
</ol>
```

각 `li`가 항목 하나다. 링크를 항목에 넣을 수도 있지만, 단순히 ul 바로 밑에 글자나 다른 목록을 아무렇게나 놓는 구조로 쓰지 않는다.

### 2.2 하위 목록은 어느 항목의 아래인가?

`HTML` 아래에 `문서 구조`와 `목록`이 있다면, 하위 ul을 HTML이라는 상위 li **안에** 넣는다. 들여쓰기가 오른쪽으로 보이는 것보다 그 소속 관계가 중요하다.

```text
상위 ul
├── li: HTML
│   └── 하위 ul
│       ├── li: 문서 구조
│       └── li: 목록
└── li: CSS
```

하위 ul을 상위 li 밖에 놓으면 ‘무엇의 하위인가’가 작성한 구조에 드러나지 않는다. 닫기 태그 `</li>`를 어디에 적는지에 따라 소속이 달라진다는 점을 본다.

### 2.3 용어와 설명은 dl로

`dt`는 설명할 이름·용어, `dd`는 그 설명이다. 순서를 번호로 매기는 것이 목적이 아니다. 새 예제에서는 `HTML`이라는 이름과 ‘웹 문서의 구조를 표시’라는 설명을 한 묶음으로 읽는다.

> 📚 **출처 · 본문 설명 확인:** 목록과 설명 목록의 구조는 [HTML 표준 — Grouping content](https://html.spec.whatwg.org/multipage/grouping-content.html)로 확인했다. 기본 사용은 양쪽 원본의 요소를 기준으로 설명한다.

## 3. 작은 예제와 결과

**설명용 새 예제 · 전체 문서.** [04_목록_복습.html](실습/04_목록_복습.html)의 내용이다.

```html
<!DOCTYPE html>
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <title>목록 복습</title>
</head>
<body>
    <h1>학습 계획</h1>
    <h2>준비물</h2>
    <ul>
        <li>편집기</li>
        <li>브라우저</li>
    </ul>
    <h2>실습 순서</h2>
    <ol>
        <li>문서 작성</li>
        <li>저장</li>
        <li>브라우저 확인</li>
    </ol>
    <h2>과목과 주제</h2>
    <ul>
        <li>HTML
            <ul>
                <li>문서 구조</li>
                <li>목록</li>
            </ul>
        </li>
        <li>CSS</li>
    </ul>
    <dl>
        <dt>HTML</dt>
        <dd>웹 문서의 내용과 구조를 표시한다.</dd>
    </dl>
    <ul>
        <li><a href="01_문서구조_복습.html">문서 구조 예제 다시 보기</a></li>
    </ul>
</body>
</html>
```

**기본 표시 기준 예상:** 준비물은 점이 붙은 목록, 실습 순서는 번호 목록으로 보인다. HTML 아래 두 항목은 중첩된 목록으로 표시되고 용어·설명 쌍은 dl 구조로 읽힌다. 모양의 정확한 들여쓰기 크기는 브라우저 설정에 따라 달라질 수 있다.

**하나만 바꾸는 실험:** 준비물의 ul 시작·종료 태그를 ol로 바꿔 본다. 항목 글자는 같아도 순서 목록으로 표현된다. 이 변경이 내용의 목적에 맞는지도 함께 생각한다. 번호가 보였다는 사실만으로 구조 선택이 항상 더 좋다고 판단하지 않는다.

## 4. 내 코드 따라 읽기

### 4.1 내 중첩 목록

**내 코드 · 원본 발췌** — `workspace_html/04_ul.html` 43–52행.

```html
        <ul>
            <li>리스트1</li>
            <!-- ul안에 ul을 추가로 넣고싶다면 li에 넣어야 접근성 위반이 안 됨 -->
            <li>리스트2
                <ul>
                    <li>리스트2-1</li>
                    <li>리스트2-2</li>
                </ul>
            </li>
        </ul>
```

두 번째 상위 항목의 `리스트2` 뒤에 하위 ul을 넣었고, 그 ul을 닫은 다음 상위 li를 닫았다. 따라서 `리스트2-1`과 `리스트2-2`는 리스트2의 하위다. 내 코드는 상위 항목의 이름도 있어 소속 관계를 읽기 쉽다.

주석에 접근성이라는 말이 있어도 이번 비교에서 확인하는 핵심은 **목록의 자식 구조와 항목의 소속**이다. 특정 도구로 전체 접근성을 검사했다는 뜻은 아니다.

### 4.2 내 용어 설명 목록

**내 코드 · 원본 발췌** — 같은 파일 56–59행.

```html
        <dl>
            <dt>dl 태그</dt>
            <dd>용어와 설명을 적는 구조</dd>
        </dl>
```

dt와 dd의 관계는 용어와 설명이다. 강사님 대응 코드와 구조·내용이 같아 중복 인용하지 않는다. 화면에서 설명이 들여써 보인다고 해서 dl을 일반 여백 도구로 사용하지 않는다.

## 5. 다른 파일과 연결하기

새 예제의 마지막 li 안에는 앞 장의 `01_문서구조_복습.html`로 가는 링크가 있다. 두 파일이 같은 실습 폴더에 있으므로 파일명으로 연결한다. 목록이 링크를 실행하는 별도 프로그램이 된 것이 아니라, **목록의 한 항목 안에 링크 요소를 넣은 것**이다.

내 수업 원본에는 다음 CSS도 있다.

**내 코드 · 원본 발췌** — 같은 파일 12–14행.

```css
            #list li {
                display: inline-block;
            }
```

이 선택자는 `id="list"`인 요소 아래 li에 표시 방식을 적용한다. 항목이 가로로 나란히 보일 수 있지만 HTML 태그가 ul에서 ol로 바뀌지는 않는다. 선택자와 inline-block의 상세 동작은 [CSS 목차](../02_CSS/README.md)에서 이어 배운다. 이 장의 새 예제에는 그 CSS를 넣지 않아 목록의 기본 구조를 먼저 확인한다.

## 6. 내 코드 돌아보기

좋은 점은 상위 항목에 이름을 적고 그 안에 하위 항목을 묶어 **무엇이 무엇에 속하는지** 보이게 작성한 것이다. 링크를 li 안에 넣은 것도 항목의 단위가 분명하다.

| 원본의 표현·선택 | 평가 종류 | 보완 |
| --- | --- | --- |
| ol은 거의 사용하지 않는다는 메모 | 설명 보완 | 빈도보다 순서의 의미로 선택 |
| 중첩 ul을 li 안에 넣음 | 구조에 맞는 선택 | 닫기 위치와 상위 이름 확인 |
| 마지막 목록을 CSS로 가로 배치 | 별도 표시 실험 | HTML 의미와 CSS 배치 구별 |
| title 안의 주석처럼 보이는 문자열 | 작성 위치 보완 | 문서 제목 바깥으로 일반 주석 이동 |

**개선 예시 · 원본에 미적용 · head 조각:** 문서 제목은 필요한 글자만 두고 설명은 밖에 쓴다.

```html
<!-- 문서 제목 -->
<title>목록 실습</title>
```

## 7. 강사님 코드에서 배울 점

**내 코드 · 원본 발췌** — 같은 파일 7–10행.

```html
        <title>
            <!-- 주석 -->
            Document
        </title>
```

title 안은 일반 본문의 주석 위치와 다르게 해석된다. `<!-- 주석 -->`이 문서 제목의 텍스트에 포함될 수 있으므로 의도한 제목만 적는 편이 맞다.

**강사님 코드 · 비교에 필요한 발췌** — 대응 파일 7–9행.

```html
    <title>
        Document
    </title>
```

이 부분은 강사님처럼 제목 텍스트만 둔 구성이 더 적절하다. 반대로 중첩 목록의 상위 이름은 내가 `리스트2`라고 적어 관계가 더 명확하다. 한 파일 전체를 어느 쪽이 낫다고 결론 내리지 않고 **개별 선택의 효과**로 비교한다.

> 📚 **출처 · 본문 설명 확인:** title의 내용과 위치는 [HTML 표준 — title](https://html.spec.whatwg.org/multipage/semantics.html#the-title-element)로 확인했다. 이 차이는 원본의 실제 작성 위치와 대조한다.

## 8. 결과와 확인 방법

| 확인할 것 | 확인 방법 | 오해하기 쉬운 부분 |
| --- | --- | --- |
| 순서의 의미 | 항목 순서를 바꿔도 뜻이 유지되는가? | 점·숫자 모양만으로 선택 |
| 하위 목록 | 상위 li 안에 하위 ul이 있는가? | 화면 들여쓰기만 확인 |
| 용어 설명 | dt와 dd 관계를 읽는가? | dl을 여백으로만 사용 |
| 탭 제목 | title에 필요한 텍스트만 있는가? | 모든 위치에서 주석이 숨는다고 가정 |
| 가로 배치 | CSS 적용 전후를 구별하는가? | 표시가 바뀌면 목록 의미도 바뀐다고 생각 |

새 예제의 목록 자식 구조·링크 파일 존재는 정적으로 검사한다. 모든 보조기기와 브라우저의 표시를 실행 검증한 문서는 아니다. 기본 화면의 들여쓰기 크기나 불릿 모양은 고정 출력으로 다루지 않는다.

## 9. 추가로 알면 좋은 것

> 💡 **TIP · 수업 범위 밖:** 목록으로 메뉴를 만들 때의 복잡한 키보드 이동·ARIA 패턴, Grid 배치 등은 별도 확장이다. 목록 태그를 썼다는 이유만으로 그러한 동작이 자동으로 생기지는 않는다. 먼저 항목과 중첩의 의미를 익힌다.

> 🔗 **다음 학습:** class·id 선택자와 display는 CSS 단원으로 연결한다. 이미 수업 원본에 나온 CSS가 있다는 사실과 이 목록 장에서 그 모든 배치 규칙을 설명하는 것은 구별한다.

## 10. 복습과 다음 학습

1. 설치 1→2→3단계를 나열할 때 ul과 ol 중 무엇을 선택할까?
2. 과일 항목 아래 사과·배 목록은 어디에 넣을까?
3. 가로로 보이는 ul을 다시 세로로 바꿨다면 내용 의미도 바뀐 것일까?

<details>
<summary>풀이</summary>

순서가 중요한 설치 단계는 ol이다. 사과·배의 하위 ul은 과일을 담은 li 안에 둔다. 가로·세로 표시는 CSS에 따른 모양 변화일 수 있어 그것만으로 목록 의미가 바뀌지 않는다.

</details>

| 빠른 선택 | 구조 |
| --- | --- |
| 순서 비핵심 | ul → li |
| 순서 핵심 | ol → li |
| 이름·설명 | dl → dt·dd |
| 하위 항목 | 상위 li 안에 하위 목록 |
| 항목의 이동 링크 | li 안에 a |
