## 1. 무엇을 묶는지에 따라 태그가 달라진다

**목록**은 관련된 항목을 한 묶음으로 나타낸다. 다음은 **설명용 재구성**이다. 준비물의 순서는 바꾸어도 뜻이 유지되므로 `ul`, 실습 단계는 순서가 중요하므로 `ol`을 쓴다.

```html
<ul><li>노트</li><li>펜</li></ul>
<ol><li>파일 저장</li><li>브라우저 확인</li></ol>
```

브라우저 기본 화면에는 첫 묶음에 점, 둘째 묶음에 번호가 붙는다. 점·번호의 모양보다 **항목의 관계**가 선택 기준이다. 이제 양쪽 수업 코드의 용어 설명 목록을 확인한다.

| 구성 | 의미 | 어울리는 내용 |
| --- | --- | --- |
| `ul` → `li` | 항목 순서가 핵심이 아닌 목록 | 준비물 |
| `ol` → `li` | 순서가 의미 있는 목록 | 실습 순서 |
| `dl` → `dt`, `dd` | 이름·용어와 설명의 묶음 | 용어 풀이 |

### 강사님 코드 — 원본 발췌

강사님 `workspace_html/04_ul.html` 42~45행

```html
    <dl>
        <dt>dl 태그</dt>
        <dd>용어와 설명을 적는 구조</dd>
    </dl>
```

`dt`의 용어와 `dd`의 설명을 `dl`로 묶었다.

### 내 코드 — 원본 발췌

내 코드 `workspace_html/04_ul.html` 56~59행

```html
        <dl>
            <dt>dl 태그</dt>
            <dd>용어와 설명을 적는 구조</dd>
        </dl>
```

같은 구조와 내용이다. 이 부분은 양쪽 코드가 같은 목적을 달성한다.

### 순서 목록과 비순서 목록 — 설명용 재구성

```html
<h2>준비물</h2>
<ul>
    <li>편집기</li>
    <li>브라우저</li>
</ul>

<h2>실습 순서</h2>
<ol>
    <li>파일 작성</li>
    <li>저장</li>
    <li>브라우저에서 확인</li>
</ol>
```

기본 스타일에서는 `ul`에 불릿, `ol`에 번호가 보인다. 내 주석의 “ol은 거의 사용하지 않는다”를 선택 기준으로 삼지 않는다. **순서에 의미가 있으면 `ol`이 적합하다.**

일반적인 목록 작성에서 보일 항목은 `li` 안에 넣는다. 원본처럼 `li` 안에 링크를 넣으면 링크가 목록의 한 항목이 된다.

## 2. 하위 목록은 해당 `li` 안에 넣는다

### 강사님 코드 — 원본 발췌

강사님 `workspace_html/04_ul.html` 32~40행

```html
    <ul>
        <li>리스트1</li>
        <li>
            <ul>
                <li>리스트2-1</li>
                <li>리스트2-2</li>
            </ul>
        </li>
    </ul>
```

두 번째 `li` 안에 하위 `ul`을 넣었다. 중첩 위치는 맞지만 상위 항목의 이름은 비어 있다.

### 내 코드 — 원본 발췌

내 코드 `workspace_html/04_ul.html` 43~52행

```html
        <ul>
            <li>리스트1</li>
            <!-- ul안에 ul을 추가로 넣고싶다면 li에 넣어야 접근성 위반이 안 됨 -->
            <li>리스트2
                <ul>
                    <li>리스트2-1</li>
                    <li>리스트2-2</li>
                </ul>
            </li>
        </ul>
```

나는 두 번째 상위 항목에 `리스트2`라는 이름을 적었다. **하위 목록이 어떤 항목에 속하는지 읽는 데 내 코드가 더 명확하다.** 주석을 제외하고 아래 구조로 생각하면 된다.

```text
상위 ul
├── li: 리스트1
└── li: 리스트2
    └── 하위 ul
        ├── li: 리스트2-1
        └── li: 리스트2-2
```

중첩은 단순히 화면을 오른쪽으로 밀기 위한 장치가 아니다. 상위 항목과 하위 항목의 관계를 나타낸다. `ul` 바로 아래에 또 `ul`을 놓는 대신, 해당 항목의 `li` 안에 넣는다.

## 3. 내 코드의 다른 실험은 어떻게 읽을까?

### 가로로 보이는 마지막 목록

내 원본에만 다음 CSS가 있다.

내 코드 `workspace_html/04_ul.html` 12~14행

```css
            #list li {
                display: inline-block;
            }
```

`id="list"`인 목록 안의 `li`에 가로로 나란히 놓일 수 있는 표시 방식을 적용했다. 글자 내용 `1`, `2`, `3`이 번호 목록이라는 뜻은 아니다. 태그는 여전히 `ul`이다. 목록 의미는 HTML, 배치 변화는 CSS 관점으로 나누어 복습한다.

여기서 CSS 선택자와 `inline-block`의 모든 규칙을 새 진도로 설명하지 않는다. CSS 과목의 선택자·display 장에서 이어서 다룬다. Grid로 바꾼 완성 예제나 ARIA 설계는 **추가로 알면 좋은 것**이다.

### `title`에 주석을 넣은 차이

#### 강사님 코드 — 원본 발췌

강사님 `workspace_html/04_ul.html` 7~9행

```html
    <title>
        Document
    </title>
```

#### 내 코드 — 원본 발췌

내 코드 `workspace_html/04_ul.html` 7~10행

```html
        <title>
            <!-- 주석 -->
            Document
        </title>
```

강사님은 `title` 안에 필요한 텍스트만 적었다. 내 코드는 그 안에 `<!-- 주석 -->`을 넣어 제목 텍스트에 포함시켰다. 제목을 의도대로 쓰려면 **강사님처럼 주석을 요소 밖에 놓는 구성이 낫다.**

설명용 수정:

```html
<!-- 문서 제목 -->
<title>목록 실습</title>
```

이 블록은 전체 문서가 아니라 `head` 안에 넣을 조각이다. 주석처럼 보이는 문자열이 모든 위치에서 주석으로 처리되는 것은 아니다.

## 4. 복습

1. 설치 순서 1→2→3이 중요하다. `ul`과 `ol` 중 무엇을 쓸까?
2. `과일` 항목 아래 `사과`와 `배`를 묶는다면 하위 `ul`은 어디에 넣을까?
3. `ul`의 `li`를 CSS로 가로 배치하면 HTML도 `ol`로 바뀔까?

<details>
<summary>정답과 예제</summary>

1. `ol`을 쓴다.
2. `과일`을 담은 `li` 안에 넣는다. 아래는 설명용 예제다.

```html
<ul>
    <li>과일
        <ul>
            <li>사과</li>
            <li>배</li>
        </ul>
    </li>
</ul>
```

3. 바뀌지 않는다. 표시 방식과 문서 구조는 다르다.

</details>

**다시 볼 핵심:** 무엇을 묶는지 → 순서가 중요한지 → 하위 목록이 어느 항목에 속하는지 순서로 결정한다.

## 💡 추가로 알면 좋은 것

> [!TIP]
> 목록을 가로로 배치하는 더 복잡한 CSS 설계나 키보드 이동을 고려한 ARIA 메뉴 패턴은 이 HTML 목록 수업의 필수 내용이 아니다. 우선 원본의 `ul`·`ol`·`dl`과 `li`의 관계를 설명할 수 있으면 된다.

정확성 참고: [HTML 표준 — 목록과 설명 목록](https://html.spec.whatwg.org/dev/grouping-content.html).
