# 추가로 알면 좋은 것 — 확장 요소와 속성

[HTML 목차](../README.md) · [시맨틱 구조](01_시맨틱_페이지_구조.md)

기존 Wiki·BACKUP에서 기본 설명에 섞여 있던 확장 기능을 모았다. 이 목록이 모두 실제 수업 내용이라는 뜻은 아니다. **기본편 문제의 풀이에 이 기능들을 요구하지 않는다.** 각 예제는 원본 발췌가 아닌 추가 학습용 조각이다.

<a id="text"></a>

## 1. 텍스트에 의미를 더 붙이기

| 요소 | 알아둘 역할 | 사용 예·주의 |
| --- | --- | --- |
| `abbr` | 약어 | 풀어 쓴 설명을 title 등으로 보완할 수 있음 |
| `time` | 날짜·시간 | 사람이 읽는 글과 기계가 읽는 datetime 구분 |
| `address` | 관련 문서·글의 연락 정보 | 모든 지명·일반 주소를 감싸는 태그는 아님 |
| `blockquote` / `q` | 인용 구역 / 문장 안 인용 | 들여쓰기 장식만을 위한 선택은 아님 |
| `code` / `kbd` | 코드 / 사용자 입력 | 의미와 기본 글꼴 모양을 구분 |

```html
<p><abbr title="HyperText Markup Language">HTML</abbr>을 공부한다.</p>
<p>작성일: <time datetime="2026-09-18">2026년 9월 18일</time></p>
<p><kbd>Enter</kbd>를 눌러 입력한다.</p>
```

약어의 풀이는 꼭 필요한 경우 보이는 문장으로도 제공한다. `title`에 넣었다고 모든 입력 환경에서 동일하게 확인할 수 있는 것은 아니다. [HTML 표준 — 텍스트 의미](https://html.spec.whatwg.org/dev/text-level-semantics.html)

<a id="media"></a>

## 2. 이미지·미디어를 확장하기

| 기능 | 기본편과 다른 점 | 실행 전제 |
| --- | --- | --- |
| `figure` / `figcaption` | 이미지·도표 등에 설명을 묶음 | 이미지마다 무조건 감쌀 필요는 없음 |
| `srcset` / `sizes` | 여러 이미지 후보와 표시 크기 정보를 제공 | 실제 후보 파일이 필요하며 선택은 브라우저가 판단 |
| `picture` / `source` | 조건·형식에 따른 이미지 후보 구성 | 최종 img와 대체 텍스트도 필요 |
| `loading="lazy"` | 로딩 시점을 지연하도록 힌트 제공 | 즉시 보여야 할 이미지에 무조건 적용하지 않음 |
| `audio` | 소리 재생 | 지원되는 실제 음원 필요 |
| `track` | 미디어 자막 등 텍스트 트랙 | 실제 자막 파일과 언어 정보 필요 |
| `iframe` | 다른 문서를 안에 삽입 | 대상의 삽입 허용과 필요한 권한을 확인 |

```html
<figure>
    <img src="lesson.png" alt="리스트 변수 두 개가 같은 객체를 가리키는 그림">
    <figcaption>두 이름이 같은 리스트를 참조하는 관계</figcaption>
</figure>
```

이 조각을 실행하려면 같은 폴더에 `lesson.png`가 있어야 한다. `alt`는 이미지 대체 설명, `figcaption`은 보이는 캡션이므로 반드시 같은 문장을 두 번 적어야 하는 것은 아니다. [HTML 표준 — 이미지](https://html.spec.whatwg.org/dev/embedded-content.html), [figure](https://html.spec.whatwg.org/dev/grouping-content.html#the-figure-element)

원본의 주석 처리된 YouTube iframe에서 여러 권한 속성을 보았다는 사실만으로 그 권한들의 세부 사용을 배웠다고 판단하지 않는다. 이 개편본은 외부 임베드·음원·자막을 자동으로 불러오는 확장 프로젝트를 기본 실습에 넣지 않는다.

<a id="forms"></a>

## 3. 폼의 묶음과 추가 검증

```html
<form method="get">
    <fieldset>
        <legend>알림 신청</legend>
        <label for="email">이메일</label>
        <input id="email" name="email" type="email" required>
    </fieldset>
    <button type="submit">입력 확인</button>
</form>
```

`fieldset`은 관련 입력을 묶고 `legend`는 그 묶음의 제목이다. `type="email"`과 `required`는 브라우저의 형식·필수 입력 검증에 관여한다. 위 기능은 이번 HTML 원본의 기본 실습 범위를 넘어간다. 서버 저장 기능이나 모든 상황의 유효성 검증을 완성한 예제는 아니다. [HTML 표준 — 폼](https://html.spec.whatwg.org/dev/forms.html)

그 밖의 `pattern`, `minlength`, `maxlength`, `autocomplete`, 파일 업로드용 `enctype` 등의 상세 설계는 필요한 시점에 별도로 학습한다. 반면 **color·date·time·number·range는 실제 양쪽 원본에 있어 기본편에 남겼다.**

<a id="table"></a>

## 4. 복잡한 표를 더 명확하게 만들기

기본편의 `caption`·`th`·병합에서 출발해, 제목 셀의 범위를 `scope`로 나타내거나 복잡한 관계를 `headers`·`id`로 연결할 수 있다. 다음은 단순한 열 제목 예제다.

```html
<table>
    <caption>학습 시간</caption>
    <tr><th scope="col">과목</th><th scope="col">시간</th></tr>
    <tr><td>HTML</td><td>2시간</td></tr>
</table>
```

`scope`는 테두리·정렬을 바꾸기 위한 속성이 아니다. `colgroup` 등 열 묶음과 복잡한 표 접근성 설계도 기본 병합 문제와 구분한다. [HTML 표준 — 표](https://html.spec.whatwg.org/dev/tables.html)

## 5. 전역 속성·링크·접기 기능

| 기존 문서의 확장 주제 | 읽을 때 구분할 점 |
| --- | --- |
| `tabindex` | 키보드 초점 순서에 영향. 큰 양수로 순서를 강제하는 설계를 쉽게 권장하지 않음 |
| `contenteditable` | 화면 내용을 편집 가능하게 함. 자동 저장 기능은 아님 |
| `draggable` | 드래그 설정. 완성된 이동·드롭 기능은 추가 처리가 필요 |
| `spellcheck`, `translate`, `dir` | 맞춤법·번역 힌트·글자 방향 등 각각의 목적을 확인 |
| `download` | 링크의 다운로드 의도. 출처·응답 조건에 따라 동작 제약이 있음 |
| `rel`의 링크 관계·보안 설정 | 새 창 대상과 opener·리퍼러 정책 등 필요한 범위를 따로 검토 |
| `details` / `summary` | 접을 수 있는 내용과 그 제목. 표 요약용 summary와 혼동하지 않음 |

`id`·`title`·`lang`·`hidden`은 이미 수업 원본에서 실제로 확인한 범위만 기본 장에 설명했다. `class`·`style`은 CSS 과목과 연결한다. **`data-*`와 JavaScript의 `dataset`은 사용자가 학습했다고 확인했으므로 JS 이벤트 장의 메인으로 다룬다.** 여기에 이름이 나온다는 이유로 JS의 학습 확인을 취소하지 않는다.

접기 기능의 작은 예제:

```html
<details>
    <summary>실행 전제 보기</summary>
    <p>이미지 파일을 같은 폴더에 준비한다.</p>
</details>
```

GitHub 문서의 접힌 정답도 이 형식을 이용하지만, 편집용 기능을 썼다는 이유로 HTML 수업에서 이미 배웠다고 분류하지 않는다. [HTML 표준 — details와 summary](https://html.spec.whatwg.org/dev/interactive-elements.html)
