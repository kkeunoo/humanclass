# HTML 동작 백과 읽기법

> 태그 이름을 외우는 대신, 브라우저가 HTML 문서를 받아 구조로 해석하고 링크·이미지·폼·접근성 기능으로 동작시키는 과정을 다시 설명하고 재현하기 위한 공통 안내서다.

## 1. HTML 파일이 화면이 되는 흐름

```text
주소 입력 또는 파일 열기
→ 브라우저가 HTML 문서 수신
→ 문자 인코딩에 따라 텍스트 해석
→ 시작·종료 태그와 속성을 순서대로 파싱
→ 부모·자식 관계의 DOM 생성
→ CSS와 연결해 layout·paint
→ JavaScript와 사용자 동작으로 DOM·상태 변경
```

HTML은 화면 모양을 세밀하게 꾸미는 언어가 아니라 콘텐츠의 구조와 의미를 표현하는 마크업 언어다. 브라우저는 일부 잘못된 마크업도 자동 보정하지만, 보이는 화면이 그럴듯하다고 구조가 올바른 것은 아니다. Elements 패널의 실제 DOM과 Validator 결과를 함께 확인한다.

## 2. 요소를 읽는 법

```html
<a href="detail.html" class="button">상세 보기</a>
```

- `a`: 요소의 의미와 기본 동작을 정하는 태그 이름이다.
- `href`: 이동할 주소를 브라우저에 제공하는 속성이다.
- `class`: CSS와 JavaScript가 요소를 찾을 수 있는 분류 이름이다.
- `상세 보기`: 사용자와 보조 기술이 링크 목적을 이해하는 텍스트다.
- 시작 태그부터 종료 태그까지가 하나의 요소이며 DOM에서는 노드가 된다.

## 3. 값은 어디로 전달되는가

| 사용자 동작 | HTML이 제공하는 값 | 브라우저 동작 |
|---|---|---|
| 링크 클릭 | `href`, `target` | URL을 해석해 새 문서를 요청하거나 위치 이동 |
| 이미지 표시 | `src`, `srcset` | 이미지 자원을 별도로 요청하고 대체 텍스트 제공 |
| 폼 제출 | `action`, `method`, 성공한 컨트롤의 name/value | 데이터를 인코딩해 서버로 요청 |
| 파일 선택 | input의 File 객체 | 사용자가 선택한 파일 정보를 브라우저가 보관 |
| 버튼 클릭 | type에 따른 의미 | submit, reset 또는 일반 버튼 동작 |

폼에서 서버로 전송되는 핵심 이름은 `id`가 아니라 `name`이다. `label for`와 input `id`는 화면의 설명과 입력 요소를 연결한다.

## 4. 경로를 읽는 기준

- 상대 경로는 현재 문서 URL을 기준으로 계산한다.
- `./`는 현재 폴더, `../`는 상위 폴더다.
- `/path`는 현재 사이트의 루트 기준이다.
- `https://...`는 스킴과 호스트를 포함한 절대 URL이다.
- Windows 탐색기 경로와 브라우저 URL 경로를 혼동하지 않는다.

Network 패널에서 브라우저가 실제 요청한 최종 URL과 200/404 상태를 확인한다.

## 5. 개발자 도구 확인 순서

1. Elements에서 브라우저가 만든 실제 부모·자식 구조를 확인한다.
2. 잘못 중첩된 태그가 자동으로 이동·종료되었는지 본다.
3. Console에서 DOM·접근성 관련 오류를 확인한다.
4. Network에서 HTML, 이미지, CSS, JavaScript 요청 URL과 상태를 본다.
5. Accessibility Tree에서 역할, 이름, 상태가 의도대로 전달되는지 확인한다.
6. 키보드 Tab, Enter, Space만으로 주요 기능을 사용할 수 있는지 시험한다.

## 6. 원본 비교 규칙

- 내 코드는 `workspace_html`의 `01_hello.html`부터 `07_form.html`까지를 기준으로 한다.
- 강사님 코드는 같은 번호의 강사님 workspace 원본을 기준으로 한다.
- 결과 화면뿐 아니라 DOM 구조, 요청 URL, 폼 전송 데이터, 접근 가능한 이름을 비교한다.
- 원본에 없는 시맨틱·실무 확장은 `Wiki 확장 학습`으로 구분한다.

## 7. 다시 사용할 수 있는지 확인하는 질문

1. 이 요소가 표현하는 의미는 무엇인가?
2. 누구의 자식이며 중첩 규칙이 올바른가?
3. 속성값은 브라우저의 어느 기능에 전달되는가?
4. 클릭·제출 때 어떤 URL과 데이터가 만들어지는가?
5. 화면이 없어도 구조와 목적을 이해할 수 있는가?
6. Elements·Network·Accessibility에서 무엇을 확인하는가?
7. 내 코드와 강사님 코드의 어느 파일에서 다시 볼 수 있는가?


## 이번 판의 읽기 기준

HTML은 기존 10개 주제 파일을 유지합니다. 문서 안에서는 목차로 이동하고, 소스 발췌→해석→화면·DOM·요청 결과→오류 진단을 연결합니다. 학습자의 이해를 돕는 반복과 연습은 보존합니다.

수업에서 직접 확인한 번호형 원본은 사용자와 강사님의 01_hello, 02_tag, 03_상대주소/03_a, 04_ul, 05_table, 06_img, 07_form입니다. 08~10의 시맨틱 설계·실무 기준·통합 프로젝트는 해당 번호형 원본 전체를 그대로 옮긴 수업이 아니라 확장 학습이 포함된 문서입니다. 💡 표시와 본문 설명으로 그 경계를 밝힙니다.

## 결과를 세 층으로 나누기

| 확인 층 | 무엇을 보는가? | 대표 질문 |
| --- | --- | --- |
| 소스 | 작성한 태그·속성·주석 | 오타가 있는가? |
| DOM과 화면 | 파싱된 객체와 실제 배치 | 보정·숨김·기본 스타일이 적용됐는가? |
| 요청과 응답 | URL·method·전송 항목·응답 | 자원과 서버 기능이 있는가? |

소스가 맞아도 파일이 없으면 이미지가 실패합니다. 화면에 입력값이 있어도 name이 없으면 전송 항목이 빠집니다. 요청이 만들어져도 서버가 처리하지 않으면 저장이 완료되지 않습니다. 이 차이를 스스로 설명하는 것이 학습 목표입니다.
