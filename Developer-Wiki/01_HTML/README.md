# HTML Developer-Wiki

태그 이름만 기억하는 요약집이 아니라, 잊었을 때 수업 코드와 동작을 다시 이해하고 사용할 수 있는 개인 강의 백과사전입니다.

## 학습 목표

- 요소와 속성의 의미를 구분한다.
- 화면·DOM·HTTP 요청 결과를 추적한다.
- 원본을 비교하고 오류를 수정한다.

## 이번 리팩토링의 핵심

기존 상세 설명·예제·비교·실습·정답을 보존하면서 실제 동작 설명을 다시 보강했습니다.

- 문서 수신과 파싱, DOM·화면의 구분
- 현재 URL과 href로 목적지를 계산하는 과정
- 표 병합의 격자 점유와 caption·summary의 차이
- 이미지 URL 계산→자원 수신→해석→표시와 실패 진단
- 입력→전송 항목 구성→GET/POST 요청→서버 응답의 흐름
- readonly의 전송 조건, name 없는 칸, 체크박스 기본값 등 실제 소스 차이
- 브라우저 Console에서 값을 읽는 확인 명령과 예상 결과

[검토 기록](./REFACTOR_REVIEW.md)에는 발견한 문제, 수정 판단, 보존 검사와 검증 한계를 기록했습니다.

## 수업과 확장 학습 구분

01~07은 사용자·강사님의 번호형 HTML 원본을 직접 비교합니다. 08~10에는 시맨틱 페이지 설계·실무 기준·통합 프로젝트 등의 확장 학습이 포함됩니다. 원본에서 같은 완성 프로젝트를 작성했다고 꾸미지 않습니다. 💡와 설명으로 보충 지식을 구분합니다.

## 반복해서 공부하는 방법

1. 먼저 의미를 읽고 작은 예제의 화면 결과를 예상합니다.
2. 원본과 개선 예제를 비교하며 다른 이유를 설명합니다.
3. 실제 파일을 열고 Elements·Console·Network에서 확인합니다.
4. 기초 실습부터 응용으로 확장하고 정답을 나중에 확인합니다.
5. 실패했을 때 화면·DOM·요청 중 어느 단계의 문제인지 좁힙니다.

문서 내 목차로 같은 파일 안에서 이동합니다. 학습 이해에 필요한 반복은 줄이지 않습니다. 큰 통합 코드는 마지막 대조 자료로 사용하고 처음부터 복사해 실행하는 것만으로 학습을 끝내지 않습니다.

## 실습 전 확인

로컬 이미지·동영상·다운로드 파일과 서버 기능은 예제의 전제입니다. 파일이 없으면 경로를 맞추거나 직접 준비합니다. 외부 서비스는 제공자 상태에 따라 달라집니다. 정적 서버에서 폼을 전송했다고 데이터가 저장되는 것은 아닙니다.
