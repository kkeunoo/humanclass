# 08. 시맨틱 페이지 구조 — 추가로 알면 좋은 것

이 문서는 **수업 원본에서 확인되지 않은 선택 학습**이다. 제목·목록·표·폼의 기본 의미는 앞선 장에서 먼저 익히고, 페이지 전체에 영역 이름을 붙이는 방법이 궁금할 때 읽는다. 아래의 예제는 강사님·내 실제 코드가 아니라 새로 만든 설명용 코드다.

- [기본 종합복습](10_HTML_종합실습.md)

원본에 있던 제목·목록·표·폼의 의미 설명은 각 기본 장에 있다. 이 문서에서는 그 태그를 이해했다는 전제에서 페이지 영역만 추가로 다룬다.

## 추가로 알면 좋은 것

> [!TIP]
> 이하의 내용은 **수업 원본에서 확인된 필수 진도가 아닌 추가 학습**이다. `header`·`nav`·`main` 등을 당장 모두 외울 필요는 없다. 먼저 “이 부분의 역할이 무엇인가?”를 설명할 수 있는지 확인하자.

<a id="extra-01-1"></a>

### 먼저 생각할 질문

페이지에 제목, 메뉴, 본문, 관련 안내가 있다. 모두 `div`로 감쌀 수 있지만, 각 영역의 역할을 드러내면 문서를 읽고 유지하기 쉽다. 이것을 공부할 때는 태그를 많이 넣는 것보다 **이 묶음이 어떤 역할인지**를 설명할 수 있어야 한다.

<a id="extra-01-2"></a>

### 1. 자주 만나는 영역

| 요소 | 사용할 때의 질문 | 주의할 점 |
| --- | --- | --- |
| `header` | 해당 페이지·구역을 소개하는가? | 화면 맨 위에만 쓸 수 있는 태그는 아님 |
| `nav` | 주요 탐색 링크를 묶는가? | 모든 링크 묶음을 무조건 nav로 만들지 않음 |
| `main` | 이 페이지의 중심 내용인가? | 보이는 중심 영역을 하나로 명확히 구성 |
| `section` | 하나의 주제로 묶을 수 있는가? | 보통 그 주제를 보여 주는 제목과 함께 생각 |
| `article` | 따로 떼어도 독립적인 글·항목인가? | 모든 네모 상자를 article로 만들지 않음 |
| `aside` | 주된 흐름과 구별되는 관련 정보인가? | 옆에 배치했다는 이유만으로 선택하지 않음 |
| `footer` | 해당 페이지·구역의 마무리 정보인가? | 페이지 아래쪽만 뜻하는 것은 아님 |
| `div` | 특별한 의미 없이 묶을 필요가 있는가? | div 자체가 잘못된 요소는 아님 |

요소의 의미와 화면 배치는 다르다. `aside`를 넣어도 CSS 없이 자동으로 오른쪽에 놓이는 것은 아니다. 영역의 구체적인 정의는 [HTML 표준의 섹션 요소](https://html.spec.whatwg.org/dev/sections.html)를 참고한다.

<a id="extra-01-3"></a>

### 2. 작은 페이지 골격 — 추가 학습용 재구성

아래는 수업 원본 발췌가 아니다. 외부 파일과 CSS 없이 저장해 구조를 확인할 수 있다.

```html
<!DOCTYPE html>
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <title>학습 기록</title>
</head>
<body>
    <header>
        <h1>학습 기록</h1>
        <nav aria-label="주요 메뉴">
            <a href="#today">오늘 배운 내용</a>
            <a href="#review">복습</a>
        </nav>
    </header>
    <main>
        <section id="today">
            <h2>오늘 배운 내용</h2>
            <article>
                <h3>폼의 name과 value</h3>
                <p>화면의 글자와 전송되는 값을 구분했다.</p>
            </article>
        </section>
        <section id="review">
            <h2>복습</h2>
            <p>체크박스의 선택과 제출 값을 다시 확인한다.</p>
        </section>
    </main>
    <aside>
        <h2>관련 공부</h2>
        <p>다음에는 CSS로 배치를 정리한다.</p>
    </aside>
    <footer>
        <p>나의 공부 기록</p>
    </footer>
</body>
</html>
```

페이지 소개 → 중심 내용 → 관련 안내 → 마무리라는 역할이 태그에 드러난다. 제목 수준은 `h1` → `h2` → `h3`로 연결했다. `section`을 만들었다는 이유만으로 그 안의 모든 제목을 `h1`로 다시 시작하지 않는다.

<a id="extra-01-4"></a>

### 3. 랜드마크와 이름은 필요한 만큼만

보조 기술에서 주요 영역을 찾아가는 단서가 되는 역할을 흔히 **랜드마크**라고 부른다. 의미 있는 HTML 요소를 먼저 고르고, 구별이 필요할 때 이름을 보완한다.

위의 `aria-label="주요 메뉴"`는 탐색 영역의 이름을 추가한다. 페이지에 탐색 영역이 여러 개라면 이름이 구분에 도움이 될 수 있다. 모든 요소에 ARIA 속성을 붙이는 것이 목적은 아니다. 보이는 제목을 참조해 이름을 연결하는 `aria-labelledby`도 있지만, 해당 `id`가 실제로 존재해야 한다.

기본 폼의 `label`과 `id`만으로 가능한 연결을 굳이 ARIA로 바꾸지 않는다. 기본편은 실제 수업에서 사용한 연결법으로 읽고, ARIA의 이름·역할·상태 조합과 스크린 리더 검수는 추가 학습으로 남긴다.

<a id="extra-01-5"></a>

### 4. 기존 페이지 유형 예제를 한 기준으로 읽기

| 기존 Wiki에 있던 페이지 유형 | 새로 판단할 핵심 |
| --- | --- |
| 블로그·뉴스 목록 | 각 글을 독립 항목으로 볼 수 있는지 |
| 랜딩 페이지·포트폴리오 | 주제별 구역과 제목이 자연스럽게 이어지는지 |
| 관리자 화면 | 주요 탐색과 실제 작업 영역이 구별되는지 |
| 관련 링크·하단 메뉴 | 중요한 탐색인지, 단순한 보충 링크인지 |

비슷한 완성 코드를 다섯 번 외우기보다 같은 판단 기준을 다른 콘텐츠에 적용한다. 스타일을 위한 모든 묶음을 `section`으로 바꾸거나, 제목 없는 영역을 무작정 늘리지 않는다.

<a id="extra-01-6"></a>

### 선택 복습

1. 오른쪽에 놓인 상자는 항상 `aside`인가?
2. 카드 모양이라는 이유만으로 모두 `article`인가?

<details>
<summary>생각해 볼 답</summary>

둘 다 아니다. 배치와 외형보다 내용의 역할을 먼저 본다. 관련 보조 정보인지, 독립적으로 읽을 항목인지 설명한 뒤 선택한다.

</details>
