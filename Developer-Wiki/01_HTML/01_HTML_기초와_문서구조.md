# 01. HTML 기초와 문서 구조

[HTML 읽기 안내](README.md) · [다음: 기본 태그](02_HTML_기본태그.md)

HTML은 웹 문서의 **내용과 구조를 표시하는 언어**다. 이번 장에서는 수업의 `hello world`가 어떤 과정을 거쳐 제목으로 보이는지, 문서 정보와 화면 내용은 어디에 적는지 알아본다.

처음에는 HTML을 **화면의 모양을 정하는 명령어 목록**처럼 읽기 쉽다. 그러나 아래의 `h1`은 “큰 글씨로 만들라”는 요청보다 “이 글은 제목이다”라는 구조를 표시한다. 브라우저가 기본 모양을 붙여 보여 주고, 모양을 세밀하게 바꾸는 일은 뒤의 CSS에서 다룬다.

이 장을 읽을 때는 **① 코드에서 내용을 찾고 → ② 감싼 태그를 읽고 → ③ 브라우저에서 어디에 나타나는지 확인**한다. 첫 두 줄로 연습한 뒤 완전한 문서 구조로 넘어간다.

## 이번 장의 범위

- 메인: 태그·요소·속성·주석, `html`·`head`·`body`·`title`, 원본의 문서 선언과 메타 정보.
- 추가로 알면 좋은 것: 브라우저 렌더링 엔진의 내부 단계, 접근성 트리 분석. 기본 예제의 선행 조건으로 다루지 않는다.

## 1. 첫 두 줄로 내용과 구조 구분

`hello world`라는 **내용은 같아도** 태그를 붙이면 문서에서 맡는 역할이 달라진다. 아래 두 줄을 브라우저에서 확인할 때 “얼마나 크게 보이는가?”뿐 아니라 “어느 줄이 제목인가?”를 답해 보자.

### 강사님 코드 — 원본 발췌

강사님 `workspace_html/01_hello.html` 1~2행

```html
hello world
<h1>hello world</h1>
```

첫 줄은 일반 텍스트다. 두 번째 줄은 같은 글자를 `h1` 요소로 표시한다. 브라우저의 기본 스타일에서는 제목이 더 크고 굵게 보인다. 역할이 제목이라는 점이 핵심이다.

### 내 코드 — 원본 발췌

내 코드 `workspace_html/01_hello.html` 1~2행

```html
hello world
<h1>hello world</h1>
```

두 코드는 동일하다. 어느 쪽을 개선 코드라고 구분할 필요가 없다. 두 줄 모두 `hello world`이지만, 두 번째는 문서의 제목 구조에 참여한다.

### 어디서 결과를 확인하나?

텍스트 편집기에서 파일을 `.html` 확장자로 저장하고 브라우저로 연다. 편집한 뒤 저장하고 브라우저를 새로고침한다. GitHub의 Markdown 코드블록은 **코드를 보여 주는 자리**이며, 그 안의 HTML을 웹페이지처럼 실행하지 않는다.

## 2. 태그와 속성 읽기

양쪽 `01_hello.html`에 있는 다음 한 줄을 살펴보자.

### 강사님 코드 — 원본 발췌

강사님 `workspace_html/01_hello.html` 11~11행

```html
<h1 title="글씨">타이틀</h1>
```

### 내 코드 — 원본 발췌

내 코드 `workspace_html/01_hello.html` 13~13행

```html
<h1 title="글씨">타이틀</h1>
```

| 코드 조각 | 이름 | 하는 일 |
| --- | --- | --- |
| `<h1 ...>` | 시작 태그 | 제목 요소의 시작 |
| `title` | 속성명 | 보충 설명을 지정 |
| `"글씨"` | 속성값 | 보충 설명의 내용 |
| `타이틀` | 내용 | 페이지에 보이는 제목 글자 |
| `</h1>` | 종료 태그 | 제목 요소의 끝 |

전체를 `h1` **요소**라고 부른다. 태그는 요소를 표시하는 문법이다. `title` 속성은 마우스를 올렸을 때 보충 설명으로 나타날 수 있지만, 표시 방식은 브라우저와 입력 환경에 따라 달라진다. 꼭 전달해야 하는 안내를 여기에만 넣지 않는다.

`<!-- 주석 -->`은 일반적인 HTML 위치에서 화면 내용으로 표시되지 않는 메모다. 다만 소스에서는 읽을 수 있으며, 모든 요소 안에서 같은 방식으로 해석되는 것은 아니다. `title` 요소 안의 사례는 4절에서 다룬다.

## 3. 문서 정보와 화면 내용을 나누기

### 강사님 코드 — 원본 발췌

강사님 `workspace_html/02_tag.html` 4~6행

```html
    <head>
        <title>최민수</title>
    </head>
```

`head`는 문서 정보를 적는 자리다. 이 `title`은 일반적으로 브라우저 탭의 문서 제목으로 쓰인다.

### 내 코드 — 원본 발췌

내 코드 `workspace_html/02_tag.html` 6~9행

```html
    <head>
        <!-- 속성값이 아닌 title의 경우 body에 넣어도 맨 마지막것으로 끌어오긴 하나 맞는 구역에 넣는것이 좋음 -->
        <title>정근욱</title>
    </head>
```

문서 제목의 글자와 주석이 다르지만 구조는 같다. 내 주석의 “body에 넣어도 맨 마지막것으로 끌어온다”는 설명은 작성 규칙으로 사용하지 않는다. `title`은 `head` 안에 둔다.

### 바로 실행할 수 있는 문서 — 설명용 재구성

아래는 두 원본의 구조와 `03_상대주소/03_a.html`의 문서 선언·메타 정보를 묶은 예제다. 원본에는 `lang="en"`이 있지만, 한국어 본문에 맞추어 `ko`로 수정했다.

```html
<!DOCTYPE html>
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>HTML 첫 실습</title>
</head>
<body>
    <h1 title="첫 번째 제목">나의 학습 기록</h1>
    <p>HTML 문서 구조를 배웠다.</p>
</body>
</html>
```

| 위치·설정 | 읽는 방법 | 확인할 결과 |
| --- | --- | --- |
| `<!DOCTYPE html>` | 현대 HTML 문서 선언 | 브라우저의 표준 모드 사용 |
| `html` | 문서의 루트 요소 | `head`와 `body`를 포함 |
| `lang="ko"` | 주된 문서 언어가 한국어 | 글자를 번역하는 설정은 아님 |
| `charset="UTF-8"` | 문자 인코딩 선언 | 파일도 UTF-8로 저장해야 함 |
| `viewport` | 모바일 화면의 뷰포트 설정 | 자동 반응형 레이아웃을 만들어 주지는 않음 |
| `title` 요소 | 문서 제목 | 탭 제목: `HTML 첫 실습` |
| `body` | 표시할 본문 | 제목과 문단이 페이지 안에 보임 |

`title` **요소**와 `title` **속성**은 이름은 같아도 역할과 위치가 다르다. 탭 제목을 바꾸려면 `head` 안의 요소를, 특정 요소의 보충 설명을 바꾸려면 속성을 확인한다.

<a id="correction"></a>

## 4. 원본 주석을 정확하게 읽기

| 원본에서 발견한 표현·상황 | 본문에서의 교정 |
| --- | --- |
| `html`은 페이지당 하나가 있는 것이 좋다 | 문서의 루트 구조로 `html` 하나를 작성한다. 단순한 취향의 문제가 아니다. |
| `title`을 `body`에 두어도 표시될 수 있다 | 오류를 복구한 화면과 올바른 작성 위치를 구별한다. |
| `charset`이 한글을 깨지지 않게 만든다 | 실제 파일 인코딩과 선언이 일치해야 한다. |
| `title` 안의 `<!-- 주석 -->` | 일반 주석처럼 숨겨지는 자리가 아니다. 제목에는 필요한 텍스트만 적는다. |

마지막 사례는 내 `04_ul.html`에 실제로 있다. 강사님은 주석을 `title` 밖에 두고, 나는 안에 두었다. **주석을 요소 밖으로 옮기는 강사님 구성이 더 적절하다.** 목록 장에서 코드 자체를 비교한다.

문법이 잘못되어도 화면이 나오는 경우가 있다. 화면에 보인다는 이유만으로 태그 구조가 올바르다고 판단하지 않는다.

## 5. 복습

1. 탭 제목을 `나의 Wiki`로, 화면 제목을 `HTML 공부`로 바꾸려면 각각 어디를 수정할까?
2. `<h1 title="설명">제목</h1>`에서 속성명·속성값·내용을 구분해 보자.
3. `lang="ko"`만 넣으면 영어 본문이 한국어로 바뀔까?

<details>
<summary>정답과 이유</summary>

1. `head`의 `<title>나의 Wiki</title>`과 `body`의 `<h1>HTML 공부</h1>`을 각각 수정한다.
2. 속성명은 `title`, 속성값은 `설명`, 요소의 내용은 `제목`이다.
3. 바뀌지 않는다. 문서의 언어를 알려 주는 설정이지 번역 기능이 아니다.

</details>

**다시 볼 핵심:** 문서 정보는 `head`, 화면 내용은 `body`. 원본 발췌와 설명용 수정 예제를 구별해서 읽는다.

## 💡 추가로 알면 좋은 것

> [!TIP]
> 브라우저는 구조가 잘못된 HTML도 화면에 표시하려고 해석을 보정할 수 있다. **보이는 결과가 곧 올바른 구조라는 뜻은 아니다.** 예를 들어 내 원본 주석처럼 `title`을 `body`로 옮겨 보는 실험을 실제 문서의 작성법으로 삼지 않는다. 브라우저 내부의 복구 규칙까지 익히는 것은 이 장의 수업 범위 밖이다.

정확성 참고: [HTML 표준 — 문서 메타데이터와 title](https://html.spec.whatwg.org/dev/semantics.html). 수업 범위는 강사님·내 원본으로 정했다.
