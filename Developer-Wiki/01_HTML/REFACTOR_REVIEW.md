# HTML 상세 학습판 검토 기록

## 결론

이번 작업은 목차와 제목만 바꾸는 UI 정리가 아닙니다. 기존 상세 학습 내용을 유지하며 입력의 출처, 브라우저의 처리 순서, 결과와 확인 방법을 보강했습니다. 학습용 반복·실습·정답은 삭제하지 않았습니다. 메모리와 참조처럼 하나의 파일로 합칠 필요가 없는 HTML은 기존 10개 주제 파일을 유지했습니다.

## 검토 질문과 수정 판단

| 세부 질문 | 문제 또는 오해 가능성 | 수정한 학습 설명 |
| --- | --- | --- |
| HTML은 무엇을 하는가? | 태그를 실행해서 화면을 출력한다고 막연하게 이해 | 입력 문서→파싱→DOM→스타일·배치→화면으로 구분 |
| DOM과 원본은 같은가? | Elements의 자동 보정을 파일 변경으로 오해 | 현재 DOM과 원본 소스를 구분 |
| 속성은 어디에 쓰이는가? | 글자 모양과 의미를 혼동 | src·href·title·alt·name의 역할을 결과와 연결 |
| 의미 태그와 디자인의 차이는? | strong/b, em/i를 단순한 허용·금지로 외움 | 요소 의미와 기본 스타일을 분리 |
| 공백은 왜 다르게 보이는가? | 원본 엔터가 모두 화면 줄바꿈이라고 생각 | 기본 공백 접힘, pre, 엔티티와 실제 태그 구분 |
| 상대 URL은 무엇을 기준으로 하는가? | 디스크 최상위가 기준이라고 생각 | 현재 문서 URL과 href의 조합, 계산 결과 표 추가 |
| 실제 원본에서 어떤 링크가 잘못됐는가? | 사용자만의 실수라고 오분류 가능 | 두 파일의 하위 폴더 01_hello 링크를 함께 확인 |
| 목록의 순서와 가로 배치는 누가 정하는가? | ol 사용 빈도와 CSS 배치를 의미 규칙으로 오해 | 항목 관계·순서 의미와 display 규칙 구분 |
| 표 병합은 어떻게 세는가? | 각 행의 td 태그 수가 항상 같아야 한다고 생각 | rowspan·colspan의 2행×3열 격자 점유를 표로 설명 |
| hidden caption은 접근성을 보장하는가? | 시각 숨김과 접근성 숨김 혼동 | 원본 차이와 hidden의 한계 설명 |
| 이미지 표시 실패는 HTML 실패인가? | 문서와 이미지 수신을 하나로 생각 | URL 계산·수신·해석·표시를 나누어 진단 |
| iframe 주석은 실행되는가? | 설명용 주석을 실제 로딩 코드로 오해 | 사용자에만 있는 주석 예제와 강사님 소스 구분 |
| readonly면 반드시 제출되는가? | 원본의 name 없는 입력까지 전송된다고 이해 | 원본 칸은 제외됨을 설명하고 이름 있는 재현 예제와 비교 |
| 체크박스 value가 없으면 무엇을 보내는가? | 화면 글자가 자동 전송 값이라고 생각 | 사용자 coffee=5와 강사님 coffee=on의 차이 설명 |
| 폼이 있으면 서버 저장까지 완성인가? | HTML 요청 구성과 서버 처리 혼동 | 입력→전송 항목→요청→응답·저장을 구분 |
| POST가 보안 또는 고정 URL을 보장하는가? | 본문 전송을 암호화로 오해 | HTTPS와 서버 redirect를 별도로 설명 |
| 확장 내용을 실제 수업처럼 소개하지 않는가? | 시맨틱 완성 프로젝트의 근거 혼동 | 번호형 원본 비교 범위 01~07, 08~10 확장 구분 |
| 어떻게 실제 값을 확인하는가? | 화면만 보고 성공 판단 | 10개 주제의 Console 확인 명령·예상 결과·전제 추가 |
| 독자가 완성 코드만 복사하게 되는가? | 통합 코드가 학습의 시작이 됨 | 작은 발췌로 먼저 설명, 완성 코드는 마지막 대조 자료로 안내 |

## 직접 비교한 소스

| 수업 파일 | 확인한 공통 내용 | 실제 차이 또는 점검 |
| --- | --- | --- |
| 01_hello.html | 일반 글자·h1·외부 img·title | 사용자 설명 주석 추가, 둘 다 이미지 alt 없음 |
| 02_tag.html | h1~h7·strong·em·mark·del·공백·pre | 제목 문자열·사용자 태그 이름·del 내용 차이 |
| 03_상대주소/03_a.html | 외부 링크·상대/루트 경로·#top | 사용자 #bottom 대상 있음, 강사님 첫 a에 href 없음; 사용자 따옴표 오타 |
| 04_ul.html | ul·ol·중첩 목록·dl | 사용자 부모 항목 설명과 가로 목록 CSS 있음 |
| 05_table.html | 병합·thead/tbody·잘못된 summary | 사용자 hidden caption·추가 게시판·잘못 닫은 th |
| 06_img.html | 동일 로컬 img·200×300·video controls/loop | 사용자 iframe 주석 예제, 강사님 여러 줄 속성 |
| 07_form.html | 입력 타입·label·GET/POST·검색 | value 없는 강사님 체크박스, gender checked 중복, 사용자 설명·실습 추가 |

개인 전화번호·메일 주소는 새 설명에 재인용하지 않았습니다. 수업 밖 API·접근성·설계 내용에는 전구 또는 확장 학습 안내를 사용했습니다.

## 보존 검사와 자체 재검토

원본의 코드 블록이 최종 문서에 같은 내용·순서로 남았는지 대조했습니다. 기존 번호형 본문의 순서, 코드 울타리, 깨진 문자, 내부 목차 앵커, 파일 링크를 검사했습니다. 학습 목표만 요청에 맞게 간략하게 정리했습니다.

두 번째 읽기에서는 새 설명이 기존 답과 모순되지 않는지 확인했습니다. 폼의 readonly 요약·정답·비교표도 전송 조건을 밝히도록 수정했습니다. 새 설명의 문자 그대로인 br가 Markdown에서 태그로 처리될 수 있어 인라인 코드로 고쳤습니다. 수업 소스, 개선 코드, 확인 명령을 구분했습니다.

## 검증 범위와 남은 확인

- URL API와 URLSearchParams를 실행하여 부모/루트/현재 폴더 경로 및 예제 GET 쿼리 계산을 확인했습니다.
- 원본 예제와 문제는 브라우저에서 실행해야 하는 문맥 예제, 의도적인 오류, 외부 자원 의존 예제를 포함합니다. 모든 코드의 독립 실행 성공을 주장하지 않습니다.
- 이 환경에는 실행 가능한 테스트 브라우저가 없어 실제 화면 렌더링·Console 명령 전부·Network 응답·스크린 리더 검수는 수행하지 못했습니다. 문서에는 학습자가 확인할 방법과 전제를 명시했습니다.
- 외부 검색·영상 서비스 응답과 로컬 자원 존재는 문서 자체로 보장하지 않습니다.
- README의 다른 파트 링크는 전체 Developer-Wiki 안에 설치할 때 연결됩니다.
- 통합 용어색인의 최종 정리는 나머지 파트 완료 뒤 진행합니다.

## 정확성 보충의 근거

폼 전송 조건은 [폼](https://html.spec.whatwg.org/multipage/forms.html)과 [input](https://html.spec.whatwg.org/multipage/input.html), 표 구조는 [표](https://html.spec.whatwg.org/multipage/tables.html), 텍스트 의미는 [텍스트 요소](https://html.spec.whatwg.org/multipage/text-level-semantics.html), 이미지 연결은 [임베디드 콘텐츠](https://html.spec.whatwg.org/multipage/embedded-content.html), 시맨틱 영역은 [섹션](https://html.spec.whatwg.org/multipage/sections.html)의 HTML 표준을 참조했습니다.

## 최종 판단

초보자는 작은 예제의 의미와 처리 순서부터 읽고 재현할 수 있고, 익숙한 독자는 문서 내 목차·비교표·오류 진단으로 필요한 조건을 찾을 수 있게 구성했습니다. 이해에 필요한 반복은 남기고 화면·DOM·요청의 구분을 강화했습니다. HTML 확인을 받은 후 CSS를 진행합니다.
