# 링크와 경로 — 현재 문서에서 목적지를 계산하기

[HTML 목차](README.md) · [이전: 기본 태그](02_HTML_기본태그.md) · [다음: 목록](04_HTML_목록태그.md)

‘파일이 있는데 링크가 안 열린다’는 상황은 파일명만 확인해서 해결되지 않을 수 있다. 링크의 기준은 **지금 읽는 문서의 주소**다. 이 장은 내 상대주소 실습에서 출발해 현재 폴더·부모 폴더·서버 루트·문서 안 식별자를 나눠 계산한다.

## 1. 이번 장에서 배울 것

| 준비·실행 조건 | 내용 |
| --- | --- |
| 앞선 학습 | 요소·속성·기본 문서 구조 |
| 실제 수업 파일 | 양쪽 `workspace_html/03_상대주소/03_a.html`, 목적지 `workspace_html/asset/detail.html` |
| 새 실행 자료 | [실습/03_경로_복습/index.html](실습/03_경로_복습/index.html), 하위 폴더의 detail.html |

| 서버 주소를 가정해 계산할 것 | `/`로 시작하는 루트 기준 경로 |
| 결과 확인 | 열린 문서의 내용과 주소 표시줄 |

코드 조각 하나만 복사하면 목적지 파일이 없을 수 있다. 제공된 경로 실습은 **폴더 구조를 함께 유지**한다. 외부 사이트·전화·메일 앱의 실제 동작은 이 로컬 파일 실습에서 재현한 결과로 쓰지 않는다.

## 2. 개념부터 이해하기

### 2.1 링크의 글자와 목적지는 다르다

```html
<!-- 설명용 새 예제 · body 안의 조각 -->
<a href="pages/detail.html">학습 내용 자세히 보기</a>
```

`a`는 링크를 나타내고 `href`는 이동할 주소다. 안의 글자는 사용자가 클릭할 안내다. 안내 글자를 `홈으로`로 바꿔도 href가 그대로라면 목적지가 홈으로 바뀌지 않는다. 링크가 잘못되면 **보이는 글자와 실제 목적지**를 각각 확인한다.

`target="_blank"`를 붙이면 새 탐색 문맥으로 열도록 요청한다. 보통 새 탭이지만 브라우저 설정에 따라 새 창일 수도 있다. 새 탭 여부와 목적지 경로가 맞는지는 서로 다른 질문이다.

> 📚 **출처 · 본문 설명 확인:** 링크 텍스트·href·경로 연결은 [MDN — Creating links](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Structuring_content/Creating_links)로 확인했다. 수업의 링크를 설명하기 위한 근거다.

<a id="relative"></a>

### 2.2 상대 경로는 지금 문서가 있는 폴더에서 시작

수업의 폴더 관계는 다음과 같다.

```text
workspace_html/
├── 01_hello.html
├── 03_상대주소/
│   └── 03_a.html       ← 링크가 적힌 현재 문서
└── asset/
    └── detail.html    ← 목적지
```

`03_a.html`에서 `../asset/detail.html`은 **부모로 한 번 올라간 뒤 asset 폴더로 들어가 detail.html을 찾는다**고 읽는다. `..`은 파일 하나를 뜻하는 이름이 아니라 경로를 계산하는 부분이다.

| 적은 href | 계산 과정 | 찾는 위치 |
| --- | --- | --- |
| `detail.html` | 현재 폴더에서 찾기 | `03_상대주소/detail.html` |
| `./detail.html` | 현재 폴더를 명시 | 위와 같음 |
| `../asset/detail.html` | 부모 → asset → 파일 | `workspace_html/asset/detail.html` |
| `../01_hello.html` | 부모 → 파일 | `workspace_html/01_hello.html` |

현재 폴더를 확인하지 않고 `../`를 무조건 붙이면 다른 위치에서도 똑같이 맞는 링크가 되지 않는다. 어떤 문서에서 적은 경로인지가 계산의 시작점이다. 이 기본 설명은 `base` 요소를 따로 두지 않은 수업 문서를 기준으로 한다.

<a id="root"></a>

### 2.3 `/`로 시작하면 무엇이 달라질까?

현재 주소를 `http://localhost:8000/03_상대주소/03_a.html`이라고 가정하자. 이 서버가 `workspace_html`을 루트로 제공한다는 전제가 있다.

| href | 기준 | 계산되는 URL |
| --- | --- | --- |
| `../asset/detail.html` | 현재 문서의 폴더 | `http://localhost:8000/asset/detail.html` |
| `/asset/detail.html` | 현재 서버 주소의 루트 | 위와 같음 |
| `https://example.com/help` | 지정한 스킴·서버·경로 | `https://example.com/help` |
| `//example.com/help` | 현재 문서의 스킴 + 지정한 서버 | 이 HTTP 전제에서는 `http://example.com/help` |

첫 두 결과가 이번 위치에서 같아도 계산 기준은 다르다. 문서 위치가 더 깊어지면 상대 경로의 필요한 `..` 수는 달라질 수 있지만, 루트 기준 경로는 같은 서버의 `/`부터 계산한다.

수업 주석은 여러 주소를 ‘절대 주소’로 함께 설명한다. 이 책에서는 전체 URL과 혼동하지 않도록 `/...`를 **루트 기준 경로**라고 구분한다. `/`는 항상 내 프로젝트 폴더를 뜻하지 않으며 서버가 어떤 폴더를 제공하는지 확인해야 한다.

> 📚 **출처 · 본문 설명 확인:** 문서 상대·부모·루트 기준 참조의 계산은 [MDN — Resolving relative references](https://developer.mozilla.org/en-US/docs/Web/API/URL_API/Resolving_relative_references)로 확인했다. 그 문서의 URL API 코드를 이 HTML 수업의 필수 문법으로 추가하지 않는다.

<a id="fragment"></a>

### 2.4 같은 문서 안으로 이동하기

`href="#end"`는 문서 안에서 `id="end"`인 요소를 찾는 연결이다. 목적지 ID에는 `#`를 붙이지 않고 href의 참조에 붙인다.

```html
<!-- 설명용 새 예제 · 두 요소를 같은 body 안에 둠 -->
<a href="#end">마지막 설명으로 이동</a>
<h2 id="end">마지막 설명</h2>
```

링크와 도착 지점 둘 다 필요하다. ID가 있어도 링크가 없으면 사용자가 그 링크를 누를 수 없고, href만 있어도 맞는 ID가 없으면 원하는 지점을 찾지 못한다. 한 문서 안에서 식별자 ID를 중복하지 않는다.

## 3. 작은 예제와 결과

새 경로 실습의 파일 구조는 다음과 같다. 이미지 태그를 아직 배우지 않아도 풀 수 있도록 텍스트 링크만 사용했다.

```text
03_경로_복습/
├── index.html
└── pages/
    └── detail.html
```

**설명용 새 예제 · 전체 index.html.** [파일 열기](실습/03_경로_복습/index.html).

```html
<!DOCTYPE html>
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <title>경로 복습 시작</title>
</head>
<body>
    <h1 id="top">학습 기록</h1>
    <p><a href="pages/detail.html">자세한 내용</a></p>
    <p><a href="#end">이 문서의 마무리</a></p>
    <h2 id="end">마무리</h2>
    <p><a href="#top">맨 위로</a></p>
</body>
</html>
```

**설명용 새 예제 · 전체 pages/detail.html.** [목적지 파일](실습/03_경로_복습/pages/detail.html).

```html
<!DOCTYPE html>
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <title>학습의 자세한 내용</title>
</head>
<body>
    <h1>자세한 내용</h1>
    <p>부모 폴더로 올라가 시작 문서로 돌아간다.</p>
    <a href="../index.html">시작 문서로</a>
</body>
</html>
```

예상 결과는 시작 → 자세한 내용 → 시작 문서의 왕복 이동이다. 첫 링크는 index의 폴더에서 `pages`로 내려가고, 돌아오는 링크는 detail의 폴더에서 `..`로 올라간다.

**하나만 바꾸는 실험:** detail의 `../index.html`을 `index.html`로 바꿔 보자. 이제 `pages/index.html`을 찾으므로 제공된 구조와 맞지 않는다. 두 파일 이름이 맞아도 기준 폴더를 빼먹으면 다른 목적지가 된다. 실험 뒤에는 원래 경로로 되돌린다.

## 4. 내 코드 따라 읽기

### 4.1 부모 폴더를 거쳐 목적지 찾기

**내 코드 · 원본 발췌** — `workspace_html/03_상대주소/03_a.html` 46행.

```html
        <a href="../asset/detail.html" target="_blank">디테일페이지 이동</a><br>
```

`href`는 목적지를 계산하고 `_blank`는 여는 문맥을 지정한다. 뒤의 br은 현재 페이지의 줄바꿈으로 링크의 목적지를 바꾸지 않는다. 현재 수업 구조에서 이 상대 경로는 실제 asset/detail.html을 가리킨다.

### 4.2 서버 루트에서 시작하는 링크

**내 코드 · 원본 발췌** — 같은 파일 55행.

```html
        <a href="/asset/detail.html" target="_blank">절대주소 디테일페이지</a><br>
```

이 코드를 파일 더블클릭의 `file:` 주소에서 시험한 결과와, HTTP 서버에서 시험한 결과를 섞으면 안 된다. 수업의 서버 루트 설명은 HTTP 주소와 그 서버의 제공 폴더를 전제로 읽는다. `/asset/...`가 항상 `D:/workspace/...`를 가리키는 규칙은 아니다.

### 4.3 내가 완성한 문서 안 이동

**내 코드 · 원본 발췌** — 같은 파일 14–15행.

```html
        <h1 id="top">여기는 맨 위</h1>
        <a href="#bottom">맨 아래로</a><br>
```

내 파일 아래에는 `id="bottom"`인 strong 요소도 있어 목적지까지 연결된다. `top`이라는 ID는 위로 돌아오는 링크에서 사용한다. ID 이름 자체가 위·아래 기능을 가진 것은 아니다. 링크와 요소가 같은 식별자를 약속했기 때문에 작동한다.

## 5. 다른 파일과 연결하기

이 HTML 연결은 함수 import가 아니라 **사용자의 링크 선택에 따라 다른 문서를 여는 관계**다. 원본의 대상 파일이 어떤 위치에 있는지까지 확인해야 코드 풀이가 끝난다.

| 출발 문서 | 적은 경로 | 도착 자료 | 확인할 내용 |
| --- | --- | --- | --- |
| 원본 `03_상대주소/03_a.html` | `../asset/detail.html` | 원본 `asset/detail.html` | 부모로 이동한 뒤 asset 아래 파일 |
| 새 `index.html` | `pages/detail.html` | 새 `pages/detail.html` | 아래 폴더로 이동 |
| 새 `pages/detail.html` | `../index.html` | 새 `index.html` | 부모로 돌아가 파일 선택 |

링크했다고 원본 파일 내용이 현재 문서 안으로 자동 합쳐지는 것은 아니다. 이동한 문서의 탭 제목과 본문은 그 파일에서 정의한 내용을 사용한다. 원본 목적지의 구현 전체가 필요하지 않은 경우에도 **어느 파일을 여는지와 목적지 문서의 역할**은 설명한다.

## 6. 내 코드 돌아보기

내 코드는 문서 안 이동의 href와 목적지 ID를 함께 작성했다. 단지 이름을 적는 데서 끝내지 않고 연결을 완성한 점이 좋다. 상대 경로의 `..`도 실제 폴더 관계와 맞는다.

| 확인한 점 | 평가 종류 | 보완·선택 |
| --- | --- | --- |
| `../asset/detail.html` | 목적에 맞는 경로 | 현재 위치가 바뀌면 다시 계산 |
| `href="01_hello.html"` | 현재 구조와 불일치 | 상위 파일이면 `../01_hello.html` |
| 이미지 링크의 `_blank` 뒤 여분 따옴표 | 문법 보완 | 속성값 따옴표를 짝에 맞게 작성 |
| 외부 링크 새 탭 | 사용자 경험 선택 | 모든 링크가 반드시 새 탭이어야 하는 것은 아님 |
| 문서 아래로 이동하려고 br 다수 사용 | 수업용 화면 실험 | 완성 문서의 여백 설계와 구별 |

**개선 예시 · 원본에 미적용 · 링크 조각:** 현재 위치에서 상위의 첫 수업 파일을 열려면 다음처럼 쓴다.

```html
<a href="../01_hello.html" target="_blank">첫 실습 열기</a>
```

부모 폴더를 가리키는 `..`를 추가한 것이 동작을 고친 핵심이다. 링크 텍스트만 바꾸거나 `_blank`를 추가하는 것으로는 잘못된 목적지가 해결되지 않는다.

## 7. 강사님 코드에서 배울 점

이 실습에서는 내 코드가 문서 안 이동 연결을 더 완성했다. 강사님과 비교할 필요가 있는 부분만 본다.

**강사님 코드 · 비교에 필요한 발췌** — 같은 수업 파일 9–10행.

```html
    <h1 id="top">맨 위</h1>
    <a>맨 아래로</a>
```

강사님 ‘맨 아래로’ 요소에는 href가 없고, 아래 strong에도 bottom ID가 없다. 이 상태를 완성된 아래 이동 기능이라고 설명하면 안 된다. 반면 내 코드는 링크와 ID를 함께 작성했다. **코드의 출처보다 실제 연결의 완성 여부**가 판단 기준이다.

다른 상대 경로는 양쪽 실행 의도가 같아 중복 인용하지 않는다. 양쪽 모두의 잘못된 첫 실습 경로는 폴더 구조에 맞춰 교정해야 한다. 이미지 링크에서는 강사님 코드처럼 따옴표의 짝을 맞춘 점을 참고하면 된다.

## 8. 결과와 확인 방법

| 현상 | 원인 후보 | 먼저 확인할 것 |
| --- | --- | --- |
| 목적지 파일을 못 찾음 | 기준 폴더·파일명 불일치 | 현재 문서 위치부터 경로 계산 |
| 맞는 파일 같은데 다른 문서가 열림 | 같은 이름의 파일이 다른 폴더에 있음 | 주소 표시줄의 전체 경로 |
| `#end`를 눌러도 큰 변화 없음 | 목적지가 이미 화면 안에 있을 수 있음 | ID 존재와 스크롤 여유 |
| 아래 이동 연결이 없음 | href 또는 ID 누락 | 링크와 목적지 둘 다 |
| `/...`가 예상과 다름 | file/HTTP 환경 또는 루트 설정 차이 | 주소의 스킴과 서버 제공 폴더 |

파일 존재와 상대 경로는 제공된 자료에서 정적으로 확인하고, HTTP 주소 계산은 주어진 서버 URL을 기준으로 검사한다. 외부 사이트 리다이렉트나 새 탭 설정, 전화·메일 앱의 실행 결과를 고정 성공값으로 주장하지 않는다.

<a id="scheme"></a>

### 실제로 배운 전화·메일·이미지 링크

`tel:`과 `mailto:`는 양쪽 원본에 있다. 연락처를 예시 값으로 바꾼 아래 코드는 **새 설명용 조각**이다.

```html
<a href="tel:01000000000">전화걸기</a>
<a href="mailto:learner@example.com">메일보내기</a>
```

연결된 앱이 있는 환경에서 전화·메일 동작을 요청한다. HTML이 직접 통화를 연결하거나 메일을 자동 발송하는 것은 아니다. 이 예문 검증에서는 실제 연락 동작을 실행하지 않는다.

이미지 링크도 원본에 있지만 이미지 속성과 파일 준비는 [06 이미지 장](06_HTML_이미지와_미디어.md)에서 자세히 다룬다. 기본 경로 문제를 풀기 위해 아직 설명하지 않은 이미지 파일을 추가로 준비하도록 요구하지 않는다.

<a id="tips"></a>

## 9. 추가로 알면 좋은 것

> 💡 **TIP · 수업 범위 밖:** `base` 요소를 사용하면 상대 URL의 기준을 별도로 지정할 수 있다. 이번 수업과 새 예제는 base를 두지 않았으므로 현재 문서 기준으로 계산했다. 기본 경로를 이해한 뒤 기준을 바꾸는 기능을 추가 학습한다.

> 💡 **TIP · 보충 정리:** `//example.com/help`처럼 시작하면 현재 문서의 스킴을 따라 다른 서버를 가리킨다. 수업 주석에도 등장하지만, `../`·`/`·전체 URL을 먼저 구분하고 그 뒤 복습한다. 새 탭의 관계·보안 속성 상세 설계는 별도 확장이다. [출처: MDN — 링크](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Structuring_content/Creating_links).

<a id="practice"></a>

## 10. 복습과 다음 학습

### 결과 예상 → 이유 설명 → 작은 수정

1. `pages/list.html`에서 같은 부모 아래 `images/photo.png`로 가는 상대 경로는?
2. 왜 파일명 `photo.png`만 같아서는 목적지 일치를 보장하지 못할까?
3. 같은 문서의 `<h2 id="finish">끝</h2>`로 이동하는 링크를 작성해 본다.

<details>
<summary>풀이</summary>

`../images/photo.png`다. 경로의 기준은 list.html이 있는 pages 폴더이기 때문이다. 문서 안 이동은 `<a href="#finish">끝으로</a>`처럼 href의 식별자와 목적지 ID를 맞춘다. 이미 화면 안의 요소라면 큰 스크롤 변화가 없을 수 있다.

</details>

### 빠른 확인표

| 표기 | 기준 |
| --- | --- |
| `file.html`, `./file.html` | 현재 문서의 폴더 |
| `../file.html` | 부모 폴더 |
| `/file.html` | HTTP 문서에서는 서버 주소의 루트 |
| `https://...` | 명시한 스킴·서버·경로 |
| `#id` | 문서 안 식별자 |
| `_blank` | 목적지 계산이 아닌 여는 문맥 |

외부 설명은 표시된 문서로 2026-10-28 확인했고, 원본 경로·함수 유무·실제 작성 차이는 수업 파일로 대조했다. BACKUP 링크 문서의 목적·문법·예제 전개를 참고했다.
