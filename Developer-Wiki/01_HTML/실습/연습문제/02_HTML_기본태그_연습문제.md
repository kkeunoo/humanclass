# 역할과 공백 처리 — 연습문제

[본문으로](../../02_HTML_기본태그.md) · [문제 목차](README.md)

이 파일은 수업 원본을 바탕으로 **새로 구성한 연습문제**다. 실제 강사님 퀴즈와 구분한다. 풀이 전에 예상과 이유를 직접 적고, 본문의 실행 파일에 적용해 확인한다.

## 목표와 실행 조건

제목·문단·강조를 구별하고, 일반 텍스트와 pre의 공백 차이를 예측한다.

HTML 조각은 본문에서 제공한 전체 파일의 적절한 위치에 넣는다. ‘코드로 예상한 결과’와 ‘브라우저에서 실제 확인한 결과’를 따로 적는다. 폼 요청은 로컬 HTTP 환경에서 관찰하고, 서버 저장 기능을 이 문제에 임의로 추가하지 않는다.

## 문제 1. 먼저 결과 예상하기

**새 설명 예제 · body 조각.** 아래에서 문단 수, 줄바꿈, 강조의 뜻을 적는다. 화면의 정확한 픽셀 크기를 맞히는 문제는 아니다.

```html
<p>첫째   내용<br>둘째 내용</p>
<p><strong>제출 전 확인</strong>을 잊지 마세요.</p>
```

첫 줄의 공백 세 개는 보통 어떻게 처리될까? br이 새 문단을 만들까?

<details>
<summary>힌트와 풀이</summary>

**힌트:** 속성 이름과 현재 값을 구별하고, 이 코드가 전체 문서인지 조각인지 먼저 확인한다.

p는 두 개다. 첫 문단 안에서 br 뒤에 줄바꿈이 생긴다. 일반 HTML 텍스트의 연속 공백은 기본 처리에서 하나로 합쳐진다. strong은 중요한 내용을 나타낸다. 기본 굵은 글씨만을 뜻으로 외우지 않는다. br은 같은 문단 안의 줄바꿈이며 두 번째 문단을 생성하지 않는다.

</details>

## 문제 2. 이유를 설명하기

다음 두 조각의 차이를 설명한다.

```html
<pre>첫 줄
  둘째 줄</pre>
<pre>&lt;br&gt;</pre>
```

pre 안의 공백·줄바꿈과 `&lt;br&gt;`의 결과를 설명한다. pre 안에 그냥 `<br>`를 쓰면 태그가 그대로 글자로 나올까?

<details>
<summary>풀이</summary>

첫 pre는 줄바꿈과 둘째 줄 앞의 공백 두 개를 보존한다. 두 번째는 `<br>`라는 글자를 표시한다. pre도 HTML이므로 태그 해석 자체를 끄지 않는다. 태그 모양을 문자로 보여 주려고 꺾쇠를 문자 참조로 적은 것이다. pre 안의 실제 br은 태그로 처리된다.

</details>

## 문제 3. 고치고 한 가지 바꾸기

제목과 설명을 다음처럼 작성했다. 구조 의도는 ‘전체 제목 하나, 하위 제목 하나, 설명 두 문단’이다. 그 의도에 맞게 고친다.

```html
<h1>복습</h1>
<h7>오늘 배운 것</h7>
첫 설명<br><br>둘째 설명
```

고친 조각을 본문의 전체 파일에 넣어 확인한다. 아래 정답은 body 조각이다.

<details>
<summary>예시 정답과 변경 실험</summary>

```html
<h1>복습</h1>
<h2>오늘 배운 것</h2>
<p>첫 설명</p>
<p>둘째 설명</p>
```

표준 제목은 h1부터 h6까지다. h7이 화면에 글자로 나타날 수 있다는 것과 표준 제목 요소라는 것은 다르다. br 여러 개로 문단 모양만 흉내 내기보다 두 p로 역할을 표현했다. h2를 h3로만 바꾸는 실험에서는 제목 단계의 의미부터 설명하고 기본 글자 크기도 관찰한다.

</details>

## 채점과 복습

| 점검 | 스스로 확인할 것 |
| --- | --- |
| 예상 | 결과를 먼저 썼는가? |
| 설명 | 왜 그런지 태그·속성·위치로 설명했는가? |
| 수정 | 요구한 조건만 바꾸었는가? |
| 검증 | 저장·새로고침 후 실제 결과와 비교했는가? |

태그가 화면에 보였다는 사실만으로 유효한 의미 구조라고 판단하지 않는다. 문단·줄바꿈·여백을 같은 말로 사용하지 않는다.

정답 글자를 외우기보다 원인을 설명하지 못한 부분을 [본문](../../02_HTML_기본태그.md)에서 다시 읽는다. 본문의 📚 출처는 배운 기능의 설명을 확인하는 근거이며, 💡 TIP은 선택 학습이다. 이 문제의 정답에 TIP 기능이 필수로 들어가지는 않는다.
