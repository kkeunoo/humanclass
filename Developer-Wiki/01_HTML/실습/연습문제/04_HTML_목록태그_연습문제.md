# 항목과 하위 항목 — 연습문제

[본문으로](../../04_HTML_목록태그.md) · [문제 목차](README.md)

이 파일은 수업 원본을 바탕으로 **새로 구성한 연습문제**다. 실제 강사님 퀴즈와 구분한다. 풀이 전에 예상과 이유를 직접 적고, 본문의 실행 파일에 적용해 확인한다.

## 목표와 실행 조건

ul·ol·dl의 역할을 고르고, 하위 목록이 어느 항목에 속하는지 설명한다.

HTML 조각은 본문에서 제공한 전체 파일의 적절한 위치에 넣는다. ‘코드로 예상한 결과’와 ‘브라우저에서 실제 확인한 결과’를 따로 적는다. 폼 요청은 로컬 HTTP 환경에서 관찰하고, 서버 저장 기능을 이 문제에 임의로 추가하지 않는다.

## 문제 1. 먼저 결과 예상하기

**새 설명 예제 · body 조각.** 목록 항목의 관계를 말이나 간단한 나무 그림으로 나타낸다.

```html
<ul>
    <li>프런트엔드
        <ul><li>HTML</li><li>CSS</li></ul>
    </li>
    <li>백엔드</li>
</ul>
```

바깥 ul의 직접 li는 몇 개인가? 전체 li 수와 같을까?

<details>
<summary>힌트와 풀이</summary>

**힌트:** 속성 이름과 현재 값을 구별하고, 이 코드가 전체 문서인지 조각인지 먼저 확인한다.

바깥 ul의 직접 항목은 프런트엔드와 백엔드 두 개다. 전체 li는 내부의 HTML·CSS까지 네 개다. 안쪽 ul이 프런트엔드 li 안에 있으므로 두 기술은 프런트엔드의 하위 항목이다. 코드 줄의 들여쓰기만으로 부모가 결정되는 것이 아니라 실제 열고 닫는 태그 위치로 결정된다.

</details>

## 문제 2. 이유를 설명하기

‘필요한 준비물’, ‘실행 순서’, ‘HTML이라는 용어의 뜻’에 ul·ol·dl 중 무엇을 선택하겠는가? 꼭 그 순서여야 하는지와 이름·설명의 관계를 기준으로 답한다.

<details>
<summary>풀이</summary>

준비물은 순서가 의미 없으면 ul, 실행 순서는 순서 자체가 중요하므로 ol, 용어와 뜻의 연결은 dl 안의 dt·dd가 적합하다. 단지 동그라미나 숫자 모양을 좋아해서 선택하지 않는다. 실제 내용이 순차 작업인지가 판단 기준이다.

</details>

## 문제 3. 고치고 한 가지 바꾸기

‘프런트엔드’의 하위 항목으로 HTML을 넣으려 했지만 다음처럼 썼다. 의도대로 고친다.

```html
<ul>
    <li>프런트엔드</li>
    <ul><li>HTML</li></ul>
</ul>
```

고친 뒤 제목 글자를 CSS로 꾸미는 것과 목록 관계를 고치는 것이 같은 작업인지 설명한다.

<details>
<summary>예시 정답과 변경 실험</summary>

```html
<ul>
    <li>프런트엔드
        <ul><li>HTML</li></ul>
    </li>
</ul>
```

하위 목록을 바깥 li가 끝나기 전에 넣었다. 들여쓰기도 그 관계를 보이게 했다. CSS는 표시를 바꿀 수 있지만 잘못 배치한 부모·자식 태그를 자동으로 올바른 구조로 만들지 않는다. 안쪽 ul만 ol로 바꾸면 하위 목록이 순서 목록이 되는 것이며 부모 항목 수는 바뀌지 않는다.

</details>

| 예상 | 결과를 먼저 썼는가? |
| 설명 | 왜 그런지 태그·속성·위치로 설명했는가? |
| 수정 | 요구한 조건만 바꾸었는가? |
| 검증 | 저장·새로고침 후 실제 결과와 비교했는가? |

직접 자식 수와 전체 후손 수를 구분한다. 원본의 CSS 선택자 설명은 HTML 구조를 이해한 뒤 연결한다.
