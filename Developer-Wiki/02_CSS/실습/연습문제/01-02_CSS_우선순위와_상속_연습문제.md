# 01-02. 우선순위와 상속 — 적용될 값을 어떻게 고를까 — 연습문제

[본문](../../01-02_CSS_우선순위와_상속.md) · [문제 목차](README.md)

이 파일은 실제 수업 기능을 바탕으로 **새로 구성한 연습문제**다. 강사님이 내주신 원본 퀴즈와 구분한다. 결과 예상 → 이유 설명 → 수정·검증 순서로 풀고, 각 정답은 먼저 생각한 뒤 펼친다.

## 목표와 실행 조건

동일 요소·동일 속성의 경쟁을 찾는다. 수업 조건에서 important·인라인·명시도·순서를 비교하고, 상속과 자식 직접 지정을 구분한다.

본문의 [전체 실행 파일](../책형_복습/01-02_CSS_우선순위와_상속.html)을 별도로 열어 실험한다. 아래 조각을 다른 원본 CSS에 그대로 덧붙이면 기존 규칙과 경쟁할 수 있다. 실험 전 원래 파일을 보존하고 매번 한 조건만 바꾼다. 브라우저에서 확인한 것과 코드 기준 예상을 따로 적는다.

## 문제 1. 작은 예제의 결과 예상

**새 설명 예제의 CSS와 body 조각**이다. 전체 파일은 위 링크에 있다. 어떤 요소가 선택되고 무엇이 어떻게 보일지 적는다. 크기가 있으면 내용·테두리 기준도 구분한다.

```css
        #parent { color: red; }
        span { color: blue; }
        .notice { color: green; }
        p { color: purple; }
```

```html
    <h1>값 결정 관찰</h1>
    <div id="parent">부모 <span>자식</span></div>
    <p class="notice">안내</p>
```

<details>
<summary>힌트와 풀이</summary>

**힌트:** 선택자 → 속성 → 기준값 → 상태 순서로 읽는다. 주석은 실행하지 않는다.

부모의 직접 글자는 빨강이고 span은 파랑이다. 부모 ID의 강한 선택자가 자식의 직접 선언을 이기려는 경쟁이 아니다. 안내 p에서는 두 규칙이 같은 요소·속성을 겨룬다. 클래스가 타입보다 구체적이어서 뒤에 p 규칙이 있어도 초록이다.

</details>

## 문제 2. 비슷한 개념을 설명하기

1. 클래스 규칙보다 뒤에 쓴 타입 규칙은 언제나 이기는가?
2. 배경이 비쳐 보이면 상속인가?
3. important는 ID 개수를 늘리는가?

숫자나 속성 이름만 적지 말고 왜 그런지 문장으로 설명한다. 필요한 전제도 함께 쓴다.

<details>
<summary>풀이와 원본으로 돌아갈 지점</summary>

언제나 이기지 않는다. 앞 단계와 명시도가 같아야 선언 순서가 결정한다. 투명한 배경을 통해 보이는 것과 상속은 다르다. important는 별도 중요도 판단이며 ID 개수를 바꾸지 않는다.

실제 작성 기록에서 확인할 부분은 다음과 같다.

내 원본은 div2에 ID·class·human 속성을 붙이고 인라인의 검정 테두리도 둔 실험이다. 발췌의 [human]에만 !important가 있어 현재 테두리는 분홍이다. 마지막 div 규칙이 빨강이라는 사실만으로 최종값을 정할 수 없다. human은 원본 실험용 속성 이름이며 새 HTML 속성 설계의 권장 명명 예시는 아니다.

</details>

## 문제 3. 한 조건을 바꾸고 확인하기

먼저 **원본에서 한 조건 변경**를 적용했을 때의 차이를 예상한다. 예상한 뒤 실제 파일의 해당 선언 하나를 바꾸고 저장·새로고침하여 비교한다. 이후 나머지 변경도 한 번에 하나씩 실험한다. 전환·hover는 상태 변화 전후를, 너비 조건은 경계값을 구분한다.

<details>
<summary>변경 실험의 예상과 점검</summary>

| 원본에서 한 조건 변경 | 예상 테두리 | 판단 |
| --- | --- | --- |
| important만 제거 | 검정 | 일반 인라인이 남음 |
| 처음 원본에서 인라인만 제거 | 분홍 | important가 여전히 있음 |
| important와 인라인 제거한 별도 조건 | aqua | ID 규칙이 남은 일반 규칙보다 구체적 |

실행 파일에서 span의 color 선언만 지우면 부모의 빨강을 상속할 수 있다. 안내의 클래스 선언을 지우면 p 규칙의 보라가 남는다. 순서 문제를 보기 전에 대상과 속성이 실제로 같은지 확인한다.

</details>
