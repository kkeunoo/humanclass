# 12. transition — 상태 사이의 값에 시간을 주기 — 연습문제

[본문](../../12_CSS_Transition과_상태변화.md) · [문제 목차](README.md)

이 파일은 실제 수업 기능을 바탕으로 **새로 구성한 연습문제**다. 강사님이 내주신 원본 퀴즈와 구분한다. 결과 예상 → 이유 설명 → 수정·검증 순서로 풀고, 각 정답은 먼저 생각한 뒤 펼친다.

## 목표와 실행 조건

기본값·hover값·전환 대상·시간을 나누어 읽는다. 전환 선언 위치에 따른 진입·복귀 차이를 설명한다.

본문의 [전체 실행 파일](../책형_복습/12_CSS_Transition과_상태변화.html)을 별도로 열어 실험한다. 아래 조각을 다른 원본 CSS에 그대로 덧붙이면 기존 규칙과 경쟁할 수 있다. 실험 전 원래 파일을 보존하고 매번 한 조건만 바꾼다. 브라우저에서 확인한 것과 코드 기준 예상을 따로 적는다.

## 문제 1. 작은 예제의 결과 예상

**새 설명 예제의 CSS와 body 조각**이다. 전체 파일은 위 링크에 있다. 어떤 요소가 선택되고 무엇이 어떻게 보일지 적는다. 크기가 있으면 내용·테두리 기준도 구분한다.

```css
        .box { width: 100px; height: 100px; background-color: green; transition: width 1s; }
        .box:hover { width: 200px; background-color: red; }
```

```html
    <h1>바뀌는 값과 시간</h1>
    <div class="box">포인터 올리기</div>
```

<details>
<summary>힌트와 풀이</summary>

**힌트:** 선택자 → 속성 → 기준값 → 상태 순서로 읽는다. 주석은 실행하지 않는다.

포인터 진입 시 너비100→200px는1초 동안 변하고 색은 즉시 빨강으로 바뀐다. 너비만 전환 대상으로 정했기 때문이다. 나올 때도 기본 규칙의 transition이 남아200→100px가 전환된다. 실제 중간 시점의 값은 진행 조건에 따라 달라지므로 시작·끝 값과 지속시간부터 읽는다.

</details>

## 문제 2. 비슷한 개념을 설명하기

1. transition만있으면자동시작하는가?
2. width만지정하면색도반드시전환하는가?
3. 양방향전환은어디에두면되는가?

숫자나 속성 이름만 적지 말고 왜 그런지 문장으로 설명한다. 필요한 전제도 함께 쓴다.

<details>
<summary>풀이와 원본으로 돌아갈 지점</summary>

값이 바뀌는 조건이 필요하다. width만 대상으로 지정하면 색은 그 전환 대상이 아니다. 이 예제는 기본 .box에 두어 진입·복귀 상태에 모두 유지한다.

실제 작성 기록에서 확인할 부분은 다음과 같다.

내 box2 hover는 빨강·radius50%·200×200에 all0.5s를 함께 뒀다. 기본 box는초록100×100이며 전환 선언 두 줄이 주석이다. 따라서 들어갈 때는 hover전환이 생기지만 나올 때 기본값으로 즉시 돌아간다. box1은 hover에도 전환이 없으므로 같은 실험이라고 읽지 않는다.

</details>

## 문제 3. 한 조건을 바꾸고 확인하기

먼저 **작은예제transition대상만all**를 적용했을 때의 차이를 예상한다. 예상한 뒤 실제 파일의 해당 선언 하나를 바꾸고 저장·새로고침하여 비교한다. 이후 나머지 변경도 한 번에 하나씩 실험한다. 전환·hover는 상태 변화 전후를, 너비 조건은 경계값을 구분한다.

<details>
<summary>변경 실험의 예상과 점검</summary>

| 한 가지 변경 | 예상 | 판단 |
| --- | --- | --- |
| 작은예제transition대상만all | 색도전환대상 | 대상넓어짐 |
| 원래지속시간만2s | 너비전환더길어짐 | 목표값같음 |
| 원래전환을hover로이동 | 진입전환·복귀즉시 | 선언위치 |
| 원래hoverwidth만100px | 너비변화없음 | 시간만있어도안움직임 |

돌아올 때 즉시 작아진다면0.5s단위 오류부터 의심하기보다 기본 상태 전환을 본다. 포인터가 이동 중 상자를 벗어나면 hover조건도 바뀔 수 있어 충분한 관찰 시간을 둔다.

</details>
