# 11. 그림자 — 이동·흐림·실제 상자 크기 — 연습문제

[본문](../../11_CSS_그림자와_시각효과.md) · [문제 목차](README.md)

이 파일은 실제 수업 기능을 바탕으로 **새로 구성한 연습문제**다. 강사님이 내주신 원본 퀴즈와 구분한다. 결과 예상 → 이유 설명 → 수정·검증 순서로 풀고, 각 정답은 먼저 생각한 뒤 펼친다.

## 목표와 실행 조건

text-shadow·box-shadow의 이동값과 blur를 구별한다. 그림자가 그려지는 범위와 레이아웃 크기, 포인터 모양과 기능을 분리한다.

본문의 [전체 실행 파일](../책형_복습/11_CSS_그림자와_시각효과.html)을 별도로 열어 실험한다. 아래 조각을 다른 원본 CSS에 그대로 덧붙이면 기존 규칙과 경쟁할 수 있다. 실험 전 원래 파일을 보존하고 매번 한 조건만 바꾼다. 브라우저에서 확인한 것과 코드 기준 예상을 따로 적는다.

## 문제 1. 작은 예제의 결과 예상

**새 설명 예제의 CSS와 body 조각**이다. 전체 파일은 위 링크에 있다. 어떤 요소가 선택되고 무엇이 어떻게 보일지 적는다. 크기가 있으면 내용·테두리 기준도 구분한다.

```css
        .text { text-shadow: 2px 3px 4px red; }
        .box { width: 150px; height: 80px; border: 1px solid black; }
        .box:hover { box-shadow: 4px 4px 6px gray; cursor: pointer; }
```

```html
    <h1>그려지는 범위</h1>
    <p class="text">글자 그림자</p>
    <div class="box">상자에 포인터 올리기</div>
    <p>다음 문단</p>
```

<details>
<summary>힌트와 풀이</summary>

**힌트:** 선택자 → 속성 → 기준값 → 상태 순서로 읽는다. 주석은 실행하지 않는다.

text는 글자 주변에 빨간 그림자를 만든다. box는 포인터를 올릴 때만 회색 그림자가 나타난다. box 내용 너비150·테두리2=152px라는 계산은 그림자 전후에 그대로다. 그림자 크기만큼 다음 문단이 밀리는 배치는 아니다. 클릭 기능은 구현하지 않았다.

</details>

## 문제 2. 비슷한 개념을 설명하기

1. blur는0~1의 투명도값인가?
2. 그림자가 커지면 width도커지는가?
3. pointer를주면 클릭기능이생기는가?

숫자나 속성 이름만 적지 말고 왜 그런지 문장으로 설명한다. 필요한 전제도 함께 쓴다.

<details>
<summary>풀이와 원본으로 돌아갈 지점</summary>

blur는 이 예제에서 px길이다. 그림자는 원래 레이아웃 width를 늘리지 않는다. cursor는 포인터 모양이며 클릭기능을 만들지 않는다.

실제 작성 기록에서 확인할 부분은 다음과 같다.

내 .red는10px 3px red라 오른쪽10·아래3 그림자다. .blur는2px 2px 4px red에 실제 글자 white·2em을 따로 지정했다. ‘blur투명도처리’ 메모는 흐림 반경으로 교정한다. .box2의 hover 그림자는4·4·6px이며 gray와 강사님의 grey는 같은 색 이름이다.

</details>

## 문제 3. 한 조건을 바꾸고 확인하기

먼저 **blur4만0px**를 적용했을 때의 차이를 예상한다. 예상한 뒤 실제 파일의 해당 선언 하나를 바꾸고 저장·새로고침하여 비교한다. 이후 나머지 변경도 한 번에 하나씩 실험한다. 전환·hover는 상태 변화 전후를, 너비 조건은 경계값을 구분한다.

<details>
<summary>변경 실험의 예상과 점검</summary>

| 한 가지 변경 | 예상 | 구별 |
| --- | --- | --- |
| blur4만0px | 더선명한그림자 | 투명도아님 |
| x2만-2px | 왼쪽으로이동 | 본문글자위치유지 |
| box blur6만12px | 흐림범위변화 | width150유지 |
| cursor만제거 | 기본포인터로돌아감 | 클릭기능변화아님 |

그림자 색과 글자 color를 혼동하면 글자가 왜 하얀지 설명하지 못한다. 먼저 본문 color, 그다음 shadow 색을 별도 선언으로 읽는다.

</details>
