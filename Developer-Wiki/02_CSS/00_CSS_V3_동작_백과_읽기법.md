# CSS V3 동작 백과 읽기법

> CSS 속성 이름을 외우는 대신, 브라우저가 어떤 요소에 어떤 규칙을 선택하고 크기·위치·색상을 계산해 화면에 그리는지 다시 설명하고 재현하기 위한 공통 안내서다.

## 1. CSS가 화면이 되는 전체 과정

```text
HTML 파싱 → DOM 생성
CSS 파싱 → CSSOM 생성
선택자로 요소와 규칙 연결
→ 상속·우선순위·작성 순서로 최종 선언 결정
→ 단위와 상속값을 계산한 computed style 생성
→ 박스의 크기·위치를 계산하는 layout
→ 배경·글자·테두리를 그리는 paint
→ 필요한 레이어를 합성해 화면 표시
```

CSS는 요소를 직접 만들지 않는다. HTML 요소가 있어야 선택자가 대상을 찾을 수 있다. 규칙이 무시되었다면 속성을 다시 쓰기 전에 선택자가 실제 요소와 일치하는지, 더 강한 규칙에 덮였는지, 값이 유효한지부터 확인한다.

## 2. 한 선언을 읽는 법

```css
.card {
  width: 300px;
  padding: 20px;
  border: 2px solid #333;
}
```

`.card`는 적용 대상을 찾는 선택자이고, `width`·`padding`·`border`는 속성, 오른쪽은 속성값이다. 기본 `box-sizing: content-box`라면 보이는 바깥 너비는 콘텐츠 300 + 좌우 padding 40 + 좌우 border 4 = 344px다. `border-box`이면 지정한 300px 안에 padding과 border가 포함된다.

## 3. 값은 어디를 기준으로 계산되는가

| 값 | 기준 |
|---|---|
| `px` | CSS 픽셀 |
| `%` | 속성에 따라 containing block 등 기준이 달라짐 |
| `em` | 해당 요소의 계산된 글자 크기와 관련 |
| `rem` | 루트 요소의 글자 크기 |
| `vw`, `vh` | viewport 너비·높이 |
| `auto` | 해당 레이아웃 알고리즘이 남은 공간과 조건으로 계산 |

같은 `%`라도 모든 속성이 같은 기준을 쓰는 것은 아니다. 문서에서 기준 요소와 containing block을 함께 확인한다.

## 4. 개발자 도구에서 확인하는 위치

- Elements: 실제 DOM 구조와 적용 class를 확인한다.
- Styles: 어떤 규칙이 적용되고 어떤 선언이 취소선 처리되었는지 본다.
- Computed: 최종 계산값과 상속 출처를 확인한다.
- Box Model: content, padding, border, margin의 실제 크기를 확인한다.
- Layout: Flex/Grid 정렬과 overlay를 확인한다.
- Device Toolbar: viewport를 바꾸며 미디어 쿼리를 검증한다.

## 5. 보이지 않는 문제의 추적 순서

1. HTML 요소와 class/id가 실제로 존재하는가?
2. CSS 파일 경로와 `<link>`가 올바른가?
3. 선택자가 일치하며 선언 값이 유효한가?
4. 더 높은 우선순위 또는 뒤의 규칙에 덮였는가?
5. 크기가 0이거나 부모에 잘렸는가?
6. `display`, `visibility`, `opacity`, 색상 때문에 보이지 않는가?
7. 위치·쌓임 맥락·viewport 밖으로 이동하지 않았는가?

## 6. 원본 비교 규칙

- 내 코드는 `workspace_html/css`의 번호형 HTML/CSS를 기준으로 한다.

- 결과 화면만 보지 않고 Styles·Computed·Box Model의 근거로 차이를 설명한다.
- 원본 오탈자도 실제 파일명과 동작을 구분해 기록한다.
- 원본에 없는 보충 설명은 `Wiki 확장 학습`으로 표시한다.
