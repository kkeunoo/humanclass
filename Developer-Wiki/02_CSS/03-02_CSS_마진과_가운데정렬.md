# 03-02. 마진과 가운데 정렬 — 남는 공간과 맞닿는 간격

[CSS 목차](README.md) · [읽기 안내](00_CSS_V3_동작_백과_읽기법.md)

상자 바깥의 간격을 만드는 margin은 상황에 따라 남은 공간을 나누기도 하고, 세로 간격끼리 상쇄되기도 한다. 숫자를 모두 더하기 전에 어느 요소 사이의 어떤 방향인지 확인한다.

## 1. 이 장에서 배울 것

일반 block의 가로 auto margin 조건과 계산을 설명한다. 형제 사이·부모 자식 사이 세로 마진 상쇄를 구별한다.

이번 장의 개념과 원본 기능은 수업 범위다. 원본에 없는 선택 기능은 9절 TIP으로 구분한다. 결과를 읽을 때는 선택된 요소·속성·기준값·실행 상태를 함께 적는다.

<a id="concepts"></a>

## 2. 무엇이며, 왜 필요한가

일반 흐름의 block에서 사용할 너비가 정해지고 부모에 남는 가로 공간이 있으면 좌우 auto margin이 그 공간을 나눈다. 부모 내용 너비 500px, 테두리까지 자식 200px이면 300px가 남아 좌우 150px씩이다. `margin:10px auto`의 첫 값은 위아래 10px이며, 두 번째가 좌우 auto다. text-align:center는 주로 안쪽 글·인라인 내용을 정렬하는 것이므로 상자 자체의 가로 가운데 배치와 다르다.

세로 마진은 일반 block 흐름의 조건에서 **상쇄**될 수 있다. 앞 상자 아래 30px와 다음 위 50px가 맞닿아 상쇄되면 간격은 80이 아닌 50px다. 이는 두 양수의 예다. 음수까지 있을 때 무조건 큰 숫자만 고르지는 않는다.

| 관계 | 확인할 것 |
| --- | --- |
| 형제의 아래·위 마진 | 두 양수 세로 마진이 상쇄되는 조건인가? |
| 부모와 첫·마지막 자식 | 경계·padding·내용 등으로 분리되는가? |
| 좌우 마진 | 같은 세로 상쇄 규칙을 적용하지 않음 |
| auto 정렬 | 현재 배치 방식·너비·남는 공간 확인 |

‘세로 auto는 안 된다’는 말도 이 일반 block 상황에 한정한다. 이후 Flex의 auto margin 등 다른 배치 방식에 그대로 확장하지 않는다.

> 📚 **출처 · 본문 설명 확인:** [W3C 마진과 상쇄](https://www.w3.org/TR/CSS2/box.html#margin-properties). 설명과 비교 표는 수업 원본을 바탕으로 새로 풀어 썼다. 외부 원문을 직접 인용한 문장은 아니다. 확인일: 2026-10-28.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 전체 파일.** [실행 파일](실습/책형_복습/03-02_CSS_마진과_가운데정렬.html)을 브라우저로 연다. 이 예제는 위 style 안에 CSS를 모두 넣어 외부 파일 연결이 필요 없다. 원본 CSS에 붙이면 다른 규칙이 섞일 수 있으므로 먼저 별도 파일로 확인한다.

```html
<!DOCTYPE html>
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>03-02. 마진과 가운데 정렬 — 남는 공간과 맞닿는 간격</title>
    <style>
        .parent { width: 500px; border: 1px solid black; }
        .child { width: 200px; margin: 10px auto; background-color: lightblue; }
        .first { margin-bottom: 30px; background-color: pink; }
        .second { margin-top: 50px; background-color: lightgreen; }
    </style>
</head>
<body>
    <h1>마진의 두 역할</h1>
    <div class="parent"><div class="child">가운데 상자</div></div>
    <div class="first">첫 상자</div>
    <div class="second">둘째 상자</div>
</body>
</html>
```

child는 별도 border·padding이 없어 테두리까지 200px다. 부모의 내용 영역 500px에서 남은 공간을 나눠 좌우 150px이다. 첫·둘째 상자 사이에서는 일반 block 흐름의 두 양수 세로 마진이 맞닿아 50px 간격을 예상한다. 부모 테두리 1px는 그 부모의 내용 500px 바깥이므로 정렬 기준 계산에 섞지 않았다.

## 4. 내가 작성한 코드를 따라 읽기

아래는 **내 원본 발췌**다. 주석의 표현도 원문대로 두었다. 설명에서 교정한 내용을 원본에 이미 수정한 것처럼 읽지 않는다.

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_html/css/asset/css/03_box.css` 93–100행

```css
#auto {
    border: 1px solid red;
    width: 250px;

    /* margin: auto는 너비가 100%가 아닌 경우에만 가능함(100%일 경우에는 꽉 차있기 때문에) 
    위, 아래는 auto가 먹지 않기 때문에 0 auto로 기재한 것, 사이즈를 조절해도 가운데 고정 */
    margin: 10px auto;
}
```

**발췌 바로 풀이:** 원리는 같고 너비만 250px다. 내 주석의 “위아래 auto가 먹지 않는다”는 이 일반 block 배치에 한정해 읽는다. 다른 배치 방식까지 모두 불가능하다는 뜻은 아니다. 글자 자체를 가운데 놓는 `text-align:center`와 상자 자체의 가운데 정렬도 구분한다.

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_html/css/asset/css/03_box.css` 139–153행

```css
#div2, #div3 {
    margin: 30px;
}

#div3 {
    margin: 50px;
}

#div1 {
    /* border: 1px solid red; */

    /* padding-top: 1px; */

    overflow: hidden;
}
```

**발췌 바로 풀이:** 선언은 같다. 부모 `#div1`의 `overflow:hidden`은 부모와 첫·마지막 자식 사이의 마진 상쇄를 막는 효과가 있다. **자식 div2와 div3 사이의 상쇄까지 전부 없애는 것은 아니다.**

내 #auto는 width250·border1이어서 테두리까지 252px다. 강사님 width150은 테두리까지152px다. 같은 부모 너비라면 남는 공간이 달라지지만 둘 다 가운데를 유지하는 원리는 같다. 두 번째 발췌의 div2·div3은 30·50px 세로 마진을 비교하고, 부모 div1에는 overflow:hidden이 활성화되어 있다.

<a id="connections"></a>

## 5. 파일·요소·값이 연결되는 흐름

부모 내용 너비 → 자식의 테두리까지 너비 → 남은 가로 공간 → 좌우 auto 배분 순서로 계산한다. 세로는 다른 화살표다. div1과 첫 자식 사이 관계, div2·div3 형제 사이 관계를 따로 그린다. 부모 overflow:hidden은 부모·자식의 상쇄를 막는 효과가 있어도 형제끼리의 상쇄를 모두 없애지 않는다.

<a id="review"></a>

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 너비를 바꿔도 가운데가 유지되는 관찰을 주석으로 남겼다. **아쉬운 점:** 배치 조건이 빠진 일반화는 다음 장에서 혼란을 줄 수 있다. **개선 방향:** auto를 쓰기 전에 현재 block인지, 남는 공간이 있는지 적는다. overflow:hidden을 간격 문제에 무조건 붙이는 처방으로 외우지 않는다. 내용이 잘릴 수 있기 때문이다.

제안은 원본을 수정한 결과가 아니다. **실제 오류**, **관찰을 위한 수업용 단순화**, **목적에 따라 가능한 선택**을 구별한다. 단지 짧게 쓰거나 최신 기능을 쓴다고 더 좋은 코드는 아니다.

<a id="teacher"></a>

## 7. 강사님 코드가 도움이 되는 비교



양쪽의 핵심 차이는 #auto 너비이며 마진 상쇄 규칙은 같다. 중복 원문 대신 내 발췌와 수치 비교를 남겼다. 주석 처리한 border·padding-top은 실험 후보이며 지금 동시에 적용되는 조건이 아니다.

## 8. 결과를 예상하고 한 가지 바꾸기

아래는 **명시한 조건에서의 코드 기준 예상**이다. 이번 편집에서 실제 브라우저 렌더링을 재실행했다는 기록과 구별한다. 매 실험은 원래 예제로 돌아가 한 조건만 바꾼다.

| 한 가지 변경 | 예상 | 이유 |
| --- | --- | --- |
| 새 예제 child만 300px | 좌우100px | 남은200을 나눔 |
| 원래 child에 border1 추가 | 좌우149px | 실제너비202 |
| 원래 second 위만20px | 형제간격30px | 양수30·20 상쇄 |

원본 자식 사이 간격이 부모 overflow:hidden을 줘도50px라면 곧바로 CSS 미적용으로 판단하지 않는다. 어떤 두 요소 사이를 재고 있는지 먼저 확인한다. 좁은 화면의 넘침과 가운데 배치는 별도 조건이다.

## 9. 추가로 알면 좋은 것과 출처

> 💡 **TIP · 수업 범위 밖:** display:flow-root와 서식 맥락 전체 이론은 별도 확장이다. 원본 관찰만으로 새 레이아웃 기능 전체를 배웠다고 간주하지 않는다.



이 절의 확장은 기본 문제의 필수 조건이 아니다. 2절의 📚 출처는 배운 기능의 설명을 확인하는 근거이며, 출처가 있다는 이유로 모두 수업 밖 내용인 것은 아니다.
