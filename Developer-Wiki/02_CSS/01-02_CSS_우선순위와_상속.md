# 01-02. 우선순위와 상속 — 왜 내가 쓴 색이 안 나올까

[CSS 목차](README.md) · [선택자로 돌아가기](01_CSS_선택자와_적용방법.md)

먼저 선택자가 요소에 맞는지, CSS 파일을 불러왔는지, 주석·오타는 없는지 확인한다. 여러 선언이 **같은 요소의 같은 속성**을 바꾸려 할 때 우선순위를 비교한다.

**설명용 예:** `p { color: blue; }`와 `.notice { color: red; }`가 함께 있고 HTML이 `<p class="notice">안내</p>`라면 글자는 빨강이다. 둘 다 같은 문단에 맞지만 클래스 선택자가 타입 선택자보다 구체적이기 때문이다. 이제 실제 원본의 `!important`와 인라인 선언까지 더해진 결과를 추적한다.

## 1. 원본의 테두리 경쟁

### 강사님 코드

`01_selector.html` 161~178행 — **원본 발췌**

```css
        #div2 {
            border: 1px solid aqua;
        }
        /* div {
            border: 1px solid red;
        } */

        [human] {
            border: 1px solid pink !important;
        }

        .c4 {
            border: 1px solid blue;
        }

        div {
            border: 1px solid red;
        }
```

원본 div2에는 `id="div2"`, `class="c4"`, `human="천안"`, 인라인 검정 테두리가 함께 있다. 이 경우 `[human]`의 분홍 테두리에 `!important`가 있으므로 최종 테두리는 분홍이다. 단순히 “마지막 div 규칙이 이긴다”가 아니다.

### 내 코드

`01_selector.html` 172~186행 — **원본 발췌**

```css
            #div2 {
                border: 1px solid aqua;
            }
            
            [human] {
                border: 1px solid pink !important;
            }
            
            .c4 {
                border: 1px solid blue;
            }
            
            div {
                border: 1px solid red;
            }
```

선언과 결과가 같다. `human`은 원본의 선택자 실험용 속성 이름이다. 새로운 HTML 속성 설계의 권장 예제로 받아들이지는 않는다.

<a id="section-2"></a>

## 2. 수업 범위에서 판단하는 순서

이 예제처럼 같은 작성자 스타일이고 별도 레이어·애니메이션·전환 경쟁이 없는 경우를 살핀다.

1. `!important` 선언과 일반 선언을 구분한다. `!important`는 선택자의 점수를 올리는 문법이 아니다.
2. 일반 선언끼리는 인라인 선언이 원본의 일반 스타일 규칙보다 우선한다.
3. 스타일 규칙끼리는 명시도, 즉 선택자의 구체성을 비교한다.
4. 앞 조건이 같다면 나중에 선언한 것이 이긴다.

| 선택자 예 | 명시도: ID / 클래스·속성·가상 클래스 / 타입·가상 요소 |
| --- | --- |
| `#li3` | 1 / 0 / 0 |
| `[id=li3]` | 0 / 1 / 0 |
| `li.c1.c2` | 0 / 2 / 1 |
| `div strong` | 0 / 0 / 2 |
| `*` | 0 / 0 / 0 |

각 칸을 왼쪽부터 비교한다. 단순한 십진수 덧셈으로 외우면 안 된다. 공백·`>`·`+` 자체는 점수를 더하지 않는다. **원본의 간단한 우선순위 주석을 CSS 전체에 예외 없는 서열로 확장하지 않는다.** [캐스케이드 표준](https://www.w3.org/TR/css-cascade-5/#cascade-sorting)

## 3. 상속과 직접 지정은 다르다

`color`, `font-size`는 일반적으로 부모에서 자식으로 상속된다. 하지만 자식에 적용되는 선언이 있으면 그 값을 먼저 결정한다. 부모의 ID가 강하다고 해서 자식에 직접 지정한 색을 이기는 방식이 아니다.

```html
<!-- 설명용 재구성: 본문에 넣을 조각 -->
<style>
    #parent { color: red; }
    span { color: blue; }
</style>
<div id="parent">부모 <span>자식</span></div>
```

부모 글자는 빨강, span 글자는 파랑이다. 둘은 서로 다른 요소에 적용된 선언이다. 원본의 `* { color: red; }`는 모든 요소에 직접 적용하는 규칙이라, `body { color: red; }`에서 상속받게 하는 것과도 구분한다.

배경색은 기본적으로 상속되지 않는다. 자식 배경이 투명해서 부모 배경이 보이는 것을 상속으로 착각하기 쉽다. 내 `02_단위.html` 13행 주석은 이 구분을 잘 짚었다.
