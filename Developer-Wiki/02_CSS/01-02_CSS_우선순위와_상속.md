# 01-02. 우선순위와 상속 — 적용될 값을 어떻게 고를까

[CSS 목차](README.md) · [읽기 안내](00_CSS_V3_동작_백과_읽기법.md)

선택자가 맞는데도 원하는 색이 나오지 않으면 같은 속성을 바꾸는 다른 선언을 확인한다. CSS는 모든 값을 무조건 더하는 것이 아니라 요소의 속성마다 사용할 값을 정한다. 그 결정 과정과 부모에서 값을 이어받는 과정은 다르다.

<a id="learn"></a>

## 1. 이 장에서 배울 것

동일 요소·동일 속성의 경쟁을 찾는다. 수업 조건에서 important·인라인·명시도·순서를 비교하고, 상속과 자식 직접 지정을 구분한다.

이번 장의 개념과 원본 기능은 수업 범위다. 원본에 없는 선택 기능은 9절 TIP으로 구분한다. 결과를 읽을 때는 선택된 요소·속성·기준값·실행 상태를 함께 적는다.

<a id="concepts"></a>

## 2. 무엇이며, 왜 필요한가

**캐스케이드**는 여러 선언에서 적용할 값을 정하는 과정이고, **명시도**는 그 판단 중 선택자의 구체성을 비교하는 기준이다. 명시도 하나가 전체 우선순위 규칙은 아니다. 수업처럼 같은 작성자 스타일, 별도 레이어·전환·애니메이션 경쟁이 없는 조건에서는 important 여부 → 일반 인라인과 규칙 구분 → 규칙 명시도 → 같은 조건에서 뒤 선언 순서로 읽는다. !important는 선택자 점수를 더하는 문법이 아니다.

| 선택자 | ID / 클래스·속성·가상 클래스 / 타입·가상 요소 |
| --- | --- |
| `#li3` | 1 / 0 / 0 |
| `[id=li3]` | 0 / 1 / 0 |
| `li.c1.c2` | 0 / 2 / 1 |
| `div strong` | 0 / 0 / 2 |
| `*` | 0 / 0 / 0 |

각 칸을 왼쪽부터 비교한다. 십진수처럼 합산해 ‘클래스 열 개면 ID 하나’라고 계산하지 않는다. 관계를 나타내는 공백·>·+ 자체는 점수를 올리지 않는다.

**상속**은 자식의 값을 정할 때 부모의 값을 이어받는 것이다. color·font-size는 일반적으로 상속하지만 배경색은 기본적으로 상속하지 않는다. 투명한 자식 뒤로 부모 배경이 보이는 것은 상속과 다르다. 자식에 직접 color가 지정되면 부모 ID의 점수와 자식 선택자 점수를 서로 겨루는 방식이 아니다.

> 📚 **출처 · 본문 설명 확인:** [W3C 캐스케이드·상속](https://www.w3.org/TR/css-cascade-5/)와 [선택자 명시도](https://www.w3.org/TR/selectors-4/#specificity-rules). 설명과 비교 표는 수업 원본을 바탕으로 새로 풀어 썼다. 외부 원문을 직접 인용한 문장은 아니다. 확인일: 2026-10-28.

## 3. 작은 예제로 먼저 이해하기

**새 설명 예제 · 전체 파일.** [실행 파일](실습/책형_복습/01-02_CSS_우선순위와_상속.html)을 브라우저로 연다. 이 예제는 위 style 안에 CSS를 모두 넣어 외부 파일 연결이 필요 없다. 원본 CSS에 붙이면 다른 규칙이 섞일 수 있으므로 먼저 별도 파일로 확인한다.

```html
<!DOCTYPE html>
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>01-02. 우선순위와 상속 — 적용될 값을 어떻게 고를까</title>
    <style>
        #parent { color: red; }
        span { color: blue; }
        .notice { color: green; }
        p { color: purple; }
    </style>
</head>
<body>
    <h1>값 결정 관찰</h1>
    <div id="parent">부모 <span>자식</span></div>
    <p class="notice">안내</p>
</body>
</html>
```

부모의 직접 글자는 빨강이고 span은 파랑이다. 부모 ID의 강한 선택자가 자식의 직접 선언을 이기려는 경쟁이 아니다. 안내 p에서는 두 규칙이 같은 요소·속성을 겨룬다. 클래스가 타입보다 구체적이어서 뒤에 p 규칙이 있어도 초록이다.

## 4. 내가 작성한 코드를 따라 읽기

아래는 **내 원본 발췌**다. 주석의 표현도 원문대로 두었다. 설명에서 교정한 내용을 원본에 이미 수정한 것처럼 읽지 않는다.

### 내 코드 — 원본 발췌

출처: `D:/workspace/workspace_html/css/01_selector.html` 172–186행

```css
            #div2 {
                border: 1px solid aqua;
            }
            
            [human] {
                border: 1px solid pink !important;
            }
            
            .c4 {
                border: 1px solid blue;
            }
            
            div {
                border: 1px solid red;
            }
```

**발췌 바로 풀이:** 선언과 결과가 같다. `human`은 원본의 선택자 실험용 속성 이름이다. 새로운 HTML 속성 설계의 권장 예제로 받아들이지는 않는다.

내 원본은 div2에 ID·class·human 속성을 붙이고 인라인의 검정 테두리도 둔 실험이다. 발췌의 [human]에만 !important가 있어 현재 테두리는 분홍이다. 마지막 div 규칙이 빨강이라는 사실만으로 최종값을 정할 수 없다. human은 원본 실험용 속성 이름이며 새 HTML 속성 설계의 권장 명명 예시는 아니다.

<a id="connections"></a>

## 5. 파일·요소·값이 연결되는 흐름

현재 div2 → 맞는 border 선언 목록 작성 → important 후보 구분 → 남은 단계 비교 → 테두리 결정 순서다. 주석 처리한 선언은 후보에서 제외한다. 상속은 이 경쟁과 구분하여 부모·자식 각각의 요소에서 본다. 전체 선택자 *는 모든 요소에 직접 적용하는 것이므로 body에 색을 주어 상속시키는 것과 결과가 달라질 수 있다.

<a id="review"></a>

## 6. 잘한 점·아쉬운 점·개선 방향

**잘한 점:** 한 요소에 여러 선택 조건을 모아 충돌을 관찰할 수 있다. **아쉬운 점:** 짧은 서열만 외우면 사용자 스타일·레이어·전환이 있는 경우에도 같은 답을 낼 위험이 있다. **개선 방향:** 기본 규칙을 이해한 뒤에는 불필요하게 경쟁하는 선언을 줄이고 클래스 역할을 명확히 한다. important는 무조건 잘못된 문법이 아니라 이 예제에서 경쟁을 드러내는 장치다.

제안은 원본을 수정한 결과가 아니다. **실제 오류**, **관찰을 위한 수업용 단순화**, **목적에 따라 가능한 선택**을 구별한다. 단지 짧게 쓰거나 최신 기능을 쓴다고 더 좋은 코드는 아니다.

<a id="teacher"></a>

## 7. 강사님 코드가 도움이 되는 비교



강사님과 내 활성 선언·현재 결과는 같다. 중복 코드는 재인용하지 않는다. 순서를 비교할 때는 양쪽의 주석까지 실행한다고 가정하지 않고, 실제 HTML의 인라인 선언도 후보에 포함한다.

## 8. 결과를 예상하고 한 가지 바꾸기

아래는 **명시한 조건에서의 코드 기준 예상**이다. 이번 편집에서 실제 브라우저 렌더링을 재실행했다는 기록과 구별한다. 매 실험은 원래 예제로 돌아가 한 조건만 바꾼다.

| 원본에서 한 조건 변경 | 예상 테두리 | 판단 |
| --- | --- | --- |
| important만 제거 | 검정 | 일반 인라인이 남음 |
| 처음 원본에서 인라인만 제거 | 분홍 | important가 여전히 있음 |
| important와 인라인 제거한 별도 조건 | aqua | ID 규칙이 남은 일반 규칙보다 구체적 |

실행 파일에서 span의 color 선언만 지우면 부모의 빨강을 상속할 수 있다. 안내의 클래스 선언을 지우면 p 규칙의 보라가 남는다. 순서 문제를 보기 전에 대상과 속성이 실제로 같은지 확인한다.

## 9. 추가로 알면 좋은 것과 출처

> 💡 **TIP · 수업 범위 밖:** 레이어·사용자 스타일·애니메이션·전환까지 포함한 전체 캐스케이드 순서는 별도 심화다. 위의 수업 조건을 CSS 전체에 예외 없는 서열로 확장하지 않는다.



이 절의 확장은 기본 문제의 필수 조건이 아니다. 2절의 📚 출처는 배운 기능의 설명을 확인하는 근거이며, 출처가 있다는 이유로 모두 수업 밖 내용인 것은 아니다.

## 10. 복습과 빠른 정리

1. 클래스 규칙보다 뒤에 쓴 타입 규칙은 언제나 이기는가?
2. 배경이 비쳐 보이면 상속인가?
3. important는 ID 개수를 늘리는가?

<details>
<summary>짧은 풀이 — 먼저 답한 뒤 확인</summary>

언제나 이기지 않는다. 앞 단계와 명시도가 같아야 선언 순서가 결정한다. 투명한 배경을 통해 보이는 것과 상속은 다르다. important는 별도 중요도 판단이며 ID 개수를 바꾸지 않는다.

</details>
